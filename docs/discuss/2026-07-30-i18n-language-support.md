# FileDock i18n 多语言支持讨论记录

## 原始需求

> 我想为当前项目增加支持 i18n 多语言功能，English 和简体中文。要求页面支持切换语言，后端返回的响应信息或者提示信息等都要给出对应的语言。另外我在 `pkg/errc/errc.go` 中也实现了错误信息的多语言版本示例，可以在请求头中携带当前用户选择语言信息，由此匹配到对应的响应。先分析当前项目，然后给出实现规划。

用户后续补充：需要在项目 `AGENTS.md` 中明确约束，后续实现的功能也必须增加多语言支持。

## 项目现状分析

- 前端使用 React 18、TypeScript、Vite、React Router、TanStack Query 与 axios。
- 当前前端只有最小版本状态页，所有用户可见文案均硬编码为简体中文，未引入 i18n 依赖。
- axios 已集中创建客户端实例，适合统一添加语言请求头。
- 后端使用 Go、Fiber 和统一响应包，当前只有 `/version` 服务接口。
- 统一响应包已预留基于 Fiber Locals 的翻译函数入口，但服务端未注册语言中间件或翻译器，因此当前未真正启用。
- 错误码包包含中英文 map 示例，但英文翻译大量缺失，部分视频、发票错误码与 FileDock 无关，错误目录也未接入统一响应链路。
- 错误对象当前主要保存最终字符串，不利于在响应出口根据请求语言翻译。
- 参数校验器固定使用中文翻译器，无法按请求语言切换。
- Fiber 全局错误处理直接返回原始错误字符串，未统一使用业务响应结构，存在语言不一致及内部技术信息泄漏风险。
- 当前改造无需修改数据库表结构，也无需处理历史兼容。

## 问答记录

### 1. 语言请求协议怎么定？

**问题：** 是否采用标准 `Accept-Language` 请求头，以 `zh-CN` 和 `en` 为规范值，并兼容常见语言变体？

**推荐答案：** 前端发送 `Accept-Language: zh-CN` 或 `Accept-Language: en`；后端将 `zh`、`zh-CN` 归一化为简体中文，将 `en`、`en-US` 等归一化为 English；请求头缺失或不支持时回退 `zh-CN`；响应增加 `Content-Language`。

**用户回答：** 确认。

### 2. 首次打开页面如何确定语言？

**问题：** 是否依次读取 localStorage、浏览器语言，最后回退 `zh-CN`；切换后立即刷新文案、保存选择、更新 `<html lang>`，且不修改 URL？

**推荐答案：** 采用该优先级及行为。

**用户回答：** 确认。

### 3. 后端哪些内容需要翻译？

**问题：** 是否翻译 API 消息、参数校验、鉴权权限及资源类业务提示、全局 HTTP 提示和 SSE 用户提示，同时不翻译日志、错误码、DTO 字段、机器状态值、用户内容及内部技术错误？

**推荐答案：** 所有面向用户的内容翻译；机器协议和内部诊断信息保持稳定。技术错误只写日志，客户端只接收安全通用译文。

**用户回答：** 确认。

### 4. 后端翻译目录怎么组织？

**问题：** 是否建立独立 i18n 核心，使用内嵌的 `zh-CN.json`、`en.json`，错误码只映射翻译键，错误对象保存错误码、插值参数和内部 cause，最终在响应出口翻译？

**推荐答案：** 采用独立深模块，替代当前两份巨大且不完整的错误文本 map。

**用户回答：** 确认。

### 5. 页面语言切换器采用什么样式？

**问题：** 是否在页面右上角放置下拉菜单，选项显示“简体中文”和“English”，不用国旗图标，支持键盘操作并即时切换？

**推荐答案：** 采用可访问的文字下拉菜单，当前最小首页所有文案同步切换。

**用户回答：** 确认。

### 6. 前端如何显示 API 错误？

**问题：** 是否直接显示后端已经本地化的业务 `message`，由前端词典负责网络错误、超时和后端不可达提示，保持 `code` 稳定，不增加 `message_key`？

**推荐答案：** 采用该边界，避免前后端重复维护业务错误翻译；通过 `Content-Language` 标明响应语言。

**用户回答：** 确认。

### 7. 参数校验错误返回什么格式？

**问题：** 是否保持现有响应结构，仅在 `message` 返回首个本地化校验错误，字段名使用 DTO JSON 名，不暴露 Go 结构名和校验标签？

**推荐答案：** 保持统一响应结构，不新增字段；首个错误提供清晰、稳定的双语提示。

**用户回答：** 确认。

### 8. 成功响应是否也翻译？

**问题：** 是否将 `zh-CN` 成功消息改为“操作成功”，将 English 成功消息设为 `Success`，并接受这会修改 `/version` 当前固定 `message: "success"` 的契约、测试和文档？

**推荐答案：** 成功、创建成功等所有面向用户的响应消息均翻译，并同步修改契约资料。

**用户回答：** 需要。

### 9. 语言选择是否保存到后端？

**问题：** 是否只在前端 localStorage 保存语言选择，不写 Cookie、数据库或用户配置，后端完全根据每次请求头无状态处理？

**推荐答案：** 当前无账号体系，无需服务端持久化；未来账号语言偏好另行设计。

**用户回答：** 确认，后端不保存，只在前端 localStorage 保存；更换浏览器时显示默认语言。

### 10. 新浏览器是否读取浏览器语言？

**问题：** “更换浏览器显示默认语言”是否表示始终使用 `zh-CN`，从而覆盖此前浏览器语言优先的约定？

**推荐答案：** 为避免歧义，明确无 localStorage 时的检测规则。

**用户回答：** 保持浏览器语言优先；浏览器语言不支持时使用 `zh-CN`。

### 11. 现有无关错误码怎么处理？

**问题：** 是否删除来自旧项目的视频、发票专用错误码，保留通用错误码，未来按 FileDock 房间、文件、会话等业务逐步增加，并保证所有保留错误码中英文完整？

**推荐答案：** 项目处于开发阶段，直接清理无关定义，不维持兼容。

**用户回答：** 确认，按照当前项目业务需求调整，无用内容可以删除。

### 12. 计划修改模块是否符合预期？

**问题：** 后端修改 i18n 核心、错误码、错误对象、响应层、校验器、Fiber 语言中间件和全局错误处理；前端增加 i18next、语言资源、检测持久化、切换组件、axios 请求头和首页翻译；同步修改项目文档，是否符合预期？

**推荐答案：** 采用上述模块边界，核心语言逻辑保持独立可测。

**用户回答：** 确认。补充要求：项目 `AGENTS.md` 必须说明后续功能也要支持多语言。

### 13. 测试范围怎么定？

**问题：** 是否为语言头解析、语言归一化、回退、词典完整性、动态参数、错误码 HTTP 映射和双语校验编写单测；为 `/version`、`Content-Language`、404 和 500 编写集成测试；前端不新增测试框架，只执行 TypeScript/Vite 构建和手工验收？

**推荐答案：** 这些逻辑含回退和安全边界，后端应覆盖测试；当前前端交互简单，构建检查加手工验收足够。

**用户回答：** 确认。

### 14. 品牌名怎么翻译？

**问题：** 是否保持 `FileDock` 品牌名不变，中文页面显示名使用“码头”，English 页面显示 `FileDock`，其余产品说明、状态标签、按钮和提示全部翻译，而版本号、分支和提交哈希不翻译？

**推荐答案：** 品牌与机器数据稳定，用户界面说明按语言翻译。

**用户回答：** 确认。

### 15. 翻译缺失时如何处理？

**问题：** 是否在服务启动时校验中英文键集合一致，解析失败或缺译时启动失败；前端通过类型约束检查键结构；运行期先回退中文，再返回安全通用提示并记录日志，不向用户显示翻译键？

**推荐答案：** 采用严格模式，避免上线后出现混合语言或裸翻译键。

**用户回答：** 确认。

## 最终共同理解

1. FileDock 首期支持且仅支持 `zh-CN` 与 `en`。
2. 前端语言优先级为 localStorage、受支持的浏览器语言、`zh-CN`。
3. 语言切换在当前页面立即生效，只保存于 localStorage，不进入 URL、Cookie、数据库或用户资料。
4. 前端通过标准 `Accept-Language` 传递当前语言；后端解析标准语法及常见地区变体，并通过 `Content-Language` 回告实际语言。
5. 所有面向用户的前端文案、API 消息、参数校验、全局错误和未来 SSE 提示均提供双语；协议字段、状态值、用户内容与内部日志不翻译。
6. 后端建立独立、严格、可测试的 i18n 模块；错误码映射翻译键，错误对象不携带最终展示文案，响应出口执行翻译。
7. 服务启动时校验双语目录完整；缺译不得静默通过。运行时仍提供安全回退，不暴露翻译键或技术错误。
8. 成功响应也必须翻译，因此允许修改当前 `/version` 的消息契约、测试与相关文档。
9. 清理与 FileDock 无关的遗留错误码，不考虑旧代码兼容。
10. 当前语言切换器使用右上角文字下拉框；品牌名 `FileDock` 保持不变，不使用国旗表达语言。
11. 后端对语言解析、目录、错误映射、校验和 HTTP 响应编写自动化测试；前端本期使用构建检查与手工交互验收。
12. 更新项目 `AGENTS.md`，将新功能同步维护简体中文与 English 文案设为持续开发规则。
13. 本轮只产出讨论记录和 PRD；获得用户明确批准 PRD 后才开始实现。
