# 统一页面布局讨论记录

日期：2026-08-08

## 原始需求

当前主要页面是首页和房间页。虽然两页已经分别有顶部布局，但整体结构、滚动方式和底部区域仍不一致。希望将页面统一为顶部 Header、中间内容区域和底部 Footer，并保持不同页面切换时整体位置稳定。

公共 Header 左侧显示 Logo、网站标题和说明，右侧显示用户头像、昵称和通知入口；公共 Footer 中间显示版本信息。房间页可以在公共区域中增加房间摘要、分享等专属内容，底部右下角保留上传/下载传输浮层。

## 逐项确认

1. **Header/Footer 的滚动行为**：首页不使用独立中间滚动容器；房间页不滚动整个中间壳，而由文件列表、文件动态、回收站、聊天和成员列表等业务面板分别滚动。公共 Header/Footer 保持稳定位置。
2. **移动端策略**：保留现有移动端交互。首页正常情况下完整展示，内容超出时允许页面自然滚动；房间页继续使用工作区和抽屉/覆盖层，不强制三栏布局。
3. **房间 Header 中央摘要**：保留当前中央布局，显示成员数量、剩余时间和房间容量；首页中央区域为空。
4. **剩余时间宽度**：按最大时间文本预留宽度，并使用等宽数字，避免倒计时每秒变化导致布局抖动。
5. **Footer 默认信息**：优先显示版本号；没有版本号时显示短 Commit ID。桌面端 Tooltip 根据字段动态显示版本号、短 Commit ID、构建时间；没有版本号时只显示短 Commit ID 和构建时间。手机端不依赖 Tooltip，仍按版本号优先、短 Commit ID 兜底。
6. **Footer 复制**：点击 Footer 当前显示区域时复制短 Commit ID，无论当前显示的是版本号还是短 Commit ID。复制成功或失败均显示多语言反馈。
7. **传输浮层位置**：统一 Footer 始终保留版本信息；房间传输摘要和展开面板固定在 Footer 右下角上方，收起时不占用内容区域，展开/收回不改变页面整体高度，继续保留自动展开和完成后 5 秒收回。
8. **Header/Footer 容器**：两者共用同一个最大宽度和水平内边距；桌面端对齐，窄屏取消最大宽度限制但保留安全边距。
9. **房间右侧图标**：桌面端当前实际显示聊天、分享、通知、用户头像；成员入口仅在成员列表隐藏的窄屏端显示。确认保持该响应式规则。
10. **移除桌面聊天入口**：桌面端移除 Header 中聊天入口图标，聊天功能保留，通过左侧成员列表进入；窄屏端继续保留聊天入口。
11. **移除下箭头**：首页和房间页统一移除用户昵称右侧下箭头，但头像与昵称整体继续作为下拉菜单触发区域，头像与昵称之间统一使用约 0.5rem 间距。
12. **房间响应式范围**：保留现有 `<=1180px` 和 `<=760px` 断点及移动端成员抽屉、聊天覆盖层；本阶段主要调整桌面端公共布局。
13. **房间过渡状态**：加载、未设置昵称、加入确认、审批等待、错误、房间失效等状态也接入统一 Header/Footer；尚未成功加入时不显示房间摘要、分享和传输等专属内容。
14. **过渡页后续优化**：本阶段只做页面壳适配，不改过渡页业务逻辑和主要视觉；加入确认、审批等待等中间内容列为下一阶段重点。
15. **插槽化壳组件**：公共页面壳使用可选区域注入：`headerCenter` 房间摘要、`headerActions` 房间图标、`footerOverlay` 传输浮层、`content` 页面主体。
16. **品牌区域**：Logo、标题和说明区域始终链接首页；点击范围限制为实际品牌内容，不包含左侧空白区域。通过内容宽度链接和焦点样式实现。
17. **中间背景**：首页和房间页保留各自中间内容背景；Header/Footer 使用页面级主题变量，保持同色系并有轻微层次区分，不使用突兀的独立纯白/纯黑背景。
18. **Header/Footer 背景**：根据当前页面整体背景和浅色/深色主题适配，统一使用主题变量、边框和层次。
19. **中央摘要列宽**：成员、剩余时间、房间容量三项统一使用固定或可控列宽；英文允许更宽；优先单行，放不下时省略，不允许文本换行造成摘要位移。
20. **摘要省略信息**：被省略的英文或长文本通过 Tooltip 或 `title` 提供完整内容；手机端使用现有详情弹层或容量详情入口。
21. **复制反馈**：复用现有复制工具；成功显示多语言成功提示，失败显示多语言错误提示；Tooltip 内容不因点击改变；支持键盘 Enter/Space。
22. **复制兼容性验收**：覆盖 `http://127.0.0.1`、局域网 HTTP、HTTPS、桌面点击、键盘复制和失败提示场景。复用已有安全上下文 Clipboard 与 legacy fallback 逻辑。
23. **路由层壳架构**：倾向由路由层统一承载 `AppShell`，路由切换只替换中间内容和可选插槽，保持公共 Header/Footer 稳定。
24. **URL 兼容性**：本阶段不新增、不修改现有 URL 路由。首页仍为 `/`，房间及过渡状态仍为 `/rooms/:code`；分享继续是房间内弹层；复制邀请链接行为不变。
25. **CSS Grid 页面壳**：使用 `min-height: 100dvh` 的 CSS Grid 三行结构，不用 `position: fixed` 固定公共 Header/Footer；房间传输浮层单独使用 fixed 右下角定位。
26. **首页溢出**：首页正常情况下不设置独立滚动容器；窗口过矮、浏览器放大或大字体导致内容超出时，允许整个页面自然滚动。
27. **Footer 图标**：桌面端保留轻量 Info 图标，图标和文本共同组成可点击按钮；移动端可隐藏 Info 图标，仅显示可点击版本文本。
28. **双重缺失兜底**：版本号和 Commit ID 都不可用时显示 `dev`；Tooltip 只显示实际存在字段；无 Commit ID 时点击不复制并显示多语言提示。
29. **验收范围**：重点验证布局一致性、多语言、三种主题、桌面/平板/手机宽度、Footer 复制、传输浮层、URL 和分享行为；运行现有 `bun test`、`bun run build`、`make build` 后进行浏览器手动验证。

## 最终共识

本阶段实现一个可插槽化的统一 `AppShell`，由路由层复用，负责公共 Header、Footer、主题背景、页面高度和响应式容器。首页和房间页共享品牌区域、用户区域、通知入口和 Footer 版本信息，页面切换时不改变公共区域位置。

房间页通过插槽增加中央房间摘要、桌面端分享等专属动作，并在 Footer 右下角显示独立传输浮层。桌面端移除聊天入口和用户下箭头；窄屏保留现有聊天/成员入口。中央摘要三列固定或可控宽度，数字使用等宽字体，英文按更宽文本适配，超出时单行省略并提供完整内容提示。

Footer 优先显示版本号，缺失时显示短 Commit ID；Tooltip 动态展示可用的版本号、短 Commit ID、构建时间；点击复制短 Commit ID，并提供中英文成功/失败反馈。复制必须兼容 `127.0.0.1`、局域网 HTTP 和 HTTPS。

本阶段不修改任何 URL、业务 API 或房间过渡页核心逻辑。加入确认、审批等待等旧版中间内容的视觉重构列入下一阶段。
