# 首页连续水波纹与节点呼吸优化讨论记录

- 日期：2026-08-03
- 状态：已达成共识
- 讨论范围：首页雷达水波纹模型、波纹强度、响应式终点、减少动态效果、房间节点呼吸与交互边界

## 原始需求

用户测试上一版首页雷达后，认为四层固定尺寸圆环虽然增强了颜色，但视觉上仍接近固定靶环闪烁，没有形成理想的雷达波或水波纹扩散效果。用户希望：

1. 波纹从中心圆外侧向远处一圈圈荡开。
2. 每圈在生命周期内从小变大，到最外侧逐渐变浅并消失。
3. 扩散过程中出现深、浅、深、浅的视觉变化。
4. 波纹持续衔接；外圈到达边缘时，中心区域不能长时间没有新波纹。
5. 同屏波纹不能太空，也不能过密，不应机械限制为四个固定圆环。
6. 房间节点不再通过圆外彩色光圈表达呼吸，而是让圆形节点本体整体变大、变小。
7. 本轮继续使用 `caveman` 精简沟通，并使用 `grill-me` 逐项确认设计，暂不直接修改代码。

## 代码核对结论

- 正式首页雷达由一个 React 组件和全局样式共同实现，当前渲染四个波纹元素。
- 当前四个圆环各自使用 `52%`、`68%`、`84%`、`100%` 的固定宽度，再在各自尺寸附近进行小范围缩放，因此视觉上更像四层靶环，不是从同一起点持续向外传播的水波。
- 当前圆环周期约五秒，错峰约 1.25 秒，缓动为 `ease-out`。外圈减速会压缩波纹间距，不利于表现连续且近似等距的传播。
- 当前雷达画布已经由 `ResizeObserver` 获取宽高并重排节点，可以复用同一尺寸观察结果计算波纹终点，无需增加第二个观察器。
- 中心头像直径为 `112px`。波纹从头像外缘约 `10px` 处出现时，起始直径应约为 `132px`。
- 当前头像和昵称作为一个纵向组合整体居中，头像自身中心并未严格落在画布中心。新水波从头像外缘出发前，需要让头像中心、波纹圆心和画布中心严格重合，并将昵称独立放置在头像下方。
- 当前五个房间节点已经使用稳定槽位派生 `2.8～4.2s` 的呼吸周期和负延迟，无需增加状态或计时器。
- 当前节点头像本体缩放峰值为 `1.06`，同时增加 `0.5rem` 彩色外扩光圈。本轮需要删除彩色光圈并把本体峰值调整为 `1.08`。
- 当前节点已经是装饰元素：禁止指针事件、标记为对辅助技术隐藏，未连接点击房间逻辑。本轮应继续保持纯展示语义。
- 当前已同时通过组件状态类和 `prefers-reduced-motion` 媒体查询停止动画；新模型需要继续覆盖两条路径。

## 完整问答记录

### 问题 1：是否继续沿用四个固定尺寸圆环？

推荐答案：取消固定四层靶环模型。让所有波纹使用相同起点，每圈在完整生命周期内从中心向外扩散。

用户回答：同意，并指出不应机械限制为四圈；波纹需要连续衔接，避免外圈存在时中心区域空白。

### 问题 2：单圈波纹从哪里开始？

推荐答案：从中心头像外缘约 `10px` 之外出现。中心头像直径为 `112px`，因此波纹起始直径约为 `132px`。这样看起来像信号从用户头像发出，又不会与头像边缘粘连。

用户回答：确认。

### 问题 3：波纹数量、周期和发射间隔如何设置？

推荐答案：使用五圈连续波纹；每圈生命周期约五秒，每隔一秒发射一圈，同屏稳定存在约五圈。全部波纹使用负延迟初始化不同相位，首屏立即形成完整波列，不等待五秒填满。

用户回答：确认。

### 问题 4：波纹扩散到哪里结束？

推荐答案：根据雷达可视区实时尺寸计算，以画布较短边约 `90%` 作为最大直径，并在到达画布边缘前完全淡出。宽屏与窄屏使用相同占比，不写死桌面像素值。

用户回答：确认。

### 问题 5：单圈如何表现“深浅深浅”？

推荐答案：不把相邻波纹永久分成深圈和浅圈，而是在每个波纹自身生命周期中设置透明度节奏：`0%` 透明出现、约 `10%` 达到深色、约 `30%` 变浅、约 `50%` 回到次深、约 `72%` 再变浅、`100%` 完全消失。五圈错峰后，画面会自然形成不断向外移动的深浅交替。

用户回答：确认。

### 问题 6：五圈是否使用不同颜色或不同强度模板？

推荐答案：五圈使用相同 FileDock 青绿色和同一套关键帧。不要给奇偶圈永久绑定强弱，否则波纹身份固定，仍容易形成靶环感。深浅变化由单圈关键帧和一秒相位差共同产生。

用户回答：确认。

### 问题 7：波纹线条如何处理？

推荐答案：主线保持 `1px`，在主线周围增加约 `3～5px` 的低透明同色柔光。柔光只软化边缘，不做粗线、实心色带或霓虹发光。

用户回答：确认。

### 问题 8：扩散采用什么速度曲线？

推荐答案：使用 `linear` 匀速缩放。相同周期、相同起点、一秒错峰配合匀速传播，可让相邻波纹在大部分时间保持近似等距；不再使用末段减速的 `ease-out`。

用户回答：确认。

### 问题 9：波纹深浅强度是多少？

推荐答案：深色峰值约 `60%`，浅色约 `25%`，次深约 `48%`，最外侧降至 `0`；柔光最终可见强度约 `10～12%`。数值作为实现基准，仍需在真实浅色背景中人工检查。

用户回答：确认。

### 问题 10：系统启用“减少动态效果”时如何显示？

推荐答案：停止水波扩散、深浅变化、节点呼吸及节点进入退出动画；改为三圈静态浅色圆环。三圈分布在头像外侧到画布外缘之间，表达雷达结构但不产生运动。

用户回答：确认。

### 问题 11：房间节点呼吸改成什么形式？

推荐答案：删除圆外扩大的彩色呼吸光圈，让整个圆形头像本体连同圆内数字、边框和基础阴影一起进行 `1 → 1.08 → 1` 的缩放；下方四位房间号标签保持不动；中心头像不呼吸。

用户回答：确认。

### 问题 12：节点呼吸节奏是否沿用错峰方案？

推荐答案：周期继续覆盖约 `2.8～4.2s`，五个节点使用不同周期和不同起始相位，缩放使用 `ease-in-out`；只删除外扩彩色光圈并把峰值提高到 `1.08`，中心头像保持稳定。

用户回答：确认。

### 问题 13：鼠标悬停节点时是否暂停或增强呼吸？

推荐答案：暂停呼吸并固定放大，以增强目标稳定性。

用户回答：不采用。鼠标悬停时呼吸动画保持不变，不受影响；首页雷达只是效果展示区域，不需要交互效果。

最终决定：悬停不暂停、不加速、不放大、不增强阴影。

### 问题 14：是否同时取消节点鼠标手型、悬停提示和悬停样式？

推荐答案：全部取消，使用默认光标，避免误导用户认为节点可点击。

用户回答：确认。

### 问题 15：波纹层级和边界如何处理？

推荐答案：波纹位于中心头像和所有房间节点下方；限制在雷达画布内，超出区域裁剪，避免波纹覆盖操作栏、顶栏或页面其他内容。

用户回答：确认。

### 问题 16：是否将以上决策作为最终共同理解并结束讨论？

推荐答案：结束讨论，写入讨论记录并生成待批准 PRD。

用户回答：确认。

## 首次实施后的人工验收反馈

首次实施按原方案使用五圈连续波纹，透明度节奏为 `0 / 60% / 25% / 48% / 25% / 0`，最大直径按雷达画布较短边约 `90%` 计算。用户提供实际页面截图后指出：

1. 五圈在浅阶段仍保持 `25%` 可见度，导致同一时刻几乎所有圆环都清晰存在，视觉上形成密集靶环，容易眼晕，效果不如上一版。
2. 用户原本所说的“深、浅、深、浅”中，“浅”应当接近完全透明，目标为 `0～10%`，而不是仍然清晰可见的 `25%`。
3. 最外圈范围偏小。用户希望首页右侧雷达面板约 `80%` 的横向区域都作为水波纹扩散范围，而不是继续由面板较短边限制。

## 人工验收修订问答

### 问题 17：是否取消“深、浅、深、浅”，改为单峰持续渐淡？

初始推荐答案：取消第二次加深，改为波纹快速出现后持续变浅，以降低视觉密度。

用户回答：不采用，并重新说明原意。仍然需要“深、浅、深、浅”，但浅色程度必须为 `0%` 或 `10%` 以下，而不是当前的 `25%`。

最终决定：保留两次深色阶段；两个浅色阶段都降到接近不可见。

### 问题 18：修订后的透明度强度是多少？

推荐答案：第一段深色 `45%`、第一段浅色 `5%`、第二段深色 `35%`、第二段浅色 `3%`、最外侧 `0%`。

用户回答：确认。

### 问题 19：“右侧 80% 区域”如何计算？

推荐答案：最大波纹直径按右侧雷达面板宽度的 `80%` 计算，不再受面板较短边限制。宽屏下若直径超过可用高度，允许最外圈顶部和底部被雷达画布自然裁剪。

用户回答：确认。

### 问题 20：第二次深色出现在哪个传播位置？

推荐答案：使用 `0% / 10% / 32% / 62% / 86% / 100%` 关键点。第一次深色位于 `10%`，第一次浅色位于 `32%`，第二次深色位于传播后半段 `62%`，第二次浅色位于 `86%`，终点完全透明。

用户回答：确认。

### 问题 21：五圈数量、五秒周期和一秒错峰是否保持？

推荐答案：全部保持。浅阶段降到接近透明后，同屏通常只有约一到两圈明显可见，不再形成五层固定靶环，同时仍保持连续传播。

用户回答：确认。

### 问题 22：减少动态效果模式中的静态圆环如何调整？

推荐答案：继续保留三圈静态环，但透明度降为 `10% / 7% / 4%`，避免静止状态仍像明显靶环。

用户回答：确认。

用户回答：确认。

## 最终共享理解

### 连续水波模型

- 完全取消四个固定尺寸靶环。
- 正常动态模式渲染五圈结构相同的波纹。
- 每圈从约 `132px` 直径开始，生命周期约五秒。
- 每隔约一秒发射一圈；五圈用负延迟形成稳定错峰，首屏直接显示完整波列。
- 每圈扩散终点直径为右侧雷达面板宽度约 `80%`，由现有尺寸观察机制实时计算。
- 终点不再受面板高度或较短边限制；宽屏下允许最外圈顶部、底部被雷达画布自然裁剪。
- 全程使用 `linear` 匀速缩放，让相邻波纹保持近似等距。
- 波纹必须以中心头像为原点；头像中心、波纹圆心和画布中心严格重合。
- 中心昵称继续显示在头像下方，但不能再参与头像的整体居中计算。

### 深浅与线条

- 五圈使用同一青绿色、同一套动画，不为奇偶圈永久绑定强弱。
- 单圈透明度按“透明→深→浅→次深→浅→透明”变化。
- 最终关键点为 `0% / 10% / 32% / 62% / 86% / 100%`。
- 最终强度为 `0 / 45% / 5% / 35% / 3% / 0`。
- “浅”表示接近不可见，必须低于 `10%`；不能继续使用 `25%`。
- 主线保持 `1px`；增加约 `3～5px`、最终可见强度约 `10～12%` 的同色柔光。
- 不使用多色圆环、粗边框、实心填充、霓虹光带、旋转或鼠标跟随。

### 房间节点呼吸

- 周围五个圆形房间节点整体缩放，圆内数字、边框和基础阴影随圆一起变化。
- 缩放范围为 `1 → 1.08 → 1`，使用 `ease-in-out`。
- 五个稳定槽位继续使用约 `2.8～4.2s` 的不同周期和不同负延迟。
- 删除外扩彩色光圈及对应颜色变量。
- 下方四位房间号标签不缩放；中心用户头像不呼吸。
- 节点进入、退出与稳定呼吸继续作用于不同层级，避免 `transform` 冲突。

### 纯展示边界

- 房间节点仅用于首页视觉展示，不承担进入房间或查看详情功能。
- 节点继续禁止指针事件，并对辅助技术隐藏。
- 鼠标悬停不改变呼吸、不显示提示、不增强阴影、不改变光标。
- 波纹位于节点和中心头像下层；雷达画布继续裁剪溢出内容。

### 减少动态效果

- 系统启用减少动态效果时，停止波纹扩散、波纹深浅动画、节点呼吸及节点进入退出动画。
- 只保留三圈静态浅色圆环；透明度依次为 `10% / 7% / 4%`，三圈分散覆盖中心外缘到画布外缘，不全部叠在起点。
- 静态节点、中心头像和昵称继续正常显示。

### 范围与质量

- 本阶段只调整正式首页雷达组件、相关 CSS 动效和文档。
- 不修改首页左右布局、房间卡、房间页面、后端、API、数据结构、节点数量、节点位置算法或生命周期。
- 不新增用户可见文案，因此不新增 i18n 翻译键；React 组件继续禁止硬编码新增文案。
- 本次属于纯视觉动效调整，不新增业务单元测试；运行现有前端测试、TypeScript 编译、生产构建和 `git diff --check`。
- 不使用 Playwright；桌面、移动端、持续动画与减少动态效果采用人工浏览器验收。
