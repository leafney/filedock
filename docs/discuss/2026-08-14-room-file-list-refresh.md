# 房间文件列表区域优化讨论

## 原始需求

用户反馈房间主要内容区域当前样式不够统一：部分控件使用原生 HTML 控件，部分使用 Ant Design，导致下拉菜单、按钮、筛选器视觉割裂；共享文件和私密文件分别使用高大的分组卡片，空白较多，文件行信息和操作区域不够紧凑。用户希望在保留共享/私密文件操作权限差异的前提下，重新设计房间文件列表区域。

## 讨论问答

### 1. 是否将共享文件和私密文件改为统一列表？

- 建议：统一列表，通过顶部“全部 / 共享 / 私密”切换，文件行使用类型标识区分。
- 用户确认：统一列表；共享文件和私密文件可操作功能不同，显示时必须保留差异。

### 2. 桌面端采用什么列表形态？

- 建议：桌面端采用紧凑表格式列表，移动端采用自适应文件行；不直接使用 Ant Design Table，文件行和操作保持业务定制。
- 用户确认，并补充文件信息最多显示两行，避免行高过高。

### 3. 文件行如何展示操作？

- 建议：每行只显示一个主要操作和一个更多菜单。普通文件显示下载；待接收私密文件显示接收，拒绝放入更多菜单；上传中显示进度。菜单由 capabilities 控制，桌面使用 Ant Design Dropdown，移动端保留底部操作面板。
- 用户确认。

### 4. 拖拽上传提示如何处理？

- 建议：空列表状态中保留拖放上传引导；已有文件时移除长期占用的一整行提示，添加文件按钮 Tooltip 补充拖放能力；拖入文件时显示覆盖遮罩；移动端只保留添加文件按钮。
- 用户确认。

### 5. 筛选工具栏是否统一使用 Ant Design？

- 建议：使用 Segmented、Input.Search、Dropdown、Select、Button，统一控件高度、边框、圆角和焦点状态；桌面端单行，窄屏换行，移动端搜索独占一行；移除原生 select。
- 用户确认。

### 6. 顶部视图切换如何处理？

- 建议：文件列表、文件动态、回收站改用 Ant Design Tabs；回收站数量使用 Badge；操作按钮作为额外内容放在右侧；移动端使用短文案。
- 用户确认。

### 7. “发送已有私密文件”按钮文案如何优化？

- 初步建议为“转发文件”，用户指出未表达私密属性。
- 用户确认最终使用“私密转发”；另一个按钮为“添加文件”。

### 8. 文件列表接口是否保留共享/私密分组返回？

- 用户明确：旧接口按共享文件和私密文件类型返回，但不需要分页。
- 结论：本次统一为非分页扁平列表接口，不保留两组独立返回和游标；共享/私密类型及 capabilities 字段保留。

### 9. 统一列表是否保留类型标签？

- 建议：保留共享文件、私密文件标签。
- 用户确认，并要求增加头部差异化标识，结合顶部类型切换共同区分。

### 10. 共享/私密如何做差异化标识？

- 建议：顶部切换使用对应图标和颜色；共享文件使用绿色文件图标背景及左侧颜色竖线；私密文件使用琥珀色加锁文件图标背景及左侧颜色竖线；行内继续保留类型标签。
- 用户确认。

### 11. “全部”模式是否全局混排？

- 建议：共享和私密文件按当前排序条件统一混排；同值使用 fileId 保证稳定排序。
- 用户确认。

### 12. 顶部类型切换是否显示数量？

- 建议：全部、共享、私密各显示当前筛选结果数量，并随搜索和身份筛选实时更新。
- 用户确认。

### 13. 混合类型批量操作如何处理？

- 建议：允许同时选择共享和私密文件；批量下载要求所有选中文件都具备下载权限；私密转发要求所有选中文件都具备再次转发权限；不满足条件时禁用对应按钮，不自动跳过部分文件。
- 用户确认。

### 14. 私密文件接收者信息如何避免撑高行高？

- 建议：第二行仅显示状态摘要，如“待接收 2 人”“已接收”“已拒绝”或混合状态；成员明细放入详情或更多菜单。
- 用户确认。

### 15. 空状态如何区分？

- 建议：全部无文件显示拖放引导和添加文件；共享/私密筛选分别显示对应空状态；搜索无结果显示未找到匹配文件并提供清除搜索；身份筛选无结果不显示拖放引导。
- 用户确认。

### 16. 深色模式如何适配？

- 建议：Ant Design 控件跟随现有 ConfigProvider；文件列表、工具栏、空状态、类型标识、下拉菜单全部使用主题变量；共享绿色和私密琥珀色在深色模式下降低饱和度和亮度；不新增硬编码白色背景；移除原生 select。
- 用户确认。

### 17. 移动端文件行如何适配？

- 建议：不显示桌面列标题；文件信息最多两行；主要操作保留“下载 / 接收”短文案；次要操作放底部操作面板；批量模式保留复选框。
- 用户确认。

### 18. 身份筛选是否随类型动态变化？

- 建议：共享范围隐藏“发给我的”；全部和私密保留全部文件、我上传的、发给我的；切换到不可用组合时自动恢复全部文件。
- 用户确认。

### 19. 是否新增“房间文件”标题？

- 建议：不新增；保留顶部 Tabs，下面直接进入筛选工具栏和统一列表。
- 用户确认。

### 20. 扁平接口最终结构是什么？

- 建议：返回 `{ items: RoomFile[], total: number }`；请求保留 range、identity、search、sort，移除 sharedCursor、directCursor、nextCursor。
- 用户确认。

## 最终共识

房间文件列表改为无分页、全局排序的统一文件列表。顶部使用 Ant Design Tabs 和统一操作按钮；筛选工具栏使用 Ant Design Segmented、Input.Search、Dropdown、Select、Button。共享/私密文件通过顶部图标颜色、列表行首图标背景、左侧色条、类型标签四层方式区分。文件行信息最多两行，操作权限完全由后端返回的 capabilities 决定。拖拽上传引导仅在空状态和拖入时显著显示。所有新增或调整文案必须补齐简体中文和 English，全部控件、菜单、下拉层和状态需兼容深色主题。
