# FileDock 首页视觉细节优化讨论记录

## 原始需求

用户在人工验证正式首页后提出以下优化：

1. 左侧雷达的五个装饰房间头像不能保持相同尺寸；每个头像应在最小尺寸与中心用户头像尺寸之间随机取值。
2. Footer 版本 Tooltip 应显示在版本按钮右侧，内容只保留版本和构建时间。
3. 右侧删除顶部“创建房间”和“加入房间”两个大按钮；删除“我的房间”标题右侧的创建入口；把下方“成员”区域改为“参与房间”，并只在标题右侧保留一个“加入房间”入口。
4. 房间卡片悬停浮层中的“加入房间”改为“进入房间”。
5. 房间卡片右侧需要显示更有辨识度的信息。
6. 右上角头像菜单第一项改为“个人中心”。
7. 个人中心的显示名称区域增加随机昵称按钮，同时保留手动输入与显式保存；注册时间固定显示为 `2026-07-30 20:05:50` 形式。

用户随后补充：头像颜色需要比现有固定数组更丰富，并为后续浅色／深色主题兼容做好准备；本阶段不实现深色主题，只写入待办。最终还明确本次不使用 Playwright 或新增前端测试框架，视觉和交互改为人工测试。

在讨论文档和 PRD 初稿生成过程中，用户又提供了长时间停留后的首页截图：雷达区域累积出大量装饰房间头像，远超此前规定的五个。该问题必须作为本轮优化的一部分修复，不能只调整新节点尺寸而保留现有替换机制。

## 问答记录

### 问题 1：装饰房间头像的随机尺寸范围如何定义？

**推荐答案：** 使用 `40～88px` 的随机直径，中心用户头像继续保持 `112px`。数字字号、边框、阴影和房间标签应随头像尺寸协调变化，避免小头像挤压文字或大头像遮挡其他元素。

**用户答案：** 确认采用推荐的 `40～88px`。

### 问题 2：随机尺寸加入后，节点碰撞与边界如何处理？

**推荐答案：** 坐标安全检查不能再使用固定中心距离，必须以两个节点实际半径之和计算碰撞范围，同时预留标签高度、中心头像禁入区和页面边缘安全间距。随机尝试失败时选择安全评分最高的候选位置。

**用户答案：** 确认。

### 问题 3：是否从 RGB 的全部颜色中完全随机取头像背景色？

**推荐答案：** 不直接使用任意 RGB，因为过浅、过暗、灰度过低或相邻颜色过近会影响白字可读性。采用受约束的 HSL 随机色：色相 `0～359`、饱和度 `55%～75%`、亮度 `38%～52%`；同屏节点保持一定色相距离，确保白色文字有稳定对比度。

**用户答案：** 确认，并要求为后续浅色与深色模式考虑颜色取值。

### 问题 4：本轮是否一并实现深色主题？

**推荐答案：** 本轮只把头像颜色、边框、阴影、标签等改为可被主题覆盖的语义变量，继续交付当前浅色页面；完整深色主题独立放入待办，避免扩大本次视觉细节优化范围。

**用户答案：** 确认，后续阶段实现深色主题，先加入 `docs/first/todo.md`。

### 问题 5：Footer Tooltip 的“显示在右侧”具体指什么？

**推荐答案：** Tooltip 整体位于版本按钮右侧，即桌面端使用右侧定位，而不是只把 Tooltip 箭头移到右侧。内容严格只有“版本”和“构建时间”两行。

**用户答案：** 确认 Tooltip 整体显示在版本按钮右侧。

### 问题 6：移动端如何处理 Footer Tooltip？

**推荐答案：** 移动端完全取消 Tooltip，Footer 只显示不可交互的简短版本文本；完整版本信息仍可在个人中心查看。这样不会出现移动端点击后悬浮层遮挡或难以关闭的问题。

**用户答案：** 确认，移动端取消显示 Tooltip。

### 问题 7：删除重复入口后，创建与加入房间分别从哪里触发？

**推荐答案：** “我的房间”没有自建房间时，固定虚线空卡片是唯一创建入口；已有自建房间时只显示真实房间卡片，不再显示创建按钮。“参与房间”标题右侧的“加入房间”是唯一加入入口；空状态只说明暂无参与房间，不再提供第二个按钮。

**用户答案：** 确认。

### 问题 8：房间卡片右侧最终显示房主昵称还是房间名称？

**最初方案：** 自建房间和参与房间右侧显示所属房主昵称。

**用户进一步考虑：** 两类房间右侧都默认显示房间名称；后续支持修改房间名称后，用户可以直接借助自定义标题辨认房间。

**最终答案：** 统一显示 `room.title`。当前显示默认标题，例如“房间 5369”；后续房主修改标题后自动显示新名称。长标题单行省略，桌面悬停可以查看完整标题。不再显示“房主”或“成员”。

### 问题 9：桌面与移动端的进入房间文案是否统一？

**推荐答案：** 桌面悬停操作浮层与移动端底部 Drawer 都使用“进入房间”，避免把已经属于用户的房间描述为再次“加入”。真正输入房间号的入口仍使用“加入房间”。

**用户答案：** 确认。

### 问题 10：个人中心随机昵称按钮是否点击后立即保存？

**推荐答案：** 随机按钮只调用现有随机昵称接口并把结果填入输入框，不自动更新身份。用户可以继续随机或手动编辑，只有点击“保存名称”才调用昵称更新接口。请求期间应防止重复点击，失败时保留现有输入并显示统一错误。

**用户答案：** 确认。

### 问题 11：注册时间按什么时区与格式展示？

**推荐答案：** 使用浏览器本地时区，固定格式为 `YYYY-MM-DD HH:mm:ss`；月份、日期、时、分、秒不足两位补零；中英文界面保持相同格式，不显示时区缩写。

**用户答案：** 确认。

### 问题 12：本轮采用什么测试范围？

**推荐答案：** 不引入新的 Vitest；自动验证仅运行现有 Go 测试和前端生产构建。原计划使用 Playwright 验证桌面与移动端视觉和交互。

**用户最终答案：** 本次不再引入 Playwright 实现测试，转为人工测试。因此桌面与移动端页面效果、Tooltip、悬停浮层、Drawer、昵称联动及响应式表现均由人工验收。

### 问题 13：节点退出和进入的过渡期间是否允许短暂出现第六个节点？

**代码检查结论：** 当前实现使用轮询定时器找到过期节点，再启动一个独立延迟回调。组件清理时只取消轮询，没有取消尚未执行的延迟回调；延迟回调追加新节点前也没有确认目标旧节点仍然存在，更没有对最终数组数量执行硬性收敛。这种异步替换方式存在陈旧回调重复追加节点的风险。

**推荐答案：** 不允许。淡入、淡出和稳定状态下，状态数组、React 渲染结果及页面 DOM 都必须始终恰好为五个装饰节点。替换过程更新固定数组槽位，不能先保留旧节点再额外追加第六个节点；组件卸载、动画偏好变化或下一轮替换开始时必须使陈旧回调失效。

**用户答案：** 确认。

## 最终共同理解

1. 左侧五个装饰房间继续保持纯视觉、不可点击和独立生命周期，但每个头像新增 `40～88px` 随机直径。
2. 雷达坐标生成与碰撞检查必须使用节点实际半径，保证节点不互相遮挡、不覆盖中心头像、不越过安全边界，房间标签也不能被裁切。
3. 节点颜色改为受约束 HSL 随机色，并避免同屏颜色过近；白色文字必须清晰。主题相关视觉值通过语义变量表达，为以后深色模式预留覆盖能力。
4. 本轮不实现深色主题，只在项目待办中增加后续任务。
5. 桌面 Footer Tooltip 整体显示在版本按钮右侧，且只展示版本和构建时间；移动端 Footer 为不可交互文本，不渲染 Tooltip。
6. 右侧不再存在重复的创建／加入按钮。空的自建房间槽是唯一创建入口，“参与房间”标题右侧按钮是唯一加入入口。
7. 房间卡片左侧显示大号四位房间号，右侧统一显示房间标题；长标题单行省略，桌面可悬停查看完整值。
8. 已有房间的动作统一使用“进入房间”；创建、加入、退出和解散的业务接口与规则保持不变。
9. 右上角头像菜单和个人中心弹窗均使用“个人中心”文案。
10. 个人中心昵称输入旁增加真实随机昵称按钮，随机结果只填充草稿，显式保存后才更新会话。
11. 注册时间使用浏览器本地时间并固定为 `YYYY-MM-DD HH:mm:ss`。
12. 所有新增或修改文案必须同时提供简体中文与 English，React 组件内不得硬编码用户可见文案。
13. 本轮不增加 Playwright、Vitest 或视觉快照测试。自动检查为 `bun run build` 与 `go test ./...`；UI 由人工按桌面和移动端清单验收。
14. 修复雷达节点长时间运行后不断累积的问题。任何阶段状态数组和 DOM 都必须恰好为五个节点，卸载或失效的异步回调不得继续修改节点。
