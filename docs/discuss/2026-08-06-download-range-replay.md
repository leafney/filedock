# 下载 Range 与短时重放讨论纪要

## 原始需求

下载时 NeatDownloadManager Chrome 插件和浏览器同时请求同一个下载 URL，后一个请求收到 HTTP 409。希望支持 2 秒内重复触发下载且只计为一次下载，并支持 Range，同时为后续上传/下载断点续传做准备。

## 根因确认

- 下载 URL 对应一次性 `DownloadTask`。
- 任务首次请求后进入 `streaming`，完成后进入 `completed`。
- 同一任务再次请求会返回 `ErrDownloadExpired`，HTTP 状态为 409。
- 本地数据库显示日志中的任务已完成且传输字节数等于文件大小，证明 409 是重复请求而非文件读取失败。
- NeatDownloadManager 的重复捕获触发了第二次请求；`Range` 当前未被服务端实现。

## 逐项确认

### 1. 本次范围

- 推荐：实现下载 Range、206、短时重放和内部区间传输抽象；不实现完整上传断点续传。
- 答案：确认。

### 2. Range 类型

- 推荐：只支持单一区间；无 Range 返回 200；有效单区间返回 206；多区间返回 416。
- 答案：确认。

### 3. 并发重放

- 推荐：每个重放请求计入现有全局、房间和用户并发限制；用户上限仍为现有 2 条流。
- 答案：确认。

### 4. 完成条件

- 推荐：完整无 Range 请求完成，或 Range 传输到文件末尾时，才允许任务完成；中间 Range 只完成传输流，不重复计数和通知；完整区间追踪留到后续。
- 答案：确认。

### 5. HEAD

- 推荐：支持 HEAD 探测，返回文件名、MIME、大小、Range 能力和对应区间响应头；不打开内容流、不消耗任务、不修改状态。
- 答案：确认。

### 6. 内部抽象

- 推荐：抽取后端内部区间读取接口；HTTP 层解析 Range，存储层安全打开并读取区间；不新增上传 API、不改变上传协议。
- 答案：确认。

### 7. 测试

- 推荐：增加 Range 解析、服务重放/计数/回收站/并发、API 200/206/HEAD/416/过期测试；保留前端测试构建；不做端到端浏览器测试。
- 答案：确认。

### 8. 重放窗口

- 推荐：传输中从首次 `startedAt` 起 2 秒；完成后从 `completedAt` 起再保留 2 秒；重放不刷新窗口；超时恢复 409。
- 答案：确认。

## 最终共识

本阶段将下载接口升级为支持单区间 HTTP Range、HEAD 探测和同一下载任务 2 秒短时重放的兼容实现。重放仅适用于相同 taskId、用户、房间和文件，新的下载操作生成新任务并正常计数。重放流计入现有并发限制，不重复修改下载状态、首次下载统计和通知；文件进入回收站、房间失效、任务取消/失败/过期或重放窗口结束后均拒绝。下载服务抽取后端内部区间传输能力，为未来上传/下载断点续传预留，但本次不实现上传恢复协议和跨重启区间合并。
