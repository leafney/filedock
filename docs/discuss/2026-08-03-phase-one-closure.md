# FileDock 一期收口讨论记录

日期：2026-08-03

## 原始需求

> 分析项目相关文档 `docs`，给出下一阶段开发规划。

用户要求先通过 `grill-me` 逐项澄清，再通过本地 PRD 形成正式开发规格；沟通采用压缩表达。项目规划将交给低智能编码模型执行，因此最终规格必须明确边界、步骤、责任和验收条件。

## 文档与代码盘点结论

1. 项目已实现匿名身份、房间生命周期、全局 SSE、在线状态、二维码、共享／私密文件上传、接收、拒绝、复用、发布共享、下载和传输进度。
2. 一对一聊天仍是前端占位区；通知仅处理房主加入审批，尚未形成全局通知中心。
3. HTTP Range、文件哈希、断点续传、分块传输和文件预览尚未实现，且已被后续批准的文件传输一期 PRD 明确排除。
4. 原始总 PRD 的阶段划分已经部分失效：SSE、在线状态和文件进度已提前实现；后续批准 PRD 对共享／私密文件、下载和房间工作区给出了更新规则。
5. 现有文件传输人工验收记录只有 7 项工程检查已完成，仍有 50 项真实浏览器场景未验收。
6. 自动质量基线已在讨论期间验证：Go 全包测试通过；前端 6 项测试通过；TypeScript 编译和生产构建通过。
7. 前端生产构建主 JavaScript 约为 943.64 kB，gzip 后约为 305.34 kB；存在分块建议警告，但仍低于旧总 PRD 的 500 kB gzip 目标，不作为一期收口阻断项。

## 问答记录

### 问题 1：下一阶段主目标是什么？

**推荐答案：** 先完成一期收口，再开发一对一聊天。先执行人工验收、修复发现的问题、建立稳定 MVP 基线，避免在未验证核心链路上继续叠加功能。

**用户答案：** 先做一期收口。

### 问题 2：收口按哪套规格验收？

**推荐答案：** 以后续已批准 PRD 为权威基准。旧总 PRD 保留为历史愿景；发生冲突时，不用旧路线图扩大一期范围。

**用户答案：** 确认。

### 问题 3：验收发现缺陷如何处理？

**推荐答案：** 本阶段直接修复并复验，但禁止新增功能。阻断、安全、权限、数据错误和已批准行为不符必须修复；不影响使用的轻微视觉问题可以记录；范围外能力不得借机加入。

**用户答案：** 确认。

### 问题 4：人工验收环境多大？

**推荐答案：** 至少使用桌面 Chrome 房主会话、桌面 Firefox 或 Edge 独立成员会话、同一局域网中的真实手机浏览器第三个成员；覆盖桌面、平板、手机视口、简体中文、English 和减少动态效果；不使用 Playwright。

**用户答案：** 确认。

### 问题 5：验收只覆盖文件，还是覆盖整个一期？

**推荐答案：** 整个一期做总验收，文件传输继续保留详细专项验收。总验收还需覆盖匿名身份、首页、三种加入模式、房间生命周期、SSE、在线状态、分享、双语和首页雷达动效。

**用户答案：** 确认做全一期总验收。

### 问题 6：文档如何收口？

**推荐答案：** 建立能力矩阵、统一历史 PRD 状态、整理待办，并新增总验收记录。

**用户答案：** 文档不处理。

**最终解释：** 不整理历史文档，不补历史 PRD 状态，不建能力矩阵，不整理待办；本次工作流仍新增讨论纪要和 PRD。

### 问题 7：人工验收结果是否落盘？

**推荐答案：** 保留验收记录。只新增一期总验收文件并引用现有文件传输专项记录，不修改其他历史文档。

**用户答案：** 确认。

### 问题 8：收口阶段补多少自动测试？

**推荐答案：** 不引入 Playwright 或新测试框架，不为普通视觉细节补单元测试；权限、文件状态、容量、会话和房间生命周期缺陷修复时必须增加回归测试；继续执行双语词典完整性测试和全部现有自动检查。

**用户答案：** 确认。

### 问题 9：人工验收由谁确认？

**推荐答案：** 编码 Agent 运行自动检查、启动服务并提供验收步骤；用户使用真实浏览器和手机逐项验收。Agent 不得代替用户勾选人工结果。用户反馈失败项后，Agent 修复并等待用户复验。

**用户答案：** 确认。

### 问题 10：一期收口是否包含发布部署？

**推荐答案：** 可包含当前开发机生产构建、前端嵌入、单二进制和局域网访问验证，但不包含跨平台发布、安装包、Docker、正式部署配置或性能压测。

**用户答案：** 不包含。

**最终解释：** 一期收口不包含发布部署，不制作、验证或交付发布产物。前端生产构建仍作为代码质量检查。

### 问题 11：验收是否使用隔离数据？

**推荐答案：** 使用干净验收数据库和文件目录，不复用带有历史数据的环境；准备不同名称、大小和状态的样本文件；验收后只处理验收数据。

**用户答案：** 确认。用户会直接删除现有 `data` 目录中的数据库数据，不需要 Agent 执行特殊处理或清理专用数据。

**最终解释：** 验收前由用户手动删除现有 `data` 目录中的数据库数据，使服务以干净数据库启动。Agent 不删除数据库、不实现清理脚本、不执行验收后数据清理。

### 问题 12：收口模块边界是什么？

**推荐答案：** 分为自动质量基线、匿名身份与首页、房间生命周期、文件传输、三端体验五块。不新增产品模块；缺陷只修改所属模块，业务缺陷补对应回归测试。

**用户答案：** 确认。

### 问题 13：什么条件算一期收口完成？

**推荐答案：** 自动检查全部通过；一期总验收和文件传输专项全部通过或被新版规格明确替代；没有阻断、安全、权限或数据一致性缺陷；控制台无新增错误；中英文、三端和多人 SSE 完成复验；最终由用户明确确认。

**用户答案：** 确认。

### 问题 14：成员加入消息在哪些页面显示？

**推荐答案：** 仅向当前正在打开该房间页面的原有成员显示临时顶部消息；新加入者自己不收到，首页和其他房间页不弹出。成员加入／退出暂不写入右上角通知 Icon，跨页面提醒、历史列表和未读状态留到后续全局通知中心实现。

**用户答案：** 确认。

## 最终共同理解

1. 下一阶段名称为“一期收口”，目标是验证和稳定现有一期能力，不开发一对一聊天或其他新功能。
2. 后续已批准 PRD 是验收权威来源；旧总 PRD 只作为历史愿景，不能覆盖后续决策。
3. 验收覆盖匿名身份、首页、房间加入与生命周期、SSE、在线状态、分享、文件传输、响应式、双语、键盘和减少动态效果。
4. 现有文件传输专项验收继续使用；另建一期总验收记录承载跨模块结果，避免复制专项清单。
5. 人工验收至少使用三个独立会话，其中包含真实手机和两个不同桌面浏览器；所有设备位于同一局域网。
6. 不使用 Playwright，不新增浏览器自动化框架。自动测试只覆盖现有质量门禁和缺陷对应的高价值业务回归。
7. 验收发现的范围内缺陷在本阶段修复并复验；范围外功能不实现。
8. 用户负责人工验收和最终签字；Agent 负责准备环境说明、运行自动检查、修复缺陷和提供复验步骤。
9. 用户负责在验收前删除现有 `data` 目录中的数据库数据。Agent 不执行任何数据库删除或额外清理。
10. 不整理历史文档，不更新能力矩阵、旧 PRD 状态或待办；只新增本次讨论、正式 PRD，以及实施阶段的一期总验收记录。
11. 不包含发布部署、跨平台产物、安装包、容器、正式配置或性能压测。
12. 自动检查、总验收、专项验收和用户最终确认全部满足后，才能声明一期收口完成。
13. 新成员首次加入或重新加入时，当前房间页的其他成员收到临时顶部消息；新加入者本人、首页和其他房间页不显示。
14. 成员加入／退出事件暂不写入右上角通知 Icon；通知历史、未读状态和跨页面提醒统一留到后续全局通知中心。
