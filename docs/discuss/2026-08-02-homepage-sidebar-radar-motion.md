# 首页侧栏换位与雷达动效优化讨论记录

- 日期：2026-08-02
- 状态：已达成共识
- 讨论范围：首页操作区换位、响应式顺序、雷达波增强、房间节点呼吸、历史原型标记

## 原始需求

用户基于当前生产首页截图提出下一阶段优化：

1. 当前首页左侧为雷达区域，右侧为“我的房间／参与房间”列表。用户希望交换两者位置，让房间列表位于左侧。用户从首页左侧点击房间进入房间页后，房间页左侧正好是成员列表，从空间认知上形成对应关系。
2. 当前白色背景中的雷达波纹太浅，中心向外扩散的效果不明显。用户希望增强波纹颜色与层次，使扩散过程更清晰。
3. 用户希望每个周围房间圆增加呼吸效果，让局域网房间发现区域更有活跃感。
4. 用户要求使用 `caveman` 压缩沟通，并使用 `grill-me` 逐项确认设计，暂不直接实现代码。

## 代码核对结论

- 当前生产首页 DOM 顺序为雷达区域在前、操作侧栏在后。
- 桌面首页网格为“自适应雷达区＋300～340px 固定侧栏”，当前侧栏位于右侧。
- 当前 `900px` 以下切换为单列上下布局，雷达在上、操作区在下。
- 未建立匿名身份时，右侧显示昵称设置卡；建立身份后，右侧显示“我的房间／参与房间”。两种状态复用同一操作侧栏。
- 雷达中心用户固定在画布中心，周围始终维护五个装饰房间节点。
- 雷达波由四个同心圆组成，使用约五秒的缩放与透明度动画，相邻圆错开约 1.25 秒。
- 当前雷达边框主色透明度约 18%，动画透明度峰值约 45%；叠加后在浅色背景上实际对比度偏低。
- 当前房间节点只有进入和退出动画。可见阶段没有持续呼吸动画。
- 节点数据已经包含稳定槽位、颜色、色相和生命周期，可用于生成稳定、错开的呼吸周期，无需增加服务端数据或持久化状态。
- `prefers-reduced-motion` 已在雷达组件中检测，但目前只停止波纹和节点进出动画；新增呼吸动画也必须受同一规则约束。
- `examples/` 当前只有房间工作区原型，不存在首页雷达原型。该房间原型已有独立 README 和页面顶部“仅原型”提示，适合增加历史过时标记。

## 完整问答记录

### 问题 1：移动端是否也改为“房间列表在上、雷达在下”？

推荐答案：确认。桌面通过左右位置建立“房间入口到成员栏”的空间映射；移动端没有左右关系，应优先展示创建、加入和进入房间等主要操作，因此操作区在上、雷达在下。

用户回答：确认。

### 问题 2：左侧房间栏宽度如何确定？

初始推荐答案：保持 320～340px，不强行与房间页 240px 成员栏像素对齐。首页房间卡包含房间号、名称、创建和加入入口，240px 偏窄；语义位置对应比像素宽度对应更重要。

用户回答：希望宽度再缩小，约 300px 即可。

最终决定：桌面左侧操作栏宽度约 300px。

### 问题 3：平板宽度不足时，侧栏如何处理？

推荐答案：901px 及以上保持 300px 左栏和自适应雷达右栏；900px 及以下直接切换上下布局，不增加 240～280px 的中间压缩状态，避免房间卡内容拥挤。

用户回答：确认保留现有 900px 上下布局断点。

### 问题 4：雷达波增强到什么程度？

推荐答案：采用中等增强。颜色继续使用 FileDock 青绿色；边框保持 1px；基础可见度从约 18% 提高到约 30%，动画峰值从约 45% 提高到约 65%；最外圈仍逐渐消失，避免页面变成固定靶盘。

用户回答：确认采用推荐效果，并提出扩散过程中希望出现“深、浅、深、浅”的颜色变化。

### 问题 5：是否采用“单圈渐淡＋相邻波纹深浅交替”？

推荐答案：单个波纹从中心出现时较深，扩散过程中逐渐变浅，外缘最终消失；四个错峰波纹中，相邻圆使用强、弱、强、弱的透明度层级。不使用实心色带。

用户回答：效果暂时不容易想象，可以先按该方案实现，之后根据实际效果调整。

### 问题 6：“每个圆呼吸”是否包含中心用户头像？

推荐答案：只让周围房间圆呼吸，中心用户头像保持稳定并保留现有阴影。中心头像持续缩放容易造成页面主体晃动；周围节点呼吸已经足够表达活跃状态。

用户回答：确认。

### 问题 7：呼吸动画强度与节奏如何设置？

推荐答案：只缩放圆形头像，房间号标签保持静止；缩放范围为 1 到 1.06 再回到 1；阴影同步轻微扩散；每个节点周期位于 2.8～4.2 秒之间并错开延迟；节点进入和退出阶段暂停呼吸，避免动画冲突。

用户回答：确认。

### 问题 8：系统开启“减少动态效果”时如何处理？

推荐答案：停止雷达扩散和节点呼吸；保留四层静态、深浅交替圆环；节点生命周期仍可更新，但节点替换不播放淡入淡出动画。

用户回答：确认。

### 问题 9：桌面左侧房间卡是否继续垂直居中？

推荐答案：保持垂直居中。当前卡片高度较小，顶对齐会造成左下方大片空白；左右位置已经建立语义映射，无需与房间页成员栏顶部进行像素对齐。

用户回答：确认。

### 问题 10：首次访问、尚未创建昵称时，昵称设置卡是否也放在左侧？

推荐答案：确认。桌面操作区始终位于左侧，雷达始终位于右侧；未建立身份时左侧显示昵称设置，建立身份后左侧显示房间列表；移动端两种状态都保持操作区在雷达上方。

用户回答：确认。

### 问题 11：雷达波数量是否保持四层？

推荐答案：保持四层。三层不足以清楚表现深浅交替，五层以上容易形成过强靶盘感；四层也可以复用现有 DOM 结构。

用户回答：确认。

### 问题 12：深浅变化使用不同颜色还是同一颜色透明度变化？

推荐答案：使用同一青绿色，只改变透明度。不切换不同色相，以保持品牌统一并避免与彩色房间节点竞争。

用户回答：确认。

### 问题 13：节点呼吸是否带彩色光晕？

推荐答案：增加轻微同色光晕。缩放峰值时，同节点颜色的阴影略微扩大；普通状态继续保留灰色柔和阴影。光晕保持低透明度，不做霓虹效果。

用户回答：确认。

### 问题 14：本阶段修改范围是什么？

推荐答案：只修改正式首页生产代码，包括首页布局、雷达组件、样式、必要测试和文档；不修改房间页、后端、API 或上传业务；不维护历史独立原型。

用户回答：确认。`examples` 原型可以标记为过时，不需要继续修改其布局和功能。

### 问题 15：历史原型的“过时”标记放在哪里？

推荐答案：在原型 README 顶部增加“已过时，仅保留历史评审参考”；同时把原型页面顶部“仅原型”提示改为“历史原型”，说明生产页面已经替代。除标记文案外，不修改原型布局、脚本或测试。

用户回答：确认。

### 问题 16：雷达波扩散速度是否调整？

推荐答案：保持现有约五秒一圈，只增强颜色和深浅节奏。当前问题是看不清，不是速度过慢；若同时改变速度并加入呼吸动画，画面容易变得躁动。四圈继续错开 1.25 秒。

用户回答：确认。

### 问题 17：是否将全部决策作为最终共同理解，并结束问答进入文档阶段？

推荐答案：确认。最终范围已覆盖布局、断点、操作区状态、雷达数量、颜色、深浅节奏、呼吸范围、减少动态效果、历史原型和变更边界。

用户回答：确认。

## 最终共享理解

### 首页布局

- 桌面与平板在 901px 及以上使用双栏：左侧固定约 300px 操作区，右侧雷达占据剩余宽度。
- 左侧操作卡在桌面双栏中垂直居中。
- 900px 及以下使用单列：操作区在上，雷达在下。
- 正式 DOM 顺序也应为操作区在前、雷达在后，保证视觉顺序、键盘顺序和屏幕阅读顺序一致，不能只通过 CSS `order` 交换。
- 未建立身份时左侧／上方显示昵称设置；建立身份后显示“我的房间／参与房间”。
- 房间卡、创建、加入、通知、个人信息和雷达节点业务逻辑保持不变。

### 雷达波纹

- 保持四层同心波纹、约五秒周期和 1.25 秒错峰。
- 使用 FileDock 青绿色单色，通过透明度表现强弱。
- 整体可见度中等增强：基础层次约 30%，动画峰值约 65%。
- 每个波纹由较深状态开始，扩散时逐渐变浅并最终消失。
- 相邻波纹采用强、弱、强、弱层级，形成深浅交替节奏。
- 不增加实心填充、不同色相、粗边框或霓虹效果。

### 房间节点呼吸

- 只有周围五个房间节点的圆形头像呼吸；中心用户头像和房间号标签保持稳定。
- 可见节点在 1 与 1.06 之间平滑缩放。
- 每个节点周期在 2.8～4.2 秒之间，开始时间错开，避免同步缩放。
- 呼吸峰值增加低透明度同色光晕，同时保留现有基础阴影。
- 进入和退出阶段不播放呼吸，避免与现有淡入淡出动画争用同一个变换属性。

### 减少动态效果

- 系统启用 `prefers-reduced-motion: reduce` 时停止波纹扩散和节点呼吸。
- 四层波纹保留为静态深浅交替圆环，仍能表达雷达结构。
- 节点替换可以继续，但不播放进入、退出或呼吸动画。

### 历史原型

- `examples` 房间工作区原型不再跟随生产页面维护。
- README 顶部标记“已过时，仅保留历史评审参考”。
- 页面顶部显示双语“历史原型／Historical prototype”及生产页面已替代说明。
- 不修改原型业务、布局、演示数据或测试。

### 质量与边界

- 本阶段不修改后端、API、房间页面、数据模型、房间节点数量和生命周期算法。
- 所有用户可见过时标记同时提供简体中文和 English。
- 本次主要是布局与 CSS 动效，不新增业务单元测试；继续运行现有前端测试、TypeScript 编译、生产构建和人工响应式验收。
- 人工验收重点覆盖桌面双栏、移动单栏、雷达深浅扩散、节点错峰呼吸、减少动态效果和历史原型提示。
