# 文件列表布局细节优化讨论

## 原始需求

用户测试统一文件列表后发现三个问题：文件列表顶部的四处数量显示应采用右上角角标；文件内容区过宽导致右侧操作内容被裁切；搜索栏出现输入区域和独立搜索按钮分隔的异常样式，需要重新优化。

## 代码分析

- 四处数量来源已确认：全部文件、共享文件、私密文件、回收站。
- 全部/共享/私密数量来自 `Segmented` 选项中的 Ant Design `Badge`；回收站数量来自 Tabs 中的 `Badge`。
- 房间工作区中心列当前存在 `minmax(540px, 1fr)` 的最小宽度；文件操作区和筛选控件也有最小宽度，导致中等窗口下中心区域无法收缩，右侧内容被裁切。
- 搜索框使用 `Input.Search`，Ant Design 会生成独立的搜索按钮区域，造成截图中的分隔边框。

## 讨论问答

### 1. 四处数量是否统一改成右上角角标？

- 建议：全部、共享、私密、回收站统一改为对应 Tab 右上角角标；文件数量使用浅灰/主题色，回收站使用警示红色，数字 0 仍显示。
- 用户确认：采用该方案。

### 2. 文件内容区如何收窄？

- 建议：中心列改为 `minmax(0, 1fr)`；文件操作区取消固定最小宽度；文件名继续 `min-width: 0` 和省略；筛选工具栏空间不足时换行；不改变左右成员区和聊天区既有宽度。
- 用户确认：采用该方案。

### 3. 搜索栏如何修复？

- 建议：从 `Input.Search` 改为普通 Ant Design `Input`，左侧放搜索图标，右侧保留清除按钮，整个搜索框使用连续边框；聚焦时使用主题色；搜索行为保持实时查询。
- 用户确认：采用该方案。

## 最终共识

本轮只优化统一文件列表的视觉布局和响应式表现，不改变后端接口、文件权限、筛选语义、排序逻辑和业务操作。实现必须兼容浅色、深色、桌面和移动端，并补充必要的中英文可见文案或 aria 标签。
