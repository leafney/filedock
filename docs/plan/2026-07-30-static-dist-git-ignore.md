# static/dist Git 跟踪规则调整 PRD

## Problem Statement

FileDock 的前端构建结果会被复制到 `static/dist`，供 Go `embed` 打包到正式二进制中。该目录中的首页、图标、样式和 JavaScript 文件此前已被 Git 跟踪，因此每次执行前端构建都会产生文件名哈希变化、旧文件删除和新文件新增，形成大量没有审查价值的 Git 变更。

开发者希望仓库只保留空目录占位文件，让构建产物继续存在于本地并参与正式打包，但不再被 Git 提交。

## Solution

调整仓库忽略规则，使 `static/dist` 下除 `.placeholder` 之外的全部内容都被忽略。将当前已经被 Git 跟踪的编译文件从索引中移除，同时保留本地文件，不重写历史提交。

继续使用现有 `make web` 生成前端资源，并通过 `make build`、`make build-lin`、`make build-lin-arm` 完成正式构建，确保 Go `embed` 在编译时能够读取本地生成的前端文件。

## User Stories

1. 作为开发者，我希望前端编译文件不再被 Git 跟踪，以便每次构建不会产生大量无意义变更。
2. 作为开发者，我希望 `static/dist` 目录在全新克隆后仍然存在，以便 Go 的嵌入声明具有稳定目录结构。
3. 作为开发者，我希望 `.placeholder` 是该目录唯一被跟踪的文件，以便目录保留规则直观明确。
4. 作为开发者，我希望停止跟踪时保留本地编译文件，以便当前开发和验证过程不受影响。
5. 作为维护者，我希望不重写既有 Git 历史，以免已有提交标识和协作分支发生变化。
6. 作为发布人员，我希望正式构建仍然先生成前端资源，以便最终二进制能够正常内嵌首页。
7. 作为开发者，我希望执行 `make web` 后 Git 工作区不出现新编译文件，以便只审查真实源码变化。
8. 作为开发者，我希望构建产生的哈希文件、首页和图标全部自动忽略，以免每次新增文件类型时重新调整规则。

## Implementation Decisions

- 修改 Git 忽略配置，使静态构建目录下的全部内容默认被忽略，并仅放行 `.placeholder`。
- 删除当前针对首页文件的放行规则。
- 删除针对资源子目录的重复忽略规则，因为上级目录规则已经覆盖全部构建内容。
- 将所有已跟踪的静态编译文件从 Git 索引移除，但不删除本地文件。
- 重新确保 `.placeholder` 被 Git 跟踪。
- 不修改前端构建命令；现有构建流程已经在复制资源后创建 `.placeholder`。
- 不修改 Go `embed` 实现。
- 不重写任何历史提交。
- 正式发布必须使用现有 `make build*` 目标；直接执行 `go build` 不保证包含前端资源。

## Testing Decisions

- 不新增单元测试，本次变更不包含业务逻辑、鉴权或复杂状态转换。
- 使用 Git 已跟踪文件列表验证静态构建目录中只有 `.placeholder`。
- 使用 Git 忽略检查验证首页、图标、样式和 JavaScript 文件均被忽略。
- 执行一次前端同步构建，确认本地编译结果存在。
- 构建完成后检查工作区，确认静态构建目录没有产生新的 Git 变更。
- 验收外部行为，不依赖具体构建哈希文件名。

## Out of Scope

- 不删除本地前端编译文件。
- 不重写 Git 历史中的旧构建产物。
- 不修改 Go 静态资源路由和嵌入机制。
- 不修改前端源代码或构建工具配置。
- 不改变正式构建命令和部署流程。
- 不处理与静态构建目录无关的工作区改动。

## Further Notes

- 全新克隆仓库后，静态构建目录中只有 `.placeholder`。正式构建前必须通过现有 `make build*` 流程生成前端资源。
- 如果未来引入其他静态产物类型，目录级忽略规则会自动覆盖，无需逐项补充扩展名。
