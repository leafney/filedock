# FileDock 房间文件列表交互优化 PRD

## Problem Statement

现有房间工作区原型已经具备共享文件、私密文件、上传下载进度、文件动态、回收站和权限投影，但文件主区仍存在四个直接影响理解和操作效率的问题。

第一，文件表格的操作列直接并排展示下载、再次发送、发布共享、回收等多个按钮。窄屏下按钮频繁换行，主要动作和低频管理动作缺少层级，匿名治理记录的操作区也显得突兀。

第二，顶部同时展示“上传共享文件”“定向发送”“选择已有文件”。这三个入口混合了文件来源与发送范围两个维度：用户需要在还没有选择文件前决定共享或私密，又无法立即理解“选择已有文件”与另外两个入口的关系。

第三，文件列表虽然技术上支持拖放，但常态界面没有稳定的拖放符号或文本。只有用户已经开始拖动文件后才显示覆盖层，发现成本过高。

第四，共享文件与私密文件在同一个平铺表格中只依赖范围标签区分。用户需要逐行读取标签，难以快速建立“房间公共目录”和“与自己相关的私密文件”两个心智模型。直接拆成两套页面又会重复搜索、排序、权限投影、批量选择和移动导航，并破坏已经确认的统一文件动态与回收站。

本期需要在不改变业务规则、不接入生产代码的前提下，重构独立原型的文件列表信息架构、上传入口、拖放提示和操作层级，使首次使用者能够快速理解文件范围与发送流程，同时保持桌面、平板和移动端的紧凑性。

## Solution

保留“文件列表／文件动态／回收站”三个顶层视图，在文件列表内部增加“全部／共享文件／私密文件”范围切换。全部模式不再平铺混合文件，而是按共享和私密两个可折叠区块展示；共享区固定在上，私密区固定在下，排序分别作用于各区块内部。

顶部上传入口简化为“添加文件”和“发送已有私密文件”。添加本地文件或拖放文件后再进入待发送区选择共享或私密，从而把“文件来自哪里”和“发送给谁”按正确顺序分开。发送已有私密文件打开独立多选器，复用已上传文件，不产生重复上传。

文件列表增加常驻可点击拖放条，文字固定为“拖放文件到这里，或点击添加文件”。整个中间工作区在拖动文件时显示统一高亮遮罩，因此用户位于文件动态或回收站时也能发起上传；关闭待发送区后返回原视图。

操作列只保留当前状态最重要的主操作。普通文件显示下载和三个点，待接收私密文件显示接收并下载与拒绝，上传中文件显示查看进度和三个点，匿名私密文件仅显示三个点。桌面三个点打开下拉菜单，移动端打开底部操作面板。普通模式不显示复选框，用户显式进入批量模式后才显示多选控件和批量操作栏。

## User Stories

1. 作为首次进入房间的用户，我希望立即看出哪些文件是全房间共享的，以便理解公共目录内容。
2. 作为房间成员，我希望私密文件与共享文件有清晰分区，以便避免误把私密文件当作公共文件。
3. 作为房间成员，我希望仍能在一个文件列表中查看全部有权看到的文件，以便不必频繁切换两个独立页面。
4. 作为用户，我希望通过“全部／共享文件／私密文件”快速切换范围，以便缩小当前列表。
5. 作为用户，我希望全部模式同时展示共享和私密分组，以便获得完整概览。
6. 作为用户，我希望共享分组始终位于私密分组上方，以便公共目录保持首要位置。
7. 作为用户，我希望两个分组默认展开，以便首次进入时不会遗漏文件。
8. 作为用户，我希望可以折叠某个分组，以便在文件较多时减少滚动。
9. 作为用户，我希望排序分别作用于两个分组内部，以便分组顺序保持稳定。
10. 作为用户，我希望搜索结果分别显示共享和私密命中数量，以便理解结果分布。
11. 作为房主，我希望匿名私密文件仍位于私密分组中，以便理解其真实文件范围。
12. 作为房主，我希望匿名私密文件保持黄色治理样式和匿名审计标签，以便不会与自己有权读取的私密文件混淆。
13. 作为用户，我希望桌面表格减少重复的范围列，以便文件名和操作区域获得更多空间。
14. 作为移动用户，我希望文件卡仍显示共享、私密或匿名审计标签，以便脱离分组标题滚动后仍能识别范围。
15. 作为用户，我希望顶部只有清晰的“添加文件”入口，以便先选择文件再决定发送范围。
16. 作为用户，我希望发送范围在待发送区确认，以便避免通过入口名称猜测最终可见性。
17. 作为用户，我希望可以选择已经上传的私密文件再次发送，以便不重复上传。
18. 作为用户，我希望“发送已有私密文件”支持选择多个文件，以便一次发送一个文件集合。
19. 作为聊天用户，我希望从聊天附件入口发送文件时自动选择私密发送和当前成员，以便减少重复操作。
20. 作为共享文件视图用户，我希望添加文件时默认预选共享范围，以便当前上下文与待发送区一致。
21. 作为私密文件视图用户，我希望添加文件时默认预选私密范围，以便减少一次切换。
22. 作为全部视图用户，我希望添加文件默认预选共享范围，以便默认行为保持安全且符合公共目录主路径。
23. 作为用户，我希望选择范围后仍必须点击最终确认，以便拖放或文件选择不会立即上传。
24. 作为桌面用户，我希望文件列表持续显示拖放提示，以便不尝试也能发现拖放能力。
25. 作为用户，我希望点击拖放提示条也能打开文件选择器，以便鼠标与拖放入口一致。
26. 作为用户，我希望拖动文件时整个中间工作区高亮，以便明确释放目标。
27. 作为查看文件动态的用户，我希望仍能拖放文件发起上传，以便无需先返回文件列表。
28. 作为查看回收站的用户，我希望仍能拖放文件发起上传，以便工作流不受当前视图限制。
29. 作为用户，我希望关闭待发送区后回到原来的顶层视图，以便不丢失正在查看的上下文。
30. 作为移动用户，我希望页面不展示无效的拖放提示，以便有限空间留给上传和下载主操作。
31. 作为用户，我希望普通文件操作区只突出下载，以便快速找到最常用操作。
32. 作为用户，我希望低频操作进入三个点菜单，以便表格保持整洁。
33. 作为待接收者，我希望直接看到“接收并下载”和“拒绝”，以便明确完成文件接收决策。
34. 作为待接收者，我希望待决策状态不再出现多余的三个点，以便避免空菜单和重复入口。
35. 作为接收者，我希望拒绝前看到二次确认，以便避免误触。
36. 作为接收者，我希望拒绝确认中看到文件、发送者、大小和后果，以便理解本次决定。
37. 作为上传者，我希望三个点菜单提供再次发送、发布共享和接收状态，以便管理私密文件。
38. 作为房主，我希望三个点菜单提供允许的匿名治理操作，以便在不读取原始信息的情况下管理文件。
39. 作为用户，我希望无权限操作完全不显示，以便不会看到无法执行的诱导入口。
40. 作为用户，我希望危险操作集中在菜单底部并使用危险色，以便降低误触风险。
41. 作为键盘用户，我希望 Escape 能关闭文件菜单、底部面板和拒绝确认，以便无需鼠标完成操作。
42. 作为桌面用户，我希望同一时间只打开一个文件菜单，以便界面状态明确。
43. 作为移动用户，我希望三个点打开底部操作面板，以便操作项有足够触控面积。
44. 作为移动用户，我希望底部面板展示文件摘要，以便确认操作目标。
45. 作为普通用户，我希望默认列表没有复选框，以便单文件操作保持简洁。
46. 作为需要批量操作的用户，我希望点击“批量选择”后再显示复选框，以便明确进入不同操作模式。
47. 作为批量用户，我希望可以跨共享和私密分组选择文件，以便一次处理相关文件集合。
48. 作为批量用户，我希望批量下载只在全部已选文件均可下载时启用，以便不会部分成功。
49. 作为批量用户，我希望私密发送只在全部已选文件均由自己上传且可复用时启用，以便权限边界明确。
50. 作为批量用户，我希望操作禁用时看到具体原因，以便知道如何修正选择。
51. 作为批量用户，我希望系统不自动忽略无权限文件，以便结果可预测。
52. 作为批量用户，我希望切换范围或筛选前确认是否保留选择，以便避免无意丢失或隐藏已选文件。
53. 作为中文用户，我希望所有新文案使用简体中文，以便完整理解新交互。
54. 作为 English 用户，我希望所有新增文案同步提供 English，以便切换语言后布局和功能完整。
55. 作为项目维护者，我希望此次变更继续局限于独立原型，以便生产应用不受影响。

## Implementation Decisions

### 1. 交付范围与隔离边界

- 本 PRD只修改独立房间工作区原型。
- 不修改生产 React 房间页、路由、API、SSE、数据库、文件存储、权限协议或构建配置。
- 不新增 npm、Bun、Go 或 CDN 依赖。
- 继续使用固定模拟数据和页面内存状态；语言仍可按既有原型规则保存在 localStorage。
- 现有共享／私密可见性、房主匿名投影、回收站、容量和聊天规则不得因视觉重构改变。

### 2. 文件范围信息架构

- 顶层视图保持“文件列表／文件动态／回收站”。
- 文件列表增加范围视图状态：全部、共享文件、私密文件。
- 内部业务状态继续使用 `shared` 与 `direct`；所有用户可见的 `direct` 文案改为“私密”及对应 English。
- 全部模式渲染两个分组：共享文件在前、私密文件在后。
- 私密分组包含当前身份完整可见的私密文件，以及房主有权看到的匿名投影；不创建“匿名文件”第三范围。
- 单独选择共享或私密范围时只渲染一个平铺列表，不显示可折叠分组标题。
- 文件动态与回收站继续使用统一视图和现有身份投影，不增加共享／私密顶层页面。

### 3. 分组、排序与折叠

- 全部模式的两个分组默认展开。
- 分组标题包含图标、本地化名称和当前搜索结果数量。
- 分组标题是可访问按钮，暴露展开状态；点击只折叠内容，不切换范围视图。
- 折叠状态只保存在当前页面内存，刷新恢复默认展开。
- 当前排序规则分别应用于共享数组与私密数组，然后按固定分组顺序合并渲染。
- 搜索、我上传、发给我等身份筛选必须先应用权限投影，再计算每个分组数量。
- 匿名投影仍只能使用稳定别名参与搜索，隐藏原名不得命中。

### 4. 文件列表顶部布局

- 桌面和平板第一行依次为范围分段控件、搜索、排序和批量选择。
- 删除原来的范围下拉选择器；范围改为始终可见的分段控件。
- 删除顶部独立总数量；数量进入分组标题。单范围视图可以在标题区域显示对应数量。
- 文件列表第一行下方放置常驻拖放条。
- 移动端第一行显示“全部／共享／私密”，第二行显示搜索和“选择”；排序放入筛选或更多入口。
- 新的 English 长文案不得挤出容器或制造横向滚动。

### 5. 顶部文件入口

- 顶部只保留“添加文件”和“发送已有私密文件”。
- “添加文件”是唯一的本地文件选择入口；点击后打开系统文件选择器。
- 删除顶部独立“私密发送”入口。私密与共享是待发送区中的范围选择，不是文件来源入口。
- “发送已有私密文件”打开历史文件多选器，只展示当前用户原始上传、仍可复用的私密文件。
- 历史文件多选器允许选择多个文件和多个新接收者；已经拥有权限的接收者保持不可选并说明原因。
- 复用历史文件只新增接收关系、聊天文件卡和事件，不增加物理容量。
- 共享文件在聊天中继续通过引用发送，不进入“发送已有私密文件”选择器。

### 6. 待发送范围预选

- 文件列表当前范围为共享时，本地选择和拖放默认预选共享。
- 当前范围为私密时，默认预选私密。
- 当前范围为全部时，默认预选共享。
- 用户位于文件动态或回收站时，使用最近一次文件列表范围；最近范围为全部或没有记录时默认共享。
- 聊天附件入口始终预选私密，并自动选中当前聊天成员。
- 所有入口都必须打开待发送区；选择文件或释放拖放不得立即创建上传任务。
- 最终按钮文案必须动态表达结果，例如“上传到共享文件”或“私密发送给 2 人”。

### 7. 拖放发现与状态

- 文件列表常驻一条紧凑虚线拖放条，完整文字固定为“拖放文件到这里，或点击添加文件”。
- 不在拖放条中增加第二行辅助文字。
- 整条拖放区域可点击并可获得键盘焦点；Enter 与 Space 触发文件选择器。
- 中间文件主区在文件拖入时显示全区域覆盖层，覆盖层明确表示释放后进入待发送区。
- 文件列表、文件动态和回收站都接受文件释放。
- 打开待发送区时记录原顶层视图；取消或关闭后恢复原视图，不强制切换文件列表。
- 移动端不渲染拖放条，也不依赖拖放事件；移动端继续使用固定添加文件操作。

### 8. 桌面表格与移动卡片

- 桌面表格删除独立范围列。
- 桌面列调整为文件、上传者、大小、时间、状态和操作；操作列只承载主操作和三个点。
- 共享分组标题使用共享图标与柔和绿色系强调；私密分组标题使用锁图标与柔和蓝色系强调，不使用大面积高饱和背景。
- 匿名审计行继续使用现有黄色治理背景和匿名审计标签。
- 移动卡片继续显示共享、私密或匿名审计标签，避免滚动离开分组标题后失去范围上下文。
- 文件名、稳定私密编号、上传者、大小、状态和进度继续遵守现有权限投影。

### 9. 单文件主操作矩阵

| 文件状态与身份 | 直接显示 | 三个点 |
| --- | --- | --- |
| 当前身份可下载的普通文件 | 下载 | 显示 |
| 当前身份待接收的私密文件 | 接收并下载、拒绝 | 不显示 |
| 上传中的文件 | 查看进度 | 显示 |
| 房主无关匿名私密文件 | 无 | 显示 |
| 当前身份无任何次级操作的异常状态 | 允许的主操作 | 不渲染空菜单 |

- 接收并下载继续直接创建模拟接收任务，并更新该接收者状态。
- 接收完成后该行恢复为“下载＋三个点”。
- 拒绝是明确的次要危险按钮，但不得收入三个点菜单。
- 主操作和三个点必须有稳定键盘焦点与屏幕阅读器名称。

### 10. 桌面三个点菜单

- 菜单相对触发按钮右对齐，避免越出文件主区。
- 同一时间只允许一个文件菜单打开；打开新菜单关闭旧菜单。
- 点击菜单外、Escape、切换范围、切换顶层视图或滚动到触发项不可见时关闭菜单。
- 完整可见文件至少提供“查看文件信息”，确保菜单不会为空。
- 当前用户是私密文件上传者时，根据状态显示再次发送、发布为共享文件和查看接收状态。
- 房主治理其他成员文件时，只显示现有权限允许的匿名信息与删除治理操作。
- 无权限操作不渲染，不通过禁用按钮泄露功能或私密状态。
- 移入回收站、永久删除等危险操作使用分隔线与危险色，固定放在菜单底部。
- 菜单只触发既有原型动作，不扩张文件权限。

### 11. 移动底部操作面板

- 移动端点击三个点打开全宽底部操作面板，不使用窄下拉菜单。
- 面板头部显示权限允许的文件名称或匿名名称、范围和大小。
- 普通操作纵向排列；危险操作独立分组。
- 底部提供取消；点击遮罩、向下关闭动作或 Escape 均可关闭。
- 关闭后焦点返回原文件卡的三个点按钮。
- 待接收私密文件的接收并下载与拒绝继续直接显示在卡片上，不打开面板。

### 12. 拒绝接收确认

- 点击拒绝打开轻量确认对话框。
- 对话框只展示当前接收者有权看到的文件名、发送者和大小。
- 文案明确说明发送者会看到已拒绝状态，并且之后仍可再次发送。
- 操作为取消与确认拒绝；确认后更新该接收者的独立状态并追加一条私密文件事件。
- 取消不得更新文件、事件或聊天状态。
- 接收并下载不增加二次确认。

### 13. 临时批量选择模式

- 普通模式不渲染复选框，保持单文件操作为默认路径。
- 点击“批量选择”进入批量模式，桌面表格和移动卡片才显示复选框。
- 批量操作栏显示已选数量、批量下载、私密发送和取消选择。
- 允许跨共享与私密分组选择；折叠分组不清除其中已选 ID。
- 批量下载只有在全部已选文件对当前身份均可下载时启用。
- 私密发送只有在全部已选文件均为当前用户原始上传、仍可复用的私密文件时启用。
- 不满足条件的操作保持禁用，并通过可见说明或 Tooltip 给出首个阻止原因。
- 不得自动忽略不兼容文件，不得把一次操作静默拆成多个批次。
- 切换范围或身份筛选且会隐藏已选文件时，提示用户保留隐藏选择或清空后继续。
- 排序变化不清除选择，因为选择以稳定文件 ID 保存。
- 退出批量模式清空选择并恢复普通操作列。

### 14. 集中状态与派生逻辑

- 新增文件范围视图、共享分组折叠、私密分组折叠、打开文件菜单、移动底部面板、拒绝确认、批量模式、批量选中 ID 和上传来源视图等集中 UI 状态。
- 所有状态变化继续通过集中动作更新；渲染函数不得直接修改业务状态。
- 将“按权限投影后分组、筛选、排序”和“共同批量操作能力”实现为纯派生函数，避免桌面与移动重复权限判断。
- 单文件菜单项由权限结果和文件状态统一派生，桌面下拉菜单与移动底部面板消费同一操作描述，不分别维护规则。
- 拖放、按钮添加和聊天附件复用同一个待发送入口，只传入来源、默认范围、预选接收者和返回视图。

### 15. 国际化

- 所有新增或修改的可见文案、ARIA 名称、确认提示、空状态、禁用原因和演示控制器文案必须同时提供简体中文与 English。
- 用户可见范围术语统一为共享／私密；English 使用 Shared／Private。
- 文件名、稳定私密编号、用户昵称、状态内部值和代码内部 `direct` 不翻译。
- 两种语言词典键必须保持完整一致。
- 切换语言不得重置范围、折叠、批量选择、打开任务或传输进度。

### 16. 无障碍与键盘

- 范围分段控件使用合适的 Tab 或单选语义，支持方向键切换。
- 分组标题暴露展开状态，Enter 与 Space 切换折叠。
- 文件菜单使用菜单语义，支持上下方向键、Home、End、Enter 和 Escape。
- 拒绝确认和移动底部面板打开后限制焦点在弹层内；关闭后返回触发按钮。
- 拖放条既是拖放目标也是可点击上传入口，提供明确可访问名称。
- 批量选择复选框使用权限投影后的安全文件名称；匿名文件使用稳定匿名名称。
- 所有新动画继续尊重减少动态效果设置。

### 17. 响应式行为

- 桌面保持 PC 即时通讯式三栏，文件操作列不得因菜单重构继续换行堆叠。
- 平板保持文件与聊天双栏；范围分段、搜索、排序和批量入口必须在可用宽度内重排，不能横向滚动。
- 移动端保持文件优先；范围切换占第一行，搜索与选择占第二行，排序收入筛选或更多。
- 移动端普通卡片直接显示主操作；三个点打开底部面板。
- 移动端进入批量模式后，底部固定上传操作暂时替换为批量操作栏，退出批量后恢复。

### 18. 实施顺序

1. 先完成集中状态、分组与操作派生纯函数及对应测试。
2. 再完成桌面范围切换、分组表格、顶部入口和拖放条。
3. 再完成桌面三个点菜单、拒绝确认和单文件操作矩阵。
4. 再完成临时批量模式与历史私密文件多选器。
5. 再完成移动卡片、底部操作面板和移动批量操作栏。
6. 最后补齐双语、键盘、三断点截图和生产工程回归。
- 每阶段完成后独立验证；用户批准本 PRD前不得开始修改原型。

## Testing Decisions

### 测试原则

- 测试外部可观察业务规则，不测试具体 DOM 层级、CSS 类名或内部函数拆分。
- 不采用全面 TDD；先完成实现，再为权限组合、分组排序和复杂状态转换补充测试。
- 继续使用现有 Bun 测试能力，不新增测试依赖。

### 纯逻辑测试

- 权限投影后，全部模式正确分成共享与私密两个集合。
- 普通成员看不到无关私密文件，隐藏文件不得影响私密分组数量。
- 房主匿名投影进入私密分组且不泄露原名、类型和下载能力。
- 共享分组始终在私密分组之前，排序只改变各自内部顺序。
- 搜索和身份筛选先于分组计数生效。
- 范围上下文正确派生共享或私密待发送默认值。
- 单文件状态正确派生主操作、拒绝按钮和三个点可见性。
- 桌面菜单与移动底部面板消费相同的安全操作集合。
- 待接收私密文件只有接收并下载与拒绝，不产生空菜单。
- 批量下载必须由全部选择共同具备下载权限。
- 批量私密发送必须由全部选择共同具备原始上传者复用权限。
- 折叠、排序不清除稳定 ID 选择；退出批量模式清空选择。
- 拒绝确认取消不产生状态变化，确认只更新当前接收者并追加一次事件。
- 历史多文件再次发送不增加容量。
- 中英文词典键继续保持完全一致。

### 浏览器验收

- 桌面检查操作列只显示主操作与三个点，不再多行堆叠。
- 平板检查顶部范围、搜索、排序、批量入口重排且无横向滚动。
- 移动检查范围切换、搜索、选择、主操作和底部操作面板。
- 检查全部、共享、私密三个范围及共享／私密分组折叠。
- 检查房主、普通成员、私密参与者和匿名治理四类权限视图。
- 检查本地添加、点击拖放条、文件列表拖放、文件动态拖放和回收站拖放。
- 检查取消待发送后返回原顶层视图。
- 检查普通下载、待接收、拒绝确认、上传进度和匿名菜单。
- 检查桌面菜单同时只打开一个，点击外部和 Escape 关闭，焦点正确返回。
- 检查移动底部操作面板的安全信息、危险分组和关闭方式。
