# FileDock 房间文件传输一期生产开发 PRD

## Problem Statement

当前生产房间页只提供房间生命周期、成员列表、加入审批、二维码和房主管理。用户进入房间后无法上传、共享、定向发送、接收或下载文件，也无法查看房间文件和文件操作历史。现有页面仍使用旧深色卡片布局，与已上线的浅色首页及已确认房间工作区原型不一致。

服务端同样缺少完整文件领域：没有文件元数据、私密接收关系、容量预留、物理文件存储、上传任务、下载任务、文件事件和权限投影。若直接在现有房间服务中拼接上传接口，会把 SQLite 事务、文件系统写入、权限、SSE 和 HTTP 流混在一起，难以验证容量一致性和匿名信息边界。

此前原始需求以“文件默认定向”为主，已被确认原型中的共享／私密双作用域替代。当前一期需要先交付一个可实际使用的纵向闭环：用户能在新版房间工作区中批量添加本地文件，选择共享或私密范围，查看真实进度，下载或接收文件，复用自己已上传的私密文件，并按身份查看文件列表和持久化文件动态。

本期必须保持边界清晰。回收站和一对一聊天尚未进入生产实现；文件哈希、秒传、去重、断点续传、Range、分块传输和预览也不在本期。页面可以表达后续布局位置，但不得用模拟数据伪装成已实现功能。

## Solution

在现有匿名会话、房间成员和 SSE 基础上新增独立文件领域。服务端负责文件元数据、共享／私密权限、房主匿名投影、整批容量预留、单请求流式上传、物理存储、持久化文件事件和绑定用户的下载任务。所有文件查询和事件查询必须先校验活动房间成员身份，再在服务端生成安全投影；前端不得先接收完整私密数据再隐藏。

多文件发送采用“整批预留、逐文件传输”。确认发送时服务端一次校验整个文件清单和接收者，在同一 SQLite 事务中创建上传批次、文件任务和私密接收关系，并预留总容量。前端按固定并发上传，每个文件独立展示进度、取消、失败和重试。单文件失败只释放自己的预留容量。

下载采用“服务端下载任务 + 浏览器原生下载”。前端创建绑定当前用户和文件的短期下载任务，再打开下载地址。服务端流式发送文件、统计字节，并通过 SSE 只向当前用户推送任务进度。这样既保留浏览器原生保存体验，也避免把大文件完整加载到 JavaScript 内存。

生产房间页按照已确认原型重构为浅色响应式工作区。桌面保留成员、文件主区和未来聊天区；聊天区明确显示尚未开放。移动端只突出文件上传、接收和下载，不显示无效聊天主入口。文件列表采用全部／共享／私密范围和分组布局，文件动态采用持久化时间轴。

## User Stories

1. 作为房间成员，我希望把文件共享到房间，以便当前和后加入的成员都能查看和下载。
2. 作为房间成员，我希望把文件私密发送给一个或多个成员，以便限制完整文件信息和下载权限。
3. 作为上传者，我希望先选择本地文件再选择范围和接收者，以便避免入口含义混乱。
4. 作为上传者，我希望拖放多个文件到文件工作区，以便快速创建待发送清单。
5. 作为移动端用户，我希望通过文件选择器添加文件，以便不依赖移动浏览器不稳定的拖放能力。
6. 作为上传者，我希望发送前看到文件名、大小、范围和接收者，以便最终确认操作结果。
7. 作为上传者，我希望容量不足时整批文件都不开始上传，以便不会产生难以理解的部分成功。
8. 作为上传者，我希望每个文件拥有独立上传进度，以便识别慢任务和失败任务。
9. 作为上传者，我希望看到上传百分比，以便估计任务状态。
10. 作为上传者，我希望可以取消正在上传的单个文件，以便释放网络和房间容量。
11. 作为上传者，我希望一个文件失败时其他文件继续上传，以便不浪费已完成工作。
12. 作为上传者，我希望失败后能重新上传该文件，以便从错误中恢复。
13. 作为上传者，我希望重试创建明确的新任务，以便旧失败状态不会被错误复用。
14. 作为上传者，我希望页面刷新后能从服务端恢复已完成文件，以便列表不依赖浏览器内存。
15. 作为上传者，我希望历史私密文件可以再次发送给新成员，以便不重复上传和占用容量。
16. 作为上传者，我希望一次选择多个历史私密文件，以便批量增加接收关系。
17. 作为上传者，我希望一次选择多个新接收者，以便完成一对多私密发送。
18. 作为上传者，我希望已拥有文件权限的成员不可重复选中，以便避免无效发送。
19. 作为上传者，我希望历史复用不增加物理容量，以便容量统计符合实际存储。
20. 作为接收者，我希望待接收私密文件直接显示“接收并下载”和“拒绝”，以便快速作出决定。
21. 作为接收者，我希望拒绝前看到文件名、发送者、大小和后果，以便避免误操作。
22. 作为接收者，我希望拒绝后上传者能看到拒绝状态，以便双方理解传输结果。
23. 作为接收者，我希望上传者再次发送后状态恢复为待接收，以便重新决定是否接收。
24. 作为接收者，我希望接受成功后自动开始浏览器下载，以便减少一次点击。
25. 作为接收者，我希望下载失败后仍可重新下载，以便不必让上传者再次发送。
26. 作为共享文件使用者，我希望无需接受即可直接下载，以便符合公共目录心智。
27. 作为下载用户，我希望页面显示接收百分比，以便了解大文件进度。
28. 作为下载用户，我希望浏览器原生处理文件保存，以便大文件不会占满页面内存。
29. 作为下载用户，我希望文件名正确保留 Unicode 和扩展名，以便保存后的文件可识别。
30. 作为上传者，我希望看到每个私密接收者的待接收、已接收、已拒绝和已下载状态，以便了解发送结果。
31. 作为私密文件上传者，我希望可以把自己的私密文件发布为共享文件，以便后续全房间使用。
32. 作为私密文件上传者，我希望发布共享前看到二次确认，以便理解该操作扩大可见范围。
33. 作为成员，我希望共享文件和私密文件明显分组，以便避免混淆权限范围。
34. 作为成员，我希望能切换全部、共享和私密范围，以便快速缩小列表。
35. 作为成员，我希望全部范围中共享分组固定在私密分组之前，以便公共目录保持主要位置。
36. 作为成员，我希望两个分组可以独立折叠，以便文件较多时减少滚动。
37. 作为成员，我希望搜索只命中自己有权知道的字段，以便不会通过搜索推断无关私密文件。
38. 作为成员，我希望按我上传的或发给我的筛选，以便快速定位相关文件。
39. 作为成员，我希望排序只改变组内顺序，以便范围分组保持稳定。
40. 作为成员，我希望普通模式不显示复选框，以便单文件操作保持简洁。
41. 作为成员，我希望显式进入批量模式后再多选，以便明确当前操作模式。
42. 作为成员，我希望批量下载只在所有选中文件都可下载时启用，以便避免部分成功。
43. 作为上传者，我希望批量私密发送只支持自己上传且仍可复用的私密文件，以便权限结果可预测。
44. 作为成员，我希望不能执行的菜单项完全不显示，以便不会泄露能力或产生误导。
45. 作为成员，我希望文件列表保留上传者、大小、时间、状态和主要操作，以便快速判断文件。
46. 作为桌面用户，我希望低频操作进入三个点菜单，以便操作列保持紧凑。
47. 作为移动用户，我希望三个点打开底部操作面板，以便操作项拥有足够触控面积。
48. 作为移动用户，我希望文件卡仍显示共享、私密或匿名审计标签，以便滚动时仍能识别范围。
49. 作为移动用户，我希望底部固定区域优先提供添加文件和历史私密发送，以便主要任务容易触达。
50. 作为移动批量用户，我希望固定上传栏替换为批量操作栏，以便不会同时出现两套主要动作。
51. 作为成员，我希望文件动态记录上传、发送、接收、拒绝和下载，以便追踪房间文件活动。
52. 作为成员，我希望文件动态刷新后仍然存在，以便历史不依赖 SSE 或页面内存。
53. 作为成员，我希望文件动态最新记录优先并可继续加载，以便快速查看近期操作。
54. 作为普通成员，我希望只看到共享文件事件和与自己相关的私密文件事件，以便隐私不被泄漏。
55. 作为房主，我希望看到房间内所有文件事件，以便治理房间存储使用。
56. 作为房主，我希望无关私密文件事件只显示匿名编号、参与者、大小、状态和时间，以便治理不等于读取内容。
57. 作为房主，我希望匿名投影不包含原文件名、扩展名、MIME、内容、哈希或下载入口，以便保护私密文件。
58. 作为房主，我希望无关私密文件仍归入私密分组，以便理解其占用范围。
59. 作为房主，我希望看到共享文件大小、私密文件大小、上传预留、总使用和总容量，以便管理空间。
60. 作为普通成员，我希望只看到总使用和总容量，以便不会获得不必要的范围统计。
61. 作为房间成员，我希望同一时刻的并发上传数量受控，以便局域网和服务端保持稳定。
62. 作为房间成员，我希望并发下载数量受控，以便单个用户不会占满服务资源。
63. 作为房间成员，我希望房间销毁后文件不可继续上传或下载，以便生命周期边界一致。
64. 作为房间成员，我希望退出或被移出房间后立即失去文件权限，以便成员关系是实时权限来源。
65. 作为房间成员，我希望 SSE 断开后页面能重新请求权威文件列表和动态，以便不会依赖丢失事件。
66. 作为上传者，我希望其他有权成员能看到节流后的服务端上传进度，以便共享任务状态可感知。
67. 作为下载者，我希望下载进度事件只发送给自己，以便下载行为不泄漏给无关成员。
68. 作为上传者，我希望下载开始和完成进入文件动态，以便了解文件使用情况。
69. 作为安全维护者，我希望所有物理文件使用内部随机名称，以便用户文件名不会成为服务端路径。
70. 作为安全维护者，我希望文件名经过长度和控制字符校验，以便响应头和界面不会被注入。
71. 作为安全维护者，我希望上传声明大小与实际大小必须一致，以便容量无法被绕过。
72. 作为安全维护者，我希望非成员不能创建上传、查询文件或创建下载任务，以便房间边界可靠。
73. 作为安全维护者，我希望下载任务绑定创建用户并快速过期，以便任务标识不能跨用户复用。
74. 作为安全维护者，我希望服务端阻止目录逃逸和符号链接绕过，以便文件只能位于房间目录。
75. 作为维护者，我希望上传失败和服务器重启后预留容量最终一致，以便房间不会永久损失可用空间。
76. 作为维护者，我希望遗留临时文件能被生命周期任务清理，以便磁盘不会无限增长。
77. 作为维护者，我希望文件业务、存储、容量、权限和下载任务拥有清晰边界，以便复杂逻辑可独立测试。
78. 作为中文用户，我希望全部文件文案和错误提示使用简体中文，以便完整理解操作。
79. 作为 English 用户，我希望同一功能拥有完整 English 文案，以便切换语言后功能不缺失。
80. 作为键盘用户，我希望范围、分组、菜单、批量选择和确认弹层可通过键盘完成，以便不依赖鼠标。
81. 作为现有用户，我希望房间加入、审批、延期、退出、踢出和销毁行为继续有效，以便文件开发不破坏生命周期。

83. 作为项目维护者，我希望回收站入口本期不显示可执行删除动作，以便不会承诺尚未实现的数据恢复能力。

## Implementation Decisions

### 1. 交付范围

- 本期是生产开发，不再使用原型模拟数据。
- 交付共享／私密文件上传、文件列表、文件动态、接收／拒绝、下载、历史私密文件复用、发布共享、容量统计、传输进度和新版房间工作区。
- 保留现有房间加入、审批、成员、延期、退出、踢出、解散、倒计时、二维码和 SSE 在线状态能力。
- 回收站和一对一聊天进入待办，不实现表、接口或模拟业务数据。
- 文件预览、内容哈希、完整性校验、重复文件秒传、物理去重、断点续传、Range、分块上传和分块下载不在本期。
- 本期不支持暂停上传；取消或失败后只能创建新上传任务。

### 2. 领域术语

- 用户可见术语统一为“共享文件／Shared files”和“私密文件／Private files”。
- 服务端内部范围值固定为 `shared` 和 `direct`；不得在数据库中存储翻译文本。
- “私密文件编号”是房间内唯一的密码学安全随机展示编号，格式为 `XXXX-XXXX`，显示为“私密文件#7K2M-A9Q4”。
- 私密编号与原名、扩展名、内容、哈希、物理路径和内部主键无关。
- “下载完成”在本期表示服务端完成响应字节发送，不表示用户已打开文件或操作系统已最终落盘。

### 3. 模块边界

- 文件业务模块负责编排上传批次、接收关系、历史复用、发布共享和状态机；不得直接拼接物理路径。
- 权限投影模块以文件、成员身份和房间角色为输入，输出完整、匿名或不可见投影；列表、动态、详情、批量能力和 SSE 受众必须复用该规则。
- 容量模块负责整批预留、单文件完成结算、失败释放和不变量检查，所有容量变化必须在 SQLite 事务中完成。
- 文件存储模块负责根目录约束、安全内部名称、临时文件、流式写入、大小校验、同步落盘、原子移动和幂等删除。
- 文件事件模块负责不可变事件写入、游标分页和身份安全投影；不得把 SSE 内存事件当作历史数据库。
- 下载任务模块负责短期任务、用户绑定、并发限制、响应计数、取消和 SSE 进度。
- 生命周期模块扩展房间销毁、失效预留和遗留临时文件清理。
- 前端传输队列负责固定并发、排队、XHR 上传进度、取消、失败和新任务重试。
- 房间工作区负责布局与交互，只消费服务端安全 DTO，不重复推导后端私密可见性。

### 4. 数据模型

- 房间增加总容量、已使用容量和预留容量。新房间默认总容量为 2 GiB。
- 已使用容量只统计状态为可用的物理文件；同一文件新增私密接收者或发布共享不重复计费。
- 预留容量只统计已经创建但尚未完成、失败、取消或失效的上传任务。
- 上传批次保存创建者、房间、幂等请求标识、范围、文件总数、声明总大小、状态和时间。
- 文件记录保存房间、批次、上传者、内部存储名称、原始名称、声明 MIME、检测 MIME、声明大小、实际大小、范围、私密编号、状态和上传时间。
- 文件状态至少包含 `reserved`、`uploading`、`available`、`failed` 和 `cancelled`。失败与取消记录不出现在当前文件列表，但保留对应文件事件。
- 私密文件必须存在私密编号；共享文件不需要向用户展示私密编号。
- 私密接收关系保存文件、接收者、状态、发送时间、接收时间、拒绝时间、首次下载时间、最后下载时间和下载次数。
- 接收状态至少包含 `pending`、`accepted`、`declined` 和 `downloaded`。
- 文件事件保存房间、文件、操作者、事件类型、内部安全载荷和发生时间。事件只追加，不原地改写。
- 上传批次、文件、接收关系和事件均使用内部稳定标识；不得使用房间四位码、文件名或私密编号作为主键。
- 当前处于开发阶段，直接调整表结构和自动迁移，不提供尚未发布旧结构的兼容层。

### 5. 容量事务与不变量

- 创建上传批次时，在一个事务中重新读取活动房间并验证创建者仍是活动成员。
- 服务端校验文件清单非空、每项大小大于零、总大小无整数溢出、私密接收者合法且去重。
- 使用条件更新保证 `used + reserved + batchTotal <= capacity`，受影响行数必须为一，否则返回容量不足。
- 条件更新成功后才创建批次、文件和接收关系；任一写入失败回滚整个事务。
- 文件开始上传只改变文件状态，不再次增加预留。
- 文件完成时在一个事务中将其从预留转为已使用，并写入可用状态和完成事件。
- 文件失败、取消或失效时只减少该文件尚未结算的预留，不改变同批其他文件。
- 容量字段不得为负数；已使用与预留不得超过总容量。服务层在每次变化后显式检查不变量。
- 并发请求必须依赖数据库条件更新，不依赖进程内先读后写判断。
- 历史私密复用、接收、拒绝、重新下载和发布共享不改变已使用或预留容量。

### 6. 多文件上传批次

- 创建批次接口一次接收范围、接收者和文件元数据数组。
- 每个文件元数据包含原始名称、声明大小和声明 MIME；服务端生成独立文件标识和上传地址。
- 客户端必须发送幂等请求标识。相同用户、房间和幂等标识重复请求返回同一批次结果，不重复预留容量。
- 共享批次不得携带接收者；私密批次必须至少有一个活动接收者且不能包含上传者自己。
- 服务端在批次创建后写入上传开始相关文件事件，并向有权用户发送文件创建通知。
- 前端固定最多同时上传 2 个文件；其余文件在当前浏览器队列中等待。
- 服务端同时限制全局上传 4、单房间 2、单用户 2。该数值本期固定，管理员配置后续实现。
- 排队中的前端任务尚未调用内容上传接口，但服务端容量已经预留。

### 7. 单文件流式上传

- 文件内容使用单次 HTTP 请求上传，必须携带正确 Content-Length；本期不接受分块协议。
- 上传接口只接受批次创建者，且文件必须处于可开始上传状态。
- 服务端使用受限读取器流式写入临时文件，不把完整内容读入内存。
- 临时路径只由服务端内部标识生成，不拼接用户文件名。
- 服务端读取文件头检测基础 MIME；用户声明 MIME 只作为元数据，不作为安全依据。
- 实际字节超过声明大小时立即中止；请求结束后实际大小必须与声明大小完全一致。
- 写入成功后同步临时文件，并在同一文件系统内原子移动到房间文件目录。
- 只有原子移动成功且容量结算事务成功后，文件才能变为可用。
- 若移动成功但数据库结算失败，存储模块必须执行补偿删除并保留内部错误日志。
- 上传过程中服务端按不高于每 500 毫秒一次且进度至少变化 1% 的规则节流发布进度。
- 上传者页面以 XHR 本地上传进度为主；其他有权用户使用服务端接收进度。

### 8. 上传取消、失败、失效与重试

- 前端取消时先中止 XHR，再调用幂等取消接口；服务端也必须能从客户端断开中识别失败。
- 取消接口只允许批次创建者操作未完成文件。
- 取消、网络中断、超出声明大小、大小不一致、并发限制、写盘失败和原子移动失败必须得到明确状态。
- 可归因用户取消时记为已取消；其他传输失败记为上传失败。
- 失败处理幂等删除临时文件、释放该文件预留、写入文件事件并通知有权用户。
- 创建后 10 分钟仍未开始内容上传的文件自动失效并按失败释放容量。
- 正在流式处理的请求由活动任务注册表保护，不得被普通失效扫描误删。
- 服务重启后，遗留 `uploading` 记录和临时文件由生命周期恢复扫描标记失败并释放容量。
- 重试不复活旧文件记录；前端以原元数据创建新批次或新单文件批次并重新传输。

### 9. 物理存储

- 文件根目录位于应用数据目录下，并按内部房间标识隔离。
- 可用文件使用内部随机存储名称且不保留用户扩展名；临时文件位于独立上传临时目录。
- 存储模块在初始化时创建目录并解析绝对根路径；每次操作验证目标仍位于允许根目录内。
- 不跟随用户可控符号链接；发现目录类型或归属异常时拒绝操作并记录内部错误。
- 房间销毁清理必须先阻止新文件任务，再取消活动上传和下载，最后幂等删除房间目录。
- 文件系统删除失败接入现有房间清理重试状态，不得先释放房间号再继续暴露旧目录。

### 10. 文件权限投影

- 非活动成员对房间文件、事件、上传和下载均无权限。
- 共享文件对所有当前活动成员返回完整投影并允许下载。
- 私密文件只对原上传者和接收者返回完整投影。
- 房主不是私密参与者时返回匿名投影；普通无关成员完全不可见。
- 完整投影可以包含原名、声明或检测 MIME、大小、上传者、私密编号、状态、时间和当前身份允许的操作。
- 匿名投影只能包含私密编号、发送者显示名、接收者显示名、准确大小、范围、状态、时间和房主管理所需的事件类型。
- 匿名投影不得包含原名、扩展名、MIME、内容、内部存储名称、内部路径、未来哈希、预览、下载任务入口或接收状态内部备注。
- 搜索必须在权限投影语义下执行。房主匿名记录只能通过私密编号匹配，隐藏原名不得影响命中或数量。
- 所有列表数量、分组数量、分页游标和空状态必须在权限过滤后计算，不得通过总数泄漏隐藏文件存在。
- 操作能力由服务端返回或由安全 DTO 中明确能力字段表达；前端隐藏无权限操作，但服务端仍必须重新鉴权。

### 11. 私密接收状态

- 私密文件批次创建时，为每个接收者创建 `pending` 关系。
- 接收接口使用条件更新从 `pending` 进入 `accepted`，并在同一事务中写入接收事件。
- 接收成功后创建当前用户下载任务；若下载任务创建失败，接收状态仍为 `accepted`。
- 拒绝接口使用条件更新从 `pending` 进入 `declined`，并写入拒绝事件。
- `declined` 接收者保留私密文件记录但没有下载权限。
- 上传者历史复用同一文件时，对没有关系的成员新增 `pending`；对 `declined` 成员重新发送时重置为 `pending` 并更新时间。
- 已经处于 `pending`、`accepted` 或 `downloaded` 的成员不得被重复发送，接口返回可识别的跳过明细或在全体无变化时返回冲突。
- 一个私密文件的各接收者状态独立变化，不相互覆盖。

### 12. 历史私密文件复用与发布共享

- 可复用列表只包含当前用户原始上传、状态可用、范围为私密的文件。
- 接收者、房主匿名观察者和其他成员不能复用该文件。
- 多文件复用在一个事务中校验全部文件仍可复用和全部目标成员仍有效，再更新接收关系。
- 不满足权限时整次请求失败，不自动忽略不兼容文件。
- 复用成功为每个文件写入一次复用事件，并通知新增或重置的接收者。
- 私密上传者可以发布为共享文件；发布需要明确二次确认。
- 发布后范围永久改为共享，本期不支持直接改回私密。
- 原接收关系保留作为历史，但不再决定下载权限；全部活动成员获得完整共享投影。
- 私密编号可以内部保留以维持历史引用，但共享列表不再作为主要标签展示。
- 发布共享不复制物理文件、不改变容量。

### 13. 文件列表接口

- 文件列表接口使用房间四位码作为外部房间定位，并校验当前活动成员。
- 查询支持范围、身份筛选、搜索、排序和游标；默认只返回可用或上传中的当前文件。
- 范围支持全部、共享和私密；身份支持全部、我上传和发给我。
- 排序至少支持最新、最早、大小升序和大小降序，并用内部稳定标识作为相同排序值的游标补充项。
- 全部范围返回共享与私密两个独立分组结果、权限过滤后的数量和各自分页状态，共享固定在前。
- 单范围查询只返回对应分组。
- 默认每个分组返回 30 项，最大 100 项；继续加载只推进目标分组游标。
- 上传失败和取消记录不进入当前文件列表；其结果只在文件动态和本地任务区展示。
- 返回 DTO 必须包含安全显示名称、范围标签、上传者、大小、时间、状态、进度、接收摘要和允许操作。

### 14. 持久化文件动态

- 事件类型至少覆盖批次创建、上传开始、上传完成、上传失败、上传取消、私密发送、历史复用、发布共享、接收、拒绝、下载开始和下载完成。
- 进度百分比不逐条写入持久化事件表，避免高频数据膨胀。
- 事件保留到房间销毁，不按 15 分钟或普通 SSE 重连窗口清理。
- 时间轴默认每页 30 条，最大 100 条，按发生时间和稳定标识倒序游标分页。
- 普通成员看到共享事件和与自己有关的私密事件。
- 私密参与者看到完整安全信息；房主无关私密事件看到匿名信息；普通无关成员看不到事件及数量。
- 上传失败事件不得向无关接收者泄漏内部错误。用户只看到安全错误分类，详细原因只进入内部日志。
- SSE 文件事件携带足以定位文件或触发查询失效的安全字段；客户端收到未知事件或发生断线时重新请求列表和时间轴。

### 15. 下载任务与进度

- 下载前先创建短期任务。任务绑定当前用户、文件、房间和期望总大小。
- 私密 `pending` 用户必须先调用接收流程；共享、私密上传者、`accepted` 和 `downloaded` 接收者可直接创建任务。
- `declined` 接收者、房主匿名观察者、无关成员和非成员不能创建下载任务。
- 下载任务标识不是权限凭证。实际下载请求必须携带有效会话并再次匹配任务用户。
- 任务默认 10 分钟未开始即过期；开始后只能有一个活动响应。重新下载创建新任务。
- 服务端固定限制全局下载 50、单房间 10、单用户 2；超过限制返回本地化业务错误。
- 下载响应使用浏览器原生附件保存，设置安全编码的 Content-Disposition、检测 MIME、Content-Length 和 `X-Content-Type-Options: nosniff`。
- 本期忽略 Range 请求并返回完整文件；不得声称支持断点续传。
- 响应写入过程中累计已发送字节，按不高于每 250 毫秒一次且至少变化 1% 的规则向任务用户推送进度。
- 流开始写入下载开始事件；完整发送后更新接收关系的下载次数与时间，并写入下载完成事件。
- 客户端断开或服务端写入失败时任务变为失败，不写下载完成事件；已接受状态不回退。
- 下载进度只发送给任务用户；持久化文件动态中的下载开始和完成按既定权限投影可见。

### 16. SSE 集成

- 复用现有按用户连接的 SSE Hub，不新增第二条房间专用 EventSource。
- 文件事件受众必须由权限模块计算，禁止简单广播全部房间成员后依赖前端隐藏。
- 共享上传进度可以发送给全部活动成员；私密上传进度只发送给上传者、接收者和房主匿名治理视图。
- 下载任务进度只发送给任务创建用户。
- 文件可用、失败、取消、接收、拒绝、历史复用和发布共享事件用于使对应查询失效或合并安全状态。
- 高频进度使用内存 SSE，不进入持久化文件事件表。
- 慢连接继续遵守现有 Hub 的有界通道和关闭策略；不能因文件进度无限堆积事件。
- SSE 断线不影响上传或浏览器下载；重连后客户端重新查询权威列表、容量和文件动态。

### 17. 房间生命周期集成

- 房间进入销毁中状态后拒绝新批次、内容上传、接收、复用、发布和下载任务。
- 销毁开始时通知活动文件任务停止；正在进行的响应按现有销毁宽限策略结束或被关闭。
- 房间清理顺序必须包含取消任务、释放或删除文件元数据、删除物理目录和清理文件事件。
- 文件目录清理失败时现有清理任务进入可重试失败状态，房间号继续锁定。
- 成员退出或被踢后，后续文件 API 立即拒绝；已创建但尚未开始的下载任务也失效。
- 房间快照增加容量字段。房主获得范围细分，普通成员只获得总使用和总容量。

### 18. 错误码与国际化

- 新增错误至少覆盖容量不足、文件清单无效、接收者无效、文件不可见、文件状态冲突、上传任务过期、上传大小不一致、上传取消、存储失败、下载任务过期、下载并发受限和成员权限失效。
- 后端业务层只返回错误码、翻译参数和内部原因；统一响应层根据 Accept-Language 生成用户消息。
- 每个新增错误码必须同时提供简体中文和 English，并通过词典完整性测试。
- 前端所有按钮、范围、状态、确认、空状态、进度、失败和权限提示必须使用翻译键。
- 文件名、私密编号、成员昵称、内部状态值、JSON 字段和日志不翻译。
- 语言选择仍只保存在前端 localStorage，后端不持久化用户语言。

### 19. 生产房间工作区

- 房间加入、PIN、审批等待、被踢、销毁和加载错误页面保持原有业务逻辑，同时迁移到统一浅色视觉。
- 桌面布局包含固定房间顶栏、左侧成员栏、中间文件主区、右侧未来聊天区和底部传输任务栏。
- 右侧聊天区只显示本地化“后续开放一对一聊天”状态，不显示模拟会话、输入框或可点击发送入口。
- 平板隐藏独立成员栏，通过抽屉查看成员；文件主区和未来聊天占位区按可用宽度重排。
- 移动端文件优先，不展示聊天主入口；成员和房间管理进入顶栏抽屉或更多菜单。
- 顶栏展示房间号、成员数、剩余时间和容量；二维码、延期、退出、解散和加入审批进入清晰操作入口。
- 房间二维码改为弹层，不在主页面底部常驻。
- 文件主区保留文件列表和文件动态两个顶层视图；回收站 Tab 本期不渲染。
- 顶部文件入口只有添加文件和发送已有私密文件。
- 桌面文件列表删除独立范围列，通过范围切换、分组标题、私密编号和匿名审计样式表达范围。
- 普通文件突出下载和三个点；待接收私密文件突出接收并下载和拒绝；上传中突出查看进度；匿名文件只有安全菜单。
- 删除、移入回收站和永久删除操作本期不得出现。
- 上传任务栏展示队列、速度、百分比、取消、失败和重试；下载任务栏展示服务端 SSE 百分比。
- 文件选择、拖放和历史复用必须进入统一待发送确认流程，不得选择后立即上传。

### 20. 前端数据与状态

- 服务端列表和动态使用 TanStack Query 管理，查询键必须包含房间、范围、筛选、搜索、排序和分页参数。
- SSE 事件优先执行精确缓存更新；无法安全合并或事件未知时使对应查询失效并重新获取。
- 传输队列使用独立集中状态，不把 File 对象写入 localStorage、IndexedDB 或查询缓存。
- 上传任务在当前页面生命周期内保存本地 File 引用；刷新后不可恢复本地字节，只显示服务端已完成或失败状态。
- 上传队列以稳定客户端任务标识关联服务端文件标识，防止列表重排丢失进度。
- 退出批量模式清空选择；排序不清空稳定选择；切换筛选会隐藏选择时要求用户选择保留隐藏项或清空。
- 批量操作由全部选择共同权限决定，不静默忽略不兼容文件。
- 下载任务进度只保存短期界面状态；页面刷新后过期任务不恢复为进行中。

### 21. 无障碍与响应式

- 范围控件使用单选或 Tab 语义并支持方向键。
- 分组折叠按钮暴露展开状态；菜单支持方向键、Home、End、Enter 和 Escape。
- 确认弹层和移动底部面板限制焦点，关闭后返回触发控件。
- 文件选择复选框使用权限安全的显示名称；匿名文件使用私密编号。
- 上传进度和下载进度使用 progressbar 语义并提供当前值。
- 拖放条可以通过 Enter 或 Space 打开文件选择器；移动端不显示无效拖放提示。
- English 长文案不得产生横向页面滚动。
- 动画尊重减少动态效果设置。

- 实施时每个主要阶段独立提交，并按项目实施规则在重大文件变更后等待用户确认。
- 任一阶段需要改变本 PRD 的权限、容量或协议时，必须先更新 PRD并获得批准。

## Testing Decisions

### 测试原则

- 测试外部可观察业务规则、事务结果、安全边界和状态机，不测试内部函数拆分。
- 数据库测试使用独立临时 SQLite，并启用与生产一致的外键和连接约束。
- 文件系统测试使用独立临时目录，不读写真实应用数据目录。
- 并发测试必须验证最终数据库容量，而不是只断言单个函数返回值。
- 不测试 Ant Design 内部 DOM、CSS 类名、图标节点或实现细节。
- 不新增 Playwright 自动验收；浏览器效果由人工验收。

### 后端纯逻辑与数据库测试

- 完整、匿名和不可见三类权限投影。
- 普通成员无法通过搜索、数量、事件或错误差异推断无关私密文件。
- 房主匿名投影不包含原名、扩展名、MIME、路径、内容和下载能力。
- 整批预留成功、容量不足整批回滚、整数边界和空清单。
- 两个并发批次竞争最后容量时最多一个成功。
- 完成结算、失败释放、取消释放、重复回调幂等和容量非负不变量。
- 私密接收、拒绝、再次发送、重新下载和多接收者独立状态。
- 历史复用不创建物理文件、不增加容量且只能由原上传者执行。
- 发布共享扩大可见性但不改变物理容量。
- 文件事件分页、稳定排序和身份投影。

### 存储与生命周期测试

- 用户文件名不能影响物理路径。
- 目录逃逸、异常符号链接和非法根目录被拒绝。
- 流式写入不超过声明大小，短写和长写均失败。
- 成功上传执行原子移动，临时文件消失且最终文件存在。
- 数据库结算失败后的物理补偿删除。
- 取消、断开、失效和服务重启遗留任务释放预留并清理临时文件。
- 房间销毁删除文件目录；删除失败进入现有清理重试状态并继续锁定房间号。

### API 与鉴权测试

- 非成员不能创建批次、上传、列出文件、查看动态、接收、拒绝、复用、发布或下载。
- 共享、私密参与者、房主匿名观察者和普通无关成员的响应差异符合权限。
- 上传任务只能由创建者使用和取消。
- Content-Length 缺失、错误或超限得到双语业务错误。
- 下载任务绑定用户、过期、重复消费、并发上限和成员失效。
- 私密待接收、已接收、已拒绝和已下载状态的下载权限。
- 文件名响应头编码不允许换行或响应拆分。

### SSE 测试

- 共享文件状态发送给全部活动成员。
- 私密状态只发送给上传者、接收者和房主安全治理视图。
- 房主接收的无关私密事件不包含敏感字段。
- 下载进度只发送给下载任务用户。
- 进度节流不会为每个写入块产生事件。
- 慢订阅者仍遵守有界通道策略，不能阻塞上传或下载流。

### 前端纯逻辑测试

- 上传队列并发上限、排队推进、取消、失败和新任务重试。
- 服务端任务标识与本地 File 引用的关联稳定。
- 权限投影后的共享／私密分组、组内排序、搜索和身份筛选。
- 匿名编号可搜索而隐藏原名不可命中。
- 单文件主要操作和菜单操作矩阵。
- 批量下载与批量私密发送采用全部选择共同权限。
- SSE 进度、完成、失败和未知事件的状态转换。
- 中英文词典键完全一致。
- 使用 Bun 执行纯逻辑测试，不引入完整 DOM 测试框架。

### 工程回归

- Go 全包测试通过。
- 前端 TypeScript 检查和生产构建通过。
- Go 单二进制构建通过并正确嵌入前端产物。
- 新增目录和临时测试文件不进入 Git。

### 人工浏览器验收

- 桌面验证三栏工作区、菜单、拖放、多文件上传、列表分组、动态和传输任务栏。
- 平板验证成员抽屉、文件主区重排、长文案和无横向滚动。
- 移动验证文件优先、固定操作栏、文件卡、底部操作面板、批量模式和系统文件选择器。
- 分别使用房主、共享成员、私密上传者、私密接收者和无关普通成员验收权限。
- 验证上传成功、取消、失败、重试、容量不足、接收、拒绝、再次发送、发布共享和下载进度。
- 验证简体中文与 English，不得出现缺失键或硬编码单语言提示。
- 验证键盘范围切换、折叠、菜单、确认弹层和焦点返回。
- 人工验收不使用 Playwright 自动化。
