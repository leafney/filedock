# 加入房间弹窗交互与布局优化 PRD

## Problem Statement

首页“加入房间”弹窗仍使用默认底部操作栏，包含“返回首页”和“加入房间”按钮，弹窗宽度偏大，且四位房间号输入上方重复显示字段标签。上一版已经确定四位输入格、自动提交和 Enter 提交，但当前首页弹窗尚未落实，导致交互和房间过渡页不一致。

## Solution

将首页加入房间弹窗收敛为以四位输入格为核心的轻量入口：保留标题、关闭图标和标准关闭方式，移除底部按钮及重复标签，使用窄宽度响应式布局。输入满四位后自动触发现有跳转逻辑；用户也可在完整四位时按 Enter 触发同一逻辑。房间不存在、需要密码或审批等状态继续由房间过渡页处理。

## User Stories

1. 作为用户，我希望打开加入房间弹窗后直接看到四个输入格，以便快速输入房间号。
2. 作为用户，我希望弹窗打开时第一个输入格自动获得焦点，以便无需额外点击即可输入。
3. 作为用户，我希望粘贴包含四位数字的内容时自动拆分到四个输入格，以便快速填写分享的房间号。
4. 作为用户，我希望输入满四位后自动提交，以便减少一次确认点击。
5. 作为用户，我希望在四位数字完整时按 Enter 提交，以便使用键盘完成操作。
6. 作为用户，我希望自动提交进行中按 Enter 不会产生重复跳转，以便避免重复请求和页面抖动。
7. 作为用户，我希望自动提交失败后仍可修改房间号或按 Enter 重试，以便纠正输入错误。
8. 作为用户，我希望房间不存在、需要密码或审批时仍进入统一房间过渡页，以便所有房间状态获得一致提示。
9. 作为用户，我希望弹窗没有底部“返回首页”和“加入房间”按钮，以便界面更简洁。
10. 作为用户，我希望不再看到重复的“房间号”字段标签和必填星号，以便四格输入区域更紧凑。
11. 作为用户，我希望可以点击右上角关闭图标、遮罩空白区域或按 Esc 关闭弹窗，以便随时取消操作。
12. 作为用户，我希望关闭后再次打开时输入内容为空，以便开始新的加入操作。
13. 作为移动端用户，我希望弹窗不会超出屏幕，输入格仍保持居中可用。
14. 作为英文用户，我希望弹窗标题、无障碍名称和相关提示继续通过中英文 i18n 正确显示。

## Implementation Decisions

- 仅修改首页加入房间弹窗组件及其样式，不修改后端接口、数据库、房间过渡页、路由协议或 SSE。
- 使用现有 `Input.OTP` 四格输入控件，长度固定为 4，输入模式为数字；输入值统一清洗为 ASCII 数字并限制最多四位。
- 保留弹窗标题“加入房间”和右上角关闭图标；设置无底部页脚（`footer` 为空），移除取消和确认按钮。
- 保留 Ant Design 默认的 `onCancel` 行为：右上角关闭、点击遮罩空白区域和按 Esc 均可关闭。
- 弹窗打开时自动聚焦第一个输入格；移动端不阻止系统数字键盘弹出。
- 关闭弹窗时清空输入值并重置提交闸门，下一次打开重新获得初始状态。
- 自动提交条件为值严格匹配四位数字；Enter 仅在值完整且没有提交请求进行中时触发。
- 自动提交和 Enter 必须调用同一提交函数及同一 `PinSubmissionGate`（或等价的本地状态闸门）：`idle -> pending -> complete`；请求/导航失败回到 `idle`，成功后进入 `complete`，避免同一输入触发重复操作。
- `onJoined` 仍然沿用当前首页到 `/rooms/{roomCode}` 的导航方式。首页不调用 `getJoinInfo` 预检；后续状态由 `RoomPage` 统一展示。
- 桌面端弹窗宽度设置为约 360px；移动端宽度为 `calc(100vw - 32px)`，最大宽度不超过桌面值。输入格水平居中，保持四格间距和可见焦点样式。
- 所有新增或调整的面向用户文案继续使用已有 i18n 键；如需新增无障碍标签，必须同时补充 `zh-CN` 与 `en`。
- 不新增数据库字段、API 参数、错误码、SSE 事件或持久化数据。

## Testing Decisions

- 重点测试外部行为，不测试 React 内部实现细节。
- 扩展现有房间过渡交互纯逻辑测试，覆盖：四位自动提交、Enter 提交、提交中去重、失败后可重试、成功后阻止重复提交、关闭后重置。
- 使用现有前端构建和双语词典测试，确保新增文案（如有）中英文键一致且无空值。
- 使用 Playwright 做页面验证：桌面端检查弹窗宽度、无底部按钮、无“房间号”标签、四格居中及自动聚焦；移动视口检查弹窗不溢出、输入可用、遮罩关闭；验证四位输入和 Enter 均能导航到现有房间过渡页。
- 完成后运行前端单元测试、前端生产构建、Go 测试/构建及 `git diff --check`。

## Out of Scope

- 不改变房间加入 API、房间密码校验、审批申请、SSE 推送或数据库结构。
- 不在首页弹窗内显示房间不存在、密码错误或审批状态详情。
- 不新增“验证并加入”按钮、二次确认弹窗或首页预检接口。
- 不修改房间过渡页、首页其他弹窗、Header/Footer、主题系统或房间工作区。

## Further Notes

- 该优化是现有加入流程的前端入口收口，房间号输入成功后的业务行为完全复用现有导航和过渡页逻辑。
- 如果后续需要在首页直接展示加入失败原因，应另行设计预检接口和错误状态，不在本 PRD 中扩展。
