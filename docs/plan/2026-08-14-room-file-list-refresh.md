# 房间文件列表区域重构 PRD

## Problem Statement

房间页面的文件列表区域存在明显的视觉和交互问题：

1. 排序和筛选使用原生 HTML `select`，弹出的系统菜单与 Ant Design 控件风格不一致。
2. 文件列表同时显示共享文件分组和私密文件分组，两个高大的卡片容器造成大量空白，信息扫描效率低。
3. 文件行信息和接收者信息容易被撑成多行，单屏可见文件数量少。
4. 共享文件和私密文件的权限不同，统一列表后不能丢失接收、拒绝、转发、公开、删除等差异。
5. 拖拽上传提示始终占据一整行；首次使用需要引导，但已有文件时不应持续浪费空间。
6. 桌面端、移动端、深色主题下控件和文件列表样式需要统一。

## Solution

将文件列表改为无分页的统一文件列表，使用 `range` 控制全部、共享、私密范围；共享和私密文件在 `all` 范围下按同一排序规则混排。前端使用 Ant Design 完成标准控件和下拉菜单，自定义文件行保留项目特有的权限操作。

文件类型采用顶部切换、行首图标背景、左侧色条和行内标签四层区分：共享使用绿色体系，私密使用琥珀色体系。文件行最多两行，成员接收状态压缩为摘要。空列表保留拖拽上传引导，已有文件时只在拖入瞬间显示覆盖层。

## User Stories

1. 作为房间成员，我希望在一个列表中查看共享文件和私密文件，以便快速比较和查找文件。
2. 作为房间成员，我希望通过“全部 / 共享 / 私密”切换列表范围，以便快速缩小查看范围。
3. 作为房间成员，我希望顶部范围切换显示各类型数量，以便了解当前文件分布。
4. 作为房间成员，我希望共享文件和私密文件有明显但克制的颜色和图标差异，以便不阅读全部文字也能识别类型。
5. 作为房间成员，我希望文件行最多占用两行，以便单屏看到更多文件。
6. 作为房间成员，我希望文件名过长时省略，而不是撑宽或换成多行。
7. 作为私密文件接收者，我希望看到待接收、已接收、已拒绝等状态摘要，以便知道下一步操作。
8. 作为房间成员，我希望接收者姓名列表不会撑高文件行，以便保持列表紧凑。
9. 作为房间成员，我希望能搜索文件名或私密编号，以便快速定位目标文件。
10. 作为房间成员，我希望搜索无结果时看到明确空状态，并能清除搜索条件。
11. 作为房间成员，我希望按文件身份筛选“全部文件 / 我上传的 / 发给我的”，以便只查看相关文件。
12. 作为房间成员，我希望共享范围中不出现永远无结果的“发给我的”选项，以便避免无效筛选。
13. 作为房间成员，我希望按最新、最早、容量从小到大、容量从大到小排序，以便按不同目的查找文件。
14. 作为房间成员，我希望“全部”范围下共享和私密文件真正按同一排序规则混排，以便排序结果可信。
15. 作为房间成员，我希望每行只突出一个主要操作，其他操作收进更多菜单，以便减少视觉噪声。
16. 作为可下载文件的成员，我希望看到下载按钮，并能在更多菜单中查看详情、执行其他被授权操作。
17. 作为待接收私密文件的成员，我希望看到接收按钮，并能在更多菜单中拒绝文件。
18. 作为无权操作某文件的成员，我不希望看到不允许的操作，以便避免误操作。
19. 作为房主，我希望删除、公开等操作继续由后端能力字段控制，以便权限规则不因界面重构改变。
20. 作为房间成员，我希望可以进入批量选择模式，以便一次处理多个文件。
21. 作为房间成员，我希望批量下载仅在所有选中文件都允许下载时可用，以便不会出现部分成功但无明确提示。
22. 作为房间成员，我希望私密转发仅在所有选中文件都允许再次转发时可用，以便避免错误转发共享文件或无权文件。
23. 作为首次使用者，我希望空列表明确提示可以拖拽文件上传，以便发现该能力。
24. 作为已有文件的成员，我不希望拖拽提示长期占用一整行，以便节省内容区域。
25. 作为成员，我希望拖入文件时看到清晰的覆盖提示，以便知道释放位置。
26. 作为移动端成员，我希望主要操作显示短文字“下载 / 接收”，以便不依赖鼠标 Tooltip。
27. 作为移动端成员，我希望次要操作打开底部操作面板，以便适配窄屏。
28. 作为深色主题用户，我希望工具栏、列表、空状态、类型标识、Dropdown 全部协调显示，以便持续阅读。
29. 作为中文用户，我希望所有新增文案都有简体中文翻译。
30. 作为英文用户，我希望所有新增文案都有 English 翻译。
31. 作为键盘用户，我希望 Tabs、筛选控件、文件操作和批量选择都可以获得焦点并操作。
32. 作为辅助技术用户，我希望文件类型、状态和操作按钮有可读的 aria 标签。

## Implementation Decisions

### 1. 后端文件列表契约

- 文件列表接口改为非分页扁平返回：`items` 保存当前范围匹配文件，`total` 保存当前范围匹配数量，并返回 `counts` 保存全部、共享、私密三类匹配数量。
- 请求参数保留：`range`、`identity`、`search`、`sort`；实现中应移除 `limit`、游标参数和分页逻辑。
- `range` 取值：`all`、`shared`、`direct`。`all` 返回共享和私密文件混合结果。
- `identity` 取值：`all`、`uploaded`、`received`。
- `search` 对当前用户可见的显示名称和允许暴露的私密编号执行不区分大小写匹配；不得因为搜索泄露匿名投影的原始文件名。
- `sort` 取值：`newest`、`oldest`、`size_asc`、`size_desc`。
- 后端必须先按权限生成安全投影，再执行搜索、排序和返回，不能先搜索原始私密名称再隐藏结果。
- 排序规则：主字段相同时用 `fileId` 做稳定的次排序；`newest` 使用完成时间，未完成上传回退创建时间。
- 每个文件继续返回 `scope`、`projection`、`privateCode`、`recipients`、`status`、`progress`、`capabilities` 等现有业务字段。
- `counts` 必须基于相同的搜索和身份筛选条件计算，结构为 `{ all: number, shared: number, direct: number }`；`range` 只决定 `items` 返回范围，不改变三类数量计算。
- 删除、接收、拒绝、下载、私密转发、公开、详情等后端业务接口不改变。

### 2. 前端查询和状态

- 文件列表只维护一个查询结果，不再为共享和私密各维护独立查询、独立游标和独立加载更多按钮。
- 查询关键字必须包含：房间号、范围、身份筛选、搜索关键字、排序值；任一条件变化都重新请求列表。
- 切换范围时动态调整身份选项：`shared` 隐藏“发给我的”；`all` 和 `direct` 显示三个身份选项。
- 当前身份选项在切换范围后不可用时自动恢复为 `all`。
- 搜索、范围、身份、排序变化时清空当前批量选择；若已有选中项，沿用现有确认提示逻辑，用户取消时不应用筛选变更。
- 文件动态、回收站、上传恢复、SSE 刷新机制保持现有行为；文件列表刷新后重新应用当前筛选和排序。

### 3. 顶部 Tabs 和操作

- 文件列表、文件动态、回收站使用 Ant Design `Tabs`。
- 回收站数量使用 Badge；数量来自现有回收站计数查询。
- 文件列表 Tab 的右侧操作使用 Ant Design Button：
  - 主按钮：图标 +“添加文件”。
  - 次按钮：图标 +“私密转发”。
- 桌面端使用完整文案；移动端使用“添加”和“私密转发”短文案。
- 保持现有打开上传草稿、打开私密文件复用/转发弹窗的行为。
- 按钮尺寸统一为中等高度，不再使用当前过大的自定义按钮。

### 4. 筛选工具栏

- 范围使用 Ant Design `Segmented`，选项包含数量：全部、共享、私密。
- 搜索使用 Ant Design `Input.Search`；支持清除按钮和现有搜索关键字。
- 身份筛选使用 Ant Design `Dropdown` 或等价菜单：全部文件、我上传的、发给我的。
- 排序使用 Ant Design `Select`：最新优先、最早优先、容量从小到大、容量从大到小。
- 批量选择使用带图标的 Button；未启用时显示空方框图标，启用后使用选中状态和主题色。
- 所有控件高度、间距、边框、焦点样式统一；禁止继续使用原生 `select`。
- 桌面端尽量保持一行；中等宽度允许搜索框独占下一行；移动端搜索框独占一行，其余控件均分可用宽度。

### 5. 统一文件列表和文件行

- 删除共享文件列表、私密文件列表两个高大分组容器，改为单一列表容器。
- 不新增“房间文件”标题；Tabs 下直接显示筛选工具栏和列表。
- 桌面端使用表格式网格对齐，但不使用 Ant Design Table；移动端切换为文件行布局，不显示列标题。
- 每行最多两行信息：
  - 第一行：文件图标、文件名或私密编号 + 文件名、类型标签、主要操作、更多菜单。
  - 第二行：上传者、大小、时间、状态摘要。
- 超长文件名、原始名称、状态摘要单行省略；完整内容通过 Tooltip 或详情弹窗查看。
- 私密编号和文件名同一行展示；匿名投影不得展示原始文件名。
- 私密接收者不直接逐个列出，第二行只显示状态摘要：待接收人数、已接收、已拒绝或混合状态。
- 文件类型视觉标识：
  - 共享：Folder/File 图标、绿色低饱和背景、绿色左侧色条、共享文件标签。
  - 私密：Lock/File 图标、琥珀色低饱和背景、琥珀色左侧色条、私密文件标签。
- 上传中行保留进度条和百分比，不显示下载操作。
- 主要操作规则：
  - `canAccept`：显示接收按钮；拒绝放更多菜单。
  - `status=uploading`：显示上传进度。
  - `canDownload`：显示下载按钮。
  - 无主要操作：仅显示更多菜单（若存在可用菜单项）。
- 更多菜单操作由现有 `fileMenuActions` 和 capabilities 决定，不按 `scope` 直接写死。

### 6. 批量操作

- 批量模式允许跨共享、私密文件选择。
- 批量下载按钮仅在所有选中文件 `canDownload=true` 时启用。
- 私密转发按钮仅在所有选中文件 `canReuse=true` 时启用。
- 不满足条件时禁用按钮，不静默跳过无权限文件。
- 批量栏显示选中数量；退出批量模式清空选择。

### 7. 拖拽上传和空状态

- 空列表且没有搜索/身份筛选时，显示 Ant Design Empty 或项目等价空状态，文案包含可拖放上传提示和添加文件操作。
- 共享/私密筛选的空列表显示对应类型文案。
- 搜索无结果显示未找到匹配文件，并提供清除搜索操作；不显示拖放上传引导。
- 身份筛选无结果显示对应筛选无结果；不显示拖放上传引导。
- 已有文件时不显示永久拖放提示行。
- 文件拖入列表时，显示覆盖整个列表区域的虚线/高亮遮罩和释放提示；释放后沿用现有上传草稿流程。
- 拖拽状态使用现有 drag depth 处理，避免子元素进入/离开造成闪烁。

### 8. 主题、国际化和可访问性

- 所有新增用户文案必须同时增加 `zh-CN` 和 `en` 翻译键；React 组件禁止硬编码文案。
- Ant Design 组件通过现有 ConfigProvider 继承主题；自定义样式只能使用全局主题变量或房间主题变量。
- 深色模式下不得出现白色列表、输入框、Dropdown 或空状态背景。
- 共享绿色和私密琥珀色在浅色、深色主题下都要满足文本对比度。
- Tabs 使用正确的 `role=tablist/tab` 和选中状态；范围切换使用可访问的单选语义。
- 搜索框、筛选菜单、主要操作、更多菜单、文件复选框都必须有可读 aria-label 或可见标签。
- Tooltip 仅用于补充完整文件名、按钮完整含义等信息；移动端不能依赖 Tooltip 才能完成操作。

### 9. 需要修改的模块

- 文件列表查询服务：改为全量扁平结果、统一排序和稳定排序。
- 文件列表 API DTO/服务类型：移除分组游标字段，增加扁平 `items/total` 返回结构。
- 房间文件工作区：替换 Tabs、筛选工具栏、按钮和查询状态。
- 文件列表组件：移除双分组渲染，新增统一列表和响应式行布局。
- 文件权限菜单：继续复用现有 capability 计算函数，仅调整承载控件。
- 文件类型/状态显示工具：增加共享、私密、接收状态摘要生成逻辑。
- 国际化词典：补齐中文和英文文案。
- 全局/房间文件样式：补齐 Ant Design 控件覆盖、统一间距、深色主题和移动端断点。

## Testing Decisions

- 后端业务测试：验证全量扁平返回、共享/私密混排、四种排序、搜索安全投影、身份筛选和数量统计。
- 后端权限测试：验证共享和私密文件的 capabilities 原样返回，匿名投影不泄露原始文件名。
- 前端组件测试：验证范围、身份、搜索、排序变化会重新查询；不可用身份筛选自动恢复；筛选变更会处理已有批量选择。
- 前端权限显示测试：验证接收、拒绝、下载、私密转发、公开、删除等菜单由 capabilities 控制。
- 批量选择测试：验证混合选择时批量下载和私密转发的启用条件。
- 空状态测试：验证无文件、筛选无结果、搜索无结果三类文案和操作差异。
- 响应式测试：至少验证桌面、窄桌面、移动宽度；文件信息不得超过两行，操作不得溢出。
- 主题测试：验证浅色和深色下工具栏、列表、Dropdown、空状态、标签和遮罩无白色异常背景。
- 国际化词典完整性测试：沿用现有中英文词典一致性测试。
- 构建验证：TypeScript、前端生产构建、后端测试、`git diff --check`。

测试只验证外部行为和用户可见结果，不绑定具体 CSS 类名或组件内部实现。

## Out of Scope

- 不新增文件预览功能。
- 不修改上传、下载、断点续传、传输记录业务逻辑。
- 不修改文件动态和回收站业务流程，仅保持刷新和切换正常。
- 不新增数据库表或字段。
- 不保留旧的共享/私密分组列表接口结构，不做旧接口兼容层。
- 不实现文件列表分页、虚拟滚动或无限加载。
- 不改变后端文件权限规则和 capabilities 计算规则。
- 不改变房间容量、文件删除、恢复、永久删除规则。

## Further Notes

- 当前项目处于开发阶段，可直接调整接口结构和前端类型，不需要旧版本兼容。
- 房间最大存活时间为 24 小时；文件列表按全量返回实现，若后续容量或文件数量显著增长，再单独评估分页或虚拟滚动。
- 低智能模型编码时必须先完成后端契约和测试，再修改前端查询类型，最后重构列表和样式，避免前后端字段不一致。
- 实现过程中每个阶段完成后提交 Git，提交信息遵循 Conventional Commits：type/scope 使用英文，description 使用简体中文。
