# 房间过渡页视觉与交互重构 PRD

## Problem Statement

FileDock 当前已完成首页、房间工作区和异常页面的统一 Header/Footer 页面壳，但房间加入前后的过渡页面仍保留旧版的流式布局。加入确认、PIN 验证、审批申请、审批等待、加载、错误、房间不存在/失效和销毁状态之间的页面结构不一致，用户在状态切换时会感到页面跳动，且房间信息、操作入口和错误反馈层级不清晰。

PIN 页面还存在自动验证不可靠的问题：输入完成四位后，当前实现没有稳定触发验证；同时按钮、自动提交和键盘操作之间缺少统一的重复请求保护。

本阶段需要在不修改后端 API、数据库、SSE 协议和房间工作区的前提下，完成房间过渡页的视觉和交互收口。

## Solution

在现有 `AppShell` 基础上，将所有房间过渡状态统一渲染为响应式居中状态卡片。卡片采用固定结构，通过状态图标、语义颜色、标题、说明、房间信息和当前可执行操作表达状态差异。

页面始终保留“返回首页”按钮，便于用户在中间区域直接退出；左上角品牌区域继续支持返回首页。按钮存在主次层级时，返回首页位于左侧，当前业务主操作位于右侧；没有其他业务操作时，返回首页单独居中显示。

PIN 页面只显示四个输入框和返回首页按钮，不显示“验证并加入”按钮。输入四位后自动验证，任意输入框按 Enter 也可验证。两种入口统一使用幂等提交函数，避免自动提交和 Enter 同时触发重复请求。

## User Stories

1. 作为房间访客，我希望加入确认页使用统一的居中卡片，以便在首页壳和房间工作区之间保持稳定的视觉结构。
2. 作为房间访客，我希望卡片显示房间标题和放大的房间号，以便确认自己加入的是正确房间。
3. 作为房间访客，我希望公开房间显示明确的“确认加入”操作，以便完成加入。
4. 作为房间访客，我希望加入确认页始终显示“返回首页”，以便不必依赖左上角 Logo 退出。
5. 作为房间访客，我希望密码房间只看到四个 PIN 输入框，以便界面更简洁。
6. 作为房间访客，我希望输入完成四位 PIN 后自动验证，以便无需额外点击按钮。
7. 作为键盘用户，我希望在任意 PIN 输入框按 Enter 都能触发验证，以便不必移动鼠标。
8. 作为房间访客，我希望 PIN 输入框按位自动前进，以便快速输入四位数字。
9. 作为房间访客，我希望退格时可以返回上一位，以便修正前一位数字。
10. 作为房间访客，我希望粘贴四位 PIN 后自动分配到四个输入框，以便快速完成验证。
11. 作为房间访客，我希望粘贴内容中的空格和非数字字符被过滤，以便常见复制格式也能正常使用。
12. 作为房间访客，我希望输入页面打开后第一格自动获得焦点，以便直接输入或粘贴。
13. 作为移动端用户，我接受自动获得焦点后系统键盘正常弹出，以便立即输入 PIN。
14. 作为房间访客，我希望 PIN 错误后输入内容保留，以便只修改错误数字。
15. 作为房间访客，我希望修改 PIN 后能再次自动验证，也能按 Enter 重试。
16. 作为房间访客，我希望 PIN 验证请求进行时输入框禁用，以便不会产生重复请求。
17. 作为房间访客，我希望 PIN 验证成功后只进入一次房间，避免重复跳转。
18. 作为房间访客，我希望提交审批后看到明确的“等待房主审批”状态，以便知道申请已经提交。
19. 作为审批申请人，我希望等待状态显示房间标题和放大的房间号，以便确认申请目标。
20. 作为审批申请人，我希望等待状态提供“取消申请”，以便在房主处理前撤回申请。
21. 作为审批申请人，我希望等待状态提供“返回首页”，以便暂时离开当前房间。
22. 作为审批申请人，我希望房主批准后通过现有 SSE 自动进入房间工作区，以便不需要手动刷新。
23. 作为审批申请人，我希望房主拒绝或房间失效后看到明确结果，以便知道为什么没有进入房间。
24. 作为房间访客，我希望加载状态使用统一卡片位置，以便加载完成后页面不跳动。
25. 作为房间访客，我希望房间不存在、过期、已销毁状态显示明确原因，并只提供返回首页操作。
26. 作为房间访客，我希望网络或服务暂时异常时可以重新加载，同时仍可返回首页。
27. 作为房间访客，我希望操作失败提示保留在当前卡片内，而不是破坏页面结构。
28. 作为中文用户，我希望所有过渡页文案使用简体中文。
29. 作为 English 用户，我希望所有过渡页文案使用 English。
30. 作为深色主题用户，我希望状态卡片、输入框、按钮、错误提示和页面背景协调显示。
31. 作为跟随系统主题用户，我希望系统主题变化后过渡页自动适配。
32. 作为移动端用户，我希望卡片不溢出屏幕，按钮和输入框保持可操作尺寸。
33. 作为桌面端用户，我希望卡片宽度适中，不因浏览器窗口变宽而过度拉伸。
34. 作为键盘用户，我希望所有按钮和 PIN 输入框都能通过键盘访问。
35. 作为屏幕阅读器用户，我希望加载、审批等待和操作结果通过可读状态及时播报。
36. 作为屏幕阅读器用户，我希望错误内容被标记为重要提示，且四个 PIN 输入框具有明确位置信息。
37. 作为减少动画用户，我希望关闭卡片过渡和加载旋转动画，以避免不适。
38. 作为后续页面开发者，我希望继续复用统一状态卡片结构，以便新增房间状态时不重复实现布局。

## Implementation Decisions

### 1. 状态卡片模块

- 新增可复用的房间过渡卡片展示模块，负责状态图标、状态标签、房间信息、说明、操作区和无障碍属性。
- `RoomGate` 继续负责 AppShell 插槽组合，不再直接拼接散落的链接、标题和按钮。
- 卡片使用统一的内容顺序：状态图标 → 状态标签 → 状态标题 → 状态说明 → 房间信息 → 操作区。
- 房间号使用较大字号、等宽数字和字母间距；不允许被普通辅助文本缩小或省略。
- 房间标题仅在接口已返回且房间确实存在时显示；不可用状态只显示已知房间号。

### 2. 状态与操作映射

| 状态 | 主要内容 | 操作 |
| --- | --- | --- |
| 加载中 | 加载图标、加载说明 | 返回首页 |
| 公开加入确认 | 房间标题、房间号、确认说明 | 返回首页、确认加入 |
| PIN 输入 | 房间标题、房间号、四格 PIN | 返回首页；四位自动验证或 Enter 验证 |
| 审批申请 | 房间标题、房间号、申请说明 | 返回首页、提交加入申请 |
| 审批等待 | 房间标题、房间号、等待说明 | 返回首页、取消申请 |
| 房间不存在/失效/销毁 | 房间号（若已知）、不可用原因 | 仅返回首页 |
| 临时网络/服务异常 | 已获取的房间信息、异常说明 | 返回首页、重新加载 |
| 操作失败 | 当前状态信息、错误原因 | 保留当前可执行操作、返回首页 |

- 返回首页按钮始终作为卡片内的安全退出入口。
- 有业务主操作时，返回首页在左、主操作在右；只有返回首页时居中显示。
- 不增加顶部额外返回链接，避免同一页面出现重复入口；品牌 Logo 返回首页能力保留。

### 3. PIN 输入与提交

- PIN 输入维持四个独立输入框，每格最多一个数字，仅接受 ASCII 数字。
- 输入数字后自动聚焦下一格；空格退格返回上一格。
- 第一格粘贴内容时提取数字并分配到四格，最多取前四位；完成后触发自动验证。
- 页面首次挂载时聚焦第一格；移动端允许浏览器正常弹出软键盘。
- 任意一格按 Enter 都调用同一个提交函数。
- 输入完成四位时调用同一个提交函数，不再通过分散的父层副作用实现自动提交。
- 提交函数必须具备幂等保护：请求进行中忽略后续触发；成功后阻止再次导航；失败后释放锁，允许编辑或 Enter 重试。
- PIN 错误时保留四位输入并显示错误状态；用户修改任意一位后允许再次自动提交。
- PIN 提交期间四个输入框禁用，错误后恢复可编辑。
- 不显示“验证并加入”按钮，避免与自动提交和 Enter 入口产生第三个触发源。

### 4. 审批状态与 SSE

- 复用已有全局 SSE 和 `room.join_request_changed` 事件，不新增 SSE 连接或协议字段。
- 提交申请成功后立即展示等待卡片。
- SSE 刷新加入信息后，若已批准则沿用现有 `alreadyMember` 流程进入工作区。
- 取消申请成功后回到可提交申请的状态。
- 房主拒绝、申请失效或房间失效时，根据现有接口结果切换卡片状态；不新增审批历史持久化。

### 5. 视觉与响应式

- 所有状态复用同一白色/深色主题卡片，不为每个状态创建独立布局。
- 语义颜色：加入确认青绿色、PIN 蓝绿色、审批等待琥珀色、加载青绿色、错误/失效红色或橙色。
- 桌面端最大宽度约 48rem；平板使用可用宽度减 3rem；手机保留 1rem～1.25rem 外边距。
- 卡片垂直、水平居中；状态切换不改变卡片整体位置。
- 桌面按钮横向排列；手机空间足够时横向排列，空间不足时纵向排列。
- Header/Footer 继续由 `AppShell` 提供，过渡状态不注入房间摘要、分享按钮或传输浮层。
- 深色主题使用现有页面主题变量；不新增独立浅色/深色组件分支。
- 首次卡片轻微淡入上移，状态更新仅内容淡入，PIN 错误只做边框颜色变化，加载只旋转图标。
- `prefers-reduced-motion: reduce` 时关闭所有过渡和旋转。

### 6. 双语与无障碍

- 所有新增或修改的用户可见文案使用 i18n 翻译键，同时补齐 `zh-CN` 和 `en`。
- 状态卡片使用语义区域和明确标题。
- 加载、审批等待、操作结果使用 `aria-live="polite"`。
- 错误信息使用 `role="alert"`。
- PIN 输入框分别提供“第 1 位”到“第 4 位”的可读标签。
- 所有按钮支持键盘聚焦和操作；Enter 在任意 PIN 输入框可提交。
- 自动聚焦只在页面首次进入时执行，不重复抢占用户焦点。

### 7. 模块与测试

- 重构 `RoomGate` 和 `JoinPanel`，使页面只负责状态组合和业务回调绑定。
- 增强 PIN 输入组件，集中处理自动前进、退格、粘贴、Enter 和完成回调。
- 抽取可独立测试的 PIN 提交去重逻辑与过渡状态映射逻辑，避免把复杂判断散落在 JSX 中。
- 新增前端纯逻辑测试，覆盖：状态到卡片视图映射、错误分类、PIN 粘贴清洗、自动/Enter 触发去重、失败后重试和成功后单次导航。
- 复用现有 `frontend/tests` 的 Bun 测试方式；不测试 CSS 私有实现细节。
- 通过浏览器手动验证所有状态、主题、语言、桌面/移动端和 SSE 审批流程。

## Testing Decisions

- 自动化测试只验证外部行为和纯逻辑，不锁定具体 CSS 数值或 Canvas/DOM 私有结构。
- PIN 逻辑测试必须覆盖逐位输入、四位粘贴、非法字符过滤、Enter、自动提交、重复触发、请求中禁用、失败重试和成功单次导航。
- 状态映射测试必须覆盖所有已确认状态及其按钮组合，尤其确认不可用状态只有返回首页，PIN 状态没有验证按钮。
- 双语词典完整性测试必须通过，所有新增键在 `zh-CN` 和 `en` 中同时存在且非空。
- 浏览器手动验收使用 `playwright-cli`，至少检查 127.0.0.1 HTTP 访问、桌面和移动视口、浅色/深色/跟随系统、中文/英文切换。
- 审批流程手动验证：提交申请、等待状态、房主批准自动进入、取消申请、房主拒绝和房间失效。
- 构建验证命令：`bun test`、`bun run build`、`make build`、`git diff --check`。

## Out of Scope

- 不修改后端 API、数据库表、SSE 协议或房间状态机。
- 不增加审批拒绝原因、审批历史或新的状态持久化字段。
- 不改变已成功进入房间后的文件、动态、回收站、聊天和传输工作区。
- 不新增房间摘要、分享、通知或传输浮层到过渡页 Header/Footer。
- 不增加 PIN 验证按钮；PIN 仅支持四位自动验证和 Enter 验证。
- 不增加语音、二维码、复杂动画、声音、全屏背景效果或其他新业务入口。
- 不改变 URL 路由和品牌 Logo 返回首页行为。

## Further Notes

- 实现前必须完整阅读本 PRD；每个主要阶段完成后提交 Git。
- 如果实现中发现必须修改后端契约或数据库，先更新本 PRD、说明原因并重新获得用户确认，再继续编码。
- 本阶段完成后，加入确认、审批等待等旧版中间页将与首页和房间工作区共享稳定的页面骨架，为后续新增房间状态提供可复用基础。
