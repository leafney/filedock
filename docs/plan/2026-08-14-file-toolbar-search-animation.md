# 文件工具栏搜索动画优化 PRD

## Problem Statement

当前文件工具栏中，筛选按钮仍显示较长的当前选项，排序按钮仅显示图标；右侧控件和搜索框争夺空间，窄桌面下容易挤出可视区域。用户希望明确显示“筛选”“排序”，右侧三个控件统一对齐，并让搜索框在桌面端聚焦时临时扩展覆盖它们，以便专注搜索。

## Solution

将工具栏重排为“范围切换、搜索输入框、右侧操作组”。右侧操作组包含“图标 + 筛选”“图标 + 排序”和原样批量选择。桌面端搜索框获得焦点后通过状态类扩展到操作组右边界，操作组淡出并禁用鼠标事件；失焦后搜索框收回，操作组恢复。窄桌面和移动端保持普通换行，不启用覆盖动画。

## User Stories

1. 作为房间成员，我希望看到“图标 + 筛选”，以便知道按钮用途。
2. 作为房间成员，我希望看到“图标 + 排序”，以便知道排序入口用途。
3. 作为房间成员，我希望批量选择按钮保持当前样式，以便不影响已有操作习惯。
4. 作为房间成员，我希望筛选、排序、批量选择三个控件统一靠右排列，以便工具栏结构清晰。
5. 作为房间成员，我希望搜索框在未聚焦时占满中间剩余空间，以便输入区域足够宽。
6. 作为房间成员，我希望点击搜索框后搜索框向右扩展，以便获得更大的连续输入区域。
7. 作为房间成员，我希望搜索框扩展时左边界不移动，以便视觉焦点稳定。
8. 作为房间成员，我希望搜索框扩展只覆盖筛选、排序、批量选择，不影响范围切换。
9. 作为房间成员，我希望搜索框扩展时右侧控件逐渐隐藏，以便动画自然。
10. 作为房间成员，我希望被覆盖的控件在动画期间不能误点击，以便避免触发不可见操作。
11. 作为房间成员，我希望搜索框失焦后自动收回，右侧控件重新显示。
12. 作为窄桌面用户，我希望工具栏自动换行，不出现覆盖或横向滚动。
13. 作为移动端用户，我希望搜索框独占一行，筛选、排序和批量选择仍可操作。
14. 作为房间成员，我希望菜单仍显示完整筛选和排序选项，按钮本身不显示当前长文案。
15. 作为键盘用户，我希望可以通过 Tab 聚焦搜索框，并通过 Escape 或点击外部失焦。
16. 作为深色主题用户，我希望扩展搜索框和右侧控件淡出过程保持主题背景和边框一致。
17. 作为中文用户，我希望按钮和 Tooltip 文案正确显示简体中文。
18. 作为英文用户，我希望按钮和 Tooltip 文案正确显示 English。

## Implementation Decisions

### 1. 工具栏 DOM 结构

- 保留范围切换组件作为左侧第一个子项。
- 新增搜索容器，包含普通 Ant Design `Input`，不是 `Input.Search`。
- 新增右侧操作组容器，按顺序放置：筛选 Dropdown、排序 Dropdown、批量选择 Button。
- 操作组必须是单独容器，便于整体控制透明度、位移和鼠标事件。
- 不修改文件查询状态、React Query key、API 参数和菜单数据。

### 2. 筛选和排序按钮

- 筛选按钮：Lucide `ListFilter` 图标 + i18n 文案“筛选 / Filter”。
- 排序按钮：Lucide `ArrowDownUp` 图标 + i18n 文案“排序 / Sort”。
- 两个按钮均使用 Ant Design Button 和 Dropdown，菜单继续使用现有 `identityItems`、`sortItems`。
- 菜单继续使用 `selectable` 和 `selectedKeys`，切换行为不变。
- 筛选按钮保留 `aria-label`，排序按钮保留包含当前排序值的 `aria-label`。
- 不把当前长选项文本渲染在按钮上；Tooltip 可显示完整入口名称，不显示会造成宽度增长的动态文本。
- 批量选择按钮不改文字、图标、权限条件或点击逻辑。

### 3. 桌面端聚焦动画

- 仅在 `min-width: 941px` 的媒体查询下启用。
- 为搜索框维护 `searchFocused` 状态；`onFocus` 设为 true，`onBlur` 设为 false。
- 未聚焦：搜索框处于 Flex 中间位置，操作组正常显示。
- 聚焦：搜索框添加 `is-focused` 状态类，使用绝对定位或等价覆盖布局，从自身左边界扩展到操作组右边界。
- 范围切换必须位于搜索容器左侧，不被扩展覆盖。
- 搜索框扩展时保持左边界不变，右边界覆盖操作组最右侧，但保留工具栏内边距。
- 操作组使用 `opacity: 0`、轻微 `translateX` 和 `pointer-events: none`；恢复时反向动画并恢复 `pointer-events`。
- 扩展动画 `220ms ease-out`；收回动画 `180ms ease-in`。
- 搜索框、操作组和工具栏必须设置 `min-width: 0`，避免动画期间产生页面横向滚动。
- 搜索框 z-index 高于操作组但低于全局弹窗；Dropdown 打开时仍使用 Ant Design Portal 层级。
- 失焦事件不能因点击清除按钮而错误关闭；清除按钮属于搜索框内部操作。

### 4. 窄桌面和移动端

- `max-width: 940px`：禁用覆盖动画，搜索框独占下一行；操作组保持可见。
- `max-width: 760px`：范围切换一行，搜索框一行，操作组下一行；三个控件均保留足够点击高度。
- 移动端不依赖 Tooltip 了解操作，筛选和排序按钮保留图标及短文字。
- 不通过 `font-size: 0` 隐藏筛选/排序按钮文字；仅批量选择沿用已有移动端样式规则。

### 5. 主题和国际化

- 新增“筛选 / Filter”“排序 / Sort”必须使用中英文翻译键。
- 动画背景、边框、焦点环、按钮文字使用现有主题变量。
- 深色模式下扩展搜索框不能出现白色背景；操作组隐藏时不能留下白色边框残影。
- 保持现有 `aria-label`，图标设置 `aria-hidden=true`。

### 6. 明确禁止

- 不修改文件列表 API。
- 不修改筛选、排序、批量权限逻辑。
- 不在按钮显示当前排序长文案。
- 不在移动端启用搜索覆盖动画。
- 不使用页面级 fixed 定位实现搜索扩展。
- 不让被遮挡控件保持可点击状态。

## Testing Decisions

- `make web`：验证 TypeScript 和 Vite 构建。
- 前端测试：沿用现有全部测试，确认筛选、排序、批量逻辑未回归。
- 结构测试：验证筛选、排序、批量三个控件处于右侧操作组，搜索框位于中间。
- 行为测试：验证搜索 focus 添加状态类，blur 移除状态类；清除按钮仍可用。
- 响应式测试：至少检查 1580px、1200px、940px、768px、430px。
- 桌面验收：聚焦时范围切换不移动，搜索右侧扩展覆盖三个控件；失焦后反向收回。
- 窄桌面/移动验收：无覆盖动画、无横向滚动、筛选/排序/批量均可点击。
- 主题和双语测试：浅色/深色、中英文下按钮尺寸和动画均不溢出。
- `git diff --check`。

## Out of Scope

- 不改变文件数据接口、筛选和排序业务含义。
- 不改变文件列表行、上传、下载、回收站和动态区域。
- 不实现移动端搜索覆盖动画。
- 不新增搜索历史、联想词或高级搜索。

## Further Notes

- 实现顺序：先调整按钮结构和 i18n，再实现右侧操作组布局，最后添加桌面 focus 动画和响应式覆盖规则。
- 每阶段完成后提交 Git；提交信息使用 Conventional Commits，type/scope 英文，description 简体中文。
