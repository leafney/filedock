# 创建房间弹窗布局与交互优化 PRD

## Problem Statement

首页创建房间弹窗仍使用默认宽度和双按钮底部操作栏。当前“返回首页”按钮与创建操作并列，但关闭图标、遮罩和 Esc 已经可以完成取消；弹窗内容在不同语言和移动端视口下也缺少针对性布局。PIN 输入的聚焦、粘贴、切换验证方式后的状态清理还需要统一。

## Solution

将创建房间弹窗改为紧凑、响应式的单提交操作布局：移除“返回首页”，保留右侧“创建房间”按钮；桌面端使用约 420px 宽度，移动端按视口缩放；保留三种验证方式和必要字段标签。PIN 验证模式提供自动聚焦、四位粘贴、两组输入自动衔接、实时状态清理和一致性校验；Enter 仅在表单有效时调用同一创建逻辑，不自动创建。创建接口和成功后的现有跳转流程保持不变。

## User Stories

1. 作为用户，我希望创建弹窗更紧凑，以便快速选择验证方式并创建房间。
2. 作为用户，我希望只有一个明确的“创建房间”提交按钮，以便减少误操作。
3. 作为用户，我希望可以用右上角关闭、遮罩空白区域或 Esc 取消创建。
4. 作为用户，我希望桌面端看到约 420px 宽的弹窗，以便表单不占用过多页面空间。
5. 作为移动端用户，我希望弹窗宽度不会超出屏幕，并保留安全边距。
6. 作为用户，我希望三种验证方式在空间足够时显示在同一行，空间不足时自然换行。
7. 作为用户，我希望验证方式、四位 PIN、再次输入 PIN 的标签清晰可见，以便理解每个输入区域。
8. 作为用户，我希望切换到 PIN 验证后第一组 PIN 自动聚焦，以便直接输入。
9. 作为用户，我希望第一组 PIN 输入完整后自动进入第二组确认输入，以便减少点击。
10. 作为用户，我希望可以一次粘贴四位 PIN，系统自动填入对应输入格。
11. 作为用户，我希望删除 PIN 中间或末尾字符时输入状态正确同步，以便能修正错误。
12. 作为用户，我希望两组 PIN 完整且一致时创建按钮可用。
13. 作为用户，我希望 PIN 不完整或不一致时创建按钮不可用，并能看到明确的不一致提示。
14. 作为用户，我希望按 Enter 能执行与点击“创建房间”相同的操作，以便使用键盘完成创建。
15. 作为用户，我希望 PIN 填满后不会自动创建房间，以便提交前仍有一次明确确认。
16. 作为用户，我希望创建请求进行中按钮显示加载且不能重复提交。
17. 作为用户，我希望创建失败后可以留在弹窗中修正或重试。
18. 作为用户，我希望关闭后再次打开时默认回到“免验证”，且 PIN、错误和加载状态均清空。
19. 作为用户，我希望从 PIN 验证切换到其他验证方式时旧 PIN 立即清除。
20. 作为用户，我希望浅色、深色和跟随系统主题下弹窗都与页面背景协调。
21. 作为英文用户，我希望验证方式和错误提示使用完整英文文案，不出现中文硬编码。
22. 作为键盘用户，我希望默认模式打开时焦点位于第一个验证方式选项，切换 PIN 后焦点进入第一组输入。

## Implementation Decisions

- 仅修改首页创建房间弹窗组件及相关样式，不修改创建房间 API、请求参数、数据库结构、SSE、路由或成功后的房间跳转。
- 保留三种验证方式及其现有业务值：open、password、owner_approval；默认模式为 open。
- 设置弹窗底部页脚只渲染创建按钮，取消按钮文本和“返回首页”按钮不再渲染；创建按钮右对齐，保留请求中的 loading 状态。
- 保留 Ant Design `Modal` 的 `onCancel` 机制，继续支持关闭图标、遮罩关闭和 Esc 关闭。
- 桌面端弹窗宽度设为约 420px，并限制最大宽度为 `calc(100vw - 32px)`；移动端不产生横向溢出。
- 表单布局采用紧凑垂直间距：验证方式单独一行；PIN 两组输入上下排列，标签和输入间距一致，四格输入水平居中。
- 使用四格 OTP 输入控件；必须通过逐次输入事件同步受控值，不能只依赖“完整四位时才触发”的变化回调，以保证删除和编辑行为正确。
- 切换到 password 模式时清空旧 PIN，并在模式切换完成后聚焦第一组 PIN；第一组完成四位后聚焦第二组。
- PIN 粘贴只保留 ASCII 数字并限制四位；非数字字符和多余字符忽略。两组 PIN 完整且相等时表单有效。
- 创建按钮的禁用规则：password 模式下任一 PIN 长度不是四位或两者不一致时禁用；open 与 owner_approval 模式可直接创建。
- Enter 提交只在表单有效、没有 mutation 进行中且当前焦点位于弹窗表单区域时触发；调用与按钮相同的 mutation，不新增自动创建。
- 打开弹窗、关闭弹窗、创建成功或创建失败时，按状态分别重置：关闭/重新打开清空 PIN、恢复 open、清理错误和加载状态；创建失败保留当前输入以便修正和重试；创建成功沿用现有回调清理并跳转。
- 所有现有面向用户文案继续使用 i18n；如需新增错误或无障碍文案，必须同时补充 zh-CN 与 en。
- 复用现有深色主题 Ant Design 覆盖，不新增主题模式或本地存储项。

## Testing Decisions

- 测试外部行为，不测试组件内部状态实现细节。
- 扩展房间/PIN 纯逻辑测试，覆盖：两组 PIN 有效性、长度校验、不一致校验、模式切换清理、Enter 与按钮共用创建条件、提交中去重和失败后可重试。
- 保留并复用现有 `normalizePin` 相关测试，增加粘贴内容、删除中间字符和非数字过滤边界。
- 运行双语词典测试，确保新增或修改的文案键在 zh-CN/en 中完整一致。
- 使用 Playwright 验证桌面端和移动端：弹窗宽度、无“返回首页”、创建按钮右对齐、验证选项换行、PIN 自动聚焦、四位粘贴、两组 PIN 自动衔接、按钮禁用/启用、Enter 创建和关闭方式。
- 完成后运行前端单元测试、前端生产构建、Go 测试、Go/前端整体验证构建及 `git diff --check`。

## Out of Scope

- 不修改后端房间创建业务、验证模式定义、PIN 校验接口或数据库。
- 不让输入完成自动创建房间，不新增预检请求或二次确认弹窗。
- 不改变加入房间弹窗、房间过渡页、首页其他弹窗、Header/Footer 或主题切换入口。
- 不新增房间名称、房间容量、房间有效期等配置字段。

## Further Notes

- 创建按钮仍是创建房间的唯一提交入口；Enter 只是该按钮的键盘等价操作。
- PIN 错误时保留输入并允许修改；只有关闭或重新打开弹窗才恢复到干净的默认状态。
- 中英文文本长度不同，验证方式区域必须使用可换行布局而不是固定宽度截断。
