# FileDock 文件删除与简化回收站 PRD

状态：实现完成，待人工验收

日期：2026-08-05

## Problem Statement

FileDock 已经支持共享文件和私密文件的上传、接收、拒绝、下载、再次发送、发布共享、文件动态和全局文件通知，但上传完成后的文件不能删除。上传错误文件、过期内容或房主需要治理的文件会一直保留到房间销毁，不仅占用房间容量，也让文件列表持续累积无效内容。

直接增加永久删除会带来较高误操作风险，也无法满足房主治理与原上传者所有权之间的平衡。尤其是房主删除其他成员文件时，原上传者需要知道发生了什么，并有机会申请恢复；房主又必须保留最终决策权。私密文件还要求房主能够治理，但不能借回收站、通知或审批流程看到原文件名、内容或下载入口。

下一阶段需要实现范围克制的文件删除和简化回收站：活动文件只能先移入回收站，回收站内再恢复或永久删除；上传者自删可以直接恢复，房主删除他人文件后需要通知上传者，上传者申请恢复必须由房主审批。回收站继续计入容量，不增加独立保留期限、管理员免费额度、批量操作或文件预览。所有状态必须与下载、通知、文件动态、成员权限和房间销毁保持一致。

## Solution

在房间文件主区增加“回收站”视图，并为可用文件增加服务端下发的删除能力。上传者可以把自己上传的文件移入回收站，房主可以治理任意文件，私密文件接收者和其他成员不能删除服务端文件。普通成员只看到自己上传的回收站文件，房主看到全部；无关私密文件对房主继续使用稳定私密编号的匿名投影。

每次文件从可用状态进入回收站都会形成独立回收周期。上传者自己删除的文件可直接恢复；房主删除其他成员文件时生成删除通知，上传者只能提交一次恢复申请。房主点击全局恢复申请通知后，应用进入对应房间回收站并打开审批 Modal；同意后立即恢复，拒绝后本周期不能再次申请。房主也可直接从回收站恢复任意文件，存在待申请时等价于同意。

回收站文件仍保存物理内容并完整计入房间已用容量。永久删除采用可恢复的内部执行阶段：先阻止并取消下载，再可靠删除物理内容，最后释放容量并把文件变为不可恢复的最小审计记录。文件动态在房间生命周期内继续显示删除、申请、拒绝、恢复和永久删除节点；房间最终销毁时再清理所有元数据。

扩展现有全局通知中心，增加文件被房主删除、恢复申请、文件已恢复、申请被拒绝和文件被永久删除五类通知。继续复用现有用户级 SSE 提示客户端刷新 REST 权威快照，不新增长连接、轮询、顶部 Message 或浏览器通知。

## Implementation Decisions

### 1. 范围与权威关系

- 本 PRD 是现有文件生命周期、文件列表、文件动态和全局通知中心的增量规格；与早期原型中的复杂回收站设想冲突时，以本 PRD 为准。
- 文件状态与回收周期是删除、恢复和永久删除的权威事实；通知记录只保存通知发生和信息型结果的已读状态，不能授予文件权限。
- REST 查询结果是客户端权威快照；SSE 只提示受影响客户端失效查询，不携带最终展示文案、删除原因或拒绝原因。
- 只允许已上传完成且当前可用的文件进入回收站。上传预留、上传中、失败、取消和过期状态继续使用现有流程。
- 项目处于开发阶段，可直接调整自动建表结构，不实现旧数据库迁移、回填或兼容分支。

### 2. 深模块划分

#### 2.1 回收站生命周期模块

- 对外提供移入回收站、直接恢复或创建申请、审批同意、审批拒绝、房主直接恢复和永久删除等少量业务命令。
- 在模块内部统一完成成员权限、当前文件状态、回收周期、原因校验、恢复申请状态、文件动态、通知记录和容量不变量。
- API、业务适配层和前端不得直接修改文件状态、回收周期或申请记录。
- 所有数据库状态转换使用事务和带当前状态、当前周期的条件更新；受影响行数不为 1 时返回统一状态错误，避免并发恢复与永久删除同时成功。

#### 2.2 文件查询与权限投影模块

- 活动文件列表只返回上传中和可用文件，不返回回收站、永久删除或内部永久删除执行态。
- 回收站列表独立查询，但复用现有文件完整、匿名、隐藏投影规则。
- 服务端返回删除、直接恢复、申请恢复和永久删除能力；前端只按能力渲染，不自行从角色推导权限。
- 文件动态继续通过统一投影读取最小审计元数据。

#### 2.3 存储与传输协调模块

- 文件移入回收站后取消该文件的下载任务和活动流。
- 永久删除协调数据库中间状态、物理文件删除、容量释放和启动恢复。
- 物理删除失败不得把业务文件标记为永久删除，不得释放容量，不得生成成功事件或通知。

#### 2.4 通知模块

- 扩展现有统一通知查询、聚合、排序、分页、总数和已读接口，不增加第二套通知列表。
- 行动型恢复申请根据申请业务状态实时投影，不通过点击标记已读。
- 信息型生命周期通知通过现有通知记录和服务端已读水位处理。

#### 2.5 前端文件与通知交互模块

- 文件工作区管理文件列表、文件动态和回收站三个视图，以及一次性通知导航目标。
- 通知抽屉只负责导航和信息型已读；恢复申请必须进入目标房间回收站后再显示审批 Modal。
- 所有操作成功后精确失效活动文件、回收站、文件动态、可复用私密文件、房间容量和通知查询。

### 3. 文件状态与回收周期

#### 3.1 状态集合

- 保留现有上传状态，并增加面向业务的“回收站”和“已永久删除”状态。
- 增加仅供服务端内部使用的“永久删除执行中”状态，用于跨数据库和磁盘操作恢复；该状态不出现在用户列表中。
- 正常状态转换为：可用 → 回收站 → 可用，或可用 → 回收站 → 永久删除执行中 → 已永久删除。
- 已永久删除是终态，不能恢复、下载、再次发送或发布共享。

#### 3.2 回收周期

- 每个文件保存递增的回收版本，初始为 0；每次从可用进入回收站时原子增加 1。
- 每个版本创建一条回收周期记录，至少保存房间、文件、版本、删除执行者、删除时间、可选删除原因、周期结果、结果执行者和结果时间。
- 删除原因去除首尾空格后可为空，最多 200 个 Unicode 字符；拒绝控制字符。用户输入按原文存储，不翻译。
- 回收周期结果至少区分仍在回收站、已恢复和已永久删除。
- 文件恢复后再次删除必须创建新版本；旧版本的拒绝不得限制新版本申请，旧通知不得在新版本复活。

#### 3.3 恢复申请

- 每个文件回收版本最多保留一个当前申请记录，不提供审批历史页面。
- 申请至少保存申请 ID、回收周期、申请用户、状态、创建时间、决策时间、决策房主和可选拒绝原因。
- 状态至少区分待处理、已同意、已拒绝和因成员离开而失效。
- 当前版本已拒绝后禁止重新提交；已失效且从未拒绝的申请，在同一身份重新加入后允许重新激活为新的待处理申请并刷新申请时间。
- 上传者不能撤回待处理申请。
- 拒绝原因使用与删除原因相同的字符和长度规则。

### 4. 权限矩阵

#### 4.1 移入回收站

- 当前活动成员且是文件原上传者时，可以删除自己当前可用的共享或私密文件。
- 当前活动房主可以删除房间内任意当前可用文件。
- 私密接收者、普通浏览者和已经离开的成员不能删除。
- 未找到、无权限或私密隐藏目标统一返回文件不存在语义，不能通过错误差异枚举文件。
- 上传者删除自己的文件时请求不得携带删除原因；房主删除其他成员文件时允许携带可选原因。

#### 4.2 回收站可见性

- 房主可以看到房间所有仍处于回收站的文件。
- 普通成员只看到原上传者为自己的回收站文件，不因共享范围而看到别人删除的共享文件。
- 房主对自己是上传者或接收者的私密文件使用完整投影；对无关私密文件使用匿名投影，只返回稳定私密编号和治理所需安全字段。
- 普通成员不因曾经是共享文件浏览者或私密接收者而获得回收站可见权。

#### 4.3 恢复

- 上传者自己删除的文件由上传者直接恢复。
- 房主删除其他成员的文件时，上传者只能提交恢复申请。
- 房主可以直接恢复任意回收站文件，不受删除执行者限制。
- 房主直接恢复已有待处理申请的文件时，同一事务把申请标记为已同意并完成恢复。
- 接收者和其他成员不能恢复或申请恢复。

#### 4.4 永久删除

- 上传者自己删除的文件可由上传者或房主永久删除。
- 房主删除其他成员的文件只能由房主永久删除。
- 待处理申请不阻止房主永久删除；永久删除会使申请失效并生成对应结果。
- 已拒绝申请不影响房主直接恢复或永久删除。

### 5. 移入回收站事务

- 请求使用文件 ID 和可选删除原因，服务端重新读取当前活动成员、房间、文件状态和角色。
- 事务必须锁定或通过条件更新保护文件当前状态和回收版本。
- 文件从可用改为回收站，回收版本加 1，并创建回收周期和“移入回收站”文件事件。
- 同一事务把该文件尚未开始的下载任务改为取消状态；活动下载流在事务提交后通过按文件取消能力终止。
- 下载流完成事务必须再次要求文件仍为可用且版本未变化；即使取消信号与完成竞争，回收成功后也不能写首次下载、完成事件或下载结果通知。
- 同一事务使该文件删除前尚未读取的拒绝和首次下载结果通知永久失效；待接收记录保留，但因文件不再可用而不展示。
- 房主删除其他成员文件时，同一事务生成“文件被房主删除”通知记录；上传者自删不通知自己。
- 事务提交后向有权用户发布文件状态变化和通知变化 SSE，再失效相关 REST 查询。

### 6. 恢复和申请事务

#### 6.1 上传者自助恢复

- 只允许当前上传者恢复由自己在当前版本主动删除的文件。
- 文件从回收站原子恢复为可用，回收周期结果改为已恢复，并创建“文件恢复”事件。
- 容量不变化，原因是回收站期间已经完整计费。
- 不创建恢复通知给执行者本人。

#### 6.2 提交恢复申请

- 只允许当前上传者针对房主删除、仍处于同一回收版本的文件申请。
- 当前版本没有申请时创建待处理申请；因离开失效且从未拒绝时允许重新激活；待处理、已同意或已拒绝状态不得重复提交。
- 创建“提交恢复申请”文件事件，并使房主的行动型恢复申请通知立即出现。
- 申请本身不改变文件状态和容量。

#### 6.3 房主同意

- 只允许当前房主处理当前房间、当前回收版本且仍待处理的申请。
- 同一事务把申请改为已同意、文件恢复为可用、回收周期结果改为已恢复，并创建一条“文件恢复”事件。
- 不额外创建“申请已同意”文件事件。
- 为原上传者创建“文件已恢复”通知；行动型申请因不再待处理自动消失。

#### 6.4 房主拒绝

- 只允许当前房主拒绝当前回收版本的待处理申请。
- 拒绝原因可空，非空时按 200 字和控制字符规则校验。
- 同一事务把申请改为已拒绝，创建“恢复申请被拒绝”事件和原上传者的信息型拒绝通知。
- 文件继续留在回收站并继续占用容量。
- 当前版本禁止重新申请，但房主仍可直接恢复或永久删除。

#### 6.5 房主直接恢复

- 房主可恢复任意仍在回收站的文件。
- 若当前版本有待处理申请，则标记为已同意；若已拒绝，不修改历史拒绝事实，但文件仍可恢复。
- 恢复其他成员文件时生成“文件已恢复”通知；恢复房主自己的文件不通知自己。
- 恢复后若再次被删除，进入新回收版本。

### 7. 原样恢复语义

- 恢复不创建新文件、不复制物理内容、不改变存储名。
- 保留文件 ID、批次、上传者、原文件名、私密编号、范围、MIME、大小、创建时间和完成时间。
- 保留全部文件接收关系、投递代次、待接收、已接收、已拒绝、已下载、首次下载时间、最后下载时间和下载次数。
- 不把恢复解释为再次发送，不创建新接收关系或新投递代次。
- 待接收私密文件通知因文件重新可用而恢复展示；删除时已永久失效的拒绝和首次下载结果不得恢复。
- 旧下载任务永不复活，恢复后必须重新创建任务并再次校验权限。

### 8. 永久删除协调

#### 8.1 用户可见规则

- 永久删除只能从回收站发起，前端必须显示不可恢复二次确认。
- 确认信息显示安全文件名称、上传者、大小、删除时间、原删除原因和当前申请状态。
- 不要求填写永久删除原因；结果通知可展示原删除原因。

#### 8.2 内部执行顺序

1. 数据库事务验证权限、文件仍在当前回收版本，并把文件改为内部永久删除执行中状态；同时取消待开始下载任务。
2. 事务提交后取消该文件全部活动下载流。
3. 删除物理存储文件；不存在按幂等成功处理，其他错误进入失败路径。
4. 物理删除失败时，把仍处于相同执行版本的文件恢复为回收站状态，保留容量、申请和操作能力，不创建永久删除成功事件或通知。
5. 物理删除成功后，在新事务中把文件改为已永久删除，回收周期结果改为已永久删除，释放房间已用容量，处理申请状态，并创建永久删除事件和必要通知。
6. 如果进程在物理删除和最终事务之间退出，启动恢复逻辑必须重新尝试幂等删除并完成最终事务；不得把执行中状态暴露为普通回收站文件。

#### 8.3 永久删除后的数据

- 删除物理内容，删除或终结该文件的下载任务，禁止所有文件内容访问。
- 保留房间生命周期内的文件最小元数据、接收关系、回收周期和文件事件，以支持既有权限投影和审计。
- 已永久删除文件不进入活动列表、回收站列表、可复用私密文件、待接收通知或文件操作接口。
- 房主永久删除其他成员文件时创建信息型永久删除通知；上传者永久删除自己的文件不通知自己。
- 当前恢复申请立即失效，房主行动型申请通知自动消失。
- 房间销毁时再按依赖顺序清理通知、申请、回收周期、接收关系、文件元数据和动态。

### 9. 下载并发规则

- 下载注册表增加按文件标识取消能力，不能只按房间或用户取消。
- 下载任务增加明确取消终态和取消时间；因回收站操作取消时，前端收到当前用户范围的下载取消 SSE 并结束传输进度。
- 创建任务和开始流都必须要求文件为可用。
- 完成下载的数据库事务必须再次验证文件为可用并且没有进入新的回收版本。
- 文件已进入回收站时，即使字节已经全部写入但完成事务尚未提交，也不得增加下载次数或产生首次完成通知。
- 恢复文件不会改变已经取消、失败、过期或完成的旧任务。

### 10. 容量规则

- 回收站文件继续完整包含在房间已用容量中，移入和恢复都不修改已用容量。
- 永久删除最终事务按文件实际大小原子减少已用容量；不得减为负数，状态与容量必须使用同一回收版本保护。
- 内部永久删除执行中仍计入容量，只有物理删除成功并完成最终事务才释放。
- 房主容量详情返回活动共享文件、活动私密文件、回收站文件、上传预留、已用总量和总容量。
- 普通成员继续只返回已用总量和总容量，不返回任何细分。
- 房主容量明细应满足：活动共享 + 活动私密 + 回收站 = 已用总量；上传预留单独参与“已用加预留不得超过总容量”的约束。

### 11. 回收站查询接口

- 新增当前房间统一回收站分页查询，支持搜索、游标和限制参数。
- 默认每页 30，最大 100；按删除时间倒序，再按稳定文件标识倒序。
- 返回当前用户可见的总数和下一页游标；总数不受分页限制。
- 搜索去除首尾空格并执行大小写不敏感匹配。
- 完整投影可按原文件名和私密编号搜索；匿名投影只能按私密编号搜索，后端不得先用原文件名筛选后再匿名化。
- 每项至少返回安全文件投影、删除执行者与时间、当前用户可见的删除原因、回收状态、申请状态、当前用户可见的拒绝原因，以及服务端能力。
- 服务端能力至少区分直接恢复、申请恢复和永久删除；不向前端暴露内部执行状态或回收版本。
- 普通成员和房主使用同一接口，由服务端实施不同权限投影。

### 12. 文件命令接口

#### 12.1 移入回收站

- 提供针对单个文件的命令，请求只包含可选删除原因。
- 成功返回当前回收状态所需的最小结果；前端随后刷新权威列表。
- 重复删除、非可用状态或并发状态变化返回统一文件状态错误。

#### 12.2 恢复或申请恢复

- 提供针对单个回收站文件的恢复命令。
- 服务端根据当前用户、删除执行者和能力决定直接恢复还是创建待处理申请，并返回可判别结果。
- 前端不得自行选择调用“直接恢复接口”或“申请接口”来绕过服务端权限。

#### 12.3 处理申请

- 提供房主同意和拒绝两个明确命令，使用不透明申请 ID。
- 同意请求不接受原因；拒绝请求接受可选拒绝原因。
- 申请 ID 必须重新绑定当前房间、当前房主、当前回收版本和待处理状态，不能跨房间使用。

#### 12.4 永久删除

- 提供针对单个回收站文件的永久删除命令。
- 命令成功只表示物理删除和最终数据库事务均已完成；中间失败必须返回统一错误并允许重试。
- 不提供活动列表永久删除、批量永久删除或前端构造的角色参数。

### 13. 文件能力和前端操作入口

- 活动文件投影增加是否可移入回收站的能力。
- 房主删除他人文件时额外返回允许填写原因的能力；前端不能通过比较用户 ID 自行决定是否显示原因。
- 文件“更多”菜单在分隔线后显示危险色“移入回收站”，并保持“详情”等既有动作。
- 删除确认 Modal 对自删说明可直接恢复；对房主删除他人文件说明上传者需要申请恢复，并显示可选原因输入框。
- 删除操作不进入现有批量选择能力。
- 操作进行中禁用重复提交；失败使用统一双语错误提示，不能乐观移除失败文件。

### 14. 回收站前端

- 文件主区顶层 Tab 固定为“文件列表 / 文件动态 / 回收站”，支持现有键盘 roving focus。
- 回收站 Tab 显示当前用户可见总数；数量变化通过查询失效更新。
- 回收站为单一列表，不按共享和私密分组；桌面延续紧凑行布局，移动端使用可触控操作面板。
- 顶部只提供搜索，不提供范围筛选、身份筛选、复杂排序或批量模式。
- 每项显示安全名称、范围、上传者、大小、删除执行者、删除时间、当前状态和有权查看的原因。
- 上传者自删文件显示“恢复”和“永久删除”。
- 上传者看到房主删除文件时，未申请显示“申请恢复”，待处理显示“等待房主处理”，已拒绝显示“恢复申请已拒绝”和可选原因；已拒绝按钮不可再次操作。
- 房主对每项显示“恢复”和“永久删除”；存在待处理申请时显示待审核标记，但不在回收站提供专门同意/拒绝按钮。
- 永久删除确认必须使用项目 Modal，不使用浏览器原生确认框；确认按钮使用危险样式。
- 回收站空状态、加载、分页、搜索无结果、错误和重试均提供中英文。

### 15. 恢复审批导航和 Modal

- 恢复申请通知项不显示同意或拒绝按钮，只能点击整项。
- 点击后通过一次性路由状态携带申请 ID 和随机令牌进入目标房间；目标页面消费后立即清除路由状态，刷新不能重复打开旧 Modal。
- 如果已在目标房间，直接切换文件主区到回收站；如果移动端聊天全屏打开，先关闭聊天。
- 回收站数据加载后定位对应申请并打开 Modal；不改变搜索条件或滚动到不相关文件。
- Modal 显示安全文件信息、申请人、申请时间、原删除原因，并提供“同意恢复”和“拒绝”选择。
- 下方始终显示“拒绝原因（可选）”，选择拒绝时可编辑，选择同意时禁用且提交时忽略；最大 200 字并显示剩余字数或最大长度。
- 提交前必须已经选择同意或拒绝；取消或关闭 Modal 不调用 API，也不增加第三种审批决定。
- 目标在导航期间失效、用户不再是房主、文件已恢复或永久删除时，显示统一“通知已失效”提示，关闭 Modal 并刷新通知。

### 16. 文件动态

- 新增移入回收站、提交恢复申请、恢复申请被拒绝、文件恢复和永久删除五类事件文案。
- 房主同意申请后只创建文件恢复事件；不创建独立同意事件。
- 恢复事件显示实际执行者，可区分上传者自助恢复和房主恢复，但使用同一事件类型。
- 删除原因和拒绝原因不放入面向文件动态的投影与文案。
- 共享文件事件按现有公共可见规则展示；私密文件事件继续按上传者、接收者、房主匿名和其他成员隐藏规则投影。
- 已永久删除文件依靠保留的最小元数据继续投影历史事件；不因物理内容删除而让整段动态消失。

### 17. 新增通知类型

新增以下可判别类型，命名在前后端保持一致：

- `file_trashed_by_owner`：房主删除其他成员文件，接收人为原上传者，信息型。
- `file_restore_requested`：上传者申请恢复，接收人为房主，行动型。
- `file_restored_by_owner`：房主恢复其他成员文件，接收人为原上传者，信息型。
- `file_restore_rejected`：房主拒绝申请，接收人为申请上传者，信息型。
- `file_purged_by_owner`：房主永久删除其他成员文件，接收人为原上传者，信息型。

规则：

- 用户恢复或永久删除自己的文件不向自己生成结果通知。
- 原因字段只在当前通知用户有权查看时返回；用户输入原样返回，不经过后端翻译。
- 通知 DTO 不返回内部文件 ID、回收周期 ID、存储名、MIME、下载地址、接收者列表或隐藏私密文件名。
- 行动型申请返回不透明申请 ID；信息型结果返回不透明已读水位。

### 18. 通知有效性

所有新通知都要求房间仍活动、尚未过期，通知用户仍是活动成员，并且当前业务记录仍匹配通知发生时的回收版本。

#### 18.1 文件被房主删除

- 当前用户必须是文件原上传者，文件仍处于同一回收版本的回收站状态，删除执行者是房主且不是上传者本人，通知尚未已读。
- 文件恢复、永久删除、进入新回收版本或房间失效后自动失效。

#### 18.2 恢复申请

- 当前用户必须是当前活动房主；申请人仍是活动成员；申请、文件和回收周期必须仍待处理且版本一致。
- 同意、拒绝、房主直接恢复、永久删除、申请人离开或房间失效后自动消失。
- 点击和关闭 Modal 都不把它标记已读；只有业务状态终结它。

#### 18.3 文件已恢复

- 当前用户是原上传者，当前文件仍为可用，通知对应的恢复周期是文件最近一次已完成周期，且尚未已读。
- 文件再次进入回收站、永久删除、用户离开或房间失效后自动失效。

#### 18.4 恢复申请被拒绝

- 当前用户是申请人，文件仍处于同一回收版本的回收站状态，申请仍为已拒绝，且通知尚未已读。
- 文件恢复、永久删除、进入新周期、用户离开或房间失效后自动失效。

#### 18.5 文件被永久删除

- 当前用户是原上传者，文件仍为同一回收版本的已永久删除状态，执行者是房主且不是上传者本人，通知尚未已读。
- 用户离开或房间失效后自动失效；同一身份在房间仍有效时重新加入，可再次看到仍有效未读结果。

### 19. 通知聚合、计数和排序

- `file_restore_requested` 每个文件申请独立一行，不聚合，每项计数 1。
- 其他四类按通知用户、房间、房主和通知类型聚合；不同类型永不合并。
- 聚合项显示最新安全文件名、最新一条当前用户可见原因、实际文件数和最新时间。
- 铃铛总数增加有效待处理申请数和有效未读生命周期结果数，按实际文件数计算，不按聚合行数计算。
- 第一优先级：加入审批和恢复申请，按活动时间倒序共同混排。
- 第二优先级：待接收私密文件。
- 第三优先级：聊天、现有文件结果和四类信息型生命周期结果，按活动时间倒序共同混排。
- 同一优先级和时间使用稳定聚合键倒序，扩展现有游标优先级但保持分页稳定。
- 信息型聚合点击继续使用服务端水位，只标记水位之前且仍属于该聚合的记录；点击期间新到结果不得误读。
- 现有已读接口扩展支持四类信息型生命周期结果，不接受恢复申请、加入审批、聊天或待接收文件。

### 20. 通知点击目标

- 文件被房主删除：标记当前聚合已读后进入对应房间回收站。
- 文件已恢复：标记已读后进入对应房间文件列表。
- 恢复申请被拒绝：标记已读后进入对应房间回收站。
- 文件被永久删除：标记已读后进入对应房间文件动态。
- 恢复申请：不标记已读，进入对应房间回收站并打开审批 Modal。
- 信息型已读失败时保留抽屉和通知，不执行导航；待申请导航失败时刷新通知并显示失效提示。
- 聚合点击不自动改变回收站搜索、活动文件筛选或时间轴位置，不高亮文件，不执行恢复或删除。

### 21. SSE 事件和缓存刷新

- 继续使用现有用户级 SSE，不新建连接。
- 新增文件状态事件至少覆盖移入回收站、提交申请、拒绝、恢复、永久删除和下载取消。
- SSE 只携带安全机器字段，例如房间号、事件类型和当前用户有权接收的标识；不得携带删除原因、拒绝原因、隐藏文件名或翻译文案。
- 所有通知发生、已读和失效变化发布现有通知变化事件，触发通知第一页权威刷新。
- 同房间文件事件精确失效活动文件、回收站、文件动态、可复用私密文件和房间容量查询。
- 下载取消事件只发送给对应下载用户，并更新传输任务状态。
- SSE 断线重连后继续通过 REST 快照恢复，不持久化补发所有 SSE 事件。

### 22. 成员离开和重新加入

- 上传文件不因上传者主动退出或被移出而删除，继续跟随房间生命周期。
- 离开后立即失去活动文件命令、回收站查询和通知权限。
- 成员状态变为非活动时，在同一成员状态事务或可靠后续事务中把其待处理恢复申请改为失效，并发布通知变化。
- 同一身份重新加入后可看到自己上传且仍在回收站的文件。
- 当前回收版本申请从未被拒绝时，允许把已失效申请重新激活；已拒绝状态不能重新申请。
- 仍符合当前业务状态的信息型未读通知可在重新加入后出现，但不得因通知存在恢复已经失效的文件权限。

### 23. 房间生命周期清理

- 回收站不设置独立过期时间、保留天数或自动清理任务。
- 房间进入销毁流程时立即失去文件和通知访问；现有房间清理负责删除整个房间物理存储，包括回收站内容。
- 数据清理按依赖顺序覆盖通知记录、恢复申请、回收周期、下载任务、文件事件、接收关系、文件元数据和上传批次。
- 清理统计增加恢复申请和回收周期数量；重复清理保持幂等，失败继续沿用现有重试机制。
- 服务启动恢复内部永久删除执行中状态时，如果所属房间已进入销毁，以房间整体清理为准，不重复制造用户通知。

### 24. 国际化、错误和输入安全

- 所有新增前端按钮、Tab、状态、确认、空状态、原因标签、长度提示、通知、文件动态和错误必须同时提供 `zh-CN` 与 `en`。
- 前端组件只使用 i18n 键，不硬编码用户可见中文或英文。
- 后端新增统一错误码及中英文词典，至少覆盖文件状态冲突、回收权限、恢复申请状态、原因过长、审批失效、永久删除失败和下载因回收取消。
- 私密文件无权访问继续返回文件不存在语义，不增加可枚举的“你无权删除此私密文件”。
- 删除原因和拒绝原因属于用户输入，不翻译；API 返回原文前仍受当前用户权限投影。
- 后端不得持久化用户语言；语言选择仍只保存在前端本地存储。

### 25. 可访问性和响应式

- 回收站 Tab 使用正确的 Tab 角色、选中状态、焦点顺序和键盘左右导航。
- 文件操作菜单、恢复按钮、危险操作和分页按钮都有可读名称和可见焦点。
- 审批 Modal 打开后聚焦标题或第一个选择控件，关闭后焦点返回通知触发位置或合理回收站位置。
- 原因输入框有可见标签、可选说明和字符上限，不只依赖占位文字。
- 危险确认不能只靠红色表达，必须包含明确文字。
- 移动端操作面板保持足够触控区域；通知导航必须退出聊天全屏，不能把回收站遮在聊天后方。

## Testing Decisions

### 1. 测试原则

- 测试外部业务行为和不变量，不断言私有函数调用次数、SQL 文本、内部组件树或 CSS 类名。
- 该功能包含权限、复杂状态转换、磁盘与数据库协调、通知水位和并发竞争，属于项目规则中必须编写测试的范围。
- 不采用全面 TDD；按阶段实现后补足关键业务测试。
- 不使用 Playwright。自动化覆盖服务逻辑和前端纯逻辑，最终浏览器交互由用户人工验收。

### 2. 回收站生命周期服务测试

1. 上传者可以移动自己的共享和私密可用文件。
2. 房主可以移动他人共享和无关私密文件，但无关私密投影不泄露文件名。
3. 接收者、普通成员、离开成员和隐藏文件目标不能删除。
4. 上传中、失败、取消、回收站、内部执行中和已永久删除状态不能再次移入。
5. 每次新回收周期版本递增，旧周期拒绝不限制新周期。
6. 上传者自删后直接恢复，文件和全部接收状态原样保留。
7. 房主删除后上传者只能创建申请，重复待处理申请被拒绝。
8. 房主同意申请在单事务中恢复并终结申请。
9. 房主拒绝可保存空原因和 200 字原因，超长和控制字符被拒绝。
10. 拒绝后同周期不能重新申请，房主仍可直接恢复。
11. 房主直接恢复待处理申请等价于同意。
12. 上传者不能永久删除房主删除的文件，房主可以。
13. 上传者和房主都能永久删除上传者自删文件。
14. 恢复与永久删除并发只有一个状态转换成功。

### 3. 下载和容量测试

1. 移入回收站不改变已用容量，恢复也不改变。
2. 永久删除成功按实际大小释放一次容量，重复请求不重复扣减。
3. 物理删除失败保留回收状态和容量，不产生永久删除事件或通知。
4. 内部执行中启动恢复可完成幂等物理删除和容量释放。
5. 待开始下载任务在回收时变为取消。
6. 活动下载流收到取消，不能提交下载完成。
7. 回收与下载完成竞争时不会增加下载次数或生成首次下载通知。
8. 恢复后旧下载任务仍不可用，新任务可以正常创建。
9. 房主容量明细满足活动共享、活动私密、回收站与已用总量不变量。
10. 普通成员容量响应不包含回收站细分。

### 4. 查询与隐私测试

1. 普通成员回收站只返回自己上传的文件，房主返回全部。
2. 共享文件删除后普通浏览者不能从回收站看到。
3. 私密文件上传者看到完整信息，房主对无关私密文件只看到匿名投影。
4. 匿名搜索按私密编号命中，按原文件名不命中。
5. 搜索、删除时间倒序、稳定游标、默认和最大限制、总数正确。
6. 已永久删除文件不进入活动、回收站和复用查询，但文件动态仍能安全投影。
7. 删除原因和拒绝原因只返回给房主和原上传者。

### 5. 通知测试

1. 房主删除他人文件生成删除通知，自删不生成。
2. 恢复申请逐文件展示且只对当前房主有效。
3. 申请人离开后申请通知消失，重新加入并重新申请后恢复。
4. 同意、拒绝、直接恢复和永久删除都会终结行动型申请通知。
5. 房主恢复他人文件生成恢复通知，恢复自己文件不生成。
6. 拒绝生成带可选原因的结果通知，原因权限正确。
7. 房主永久删除他人文件生成结果，自行永久删除不生成。
8. 四类信息型通知按房间、房主和类型聚合，恢复申请不聚合。
9. 铃铛按实际文件和申请数计数，不按聚合行数。
10. 排序符合行动型审批、待接收文件、普通结果三级优先级。
11. 已读水位只清除当前快照，新到记录保持未读。
12. 删除通知在恢复或永久删除后失效；恢复通知在再次删除后失效；拒绝通知在恢复或永久删除后失效。
13. 删除前旧拒绝和首次下载结果在恢复后不复活，待接收通知可重新出现。
14. 房间失效和成员失去资格后所有相关通知不可见。

### 6. 成员和生命周期测试

1. 主动退出和被移出都会失效待处理恢复申请。
2. 同一身份重新加入后可见自己的回收站文件。
3. 失效且未拒绝申请可重新激活，已拒绝申请不可重新提交。
4. 房间清理删除物理内容、通知、申请、周期和最小元数据。
5. 重复清理幂等，清理失败保留任务并可重试。

### 7. 前端纯逻辑测试

1. 活动文件菜单只在 `canTrash` 时显示删除。
2. 回收站能力映射到直接恢复、申请恢复和永久删除按钮。
3. 待处理和已拒绝状态禁用重复申请。
4. 新通知类型生成正确的一次性文件列表、回收站、时间轴或审批目标。
5. 信息型通知与行动型申请采用不同已读行为。
6. SSE 文件事件只失效相关文件、回收站、容量和通知查询，进度事件不制造额外通知刷新风暴。
7. 中英文词典键完全一致且无空值。

### 8. 回归验证

- 运行全部 Go 测试，确保房间生命周期、上传下载、私密接收、再次发送、文件通知、聊天和成员权限没有回归。
- 运行全部前端测试和 TypeScript 生产构建。
- 运行项目总构建命令，确认静态资源嵌入和服务端构建成功。
- 使用格式检查确认没有空白错误，最终工作区只包含计划内变更。

## Manual Acceptance Checklist

1. 上传者删除自己的共享文件，文件从活动列表消失、进入自己的回收站、容量不变化，可直接恢复。
2. 上传者永久删除自己主动删除的文件，物理内容不可下载、文件离开回收站、容量减少。
3. 普通成员不能删除他人共享文件，也看不到他人的回收站文件。
4. 私密接收者不能删除发送者文件；待接收私密文件被删除后通知和文件列表同步消失。
5. 房主删除他人共享文件，上传者收到带可选删除原因的通知。
6. 房主删除无关私密文件，只看到私密编号，看不到原文件名、内容和下载入口。
7. 上传者点击删除通知进入对应房间回收站，通知变为已读。
8. 上传者提交恢复申请后按钮变为等待处理，不能重复提交或撤销。
9. 房主在首页点击申请通知，进入正确房间回收站并自动打开审批 Modal。
10. 房主在其他房间或目标房间点击申请通知，导航和 Modal 行为一致。
11. Modal 选择同意时拒绝原因禁用，提交后文件立即恢复且上传者收到恢复通知。
12. Modal 选择拒绝时可以留空或填写原因；上传者收到结果并在回收站看到原因。
13. 被拒绝后同一回收周期不能重新申请；房主仍能直接恢复。
14. 文件恢复后再次被房主删除，上传者可以对新周期重新申请。
15. 房主在回收站直接恢复待申请文件，申请通知消失并向上传者发送恢复通知。
16. 房主永久删除有待申请或已拒绝的他人文件，申请失效，上传者收到永久删除通知。
17. 点击永久删除通知进入文件动态，能看到安全审计记录但不能恢复或下载文件。
18. 回收站文件计入总容量，房主看到回收站细分，普通成员看不到细分。
19. 文件删除时待开始下载失效，正在下载被取消，不产生首次下载完成通知。
20. 恢复后旧下载链接仍失效，重新点击下载可以正常工作。
21. 删除前未读拒绝和首次下载结果在恢复后不重新出现；仍待接收通知可重新出现。
22. 删除、恢复、拒绝和永久删除聚合通知数量与铃铛真实文件数一致。
23. 多标签页通过 SSE 同步回收站、容量、审批和通知变化。
24. 上传者退出后申请失效；同一身份重新加入后按拒绝状态正确恢复能力。
25. 房间销毁后回收站、通知、申请、审计元数据和物理文件全部不可访问。
26. 桌面和移动端检查回收站列表、操作面板、确认 Modal、审批 Modal、键盘焦点和中英文切换。

## Out of Scope

- 文件内容预览、缩略图、在线打开或媒体播放。
- 批量移入回收站、批量恢复、批量申请和批量永久删除。
- 回收站独立保留期限、自动清理倒计时和提前清理策略。
- 管理员回收站容量开关、免费额度、独立上限或磁盘配额管理页面。
- 上传者撤销恢复申请、拒绝后重复申请和审批历史页面。
- 永久删除第二份原因。
- 向共享文件浏览者或私密文件接收者广播删除、恢复或永久删除通知。
- 顶部 Message、浏览器系统通知、邮件通知、新 SSE 连接或通知轮询。
- 已读通知历史、全部已读和在通知抽屉内直接恢复、永久删除或审批。
- 回收站范围分组、身份筛选、复杂排序和文件高亮定位。
- 旧数据库迁移、回填、兼容读取或专用清理脚本。
- 文件重命名、移动目录、版本管理、所有权转移或跨房间恢复。

## Further Notes

- “永久删除”表示物理文件内容不可恢复并释放容量；为了在最长 24 小时的房间生命周期内保留审计，最小元数据会保留到房间销毁。
- 回收站继续计入容量是本期简化模型的关键，不实现早期原型讨论中的免费回收额度和计费开关。
- 删除原因和拒绝原因是用户输入，不属于项目翻译内容；相关标签、空原因说明和错误提示必须双语。
- 房主对无关私密文件的治理能力绝不等于查看或下载权限。任何回收站、通知、审批和文件动态投影都必须重新遵守匿名规则。
- 正式实现必须等用户明确批准本 PRD 后开始。
