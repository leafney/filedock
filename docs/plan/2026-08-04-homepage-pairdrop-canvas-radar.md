# 首页 PairDrop 风格 Canvas 雷达开发 PRD

Related discussion: [docs/discuss/2026-08-04-homepage-pairdrop-canvas-radar.md](../discuss/2026-08-04-homepage-pairdrop-canvas-radar.md)

- 日期：2026-08-04
- 状态：待批准
- 变更类型：前端装饰渲染架构与动效修订
- 前置规格：`docs/plan/2026-08-04-homepage-subtle-radar.md`
- 外部参考：[PairDrop](https://pairdrop.net/)
- 影响范围：首页雷达背景、Canvas 生命周期、响应式与高清屏、减少动态效果

## Problem Statement

当前首页雷达使用四个 `132px` HTML 圆环，通过 CSS `transform: scale()` 放大到画布对角线范围。虽然透明度已经降低，但 CSS 变换会同时放大圆环直径和 `border`，导致线条越往外越粗。实际截图中，内圈接近细线，外圈和中段弧线明显变宽，无法获得 PairDrop 那种稳定、均匀的背景圆环。

当前模型还让每个圆环在 `8s` 内独立穿过整个画布。即使发射间隔为 `2s`，大范围独立缩放仍会产生较明显的运动速度，用户持续查看时感到烦躁。

对 PairDrop 公开实现的分析表明，它使用 Canvas 绘制 8 个固定线宽、等距圆环。整组圆环每 `2s` 向外平移一个间距，周期结束后通过圆环身份轮换无缝补入内圈。其平静感来自固定线宽、等距排列、整组平移和半径透明度衰减，而不是单个圆环快速缩放。

本阶段需要用 PairDrop 同类 Canvas 模型替换 CSS 圆环，并先采用 PairDrop 的主要动画参数进行一版人工验收。FileDock 保留自己的中心圆点、品牌青绿色和更低透明度；暂不自定义为更慢的 `3s / 24s` 方案，也不引入 OffscreenCanvas Worker。

## Solution

首页雷达背景改为一个覆盖雷达画布的 Canvas。Canvas 每帧绘制 8 个以中心头像为圆心的等距圆环，固定线宽为 `2px`。间距使用 `round(max(width × 0.6, height) ÷ 10)`，起始半径为 `33px`。相位每 `2s` 从 `0` 平滑推进到一个完整间距；周期重置时，最外圈消失，其他圆环视觉位置由相邻索引无缝接替，中心补入新圈。

桌面使用 FileDock 青绿色和 `0.18` 基础透明度；`768px` 以下使用 `0.12`。每圈透明度先按半径相对面板最大边线性衰减；超过第 7 个间距后再额外衰减，在第 8 个间距处归零。圆心继续位于雷达画布几何中心，不照搬 PairDrop 的页面底部圆心。

Canvas 内部分辨率按设备像素比放大，绘图坐标仍使用 CSS 像素，使 `2px` 线宽在普通屏和 Retina 屏保持一致。动画在主线程通过 `requestAnimationFrame` 运行，目标 `60fps`；页面进入后台时暂停，返回后从原相位继续。首版不使用 OffscreenCanvas Worker。

系统启用减少动态效果时不启动动画循环，只绘制相位为零的 8 圈静态雷达。Canvas 上下文不可用时静默隐藏圆环，中心头像、随机节点和首页业务继续正常工作。

## User Stories

1. 作为首页用户，我希望内圈和外圈线宽一致，以便雷达不会越扩散越粗。
2. 作为首页用户，我希望圆环保持固定 `2px`，以便获得接近 PairDrop 的稳定线条。
3. 作为首页用户，我希望圆环等距排列，以便背景节奏整齐而不是随机疏密。
4. 作为首页用户，我希望整组圆环缓慢外移，以便动画不产生独立圆环快速冲出的烦躁感。
5. 作为首页用户，我希望内圈能够无缝补入，以便每个相位结束时看不到整体跳回。
6. 作为首页用户，我希望外圈逐渐消失，以便圆环不会形成固定页面边框。
7. 作为首页用户，我希望外侧节点仍位于圆环覆盖范围内，以便节点与雷达背景保持空间联系。
8. 作为首页用户，我希望雷达使用 FileDock 青绿色，以便视觉风格与产品一致。
9. 作为首页用户，我希望青绿色透明度低于 PairDrop 灰色，以便白色背景中不会抢占焦点。
10. 作为首页用户，我希望雷达圆心与当前身份头像同心，以便信号来源明确。
11. 作为首页用户，我希望节点不随雷达经过而闪烁，以便不会误解为通知或交互状态。
12. 作为首页用户，我希望节点继续清楚呼吸，以便页面仍表达局域网活跃状态。
13. 作为移动端用户，我希望圆环进一步变淡，以便小画布中主要操作仍最醒目。
14. 作为高清屏用户，我希望圆环边缘清晰，以便 Retina 屏不会模糊或锯齿。
15. 作为页面用户，我希望切换到其他标签后动画停止，以便减少后台 CPU 与电量消耗。
16. 作为页面用户，我希望返回标签时动画从暂停位置继续，以便不会突然跳跃。
17. 作为页面用户，我希望调整窗口大小后圆环立即适配，以便没有拉伸或错位。
18. 作为减少动态效果的用户，我希望 Canvas 不播放扩散，以免持续运动造成不适。
19. 作为减少动态效果的用户，我希望仍能看到静态雷达结构，以便页面设计保持完整。
20. 作为 Canvas 不可用环境的用户，我希望首页主要功能仍正常，以便装饰效果失败不阻断使用。
21. 作为键盘用户，我希望 Canvas 不进入焦点顺序，以便不会访问无操作背景。
22. 作为屏幕阅读器用户，我希望 Canvas 被视为装饰，以便不会朗读无意义内容。
23. 作为维护者，我希望动画生命周期在组件卸载时完全清理，以便不会残留动画帧或监听器。
24. 作为维护者，我希望 Canvas 尺寸和节点布局复用同一个画布尺寸来源，以便避免两个区域错位。
25. 作为维护者，我希望绘图计算封装在简单接口内，以便后续只调整参数即可改变效果。
26. 作为维护者，我希望首版不引入 Worker，以便先低成本验证视觉方向。
27. 作为维护者，我希望不恢复旧 CSS 或 SVG 圆环，以便只维护一种雷达背景模型。
28. 作为维护者，我希望不新增用户文案和依赖，以便词典与构建保持稳定。
29. 作为维护者，我希望现有测试和生产构建继续通过，以便确认业务没有回归。

## Implementation Decisions

### 1. 变更边界与替代关系

- 本 PRD 替代前置规格中的 HTML 波纹元素、CSS 缩放关键帧、对角线终点缩放变量、桌面和移动端波纹透明度变量、静态 CSS 圆环。
- 此前讨论但未实现的 SVG 非缩放描边方案取消，不保留双重实现。
- 前置规格中已经实现的中心头像对齐、节点定位、节点生命周期、节点呼吸 `1.12`、标签不缩放、纯展示语义继续有效。
- 不修改首页布局、操作侧栏、断点、房间卡、顶栏、后端、API、房间页面或随机节点算法。
- 不新增第三方依赖。

### 2. Canvas DOM 与层级

- 用一个 Canvas 元素替换当前包含四个空元素的波纹容器。
- Canvas 使用绝对定位覆盖整个雷达画布：宽高为父容器 `100%`，四边为零。
- Canvas 层级低于随机房间节点和中心身份，高于页面背景。
- Canvas 禁止指针事件、不可聚焦，并标记为装饰内容。
- 不在 Canvas 中绘制中心头像、昵称、节点或标签；这些内容继续由现有 DOM 渲染。

### 3. 常量参数

- 圆环数量：`8`。
- 固定视觉线宽：`2 CSS px`。
- FileDock 圆环颜色：现有主青绿色，对应 RGB `13 148 136`。
- 桌面基础透明度：`0.18`。
- 移动端基础透明度：`0.12`。
- 移动端断点：视口宽度 `768px` 及以下。
- 起始半径：`33 CSS px`。
- 速度参数：`0.5`。
- 目标帧率：`60fps`。
- 相位周期：`2000ms`。
- 首版不得替换为 `3000ms`、`24s` 完整行程或其他自定义慢速参数。

### 4. 间距与半径算法

- 使用雷达画布的 CSS 像素宽度和高度计算，不使用 Canvas 位图像素。
- 圆环间距：`round(max(width × 0.6, height) ÷ 10)`。
- 间距最小值至少为 `1px`，防止极端零尺寸后的除零。
- 当前相位进度：`(累计动画时间 % 2000ms) / 2000ms`，范围 `[0, 1)`。
- 当前相位位移：`spacing × phaseProgress`。
- 第 `index` 圈半径：`spacing × index + phaseOffset + 33px`，`index` 为 `7` 到 `0`。
- 绘制顺序从外圈到内圈，与 PairDrop 保持一致；由于只有描边，顺序不改变颜色混合语义。
- 相位从接近 `1` 重置为 `0` 时，旧 `index` 圈位置由下一个索引的圆环接替，形成无缝循环。

### 5. 透明度算法

- 当前最大边：`max(width, height)`，最小按 `1px` 处理。
- 基础半径衰减：`max(0, baseOpacity × (1 - 1.2 × radius / maxDimension))`。
- 当 `radius > spacing × 7` 时，再乘以外圈系数：`clamp((spacing × 8 - radius) / spacing, 0, 1)`。
- 最终透明度必须限制在 `[0, baseOpacity]`。
- 桌面 `baseOpacity = 0.18`；移动端 `baseOpacity = 0.12`。
- 不增加柔光、阴影、渐变或第二次透明度增强。
- 使用完整 RGB 青绿色加最终 alpha 绘制，不能让 Canvas 整体再叠加第二层 opacity。

### 6. Canvas 高清屏尺寸

- 每次画布 CSS 尺寸变化时读取设备像素比。
- 有效设备像素比建议限制为 `min(window.devicePixelRatio || 1, 2)`，避免超高像素比设备产生过大位图；视觉清晰度仍满足 Retina 屏。
- Canvas 位图宽度为 `round(cssWidth × dpr)`，高度为 `round(cssHeight × dpr)`。
- Canvas CSS 宽高继续为 `100%`，不得使用位图宽高撑开布局。
- 重设位图尺寸后，使用上下文变换把绘图坐标恢复为 CSS 像素。
- `lineWidth = 2` 表示 `2 CSS px`，不能再乘以半径、缩放倍数或设备像素比。

### 7. 圆心

- 圆心固定为雷达画布几何中心：`width / 2`、`height / 2`。
- 圆心继续与 `112px` 中心头像几何中心重合。
- 不照搬 PairDrop 的底部页脚圆心偏移。
- 窗口尺寸变化后必须同步更新圆心。

### 8. 动画时钟与帧率

- 使用 `requestAnimationFrame` 驱动主线程 Canvas。
- 首版不创建 Worker，不调用 `transferControlToOffscreen`。
- 动画目标为 `60fps`；可以通过记录上一绘制时间跳过间隔不足约 `1000 / 60ms` 的重复帧。
- 动画累计时间只在页面可见且非减少动态效果时增加。
- 每帧先清空整张 Canvas，再绘制 8 圈。
- 不调用 React `setState` 更新每帧相位；帧号、累计时间和动画请求 ID 使用局部变量或 ref。

### 9. 页面隐藏、恢复与卸载

- 监听 `document.visibilitychange`。
- 页面变为隐藏时取消当前动画帧，并记录已累计动画时间。
- 页面恢复可见时从原累计时间继续，第一帧不能把后台停留时间加入相位。
- 组件卸载时取消动画帧、断开尺寸观察器，并移除可见性、移动端媒体查询和减少动态效果监听器。
- 不允许重复启动多个并行动画循环。

### 10. 尺寸变化

- 继续使用雷达画布现有尺寸观察机制获取宽、高。
- 同一尺寸变化同时触发节点合法重排与 Canvas 位图重设。
- 尺寸小于等于零时不绘制，不抛出异常。
- 位图重设会清空 Canvas；完成重设后必须立即按当前相位重绘，不能等待下一完整周期。
- 尺寸变化不重置累计动画相位。

### 11. 移动端

- 使用媒体查询状态判断 `768px` 及以下，不通过 Canvas 自身宽度猜测设备类型。
- 移动端只把基础透明度从 `0.18` 改为 `0.12`。
- 圆环数量、`2px` 线宽、间距公式、`2s` 相位周期、`60fps` 和圆心不变。
- 断点跨越时立即按当前相位重绘，不重启动画周期。

### 12. 减少动态效果

- 继续监听 `prefers-reduced-motion: reduce`，并与现有雷达减少动态状态保持一致。
- 减少动态效果开启时取消 Canvas 动画帧，累计相位停止。
- 使用相位进度 `0` 绘制 8 圈静态等距圆环，透明度继续应用相同半径衰减公式。
- 减少动态效果关闭时从保留相位继续启动动画，不把停止时间计入。
- 现有 CSS 继续停止节点呼吸、进入和退出动画。

### 13. Canvas 不可用降级

- 如果 Canvas 元素、二维上下文或 `requestAnimationFrame` 不可用，跳过雷达背景绘制。
- 不恢复旧 HTML/CSS 圆环，不新增 SVG 备用层。
- 不显示用户错误消息，不阻断首页渲染，不抛出未捕获异常。
- 中心头像、昵称、随机节点、操作侧栏和所有业务继续正常工作。

### 14. 绘图模块边界

- Canvas 尺寸、相位、间距、半径、透明度、绘制、暂停与清理应封装在一个内部渲染器或等价的集中实现中。
- React 组件只负责创建 Canvas、传入尺寸与系统偏好、在卸载时清理；不得把每帧数据存入 React 状态。
- 渲染器至少需要表达：调整尺寸、绘制当前帧、启动、暂停、销毁。
- 本阶段不要求导出公共 API，不让房间页面复用该装饰渲染器。

### 15. CSS 清理

- 删除旧波纹空元素的尺寸、边框、动画、延迟、关键帧、移动端透明度变量和静态环选择器。
- 保留雷达画布容器的定位、裁剪和独立层叠上下文。
- 为 Canvas 保留绝对定位、全尺寸、低层级与 `pointer-events: none`。
- 节点呼吸关键帧继续保持峰值 `1.12`，不得回退到 `1.08`。

### 16. i18n

- 本阶段不新增或修改用户可见文案，不需要新增翻译键。
- Canvas、随机房间号、颜色和内部参数不属于翻译内容。
- React 组件不得增加硬编码说明文案。

### 17. 实施顺序

1. 增加内部 Canvas 渲染器及常量，完成间距、半径、透明度和单帧绘制。
2. 用 Canvas 替换四个 HTML 波纹元素，清理旧终点缩放参数。
3. 把现有尺寸观察流程接入 Canvas 高清屏尺寸和当前帧重绘。
4. 接入 `requestAnimationFrame`、`2s` 相位、`60fps` 限制、后台暂停和恢复。
5. 接入移动端 `0.12` 与减少动态效果静态帧。
6. 清理旧波纹 CSS 与关键帧，确认节点呼吸仍为 `1.12`。
7. 运行自动检查并执行人工浏览器验收。

## Acceptance Criteria

### Canvas 与线宽

1. 首页雷达背景使用一个 Canvas，不再渲染四个 HTML 波纹空元素。
2. 正常与静态模式均绘制 8 个圆环。
3. 所有圆环视觉线宽固定为 `2px`。
4. 内圈、中圈、外圈线宽一致，不随半径增加。
5. Canvas 位于节点和中心头像下方，不遮挡内容。
6. Canvas 不响应点击、悬停或键盘焦点。

### PairDrop 参考算法

7. 圆环间距为 `round(max(width × 0.6, height) ÷ 10)`。
8. 最内圈基础半径偏移为 `33px`。
9. 8 圈始终保持相同间距。
10. 每 `2s` 整组圆环向外移动一个间距。
11. 周期边界无明显整体跳回或闪烁。
12. 一个逻辑圆环经过 8 个间距约需 `16s`。
13. 动画目标 `60fps`，线条移动连续。

### 颜色与透明度

14. 圆环使用 FileDock 青绿色 `rgb(13 148 136)`。
15. 桌面基础透明度为 `0.18`。
16. `768px` 及以下基础透明度为 `0.12`。
17. 每圈透明度随半径持续降低。
18. 超过第 7 个间距后额外渐隐，并在第 8 个间距处归零。
19. 圆环没有柔光、阴影、渐变或二次加深。

### 圆心与覆盖

20. Canvas 圆心与中心头像几何中心重合。
21. 圆环覆盖中心、中段和外侧节点区域。
22. 超出雷达画布的圆环被裁剪，不覆盖页面其他区域。
23. 调整画布宽度或高度后，圆心、间距和圆环立即更新。

### 高清屏与性能

24. 普通屏和 Retina 屏圆环均清晰，无明显锯齿或模糊。
25. Canvas 位图尺寸按有效设备像素比设置，不改变页面布局尺寸。
26. 动画帧不触发 React 状态更新或组件每帧重渲染。
27. 页面进入后台后动画帧停止。
28. 返回前台后从暂停相位平滑继续，不发生相位跳跃。
29. 组件卸载后没有残留动画帧、观察器或事件监听器。

### 减少动态效果与降级

30. 开启减少动态效果后 Canvas 不播放动画。
31. 减少动态效果下显示 8 圈静态等距圆环。
32. 减少动态效果下节点呼吸、进入和退出动画停止。
33. Canvas 二维上下文不可用时，首页仍正常显示头像、节点和业务操作。
34. 降级时不恢复旧 CSS 或 SVG 圆环，不显示用户错误。

### 回归与质量

35. 节点呼吸峰值继续为 `1.12`，周期与错峰不变。
36. 节点标签不缩放，节点不与圆环联动。

## Testing Decisions

- 本阶段修改装饰渲染实现，不包含业务规则、鉴权、支付或持久化状态；按照项目规则不新增 TDD 或 Canvas 像素快照测试。
- 不测试 Canvas 内部每次 `arc()` 调用、具体帧号或私有变量，这些属于实现细节。
- 现有节点算法不变，不新增随机节点测试。
- 自动检查继续运行正式前端测试、历史原型测试、TypeScript 编译、生产构建和 `git diff --check`。
- 不使用 Playwright。Canvas 视觉、帧率、暂停恢复和高清屏清晰度采用人工浏览器验收。
- 桌面建议观察至少 `18s`：确认超过一个逻辑圆环完整行程，8 圈等距、线宽恒定、周期边界无跳动。
- 使用浏览器性能面板观察数秒：确认没有持续 React 提交、重复动画循环或明显长任务。
- 调整窗口宽高和设备方向：确认 Canvas 位图、圆心、间距与节点区域同步更新。
- 切换浏览器标签并返回：确认后台停止绘制，返回后从暂停相位继续。
- 切换 `768px` 断点：确认透明度变化但相位、间距和圆环数量不重置。
- 开启减少动态效果：确认 Canvas 静止且 8 圈可见，节点动画停止。
- 在普通屏与 Retina 屏验收：确认 `2px` 视觉线宽一致、边缘清晰。
- 人工验收期间检查控制台，不能出现新增错误或警告。

## Further Notes

- PairDrop 参数来自 2026-08-04 对其公开线上资源的只读分析；FileDock 只参考渲染模型与公开参数，不复制页面业务结构。
- PairDrop `speed = 0.5` 表示 `2s` 完成一个间距相位，不表示单个圆环 `2s` 穿过全屏。
- “完整行程约 `16s`”是 8 个间距乘以每间距 `2s` 的逻辑理解；Canvas 实际通过索引轮换形成无缝圆环场。
- 固定 `2px` 是首版验收参数。若用户仍认为偏粗，后续只需调整 Canvas `lineWidth`，不会再出现外圈比内圈粗的问题。
- DPR 只提升位图清晰度，不改变 CSS 坐标中的半径、间距或线宽。
- 透明度 `0.18 / 0.12` 是半径衰减前的基础值；实际外圈透明度会更低。
- 本 PRD 获得用户明确批准后才能修改生产代码。
