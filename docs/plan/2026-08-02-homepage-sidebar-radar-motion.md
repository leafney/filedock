# 首页侧栏换位与雷达动效优化开发 PRD

Related discussion: [docs/discuss/2026-08-02-homepage-sidebar-radar-motion.md](../discuss/2026-08-02-homepage-sidebar-radar-motion.md)

- 日期：2026-08-02
- 状态：已完成，待人工验收
- 变更类型：前端布局、视觉动效、响应式与历史原型说明优化
- 影响范围：首页操作侧栏、雷达画布、雷达波纹、装饰房间节点、减少动态效果、历史房间原型提示

## Problem Statement

当前生产首页在桌面端把雷达视觉区放在左侧，把“我的房间／参与房间”操作区放在右侧。用户从右侧房间列表进入房间页面后，房间页面的成员上下文位于左侧，两级页面的空间位置缺少连续性。创建、加入和进入房间是首页主要任务，却位于页面右侧次要区域；移动端改为单列后，雷达又先于操作区出现，用户需要先经过装饰内容才能执行主要任务。

首页雷达在浅灰白背景上还存在可见度不足。四层波纹使用较低透明度边框，再叠加较低动画透明度，中心向外扩散的过程很浅。用户可以看到静态同心圆，但不容易感知“局域网信号正在扩散”。周围五个房间节点仅在创建与替换时短暂淡入淡出；节点稳定显示期间完全静止，页面缺少持续但克制的活跃感。

此外，仓库内保留的独立房间工作区原型已经被生产页面实现替代，但原型页面仍只显示“仅原型”，README 也没有明确说明它已经过时。维护者或评审者可能误把历史原型当成当前设计基准。

本阶段需要在不改变首页业务、房间业务和雷达节点算法的前提下，交换首页操作区与雷达区的位置，增强雷达波深浅扩散效果，为周围房间圆增加错峰呼吸，并明确标记历史原型已经过时。

## Solution

首页桌面布局改为左侧固定约 300px 的操作区和右侧自适应雷达区。操作区始终承载当前用户在首页需要执行的任务：未建立身份时显示昵称设置，建立身份后显示“我的房间／参与房间”。操作区在真实 DOM 中排在雷达前面，使桌面视觉顺序、移动端上下顺序、键盘导航顺序和屏幕阅读顺序保持一致。900px 及以下继续使用单列，但改为操作区在上、雷达在下。

雷达继续使用四层同心圆、五秒扩散周期和 1.25 秒错峰，不改变波纹数量与速度。波纹统一使用 FileDock 青绿色，通过较高可见度、单圈由深到浅消失、相邻波纹强弱交替，增强扩散层次。画面仍保持 1px 轻量圆环，不增加实心色带、渐变色相或霓虹效果。

周围五个装饰房间节点在稳定可见阶段增加呼吸。只有圆形头像在 1 到 1.06 之间缩放，房间号标签不动。五个槽位使用不同的 2.8～4.2 秒周期与错开延迟，呼吸峰值增加节点同色低透明度光晕。进入和退出动画继续作用于节点外层，呼吸只作用于头像内层，避免两个动画争用同一个 `transform`。

系统启用减少动态效果时，停止波纹扩散和节点呼吸，保留四层静态深浅圆环及静态节点。历史房间原型只更新 README 与页面顶部双语提示，明确它已被生产页面替代；不继续维护其布局和业务演示。

## User Stories

1. 作为首页用户，我希望房间操作区位于桌面左侧，以便第一眼看到创建、加入和已有房间。
2. 作为已有房间的用户，我希望从首页左侧房间列表进入房间后，在房间页左侧看到成员上下文，以便两个页面形成稳定的空间映射。
3. 作为首次访问者，我希望昵称设置位于首页左侧主要操作区，以便不必先阅读装饰内容。
4. 作为首次访问者，我希望昵称输入继续实时更新雷达中心头像和昵称，以便现有身份预览行为不变。
5. 作为已建立身份的用户，我希望“我的房间”和“参与房间”继续使用现有数据与操作，以便布局调整不改变业务。
6. 作为房主，我希望创建房间、进入房间和解散房间行为保持不变，以便布局调整不会带来功能回归。
7. 作为普通成员，我希望加入、进入和退出房间行为保持不变，以便布局调整不会影响成员关系。
8. 作为桌面用户，我希望左侧操作区宽度约为 300px，以便房间卡紧凑且右侧雷达获得更多空间。
9. 作为桌面用户，我希望左侧操作卡垂直居中，以便短列表不会贴在页面顶部并留下失衡空间。
10. 作为宽屏用户，我希望雷达区域自动占据操作区以外的剩余宽度，以便中心辐射构图保持视觉主体地位。
11. 作为平板用户，我希望页面在宽度允许时仍使用 300px 左栏和自适应雷达，以便主要操作与视觉区并存。
12. 作为窄屏用户，我希望页面在 900px 及以下切换单列，以便操作卡不会被压缩到不可读。
13. 作为移动用户，我希望操作区位于雷达上方，以便先执行创建、加入和进入房间。
14. 作为键盘用户，我希望焦点先经过操作区再进入雷达后的页面内容，以便焦点顺序与视觉顺序一致。
15. 作为屏幕阅读器用户，我希望文档阅读顺序与移动端显示顺序一致，以便不依赖 CSS 视觉重排理解页面。
16. 作为首页用户，我希望雷达波在浅色背景上更明显，以便理解中心用户正在发现局域网房间。
17. 作为首页用户，我希望波纹从中心向外扩散时由深变浅，以便方向感清楚。
18. 作为首页用户，我希望相邻波纹呈现强弱交替，以便四层圆环具有自然的深浅节奏。
19. 作为首页用户，我希望波纹保持青绿色单色，以便页面符合 FileDock 品牌视觉。
20. 作为首页用户，我希望波纹边框保持轻量，以便增强可见度后不会形成厚重靶盘。
21. 作为现有用户，我希望波纹扩散速度保持原有节奏，以便新增效果不会让页面突然变得急促。
22. 作为首页用户，我希望周围房间圆轻微呼吸，以便感知局域网环境持续活跃。
23. 作为首页用户，我希望不同节点错峰呼吸，以便它们不会像统一节拍器一样同时跳动。
24. 作为首页用户，我希望呼吸幅度克制，以便房间节点不会抢夺中心身份的视觉焦点。
25. 作为首页用户，我希望房间号标签保持静止，以便动画期间仍容易阅读。
26. 作为首页用户，我希望中心用户头像保持稳定，以便页面视觉锚点不会持续晃动。
27. 作为首页用户，我希望呼吸峰值出现轻微同色光晕，以便不同颜色节点仍保留各自身份感。
28. 作为首页用户，我希望节点淡入或淡出时不同时呼吸，以便状态过渡平滑且不发生缩放冲突。
29. 作为减少动态效果的用户，我希望系统偏好开启后停止持续扩散和呼吸，以免产生不适。
30. 作为减少动态效果的用户，我希望停止动画后仍看到静态深浅圆环，以便雷达结构和品牌表达仍然存在。
31. 作为维护者，我希望保留现有五节点数量、随机位置、颜色、生命周期和替换规则，以便本阶段不扩张到算法重构。
32. 作为维护者，我希望呼吸周期从现有稳定节点信息派生，以便不增加计时状态、持久化字段或额外渲染循环。
33. 作为维护者，我希望进入／退出动画与呼吸动画作用于不同元素，以便 CSS `transform` 不互相覆盖。
34. 作为评审者，我希望历史房间原型明确显示已经过时，以便不会把旧页面当成生产设计。
35. 作为中英文评审者，我希望历史原型提示同时提供中文和英文，以便不同语言下都不会产生误解。
36. 作为维护者，我希望历史原型只保留参考价值，不继续同步生产功能，以便减少双份界面维护成本。
37. 作为维护者，我希望首页 API、通知、个人信息、房间卡和路由逻辑保持不变，以便视觉优化不会引入业务风险。
38. 作为维护者，我希望现有前端测试、TypeScript 编译和生产构建继续通过，以便确认没有结构性回归。

## Implementation Decisions

### 1. 变更边界

- 本阶段只修改正式首页的布局组合、雷达渲染参数、全局首页样式、历史原型说明和相关文档。
- 不修改后端、数据库、API、SSE、房间路由、房间页面、文件传输、通知查询、会话模型或房间数据结构。
- 不改变首页创建房间、加入房间、进入房间、退出房间、解散房间、通知处理、个人信息和昵称设置的业务逻辑。
- 不改变雷达节点数量、尺寸范围、位置避让、颜色生成、房间号生成、生命周期、替换队列或 ResizeObserver 重排逻辑。
- 不新增依赖，不引入 Canvas、SVG 动画库或第三方动效包。

### 2. 首页 DOM 与语义顺序

- 首页主内容中的操作侧栏必须放在雷达区域之前，采用真实 DOM 顺序调整。
- 不允许只通过 `order`、负网格线或视觉方向反转把右栏显示到左侧，因为该做法会导致键盘与屏幕阅读顺序仍旧相反。
- 操作侧栏内部状态保持不变：存在匿名会话时显示房间区域；不存在会话时显示昵称设置区域。
- 雷达区域继续接收当前显示名称，昵称输入和昵称更新仍驱动中心头像与昵称。
- 顶栏、页脚、所有 Modal、Drawer 和查询组合顺序不因主内容换位而改变。

### 3. 桌面双栏布局

- 双栏断点为视口宽度大于 900px。
- 网格第一列为约 300px 固定操作栏；第二列使用 `minmax(0, 1fr)` 占据剩余空间。
- 操作栏不得恢复到原有 320～340px 范围，也不得压缩到房间页成员栏的 240px。
- 操作侧栏在双栏区域中保持垂直居中，现有卡片圆角、边框、阴影和内部间距不重设计。
- 雷达区域继续水平、垂直居中画布，画布宽度为右侧列的完整可用宽度。
- 主内容最大宽度、页面左右留白、顶栏宽度和页脚布局保持现有规则。
- 双栏之间保留响应式间距；间距可以复用现有范围，但必须检查 901px 附近不会横向溢出。

### 4. 平板与移动布局

- 900px 及以下切换单列，不增加额外中间断点。
- 单列第一项为操作侧栏，第二项为雷达区域。
- 操作侧栏在单列中取消垂直居中约束，按正常文档流从顶部显示，并继续使用现有最大宽度限制与水平居中。
- 雷达在操作区下方保持现有移动高度量级，不因换位造成零高度、过长空白或横向滚动。
- 560px 及以下继续隐藏品牌 Slogan、用户昵称和下拉箭头，首页本阶段不改变统一顶栏规则。
- 移动端房间卡的点击、底部房间操作 Drawer、创建和加入 Modal 保持现有行为。

### 5. 雷达波纹结构

- 继续渲染四个空元素表示四层圆环，不增加或删除层数。
- 四层圆环继续以画布中心为共同原点，并保持现有相对尺寸级差。
- 每圈动画总周期保持约五秒，相邻波纹继续错开约 1.25 秒。
- 波纹动画只改变 `opacity` 与 `transform: scale()`，不能修改布局尺寸、位置或触发重排。
- 圆环边框保持 1px；不使用粗边框、实心背景、模糊整面填充或不同色相渐变。

### 6. 波纹颜色与深浅节奏

- 波纹统一使用 FileDock 主青绿色，不与节点随机色绑定。
- 整体颜色可见度从当前低透明度提高到中等强度。实现目标为普通白色或浅灰背景下无需仔细观察即可看见扩散，但圆环不得比中心头像或房间节点更醒目。
- 单圈关键帧顺序必须体现：靠近中心时较深，扩散中段逐渐变浅，接近最外缘时完全透明。
- 相邻圆环必须使用强、弱、强、弱的边框透明度或强度变量；第一、第三圈为较强组，第二、第四圈为较弱组。
- 强弱差异通过同色透明度实现，不能改变青绿色色相。
- 推荐把强色、弱色抽成雷达样式变量，避免在多个选择器中复制颜色值。
- 动画透明度与边框颜色透明度会相乘；编码时必须按最终视觉结果调节，不能把两者都设得过低。

### 7. 节点呼吸作用层级

- 节点外层继续负责定位、整体进入动画和整体退出动画。
- 圆形头像内层负责呼吸动画。
- 房间号标签位于呼吸元素之外，不随头像缩放。
- 中心用户头像不添加呼吸类名、缩放关键帧或彩色光晕。
- 只有节点阶段为稳定可见时才启用呼吸；进入和退出阶段不得启用。
- 该分层用于避免外层进入／退出与内层呼吸同时写入同一个 `transform`。

### 8. 呼吸关键帧

- 呼吸关键帧从 `scale(1)` 开始，中点达到 `scale(1.06)`，结束回到 `scale(1)`。
- 缩放使用平滑的 `ease-in-out` 或等价缓动，不能使用弹跳、回弹或阶梯缓动。
- 节点基础阴影继续存在；呼吸峰值叠加一层低透明度同色外扩光晕。
- 光晕颜色从节点自身颜色或色相派生，不能统一使用青绿色，也不能使用高饱和霓虹阴影。
- 呼吸动画不得改变节点文字颜色、边框宽度、DOM 尺寸或点击行为。
- 节点仍为装饰元素，保持不可点击与 `aria-hidden` 语义。

### 9. 节点错峰规则

- 五个节点的呼吸周期覆盖约 2.8、3.15、3.5、3.85 和 4.2 秒，或使用等价的 2.8～4.2 秒离散分布。
- 每个槽位使用稳定周期与不同延迟，避免组件重渲染后周期随机突变。
- 延迟可以为负值，使首次渲染时节点已经位于不同动画相位，避免全部从缩放起点同时开始。
- 周期和延迟从现有稳定槽位、色相或稳定标识派生；不新增 React 定时器、不新增每帧状态更新、不把动效参数存入后端或 localStorage。
- 替换节点继承该槽位的呼吸节奏，节点内容变化不要求重新随机整个动画表。

### 10. 减少动态效果

- 继续复用现有系统偏好检测和雷达减少动态类名，不创建第二套媒体查询状态 Hook。
- 开启减少动态效果时，停止四层圆环扩散动画。
- 停止所有节点呼吸动画、进入动画和退出动画。
- 四层圆环仍静态可见，并保持强、弱、强、弱透明度层次。
- 静态圆环必须使用固定缩放或现有四层尺寸，不能全部重叠到同一大小。
- 节点替换逻辑继续运行时采用无动画更新，不改变现有生命周期业务。
- 减少动态样式必须同时覆盖组件类名和 `prefers-reduced-motion`，避免首屏状态检测前出现持续动画。

### 11. 现有雷达行为保留

- 周围房间节点数量继续固定为五个。
- 节点继续随机生成四位房间号、直径、颜色和合法位置。
- 节点继续避开中心用户、画布边缘和其他节点。
- 节点继续按 10～30 秒生命周期逐个退出和替换。
- 进入和退出持续时间保持现有量级，本阶段不调整替换轮询频率。
- ResizeObserver 在左右换位后会获得新的右侧画布尺寸；必须继续触发节点合法重排。
- 布局换位后不得出现节点覆盖中心用户、溢出画布或标签被 300px 左栏遮挡的问题。

### 12. 历史原型标记

- 仓库中的房间工作区独立原型标记为历史原型，不删除目录和文件。
- README 标题下方增加醒目说明：该原型已经过时，只保留历史评审参考；当前行为和视觉以生产前端为准。
- 原型页面顶部徽标中文改为“历史原型”，英文改为“Historical prototype”。
- 原型页面顶部说明中文表达“已由生产页面替代，仅供历史参考”，英文提供含义一致的翻译。
- 原型页面元描述与标题可以补充历史属性，但不能移除“不连接生产服务”的安全说明。
- 原型双语词典必须同时更新对应键，中文和英文结构继续一致。
- 除说明文字外，不修改原型布局、样式、模拟数据、交互、权限逻辑或测试。

### 13. i18n

- 正式首页布局与雷达动效不新增用户可见功能文案，因此不应为了 CSS 动画增加生产词典键。
- 历史原型新增或修改的可见提示必须同时提供简体中文与 English。
- 产品名、房间号、节点随机值和 CSS 内部变量不翻译。
- React 生产组件中不得新增硬编码用户文案。

### 14. 实施顺序

1. 先调整首页主内容 DOM 顺序与桌面网格列，完成操作栏左置和雷达右置。

## Acceptance Criteria

### 首页布局

1. 视口宽度大于 900px 时，首页左侧为约 300px 操作栏，右侧为自适应雷达区。
2. 操作侧栏在真实 DOM 中位于雷达区域之前。
3. 桌面键盘焦点与屏幕阅读顺序先经过操作区相关控件，再进入后续页面内容。
4. 已建立身份时，左侧正确显示“我的房间／参与房间”。
5. 未建立身份时，左侧正确显示昵称设置卡。
6. 左侧操作卡在桌面双栏中垂直居中。
7. 雷达在右侧剩余空间中保持中心对齐，不被左栏覆盖。
8. 900px 及以下切换为单列，操作区在上，雷达在下。
9. 901px 附近无横向滚动、房间卡压缩、网格重叠或雷达零宽度。
10. 移动端创建、加入、进入、退出、解散及房间操作 Drawer 保持可用。
11. 首页顶栏、个人信息、通知、Modal 和页脚行为保持不变。

### 雷达波纹

12. 雷达继续显示四层圆环。
13. 波纹在浅色背景中明显强于当前版本，但不盖过中心头像或节点。
14. 单圈从较深状态向外扩散并逐渐变浅，最终消失。
15. 四圈在同一时刻呈现强、弱、强、弱的层级感。
16. 所有波纹使用同一青绿色色相。
17. 波纹边框仍为轻量圆环，没有实心色带、彩虹渐变或霓虹效果。
18. 波纹周期仍约为五秒，相邻圈错开约 1.25 秒。
19. 波纹动画只改变透明度和缩放，不触发布局跳动。

### 节点呼吸

20. 五个周围房间圆在稳定可见阶段持续轻微呼吸。
21. 呼吸缩放峰值约为 1.06，不出现明显放大跳动。
22. 五个节点周期位于 2.8～4.2 秒范围并明显错峰。
23. 节点房间号标签不随圆形头像缩放。
24. 中心用户头像不呼吸。
25. 呼吸峰值显示低透明度、与节点颜色一致的光晕。
26. 节点进入和退出时不播放呼吸，原有进入／退出动画正常。
27. 节点替换后新节点继续使用稳定槽位节奏，不要求刷新页面。
28. 动效没有新增 React 定时器、逐帧状态更新或渲染循环。

### 减少动态效果

29. 开启系统减少动态效果后，波纹扩散停止。
30. 开启系统减少动态效果后，节点呼吸、进入和退出动画停止。
31. 动画停止后仍显示四层静态深浅交替圆环。

## Testing Decisions

- 本阶段主要修改 DOM 排列、CSS 网格和 CSS 动效，不包含业务规则、鉴权、支付或复杂状态转换；按照项目规则不新增 TDD 或组件内部实现测试。
- 现有雷达节点生成与布局算法不修改，因此本阶段不为随机位置、颜色或生命周期补写单元测试。
- 继续运行现有前端测试，确保文件业务逻辑与简体中文／英文词典完整性没有回归。
- 运行 TypeScript 编译与生产构建，用于检查 JSX 顺序调整、内联 CSS 自定义属性类型、未使用导入和打包问题。
- 不使用 Playwright。浏览器布局与动画采用人工验收。
- 桌面人工验收建议使用约 1440×900：检查 300px 左栏、右侧雷达、垂直居中、四层波纹和五节点错峰呼吸。
- 断点人工验收覆盖 899px、900px 和 901px：检查单列切换、顺序、横向滚动与节点重排。
- 移动人工验收建议使用约 390×844：检查操作区在上、雷达在下、房间操作 Drawer 和页面总滚动。
- 动画人工验收至少持续观察十秒：确认波纹深浅扩散连续，五个节点不是同步缩放，标签保持稳定。
- 节点生命周期验收至少持续观察一个节点替换：确认退出阶段停止呼吸，新节点进入后再开始呼吸。
- 减少动态效果人工验收：开启系统或浏览器模拟偏好后，确认持续动画全部停止且静态四环仍可见。
- 历史原型人工验收分别切换中文与英文，确认过时提示正确且页面其他演示仍可打开。
- 人工验收期间检查浏览器控制台，不能出现新增运行时错误或警告。

## Further Notes

- “左侧对应”表示首页左侧为房间入口，进入后房间页左侧为成员上下文；两者不要求使用相同宽度。
- 首页左栏最终宽度约 300px，覆盖最初 320～340px 推荐。
- “深浅交替”表示同一青绿色的透明度强弱，不表示多色雷达。
- 波纹实际可见度取决于边框颜色透明度与动画 `opacity` 的乘积。实现者必须在真实浅色背景上人工观察，不能只按单个数值判断。
- “呼吸”只作用于节点圆形头像内层。若把动画放在节点外层，会覆盖现有进入／退出 `transform`，属于错误实现。
- 节点呼吸节奏应稳定派生，不能在每次 React 渲染中调用随机数，否则任意状态更新都会让动画周期跳变。
- 历史原型标记不代表删除或迁移；它仍可用于理解早期讨论，但不再是生产验收基准。
- 本 PRD 获得用户明确批准后才能开始修改生产代码。
