# 文件列表布局细节优化 PRD

## Problem Statement

统一文件列表上线后，顶部数量、内容区宽度和搜索框仍有视觉问题：四处数量以行内 Badge 显示，不符合右上角角标预期；中心文件区存在最小宽度约束，窄窗口下右侧操作被裁切；`Input.Search` 生成独立搜索按钮区域，出现分隔边框。

## Solution

将全部、共享、私密、回收站四处数量改为对应标签右上角角标。放宽房间中心工作区收缩能力，取消文件行和筛选控件不必要的固定最小宽度，保证右侧操作在可用空间内显示。将搜索组件改为普通 Ant Design Input，使用左侧搜索图标和连续边框，保留清除和实时查询。

## User Stories

1. 作为房间成员，我希望在全部、共享、私密三个类型标签右上角看到数量，以便快速知道各类型文件数量。
2. 作为房间成员，我希望在回收站标签右上角看到数量，以便快速识别是否有回收站文件。
3. 作为房间成员，我希望数量角标不改变标签文字对齐和点击区域，以便切换操作稳定。
4. 作为房间成员，我希望文件数量为 0 时角标仍显示，以便确认当前筛选确实没有文件。
5. 作为房间成员，我希望回收站数量使用警示色，而普通文件数量使用中性色，以便区分待处理内容。
6. 作为房间成员，我希望在窄桌面窗口中仍能看到文件行右侧的主要操作和更多菜单，以便不需要横向滚动。
7. 作为房间成员，我希望文件名空间不足时省略，而不是把操作区推出可视区域。
8. 作为房间成员，我希望筛选控件在空间不足时换行，且顺序保持可理解。
9. 作为房间成员，我希望搜索框是一个连续的输入区域，不出现突兀的独立搜索按钮分隔。
10. 作为房间成员，我希望搜索框左侧有搜索图标，右侧可清除内容，以便识别和操作。
11. 作为房间成员，我希望搜索输入行为保持实时查询，不改变现有筛选结果逻辑。
12. 作为深色主题用户，我希望角标、搜索框、文件区收缩后的背景和边框与深色主题协调。
13. 作为移动端用户，我希望角标不会遮挡标签文字，搜索框仍能占满可用宽度。
14. 作为键盘用户，我希望搜索框、Tabs 和筛选控件仍保持焦点可见和可操作。

## Implementation Decisions

### 1. 数量角标

- 文件类型 Tabs 的全部、共享、私密数量使用相对定位容器，在标签右上角显示 Ant Design Badge。
- 不要把 Badge 直接拼接在普通文本后面；每个 Tab 的 label 必须使用一个 `position: relative` 的包裹元素，包裹元素内包含图标、文字和 Badge。
- Badge 的定位基准必须是当前 Tab label 包裹元素，而不是整个 Tabs 容器；使用 `position: absolute` 放在包裹元素右上方。
- Badge 不得覆盖文字：右侧预留足够 padding，长中文和英文标签都要完整显示。
- 数量角标不得参与标签主文案的普通行高计算，避免导致 Tab 高度变化。
- 文件数量角标使用主题中性色或当前主题色；当前选中项使用更明显的主题对比色。
- 回收站数量角标使用警示红色；数量为 0 时仍渲染。
- 角标最大宽度和长数字显示需稳定；超过 99 时使用 Ant Design 紧凑显示，不撑开 Tab。
- 角标在桌面和移动端均显示在右上角；移动端缩小尺寸但不隐藏。
- 不要修改数量来源：文件类型数量继续来自 `fileCounts`，回收站数量继续来自 `trashCountQuery`。
- 不要把四个数量合并为一个总数，也不要在切换 Tab 时隐藏非当前类型角标。

### 2. 房间工作区宽度

- 房间中心工作区列允许从 0 开始收缩，不能继续使用会阻止收缩的固定最小宽度。
- 桌面工作区网格中心列使用 `minmax(0, 1fr)`；不得写成 `minmax(540px, 1fr)` 或其他固定最小值。
- 成员区和聊天区的既有列宽不改变；中心区承担剩余空间。
- 文件列表根容器、统一列表、文件主信息列继续设置 `min-width: 0`。
- 所有作为 Grid/Flex 子项的中间容器都检查 `min-width: 0`，尤其是 Tabs、筛选工具栏、统一列表和文件主信息列。
- 文件行操作区使用内容自适应宽度；空间不足时文件主信息优先省略，操作按钮不能被推出容器。
- 文件行右侧操作区不得使用 `width: 100%`、固定超大 `min-width` 或会强制父级撑宽的长文案。
- 筛选工具栏在桌面宽度不足时换行；搜索框可以独占下一行，其余筛选控件保持同一顺序。
- 换行顺序固定为：第一行范围切换和身份/排序/批量控件，第二行搜索框；移动端顺序为范围切换、搜索框、身份、排序、批量。
- 禁止出现页面级横向滚动条；文件区只允许必要的纵向滚动。
- 移动端维持现有单列工作区和文件行布局，不因桌面收缩规则破坏按钮点击区域。

### 3. 搜索框

- 将 Ant Design `Input.Search` 替换为普通 `Input`。
- 只替换视觉组件，不修改 `search` state、`onChange` 回调、React Query key 或 API 参数名。
- 左侧使用 Lucide Search 图标作为 prefix；不得渲染独立的搜索提交按钮。
- 组件结构应只有一个 Ant Design Input 外壳；不能再额外嵌套一个原生 input、button 或自定义搜索框。
- 保留 `allowClear`，清除时将搜索值设为空并触发当前列表查询。
- 输入值仍直接绑定现有 `search` 状态，查询 key 和后端 `search` 参数不变。
- 搜索框在桌面端可伸缩，在中等宽度独占一行，在移动端独占整行。
- 浅色和深色主题使用现有 Ant Design ConfigProvider 和主题变量；聚焦边框必须清晰。
- 搜索图标仅用于视觉提示，必须设置 `aria-hidden="true"`；Input 必须保留现有 aria-label 和 placeholder 翻译。

### 4. 不变内容

- 不修改文件列表 API、`items/total/counts` 返回结构和查询参数。
- 不修改共享/私密权限、capabilities、批量操作规则。
- 不修改文件动态、回收站、上传、下载和 SSE 刷新逻辑。
- 不新增数据库字段，不做数据迁移。
- 所有现有中文/英文文案和筛选语义保持不变，除非新增 aria 标签需要翻译键。

## Testing Decisions

- 前端构建测试：执行 `make web`，确保 TypeScript 和 Vite 构建通过。
- 组件行为测试：验证四处数量角标均显示，0 值不隐藏，回收站使用警示样式。
- 响应式测试：至少检查宽桌面、窄桌面、移动宽度；确认无页面横向溢出，文件行右侧主要操作和更多菜单可见。
- 搜索测试：验证输入、清除、焦点状态和实时查询 key 不变。
- 主题测试：验证浅色和深色下 Badge、Input、Tabs、筛选工具栏均有可读对比度。
- 国际化测试：沿用现有双语词典一致性测试。
- 静态检查：执行 `git diff --check`。

### 低智能模型验收清单

- [ ] `FileWorkspace` 中四个数量仍来自原有查询状态，没有新增重复请求。
- [ ] 全部、共享、私密、回收站四个角标均位于各自标签右上方，而不是文字右侧普通流布局。
- [ ] 数量为 0 时仍显示角标；回收站角标仍为警示红色。
- [ ] 中文和英文切换后，角标不覆盖 Tab 文字，英文长文案不造成横向溢出。
- [ ] `RoomWorkspace` 中心列不再使用固定 540px 最小宽度。
- [ ] 1580px、1200px、900px、768px、430px 宽度下没有页面级横向滚动条。
- [ ] 文件行右侧下载/接收和更多菜单在窄桌面仍完整可见。
- [ ] 搜索框只有一个连续边框，没有独立右侧搜索按钮分隔线。
- [ ] 搜索图标位于输入框左侧，清除按钮位于输入框右侧。
- [ ] 输入搜索文字仍会刷新相同的 `room-files` 查询；清除后恢复全部结果。
- [ ] 共享/私密文件权限、操作菜单、批量按钮行为未被改动。
- [ ] 浅色和深色模式均完成一次人工检查。

## Out of Scope

- 不改变文件列表接口和后端业务逻辑。
- 不改变文件行信息内容、权限菜单和批量操作规则。
- 不新增分页、文件预览或虚拟滚动。
- 不调整房间成员区、聊天区的业务和布局宽度。

## Further Notes

- 这是已完成文件列表重构后的视觉收口，适合由低智能模型按“角标 → 宽度 → 搜索框 → 响应式验证”顺序执行。
