# FileDock 房间一对一聊天 MVP PRD

状态：已批准，实施中

日期：2026-08-03

## Problem Statement

FileDock 一期已经支持匿名身份、房间成员、在线状态、共享／私密文件和实时 SSE，但房间右侧仍是聊天占位区。成员需要离开 FileDock 使用其他工具沟通文件用途、接收结果和协作安排，房间本身不能形成完整的即时协作闭环。

历史文档对聊天提出过文字、表情、图片、文件卡片、撤回、未读和已读等完整愿景。如果一次接入全部能力，会同时扩大聊天状态、文件权限、附件生命周期、全局通知和离线缓存范围。本阶段必须先交付边界清晰、可独立验收的一对一文字聊天 MVP，并为后续图片、文件引用和全局通知保留稳定扩展点。

## Solution

在现有房间工作区内直接实现生产级一对一文字聊天：成员主动选择同房间的另一名成员后，可发送纯文本、换行和 Unicode 表情。消息由 SQLite 持久化，通过现有全局 SSE 实时同步；历史使用游标分页；每个会话维护未读数量和服务端已读游标。

聊天支持复制、两分钟内撤回、撤回并编辑、仅自己删除以及转发给当前房间一个或多个成员。桌面界面参考微信的一对一聊天结构，使用左右消息气泡、头像、时间节点、顶部会话信息和固定输入区；移动端保持文件操作优先，聊天作为带未读数量的二级全屏界面。

当前会话顶部提供聊天记录入口，可查看、搜索并定位双方历史。聊天提醒只出现在当前房间页，不接入首页、其他房间、通知 Icon、系统通知或新的 SSE 通道。

## User Stories

1. 作为房间成员，我希望点击另一名成员后开始私聊，以便围绕当前房间协作。
2. 作为房间成员，我希望进入房间时不自动打开会话，以便未查看的消息不会被误标为已读。
3. 作为房间成员，我希望给离线但仍在房间中的成员发送消息，以便对方回来后继续查看。
4. 作为隐私敏感用户，我希望房主不能查看与自己无关的私聊，以便一对一消息保持私密。
5. 作为聊天用户，我希望发送纯文本、换行和 Unicode 表情，以便完成基础沟通。
6. 作为聊天用户，我希望用 `Enter` 发送、用 `Shift + Enter` 换行，以便快速输入。
7. 作为聊天用户，我希望纯空白消息不能发送，以便避免无意义记录。
8. 作为聊天用户，我希望单条消息有明确长度上限，以便粘贴异常内容时得到可理解提示。
9. 作为聊天用户，我希望发送失败时保留输入内容，以便修正或重试。
10. 作为聊天用户，我希望发送中、已发送、已读和发送失败状态清晰可见，以便了解消息状态。
11. 作为网络不稳定用户，我希望重试不会生成重复消息，以便历史记录保持准确。
12. 作为聊天用户，我希望新消息通过现有 SSE 立即出现，以便不依赖轮询。
13. 作为多标签页用户，我希望消息和已读状态在标签页之间同步，以便不同页面状态一致。
14. 作为聊天用户，我希望每个成员显示对应会话未读数，以便快速找到新消息。
15. 作为移动端用户，我希望聊天入口显示总未读数，以便文件主界面仍能提示新消息。
16. 作为正在阅读当前会话的用户，我希望前台可见时新消息自动标记已读，以便回执符合实际阅读状态。
17. 作为切到后台的用户，我希望消息不被自动标记已读，以便未读状态可信。
18. 作为消息发送者，我希望看到对方是否已读，以便判断是否需要继续提醒。
19. 作为聊天用户，我希望首次打开加载最近消息，以便快速看到当前上下文。
20. 作为聊天用户，我希望向上滚动加载更早消息，并保持当前阅读位置，以便历史不会跳动。
21. 作为有未读消息的用户，我希望首次打开定位到第一条未读消息，以便从未读位置开始阅读。
22. 作为正在查看旧消息的用户，我希望新消息不会强制把我拉到底部，以便当前阅读不被打断。
23. 作为聊天用户，我希望看到“有新消息”按钮，以便需要时快速回到底部。
24. 作为聊天用户，我希望消息按日期和时间节点分隔，以便理解上下文。
25. 作为桌面用户，我希望自己和对方的消息使用不同方向与颜色的气泡，以便快速区分。
26. 作为移动端用户，我希望聊天在二级全屏界面打开，以便有限屏幕仍以文件操作为主。
27. 作为键盘用户，我希望聊天菜单、输入框和历史面板可用键盘操作，以便无需鼠标。
28. 作为桌面用户，我希望右键消息打开操作菜单，以便快速执行常用操作。
29. 作为不熟悉右键的用户，我希望悬停时看到更多按钮，以便发现消息操作。
30. 作为触屏用户，我希望长按消息打开同一菜单，以便移动端也能使用消息操作。
31. 作为聊天用户，我希望复制可见消息正文，以便在其他位置使用。
32. 作为局域网 HTTP 用户，我希望复制继续使用兼容回退，以便不受安全上下文限制。
33. 作为误发消息的用户，我希望在两分钟内撤回，以便双方不再看到错误正文。
34. 作为误发消息的用户，我希望撤回并编辑，以便修正后重新发送。
35. 作为已有草稿的用户，我希望撤回并编辑前确认是否替换，以便草稿不会意外丢失。
36. 作为消息接收者，我希望撤回后看到明确占位，以便理解消息序列没有无故断开。
37. 作为聊天用户，我希望删除只影响自己的历史，以便整理界面而不改变对方记录。
38. 作为聊天用户，我希望删除前看到“仅自己删除”的提示，以便理解操作范围。
39. 作为聊天用户，我希望把可见消息转发给当前房间一个或多个成员，以便复用信息。
40. 作为隐私敏感用户，我希望转发不暴露原消息发送者，以便原会话关系不泄漏。
41. 作为聊天用户，我希望已撤回或已删除的消息不能转发，以便不可见内容不会被恢复。
42. 作为聊天用户，我希望历史面板只查看当前双方记录，以便不会混入其他私聊。
43. 作为聊天用户，我希望搜索中文、英文和 Unicode 表情正文，以便快速找到旧消息。
44. 作为聊天用户，我希望搜索不返回已撤回或自己已删除的消息，以便结果与可见历史一致。
45. 作为聊天用户，我希望点击搜索结果定位并高亮原消息，以便恢复上下文。
46. 作为主动退出成员，我希望退出后不能继续访问聊天，以便房间权限立即生效。
47. 作为重新加入成员，我希望同一身份恢复原私聊历史，以便协作可以续接。
48. 作为被踢成员，我希望聊天访问立即终止且不能恢复，以便房主移除操作有效。
49. 作为房间成员，我希望房间销毁后聊天数据随房间清理，以便不保留孤立私聊。
50. 作为中英文用户，我希望聊天文案、状态、菜单和错误都有完整双语，以便切换语言后仍可使用。

## Implementation Decisions

### 1. 阶段边界

- 本阶段只实现同一房间成员之间的一对一文字聊天。
- 不实现群聊、跨房间聊天、好友关系、语音、视频、通话、富文本或 Markdown。
- 纯文本按普通文本节点渲染并保留换行；不得解析用户 HTML，不自动执行或内嵌任何内容。
- Unicode 表情视为普通文本，不引入大型表情包、贴纸资源或第三方表情服务。
- 不实现图片消息、私密文件卡片、共享文件引用、附件上传或附件生命周期。
- 不实现 IndexedDB 消息缓存、离线发送队列或刷新后草稿恢复。
- 不接入全局通知中心、首页通知、其他房间提醒、通知 Icon 或浏览器系统通知。
- 继续复用现有用户级全局 SSE，不新增房间 SSE 或第二条长连接。

### 2. 后端模块边界

新增独立聊天领域模块，并保持现有分层：

1. 聊天模型负责会话、消息、已读游标和用户级删除记录。
2. 聊天服务负责权限、验证、幂等、序号、分页、搜索、状态转换、限速和 SSE 投影。
3. 聊天业务层只负责服务结果到 DTO 的转换，不拼接用户消息。
4. 聊天 API 负责请求解析、身份提取、查询参数边界和统一响应。
5. 路由与依赖注入把聊天模块接入现有服务器、数据库、SSE Hub 和限速器。
6. 生命周期清理显式删除聊天关联数据，并把数量纳入清理测试；不得只依赖未验证的级联行为。

聊天服务是深模块。前端或 API 不得自行拼接数据库查询、推导越权结果或直接操作 SSE Hub。

### 3. 数据模型

#### 3.1 一对一会话

每个房间、每对用户最多一条会话记录：

- 使用 ULID 作为会话 ID。
- 保存房间 ID、排序后的用户 A ID、用户 B ID、当前最后序号、创建时间和更新时间。
- 用户 A／B必须按用户 ID稳定排序，避免同一对成员出现正反两条会话。
- 对房间 ID、用户 A ID、用户 B ID建立唯一约束。
- 会话在第一条消息写入时惰性创建；只打开空会话不写数据库。
- 会话记录不授予权限；每次 API 调用仍以当前房间成员状态为准。

#### 3.2 聊天消息

每条消息保存：

- ULID 消息 ID。
- 会话 ID与房间 ID。
- 会话内单调递增序号。
- 发送者用户 ID、接收者用户 ID和发送者昵称快照。
- 客户端消息 ID，用于幂等。
- 纯文本正文。
- 是否为转发消息。
- 创建时间和可空撤回时间。

约束与索引：

- 会话 ID + 序号唯一。
- 房间 ID + 发送者 ID + 客户端消息 ID + 接收者 ID唯一。
- 为会话历史的序号倒序查询、接收者未读查询和房间清理建立索引。
- 正文最长 2000 个 Unicode 字符；数据库保存规范化后的最终正文。
- 撤回后保留消息 ID、参与者、序号、发送者昵称快照和时间，但把正文清空并写入撤回时间。
- 转发消息只保存转发后的新正文和转发标记，不保存或暴露原发送者关系。

#### 3.3 已读状态

每个会话、每个参与者最多一条已读状态：

- 复合唯一键为会话 ID + 用户 ID。
- 保存最后已读序号、最后已读时间和更新时间。
- 游标只允许单调增加，不允许回退。
- 服务端把客户端提交值限制到该会话当前存在的最高序号，禁止伪造未来游标。
- 一条自己发送的消息是否已读，由对方最后已读序号是否大于等于该消息序号决定。

#### 3.4 用户级删除

每条消息、每个用户最多一条删除记录：

- 复合唯一键为消息 ID + 用户 ID。
- 保存删除时间。
- 删除记录只改变该用户的列表、搜索和未读统计，不修改消息本体，不推送给对方。
- 同一用户的其他标签页通过只发给本人的 SSE 删除事件同步。

### 4. 权限与隐私

- 发送、历史、搜索、已读、撤回、删除和转发都要求请求者当前是活动房间成员。
- 接收者必须是同一房间的另一名活动成员；允许接收者在线、暂离或离线，但不允许已退出、被踢或已销毁成员。
- 用户只能查询自己参与的会话；使用其他成员 ID、消息 ID或会话 ID不得绕过该规则。
- 房主与普通成员使用相同聊天隐私规则。房主无权查看、搜索、撤回或删除与自己无关的私聊。
- 主动退出后，所有聊天 API立即返回成员权限错误；同一用户身份重新加入后恢复原会话访问。
- 被踢成员继续受到现有禁止重新加入规则约束，因此不能恢复聊天。
- 房间进入销毁流程后禁止发送、转发、撤回和已读写入；是否允许短暂只读不新增特殊规则，统一按现有活动房间校验处理。
- API 的未找到与无权限响应不得泄漏目标消息是否真实存在。

### 5. 内容验证与发送限速

- 请求正文先把 Windows 换行规范化为 `\n`，再去除首尾 Unicode 空白。
- 规范化后为空时拒绝。
- 使用 Unicode 字符数量而不是 UTF-8 字节数计算长度，最大 2000。
- 保留正文内部空格与换行；不自动修改用户文字。
- 每个用户每个房间同时执行两个内存限速窗口：10 条／10 秒、60 条／分钟。
- 普通发送消耗 1 个额度；转发给 N 个成员消耗 N 个额度。
- 多人转发必须先一次性检查并消费所需额度；额度不足时整个转发失败，不创建部分消息。
- 限速器需要支持按数量原子消费，键使用房间 ID与用户 ID，不使用 IP 作为聊天主限速键。
- 进程重启后内存限速重置，符合当前开发阶段其他接口限速方式。
- 超限返回聊天专用双语错误；前端保留正文或转发选择。

### 6. 幂等与消息序号

- 每次普通发送由前端生成客户端消息 ID。
- 同一发送者、房间、客户端消息 ID和接收者的重复请求返回原消息，不新增记录、不重复推进序号、不重复发送创建事件。
- 转发请求携带一个幂等键；对每个目标接收者使用同一键配合接收者唯一约束。
- 多人转发在一个数据库事务内完成：任一接收者无效、限速失败或写入失败时全部回滚。
- 会话序号在同一事务内原子递增，然后写入消息；不得通过“先查最大值再无锁加一”实现。
- SQLite 当前只有一个写连接，但仍必须依赖事务与唯一约束保证正确性。
- REST 响应和 SSE 可能以任意顺序到达，前端必须按消息 ID／客户端消息 ID合并，而不是追加两次。

### 7. API 契约

所有接口使用现有会话 Cookie、统一响应格式和 `Accept-Language`。

#### 7.1 会话摘要

`GET /api/v1/rooms/:code/chat/conversations`

- 返回当前活动成员中除自己外的会话摘要。
- 每项包含成员 ID、显示名、角色、在线状态、未读数量、最后消息时间和安全预览。
- 没有消息的成员也返回，未读为 0，最后消息字段为空。
- 安全预览不返回已撤回正文或当前用户已删除的正文。
- 未读数量超过 99 时 API仍返回真实数字，前端负责显示 `99+`。

#### 7.2 获取消息历史

`GET /api/v1/rooms/:code/chat/conversations/:peerUserId/messages`

- 默认返回最近 30 条，响应按序号升序排列供界面直接渲染。
- `beforeSequence` 为排他游标，用于加载更早消息。
- `aroundSequence` 用于搜索结果定位，返回目标前后合计最多 30 条上下文。
- `beforeSequence` 与 `aroundSequence` 不得同时出现。
- `limit` 默认 30，最大 100。
- 返回上一页游标、是否还有更早消息、当前用户已读游标和对方已读游标。
- 排除当前用户已删除的消息；撤回消息返回无正文占位投影。

#### 7.3 发送普通消息

`POST /api/v1/rooms/:code/chat/messages`

请求包含客户端消息 ID、单个接收者用户 ID和正文。响应返回完整消息投影，包括消息 ID、客户端消息 ID、双方用户 ID、发送者昵称快照、正文、转发标记、序号、创建时间、撤回截止时间和当前操作能力。

#### 7.4 标记已读

`POST /api/v1/rooms/:code/chat/conversations/:peerUserId/read`

- 请求包含最后已读序号。
- 幂等且单调；重复或更小游标直接返回当前状态。
- 服务端限制到会话最高序号。
- 成功后向会话双方推送已读更新事件。

#### 7.5 撤回

`POST /api/v1/rooms/:code/chat/messages/:messageId/recall`

- 只有发送者可调用。
- 允许条件为服务端当前时间不晚于创建时间加 120 秒；边界时刻仍允许。
- 已撤回、已超过时限、请求者已退出或消息不属于当前会话时拒绝。
- 成功后清空正文，返回撤回投影并向双方推送撤回事件。
- “撤回并编辑”不增加后端接口；前端在调用前保存原正文，成功后放回输入框。

#### 7.6 仅自己删除

`DELETE /api/v1/rooms/:code/chat/messages/:messageId`

- 请求者必须是消息参与者。
- 重复删除幂等成功。
- 写入用户级删除记录，不修改对方数据。
- 向当前用户所有 SSE 连接推送本地删除事件。

#### 7.7 转发

`POST /api/v1/rooms/:code/chat/messages/:messageId/forward`

- 请求包含幂等键和一个或多个接收者用户 ID。
- 接收者去重后必须至少 1 人，最多为房间成员上限减 1，不允许包含自己。
- 所有接收者必须是当前房间活动成员。
- 源消息必须对当前用户可见、未撤回、未被当前用户删除且正文非空。
- 每个接收者生成独立消息；新发送者为当前用户，正文复制，转发标记为真。
- 响应返回创建或幂等命中的消息列表。
- 不在响应和新消息中暴露源消息 ID、原发送者或原会话。

#### 7.8 当前会话历史搜索

`GET /api/v1/rooms/:code/chat/conversations/:peerUserId/search`

- `query` 去除首尾空白后长度为 1～100 个 Unicode 字符。
- `beforeSequence` 为排他游标，默认返回最新匹配。
- `limit` 默认 30，最大 100。
- 只搜索当前用户与指定成员的当前房间会话。
- 排除撤回消息和当前用户已删除消息。
- 使用 SQLite 参数化子串查询；必须转义 `%`、`_` 和转义符本身，禁止拼接 SQL。
- English 使用 SQLite 可提供的大小写不敏感匹配；中文和表情按原字符子串匹配。
- 本阶段不引入 FTS 虚拟表。
- 结果包含消息 ID、序号、发送者显示名、正文安全摘要和创建时间。

### 8. 后端错误与国际化

新增聊天专用错误定义，至少区分：

- 消息正文无效或过长。
- 接收者列表无效。
- 消息不存在或当前用户不可访问。
- 消息状态冲突。
- 撤回已超时。
- 聊天发送频率超限。

业务服务只返回错误码、翻译参数和内部原因，不直接返回中文或英文句子。每个新错误码必须同时补齐后端 `zh-CN` 与 `en` 词典，并通过错误定义与词典完整性测试。

### 9. SSE 事件

继续使用现有事件外壳和用户级 SSE Hub。新增：

1. `chat.message_created`：发送给发送者与接收者，携带房间号、消息投影和会话对端 ID。
2. `chat.message_recalled`：发送给双方，携带房间号、消息 ID、序号、撤回时间和执行者 ID，不携带原正文。
3. `chat.message_deleted_local`：只发送给执行删除的用户，携带房间号和消息 ID。
4. `chat.read_updated`：发送给双方，携带房间号、已读用户 ID和最后已读序号。

事件处理规则：

- 事件只投递给消息参与者，不能广播给房间其他成员。
- 前端先按 `roomCode` 过滤，再更新对应会话。
- 创建事件按消息 ID去重；撤回与删除事件必须能作用于尚未加载到当前页的消息摘要。
- 全局流断线重连后，现有查询失效机制重新获取会话摘要和已打开会话；本阶段不实现聊天事件持久化补发。
- 事件仅用于加速同步，SQLite 与 REST 查询仍是事实来源。

### 10. 撤回、撤回并编辑、删除状态规则

#### 10.1 撤回

- 自己发送且仍在 120 秒内：菜单显示“撤回”和“撤回并编辑”。
- 超过 120 秒：两个操作立即从菜单移除，服务端仍做最终校验。
- 收到的消息：不显示撤回操作。
- 撤回后双方显示本地化占位；发送者显示“你撤回了一条消息”，接收者显示“某某撤回了一条消息”。
- 撤回占位只允许执行“删除”，不允许复制、转发或再次撤回。

#### 10.2 撤回并编辑

1. 前端在调用接口前保存原正文。
2. 当前会话草稿为空时直接调用撤回。
3. 草稿非空时先询问是否替换；取消时不调用接口。
4. 服务端确认撤回成功后，把保存的原正文写入该会话草稿并聚焦输入框。
5. 用户修改后再次发送会生成全新消息 ID和序号，不恢复原消息。
6. 撤回失败时保留现有草稿和原消息，不自动填充。

#### 10.3 仅自己删除

- 可删除自己发送或接收的普通消息，也可删除撤回占位。
- 删除前明确提示“只会从你的聊天记录中删除，对方仍可查看”。
- 删除后不提供恢复或撤销入口。
- 对方的消息、未读、搜索和已读状态不因本地删除改变。

### 11. 转发规则

- 普通可见文字消息均可转发，包括自己发送和收到的消息。
- 转发选择器列出当前房间活动成员并排除自己，允许多选。
- 选择器显示头像、名称和在线状态；离线但活动的成员可以选择。
- 提交期间禁用重复提交，失败时保留选择。
- 新消息显示本地化“转发”标识，但不显示源用户、源消息 ID或源会话。
- 原消息后来撤回或被删除，不修改已经生成的转发消息。
- 转发消息本身可以再次复制、撤回、撤回并编辑、转发或仅自己删除，规则与普通消息相同。

### 12. 前端状态与查询

前端聊天状态分为服务端状态和页面临时状态：

- 服务端状态使用现有查询库管理：会话摘要、历史分页、搜索结果和已读游标。
- 页面临时状态包括当前成员、每会话内存草稿、右键菜单位置、转发选择、历史面板状态、滚动锚点和发送失败项。
- 不把服务端消息复制到新的全局状态库；查询缓存是服务端状态的唯一前端副本。
- 每个房间维护一个当前页面生命周期内的草稿映射，键为对端用户 ID；切换成员不丢草稿，刷新页面清空。
- 发送时先插入带客户端消息 ID的乐观消息；REST 或 SSE 返回后合并为服务端消息。
- 失败消息保留正文和重试入口；重试继续使用相同客户端消息 ID，依赖服务端幂等。
- 收到聊天 SSE 后更新会话摘要与未读，必要时失效对应历史查询；不得失效所有无关文件查询。

可独立测试的纯逻辑模块至少包括：

- 消息操作能力计算。
- 未读与已读状态合并。
- REST／SSE／乐观消息去重。
- 新消息是否自动滚动的判断。
- 日期分组、时间节点和未读分界线计算。

### 13. 桌面聊天界面

- 替换房间右侧占位区，不新建独立原型。
- 未选择成员时显示轻量空状态和“从成员列表选择一位成员开始聊天”。
- 点击成员行打开会话；踢人按钮等管理操作必须阻止事件冒泡，不能误切换聊天。
- 当前成员行高亮，并显示该会话未读徽标。
- 聊天顶部显示返回／关闭入口、成员头像、显示名、在线状态和聊天记录 Icon。
- 不显示语音、视频、电话、截图、文件夹或其他未实现按钮。
- 消息区使用浅灰背景；收到消息左侧灰色气泡，自己消息右侧 FileDock 品牌绿色气泡。
- 双方显示稳定头像；消息正文使用安全文本渲染并保留换行。
- 连续消息减少垂直间距，但不得因视觉合并隐藏消息边界或右键命中区域。
- 时间节点居中显示；按日期分隔，不为每条消息重复完整时间。
- 自己消息显示发送状态；失败状态提供重试。
- 输入区固定在底部，支持多行输入、Unicode 表情入口、字符计数临界提示和发送按钮。
- `Enter` 发送，`Shift + Enter` 换行；输入法组合过程中按 Enter 不得误发送。
- 空消息、发送中重复点击和超长消息禁用发送。

### 14. 消息菜单

- 桌面右键消息气泡打开自定义菜单，并阻止该消息区域的浏览器原生菜单。
- 桌面悬停或键盘聚焦时显示“更多”按钮，点击打开同一菜单。
- 移动端长按约 500 毫秒打开；移动距离超过约 10 像素时取消长按，避免滚动误触。
- 菜单支持方向键、Enter、Escape、点击外部关闭和焦点返回。
- 复制使用现有兼容复制能力，局域网 HTTP 下使用同步回退。
- 收到的普通消息：复制、转发、删除。
- 自己发送且可撤回的普通消息：复制、撤回、撤回并编辑、转发、删除。
- 自己发送但撤回超时的普通消息：复制、转发、删除。
- 撤回占位：仅删除。
- 删除和撤回显示二次确认；转发通过成员选择器确认。

### 15. 历史分页与滚动

- 打开会话先加载最近 30 条。
- 有未读时定位第一条未读并显示未读分界线；无未读时定位底部。
- 向上触顶加载更早 30 条，使用加载前后的滚动高度差恢复视口。
- 距离底部在约 80 像素以内视为“靠近底部”；此时新消息自动滚动。
- 不靠近底部时保持位置并显示“有新消息”按钮及数量。
- 点击按钮滚到底部；减少动态效果开启时使用立即滚动，不使用平滑动画。
- 切换会话分别保存当前页面生命周期内的滚动位置；刷新后无需恢复。
- 消息撤回或删除导致高度变化时尽量保持当前锚点，不强制回到底部。

### 16. 已读触发条件

同时满足以下条件才调用已读接口：

1. 已选择具体会话。
2. 浏览器 `document.visibilityState` 为 `visible`。
3. 窗口拥有焦点。
4. 对应消息已经加载并进入当前会话可读范围。

实现要求：

- 初次打开会话后提交当前最高可读序号。
- 新消息在当前会话到达且页面前台时推进游标。
- `visibilitychange`、`focus` 和会话切换时重新判断。
- 读取请求合并或短暂防抖，避免每条消息产生重复请求。
- 游标只增不减；失败时保留未读，下一次条件满足时重试。
- 已读事件更新发送者消息状态和同一用户其他标签页。

### 17. 新消息提醒范围

- 当前房间、当前会话、页面前台：追加消息并标记已读。
- 当前房间但其他会话：对应成员未读数增加，不弹顶部临时消息。
- 手机文件主界面：聊天入口显示所有会话未读总和。
- 首页、其他房间页和通知 Icon不显示聊天记录或未读。
- 不调用 Web Notification API，不申请浏览器通知权限。

### 18. 移动端

- 小屏继续默认显示文件工作区，不把文件、聊天、成员改成三个等权 Tab。
- 房间顶栏增加聊天入口，并显示总未读数。
- 点击入口先显示成员会话列表；选择成员后进入全屏聊天。
- 全屏聊天顶部提供返回会话列表、成员信息和聊天记录 Icon。
- 消息气泡、长按菜单、历史面板、输入框和软键盘区域不得产生横向滚动。
- 输入框跟随可视视口，不能被软键盘永久遮挡。
- 返回文件区时上传下载继续运行，当前页面内聊天草稿保留。
- 真机验收至少覆盖一台局域网手机浏览器。

### 19. 历史记录与搜索界面

- 当前会话顶部提供带无障碍名称的聊天记录 Icon。
- 桌面打开侧边抽屉；移动端打开全屏历史页面。
- 默认按时间倒序展示当前双方历史，可继续分页。
- 搜索输入防抖约 300 毫秒；空查询恢复普通历史。
- 显示搜索中、无结果、失败和重试状态。
- 每个结果显示发送者、正文摘要和时间，不显示其他会话信息。
- 点击结果关闭历史面板，调用 `aroundSequence` 获取上下文，定位并短暂高亮目标消息。
- 如果目标在点击到加载之间被撤回或本地删除，显示双语“消息已不可用”提示，不泄漏原正文。

### 20. 房间生命周期与清理

- 主动退出立即终止聊天 API访问，但不删除消息、已读游标或用户级删除记录。
- 同一用户重新加入后，原会话与历史重新可见，仍遵守自己的删除记录。
- 踢出沿用现有永久禁止重新加入规则。
- 房间进入销毁阶段时，前端聊天输入和消息动作禁用。
- 房间最终清理时，按依赖顺序删除消息删除记录、已读状态、消息和会话。
- 清理失败必须进入现有重试／失败机制；聊天数据未清完时不能把清理任务标记成功。
- 清理测试增加聊天关联计数与重复执行幂等验证。

### 21. 实施顺序

按以下任务顺序实施，后一步不得绕过前一步的契约：

1. 定义聊天状态常量、数据模型、约束、索引和迁移测试。
2. 增加聊天错误码及中英文后端词典，先通过完整性测试。
3. 实现聊天服务的成员校验、会话惰性创建、幂等发送、序号和限速。
4. 实现历史分页、会话摘要、已读游标、撤回、本地删除、多人转发和搜索，并补业务回归测试。
5. 接入生命周期清理及其失败／重试测试。
6. 增加 DTO、业务层、API、路由、依赖注入和聊天 SSE 事件。
7. 增加前端聊天领域类型、API函数、查询逻辑、SSE 去重和纯逻辑测试。
8. 替换桌面聊天占位区，实现成员切换、消息列表、输入、状态、滚动和右键菜单。
9. 实现撤回并编辑、转发选择器、仅自己删除和确认交互。
10. 实现历史抽屉、搜索、上下文定位和高亮。
11. 实现移动端会话列表、全屏聊天、长按菜单和软键盘适配。
12. 补齐全部中英文前端文案，运行自动质量门禁，再交给用户手动验收。

## Acceptance Criteria

1. 活动房间成员可以与同房间另一名活动成员建立一对一文字会话。
2. 房主不能查看与自己无关的聊天。
3. 非成员、已退出成员和被踢成员不能使用聊天 API。
4. 同一身份主动退出再加入后可恢复历史。
5. 纯文本、换行和 Unicode 表情正确保存、加载与实时推送。
6. 空白或超过 2000 个 Unicode 字符的消息被后端拒绝并返回双语错误。
7. 发送限速按用户和房间同时满足 10 条／10 秒与 60 条／分钟。
8. 重复客户端消息 ID不产生重复消息或重复序号。
9. REST 与 SSE 任意到达顺序不会在界面产生重复消息。
10. 初始历史加载 30 条，向上分页保持视口稳定。
11. 第一条未读定位、未读分界线、新消息按钮和底部自动滚动符合规格。
12. 页面后台、隐藏或未打开会话时不自动标记已读。
13. 已读游标单调并通过 SSE 更新发送者消息状态。
14. 进入房间不自动选择会话或清除未读。
15. 两分钟内发送者可撤回，边界允许；超时或非发送者不能撤回。
16. 撤回清空服务端正文，双方只看到本地化占位，搜索不能找到原文。
17. 撤回并编辑在成功后恢复原正文到输入框，已有草稿时先确认。
18. 本地删除只影响当前用户，对方记录不变，当前用户搜索和历史不再返回。
19. 转发只允许当前房间一个或多个活动成员，并以事务方式全部成功或全部失败。
20. 转发消息不暴露原发送者、原消息或原会话。
21. 桌面右键、悬停更多按钮、键盘菜单和移动端长按使用同一能力规则。
22. 局域网 HTTP 地址下复制消息正文仍可用兼容回退。
23. 桌面聊天视觉具有左右气泡、头像、时间节点、顶部成员信息和固定输入区。
24. 移动端保持文件优先，聊天从带未读数量的入口进入全屏界面。
25. 当前会话历史可以查看、搜索、分页、定位和高亮。
26. 搜索不跨成员或房间，不返回撤回或当前用户已删除消息。
27. 聊天不会写入首页、其他房间页或通知 Icon，也不弹顶部临时消息。
28. 房间最终清理会删除所有聊天关联数据，失败时保留清理失败状态并可重试。
29. 所有新增前后端用户文案完整支持 `zh-CN` 与 `en`。
30. Go 全包测试、前端现有测试、TypeScript、生产构建和 `git diff --check` 全部通过。
31. 用户使用两个独立桌面会话和一个真实手机会话完成手动验收。

## Testing Decisions

### 测试原则

- 只测试外部可观察行为与业务不变量，不断言私有函数调用次数、具体 SQL 字符串或 DOM 内部结构。
- 不引入 Playwright、浏览器自动化、视觉快照或新的测试框架。
- 后端业务测试使用项目现有 SQLite 测试方式和真实事务，不使用只能证明 Mock 调用的浅测试。
- 前端只为去重、能力矩阵、未读合并、滚动决策和分组等纯逻辑补测试；普通按钮和 CSS 通过手动验收。

### 后端必须覆盖

1. 正常发送、Unicode、换行、空白和 2000 字符边界。
2. 非成员、退出、被踢、跨房间接收者和给自己发送的拒绝。
3. 房主不能访问其他两名成员的会话。
4. 离线活动成员可作为接收者。
5. 会话惰性创建与正反用户顺序唯一。
6. 并发或重复请求下客户端消息 ID幂等、序号唯一且单调。
7. 10 条／10 秒、60 条／分钟及多人转发按接收者数量消费额度。
8. 历史初始页、排他游标、最大限制、时间顺序和用户级删除过滤。
9. 已读游标推进、重复、回退、超过最高序号和 SSE 投递对象。
10. 119 秒、120 秒和 121 秒撤回边界；非发送者、已撤回和退出后的拒绝。
11. 撤回清空正文且搜索不再命中。
12. 本地删除幂等、只影响本人、对方仍可读取。
13. 多人转发正常、重复目标去重、任一无效全回滚、幂等重试和不泄漏源关系。
14. 搜索中文、English、表情、特殊通配字符、分页、隐私和删除／撤回过滤。
15. SSE 创建、撤回、本地删除、已读事件只发送给正确用户。
16. 主动退出再加入恢复历史，被踢用户不可恢复。
17. 房间清理删除聊天数据，重复清理幂等，清理失败不释放房间号。
18. 新错误码定义、HTTP 状态和中英文词典完整。

### 前端纯逻辑测试

1. 消息菜单能力矩阵。
2. 乐观消息、REST 和 SSE 按消息 ID／客户端消息 ID去重。
3. 未读数量与已读游标单调合并。
4. 靠近底部时自动滚动、查看旧消息时显示新消息按钮。
5. 日期分组、时间节点和第一条未读分界线。
6. 双语词典键一致且无空文案。

### 手动验收

- 会话 A、B使用两个独立桌面浏览器；会话 C使用同一局域网真实手机。
- 验证 A↔B 实时发送、离线后恢复、未读、已读、多标签同步和不自动打开会话。
- 验证 A不能查看 B↔C 内容，房主身份不改变隐私规则。
- 验证撤回、撤回并编辑、已有草稿确认、删除、复制和多人转发。
- 验证桌面右键／更多按钮、键盘操作和手机长按。
- 验证历史分页、中文／英文／表情搜索、定位高亮和不可用结果。
- 验证主动退出再加入、踢出、解散和清理后的状态。
- 验证中文、English、桌面、窄屏、手机软键盘和减少动态效果。

## Out of Scope

- 群聊、聊天室或广播消息。
- 跨房间聊天、好友系统、联系人系统或私信首页。
- 图片、视频、音频、语音、贴纸、文件附件和共享文件引用。
- 富文本、Markdown、代码高亮、链接预览或网页抓取。
- 消息编辑接口；“撤回并编辑”始终创建新消息。
- 全局通知中心、通知数据库、通知 Icon聊天记录、系统通知和声音提醒。
- IndexedDB 消息缓存、持久草稿、离线发送和服务端事件补发。
- 聊天导出、批量删除、会话置顶、免打扰、屏蔽或举报。
- 跨会话或跨房间全文搜索、SQLite FTS、搜索索引管理。
- 管理员查看聊天内容或聊天审计后台。
- 端到端加密、消息加密密钥协商或内容合规扫描。
- 新的独立原型、Playwright 和视觉快照。
