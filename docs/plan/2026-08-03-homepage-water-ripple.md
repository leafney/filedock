# 首页连续水波纹与节点呼吸优化开发 PRD

Related discussion: [docs/discuss/2026-08-03-homepage-water-ripple.md](../discuss/2026-08-03-homepage-water-ripple.md)

- 日期：2026-08-03
- 状态：修订已完成，待人工复验
- 变更类型：前端视觉动效与响应式渲染优化
- 影响范围：首页雷达波纹、中心头像定位、装饰房间节点呼吸、减少动态效果

## Problem Statement

上一阶段已经增强首页雷达颜色并为房间节点增加呼吸，但雷达仍由四个不同尺寸的固定圆环组成。每个圆环只在自身尺寸附近进行小幅缩放，因此用户看到的是固定靶环明暗闪烁，不是从中心向外传播的雷达波或水波纹。

固定四环还会造成空间节奏断裂：外层圆环扩散时，中心附近可能没有新波纹；不同基础尺寸与 `ease-out` 缓动又让相邻波纹间距不稳定。用户希望看到连续波列——新波纹不断从中心头像外缘出现，匀速扩散，经历深浅变化，到最外侧变淡消失。

当前房间节点的呼吸效果也不符合预期。节点本体只轻微缩放，同时外侧出现明显扩大的彩色光圈，视觉上更像发光提示或可交互状态。首页雷达节点实际只是装饰内容，不提供点击操作，因此该光圈和潜在悬停反馈都会形成错误暗示。

此外，当前中心头像和昵称作为一个组合整体居中，头像自身中心没有严格位于雷达画布中心。新波纹若直接从画布中心扩散，会与头像中心错位，无法形成“波纹从头像外缘发出”的效果。

本阶段需要把固定靶环改造成连续、等距、响应式的水波纹，校正雷达原点，简化节点呼吸，同时保持现有首页业务和雷达节点算法不变。

首次实施后的人工验收截图表明，原定 `25%` 浅色仍然过深。五个波纹在浅阶段依旧清晰可见，页面同时呈现多层完整圆环，产生明显靶环感并容易造成视觉眩晕。用户进一步明确：“深、浅、深、浅”中的“浅”应接近完全透明，必须低于 `10%`。同时，按画布较短边计算的扩散终点在右侧宽面板中过小，没有覆盖预期横向范围。

## Solution

正常动态模式使用五圈同构波纹。每圈起始直径约 `132px`，即从 `112px` 中心头像外缘约 `10px` 外开始；每圈用约五秒匀速扩散至右侧雷达面板宽度约 `80%`，每隔约一秒错开发射。五圈使用负动画延迟，使页面首次显示时已经存在完整波列，不需要等待动画逐圈填充。终点不再受面板较短边限制；宽屏下允许最外圈顶部、底部被雷达画布自然裁剪。

每圈统一使用 FileDock 青绿色和相同关键帧，在一次生命周期内经历“透明出现、深色、接近透明、次深、接近透明、完全消失”。关键点固定为 `0% / 10% / 32% / 62% / 86% / 100%`，对应透明度固定为 `0 / 45% / 5% / 35% / 3% / 0`。主线保持 `1px`，周围增加低透明同色柔光。浅阶段低于 `10%`，使同屏只有约一到两圈明显可见，避免五层靶环造成眩晕。

雷达尺寸继续由现有画布尺寸观察机制提供。每次画布变化时，根据面板宽度计算终点直径及缩放系数，并同步提供给波纹样式。中心头像严格锚定画布中心；昵称继续放在头像下方，但不改变头像中心位置。

房间节点保留现有错峰周期，让整个圆形头像本体在 `1` 与 `1.08` 之间呼吸。圆内数字、边框和基础阴影随本体缩放，下方房间号标签不动。删除外扩彩色光圈和相关动态颜色参数。节点仍是纯展示元素，悬停不产生任何样式、提示或动画变化。

系统启用减少动态效果时，停止所有持续动画和节点进入退出动画，改为三圈 `10% / 7% / 4%` 的静态浅色圆环。静态环分布在中心头像外侧到画布外缘之间，保持雷达语义而不制造明显靶环。

## User Stories

1. 作为首页用户，我希望波纹从中心头像外缘出现，以便理解信号由当前用户向局域网传播。
2. 作为首页用户，我希望每圈从小变大扩散，以便看到真实的水波传播方向。
3. 作为首页用户，我希望波纹到达外侧前逐渐消失，以便边缘不会形成固定边框。
4. 作为首页用户，我希望波纹持续从中心发出，以便中心区域不会在外圈传播时长时间空白。
5. 作为首页用户，我希望同屏波纹疏密适中，以便画面既连续又不过度拥挤。
6. 作为首页用户，我希望相邻波纹近似等距，以便波列看起来平稳连贯。
7. 作为首页用户，我希望扩散过程中出现深浅变化，以便波纹具有水波起伏感。
8. 作为首页用户，我希望深浅变化随波纹向外移动，以便页面不会重新呈现固定靶环。
9. 作为首页用户，我希望所有波纹使用统一青绿色，以便保持 FileDock 视觉一致性。
10. 作为首页用户，我希望圆环保持细线，以便水波增强后仍然轻盈。
11. 作为首页用户，我希望细线具有轻微柔光，以便浅色背景上容易看见又不刺眼。
12. 作为首页用户，我希望首次进入首页时立即看到完整波列，以便不必等待动画启动。
13. 作为桌面用户，我希望波纹最大直径达到右侧面板宽度约 `80%`，以便宽屏下不再只挤在中心。
14. 作为宽屏用户，我希望外圈不受面板高度限制，以便横向扩散范围符合预期。
15. 作为页面用户，我希望超出雷达画布的上下部分被自然裁剪，以便波纹不会覆盖左侧操作栏、顶栏或页脚。
16. 作为首页用户，我希望中心头像与波纹严格同心，以便扩散来源明确。
17. 作为首页用户，我希望昵称仍显示在头像下方，以便识别当前身份。
18. 作为首页用户，我希望昵称不会把头像推离雷达中心，以便中心构图保持准确。
19. 作为首页用户，我希望周围房间圆本体进行呼吸，以便节点具有自然活跃感。
20. 作为首页用户，我希望圆内数字和边框随节点一起缩放，以便节点保持完整圆形。
21. 作为首页用户，我希望节点呼吸峰值清楚但克制，以便能感知动画又不抢夺中心焦点。
22. 作为首页用户，我希望五个节点错峰呼吸，以便它们不会同步跳动。
23. 作为首页用户，我希望节点房间号标签保持静止，以便动画期间仍可阅读。
24. 作为首页用户，我希望中心用户头像保持静止，以便页面存在稳定视觉锚点。
25. 作为首页用户，我希望节点周围不再出现扩大彩色光圈，以便呼吸不像通知或选中状态。
26. 作为首页用户，我希望鼠标经过装饰节点时动画不改变，以便展示效果保持连续。
27. 作为首页用户，我希望装饰节点不显示手型光标，以便不会误认为它可以点击。
28. 作为首页用户，我希望装饰节点不显示悬停提示或高亮，以便交互含义清晰。
29. 作为键盘用户，我希望装饰节点不进入焦点顺序，以便不会访问不可操作内容。
30. 作为屏幕阅读器用户，我希望装饰节点不被朗读为真实房间，以便不会接收虚假业务信息。
31. 作为减少动态效果的用户，我希望水波扩散和深浅变化停止，以免持续运动造成不适。
32. 作为减少动态效果的用户，我希望节点呼吸及进入退出动画停止，以免页面仍存在局部运动。
33. 作为减少动态效果的用户，我希望动画停止后仍看到低于或等于 `10%` 的静态雷达圆环，以便页面结构保持完整但不过分醒目。
34. 作为减少动态效果的用户，我希望三圈静态圆环使用 `10% / 7% / 4%` 强度并均匀分布，以便不会退回拥挤的明显靶环。
35. 作为维护者，我希望复用现有尺寸观察机制，以便不创建重复的观察器和生命周期。
36. 作为维护者，我希望波纹缩放由 CSS 完成，以便不增加逐帧 React 状态更新。
37. 作为维护者，我希望画布尺寸只在实际变化时更新动效参数，以便避免无意义重渲染或观察循环。
38. 作为维护者，我希望保留现有五节点数量、位置算法与替换逻辑，以便视觉调整不扩大业务风险。
39. 作为维护者，我希望节点周期继续由稳定槽位派生，以便重渲染后呼吸节奏不会随机突变。
40. 作为维护者，我希望节点进入退出与呼吸作用于不同元素，以便动画变换不会互相覆盖。
41. 作为维护者，我希望本次不新增用户文案，以便无需改变中英文词典。
42. 作为维护者，我希望现有前端测试、编译和生产构建通过，以便确认没有结构回归。

## Implementation Decisions

### 1. 变更边界

- 本阶段只修改首页雷达渲染组件、雷达相关样式和本 PRD 文档状态。
- 不修改首页双栏布局、操作侧栏宽度、房间卡、昵称业务、全局顶栏、房间页面、后端、API、SSE 或数据模型。
- 不修改雷达房间节点数量、尺寸范围、随机位置、颜色、房间号、生命周期、替换队列或避让算法。
- 不新增依赖，不引入 Canvas、SVG 动画库、JavaScript 逐帧动画或第三方动效包。

### 2. 波纹 DOM 结构

- 正常与减少动态效果模式共用五个波纹元素，避免偏好切换时重建不同结构。
- 五个波纹元素使用完全相同的基础直径、颜色、边框、柔光与关键帧。
- 不再为不同序号设置不同基础宽度，不再设置奇偶强弱颜色。
- 波纹容器覆盖完整雷达画布，并以画布几何中心作为定位原点。
- 波纹层必须位于中心头像和所有房间节点下方，禁止响应指针事件，并继续对辅助技术隐藏。

### 3. 波纹起点与雷达原点

- 中心头像直径继续保持 `112px`。
- 所有动态波纹基础直径统一为约 `132px`，表示距离头像四周约 `10px` 的起点。
- 中心头像的几何中心必须严格位于雷达画布的水平与垂直 `50%` 位置。
- 昵称继续显示在头像下方约现有间距处，但应脱离头像居中尺寸计算。可使用绝对定位或等价布局，使昵称高度不再把头像向上推离中心。
- 头像、波纹和节点布局算法使用同一画布中心，不允许分别使用不同偏移修正。

### 4. 响应式终点计算

- 每次雷达画布获得有效宽高时，使用画布宽度计算动态终点；高度只用于现有节点布局，不能继续限制波纹直径。
- 动态波纹最大直径目标为右侧雷达面板宽度约 `80%`。
- 终点缩放系数等于“画布宽度 × `80%` ÷ 约 `132px` 基础直径”，且不得小于 `1`。
- 终点缩放系数通过 CSS 自定义属性或等价的单值接口提供给全部波纹，五圈不能分别计算不同终点。
- 复用当前节点重排所使用的同一个 `ResizeObserver` 回调，不新增第二个观察器。
- 尺寸小于等于零时不更新；宽高变化不足现有容差时不重复更新，继续防止 ResizeObserver 循环。
- 尺寸变化只更新终点参数和节点合法位置，动画每帧仍完全由 CSS 执行。
- 宽屏下最大直径可能超过画布高度。该情况属于预期效果，最外圈顶部和底部由雷达画布的溢出裁剪自然隐藏，禁止为了保持完整圆形再次使用短边上限。

### 5. 波纹数量与时间模型

- 正常动态模式同时维护五圈波纹。
- 每圈动画总时长约五秒。
- 相邻波纹的相位差约一秒，对应每秒发射一圈。
- 五圈分别使用约 `0s`、`-1s`、`-2s`、`-3s`、`-4s` 的动画延迟，或语义等价的负延迟排列。
- 负延迟保证首屏首次绘制时各圈已处于不同传播位置，不能让五圈先重叠再逐个散开。
- 五圈使用无限循环；一个周期结束并回到起点时必须处于完全透明状态，避免外圈瞬间跳回中心。

### 6. 匀速传播

- 波纹缩放从 `scale(1)` 线性变化到响应式终点缩放系数。
- 动画时间函数必须使用 `linear`，不能继续使用 `ease-out`、弹跳或分段位移缓动。
- 中间透明度关键帧不得改变传播速度。所有关键点应根据相同线性进度设置对应缩放，或只定义起终点缩放并让浏览器线性插值。
- 波纹只能改变 `transform`、`opacity` 等合成属性，不得在动画中改变 `width`、`height`、边距或定位。

### 7. 单圈深浅关键帧

- 单圈在 `0%` 时位于起点并完全透明，目标可见度为 `0`。
- `10%` 时达到第一段深色峰值，目标可见度为 `45%`。
- `32%` 时降到第一段浅色，目标可见度为 `5%`。
- `62%` 时回到第二段深色，目标可见度为 `35%`。
- `86%` 时降到第二段浅色，目标可见度为 `3%`。
- `100%` 时到达最大直径并完全透明，目标可见度为 `0`。
- 两个浅色阶段必须低于 `10%`，不得使用首次实现中的 `25%`，也不得通过边框基础透明度叠加后使最终视觉高于目标。
- 上述透明度表示最终视觉目标。若边框颜色自身带透明度，必须考虑它与元素 `opacity` 的叠加结果，不能让实际强度远低于目标。
- 所有五圈复用同一关键帧，禁止通过序号永久改变峰值。

### 8. 边框和柔光

- 主圆环保持 `1px` FileDock 青绿色边框。
- 圆环增加约 `3～5px` 范围的同色柔光，可用轻量阴影或等价 CSS 实现。
- 第一段深色峰值时，柔光最终可见强度目标约 `10～12%`；其他阶段随元素透明度同步变浅。
- 柔光不能变成第二条清晰外圈，也不能使用高不透明度、大半径或多层霓虹阴影。
- 不使用实心背景、粗线、不同色相、彩虹渐变、发光粒子或扫描扇形。

### 9. 节点呼吸

- 只有阶段为稳定可见的周围房间圆形头像播放呼吸；中心头像不播放。
- 呼吸作用于圆形头像内层，节点定位与进入退出继续由外层承担。
- 关键帧为 `scale(1) → scale(1.08) → scale(1)`，使用 `ease-in-out`。
- 圆内两位数字、边框和现有基础阴影跟随头像本体缩放。
- 下方四位房间号标签位于缩放元素之外，不得移动或缩放。
- 继续使用五个稳定槽位对应的约 `2.8s`、`3.15s`、`3.5s`、`3.85s`、`4.2s` 周期及不同负延迟。
- 删除呼吸峰值的外扩彩色光圈。节点基础阴影全程保持，不再为每个节点传入动态光圈颜色变量。
- 节点进入和退出阶段不播放呼吸；进入完成后才开始，退出开始时立即停止。

### 10. 节点交互语义

- 雷达房间节点继续是纯装饰内容，不接入真实房间详情或进入操作。
- 节点和波纹继续禁止指针事件，不注册点击、悬停、聚焦或键盘事件。
- 节点使用默认光标；不得添加手型光标。
- 悬停时不得暂停、重置、加速或增强呼吸，不得放大节点、增强阴影、显示浮层或提示。
- 节点不得进入键盘焦点顺序，并继续对辅助技术隐藏，避免随机房间号被误认为真实业务数据。

### 11. 层级与裁剪

- 雷达画布继续建立独立层叠上下文并裁剪溢出内容。
- 波纹层为最低视觉层；房间节点位于波纹上方；中心头像与昵称位于最上方。
- 波纹最大直径按画布宽度 `80%` 计算；左右方向保持在画布内，顶部和底部允许被画布裁剪。
- 波纹不得穿透到左侧操作栏、全局顶栏、页脚或页面滚动区域。

### 12. 减少动态效果

- 继续同时支持运行时系统偏好状态类和 `prefers-reduced-motion: reduce` 媒体查询，防止首次渲染检测前短暂播放动画。
- 减少动态效果开启时，停止五圈波纹的缩放与深浅动画。
- 只显示前三个波纹元素作为三圈静态浅色圆环，隐藏其余两个；不得显示五圈重叠圆环。
- 三圈静态环应分别位于头像外缘到最大终点之间的内、中、外位置，透明度依次固定为 `10% / 7% / 4%`。
- 静态环尺寸由画布宽度 `80%` 终点和 `132px` 起点计算，响应桌面与移动画布变化；外圈顶部、底部允许裁剪。
- 停止节点呼吸、进入和退出动画；节点替换逻辑继续无动画运行。
- 中心头像、昵称、房间节点和标签保持可见，画布高度与节点布局不得塌陷。

### 13. i18n

- 本阶段不新增或修改用户可见文案，不需要新增生产翻译键。
- React 组件中不得为了说明动效新增硬编码中文或英文。
- 产品名、随机房间号、CSS 变量名和内部错误日志不属于翻译内容。

### 14. 实施顺序

1. 调整中心身份布局，使头像中心与画布中心、波纹圆心严格重合，昵称保留在头像下方。
2. 把四个固定尺寸波纹改为五个同起点波纹。
3. 在现有尺寸观察回调中把终点计算从较短边 `90%` 改为面板宽度 `80%`，并同步更新三圈静态位置参数。
4. 把水波关键帧更新为 `0 / 45% / 5% / 35% / 3% / 0`，保持五秒周期、一秒错峰、边框柔光、层级和裁剪规则。
5. 调整节点本体呼吸峰值，删除外扩彩色光圈及动态颜色变量。
6. 补齐减少动态效果下的三圈静态响应式圆环和全部动画停止规则。
7. 运行自动检查，并执行桌面、移动端、持续动画、节点替换和减少动态效果人工验收。

## Acceptance Criteria

### 连续水波

1. 正常动态模式存在五圈连续传播的波纹，不再显示四个固定尺寸靶环。
2. 五圈均从约 `132px` 的相同直径开始。
3. 起始圆环距离 `112px` 头像外缘约 `10px`。
4. 每圈约五秒完成一次传播。
5. 相邻圈相差约一秒，同屏稳定保持约五圈不同相位。
6. 页面首次显示时已经存在完整波列，不出现五圈在中心重叠后再散开的过程。
7. 波纹从起点匀速扩散，视觉上相邻波纹近似等距。
8. 最大直径约为右侧雷达面板宽度 `80%`。
9. 桌面和移动端改变画布宽度后，波纹终点正确更新。
10. 宽屏下外圈顶部、底部可被画布自然裁剪，左右方向不越过雷达画布。
11. 单圈按“透明、深、浅、次深、浅、透明”的顺序变化。
12. 两次深色峰值分别为 `45%` 和 `35%`，两次浅色分别为 `5%` 和 `3%`，起点与终点均为 `0`。
13. 深浅区域随波纹向外移动，不形成永久的奇偶强弱固定环。
14. 五圈使用相同青绿色和相同动画模板。
15. 圆环主线保持 `1px`。
16. 圆环存在轻微同色柔光，但没有粗线、实心色带或霓虹效果。
17. 动画只修改合成属性，不导致页面布局跳动或每帧 React 渲染。

### 中心与层级

18. 中心头像几何中心与雷达画布中心严格重合。

## Testing Decisions

- 本阶段属于视觉布局校正和 CSS 动效调整，不包含业务规则、鉴权、支付或复杂状态转换；按照项目规则不新增 TDD 或动效实现细节单元测试。
- 现有雷达节点算法不修改，继续依赖已有代码行为和前端构建检查，不为随机位置与生命周期补写新测试。
- 自动检查继续覆盖现有前端测试、TypeScript 编译、生产构建和格式检查。
- 测试只验证外部结果，不绑定具体选择器排列、关键帧声明顺序或内部变量名称。
- 不使用 Playwright。浏览器动效与响应式效果由人工验收。
- 桌面人工验收建议使用约 `1440×900`：持续观察至少十秒，确认浅阶段接近不可见、同屏不再形成五层靶环、最大直径达到右侧面板宽度约 `80%`，以及节点错峰呼吸保持不变。
- 移动人工验收建议使用约 `390×844`：确认波纹最大直径按右侧雷达面板宽度 `80%` 更新，超出高度的部分仅在雷达画布内自然裁剪，首页操作顺序保持不变。
- 调整浏览器宽度或设备方向：确认终点及时更新，没有波纹瞬间永久卡住、节点越界或 ResizeObserver 警告。
- 鼠标反复经过五个节点：确认光标、呼吸、阴影和页面提示均不改变。
- 至少等待一个节点完成退出和替换：确认退出时停止呼吸，新节点进入完成后恢复对应槽位节奏。
- 开启系统或浏览器减少动态效果：确认只显示三圈静态浅环，全部持续动画停止，页面结构仍完整。
- 人工验收期间持续检查浏览器控制台，不能出现新增错误或警告。

## Further Notes

- “五圈”表示五个错峰复用的传播实例，不表示五个固定半径的静态圆环。
- “每秒发射一圈”通过五秒周期与一秒相位差循环实现，不需要 JavaScript 每秒创建或删除 DOM。
- `132px` 是基于 `112px` 头像直径和单侧约 `10px` 间距得出的起点基准。
- “终点为面板宽度约 `80%`”指圆环直径，不是半径；实现时不得再次乘以二，也不得改回短边上限。
- 宽屏下外圈上下裁剪是确认后的设计效果，不属于溢出缺陷；波纹仍必须由雷达画布裁剪，不能覆盖页面其他区域。
- “浅”表示接近不可见。两次浅色最终视觉必须分别约为 `5%` 和 `3%`，不能恢复为首次实现的 `25%`。
- 深浅数值是最终视觉目标。边框自身透明度、元素透明度和柔光透明度叠加时应按最终结果校准。
- 五圈必须共用同一终点和线性位移。若为每圈保留不同基础宽度或不同终点，会重新产生不等距靶环。
- 中心昵称不得继续参与整个身份组的垂直居中，否则波纹圆心与头像圆心会存在可见偏差。
- 节点基础阴影保留；删除的是呼吸峰值额外扩大的彩色光圈。
- 装饰节点无交互是产品决策，不应添加悬停暂停来“提高可点击性”。
- 本 PRD 获得用户明确批准后才能开始修改生产代码。
