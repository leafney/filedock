# FileDock 聊天成员导航与右栏布局优化 PRD

状态：已完成

日期：2026-08-03

## Problem Statement

房间桌面页当前同时在左侧成员栏和右侧聊天栏展示成员列表。用户无法明确理解哪一处才是聊天入口，右侧重复的头像、昵称和在线状态也挤占了本来就有限的消息区域。

左侧成员项为了接入点击聊天而增加了一层按钮结构，但原有样式仍只匹配旧的直接子元素，导致用户认可的“彩色圆点 + 在线状态文字”布局失效，看起来像被改成了普通文字状态。

右侧会话的选择状态仍由聊天组件内部管理，房间工作区只传递一次性初始成员。这种结构无法可靠支持左侧当前成员高亮、把每位成员的未读徽标放回左侧、从右侧关闭当前会话，以及按成员隔离草稿。当前单一草稿还可能在切换成员后出现在另一位成员的输入框中，存在误发风险。

## Solution

将桌面左侧成员列表确立为唯一的聊天对象导航。进入房间时右侧只显示“请选择左侧成员开始聊天”的空状态；单击除自己以外的有效成员后，右侧直接显示该成员的聊天窗口，左侧对应成员保持选中高亮。

左侧恢复“彩色圆点 + 在线／暂离／离线文字”的原样式。离线只表示当前不在线，不影响发送消息。每个会话的未读数量显示在对应成员头像右上角，房主皇冠仍显示在头像左上角。

选中会话的右侧顶部采用用户确认的紧凑结构：左侧显示头像、昵称、彩色状态圆点和状态文字；右侧显示聊天记录图标与关闭图标；移除额外标题和返回会话列表按钮。关闭只清除当前会话并回到右侧空状态，不退出房间。

聊天草稿按房间、当前用户和聊天对象隔离保存在浏览器本地存储。切换成员、关闭会话或离开页面时保留草稿；发送成功后删除；最后编辑超过 7 天后自动失效。该能力只在当前浏览器生效，不增加服务端存储或多端同步。

本次严格限定为桌面三栏页面优化。移动端现有全屏聊天、移动端会话列表和成员抽屉行为保持不变；后端数据库、聊天 API、SSE 事件和离线消息逻辑均不修改。

## User Stories

1. 作为桌面房间成员，我希望左侧成员列表是唯一的聊天对象入口，以便不会在左右两处重复寻找联系人。
2. 作为刚进入房间的用户，我希望右侧默认显示选择成员的提示，以便明确下一步操作且不会误读任何会话。
3. 作为房间成员，我希望单击左侧另一位成员即可打开聊天，以便快速开始沟通。
4. 作为房间成员，我希望不能与自己打开一对一聊天，以便避免无意义会话。
5. 作为房间成员，我希望离线但仍在房间中的成员可以被选择和接收消息，以便对方上线后继续协作。
6. 作为房间成员，我希望已离开、被踢或不再有效的成员不能成为聊天目标，以便权限与房间状态一致。
7. 作为房间成员，我希望左侧状态恢复为彩色圆点与文字组合，以便快速、直观地判断成员在线状态。
8. 作为房间成员，我希望在线、暂离和离线使用不同颜色并配合文字，以便颜色辨识困难时仍能理解状态。
9. 作为正在聊天的用户，我希望左侧当前成员保持高亮，以便知道右侧正在显示谁的会话。
10. 作为同时与多人沟通的用户，我希望切换成员时高亮与右侧内容同步变化，以便不会把消息发错对象。
11. 作为收到私聊的用户，我希望未读数显示在对应成员头像右上角，以便知道具体是谁发来了消息。
12. 作为有大量未读消息的用户，我希望超过 99 条时显示 `99+`，以便徽标不会撑坏成员行布局。
13. 作为房主，我希望左上角皇冠和右上角未读徽标可以同时显示，以便角色与消息状态都不丢失。
14. 作为正在查看其他会话的用户，我希望新消息只更新未读徽标，不自动切换当前聊天，以便当前操作不被打断。
15. 作为聊天用户，我希望右侧顶部显示当前成员头像、昵称和在线状态，以便始终知道聊天对象是谁。
16. 作为聊天用户，我希望右侧顶部不再显示重复的“一对一聊天”或“房间会话”标题，以便有效空间用于会话信息。
17. 作为聊天用户，我希望点击聊天记录图标继续查看和搜索当前双方历史，以便原有能力不受布局调整影响。
18. 作为聊天用户，我希望点击关闭图标只关闭当前会话，以便回到选择状态而不离开房间。
19. 作为关闭会话的用户，我希望左侧选中高亮同步取消，以便界面状态一致。
20. 作为正在输入的用户，我希望切换到其他成员时原草稿得到保留，以便稍后回来继续输入。
21. 作为同时与多人沟通的用户，我希望每位成员拥有独立草稿，以便甲的文字不会出现在乙的输入框中。
22. 作为误关会话的用户，我希望重新点回同一成员时恢复草稿，以便未发送内容不会丢失。
23. 作为刷新或重新打开页面的用户，我希望当前浏览器可以恢复未过期草稿，以便短暂离开不影响编辑。
24. 作为成功发送消息的用户，我希望对应草稿立即清除，以便已发送内容不会再次恢复。
25. 作为发送失败的用户，我希望失败正文只恢复到原接收者的草稿中，以便切换会话期间也不会串稿。
26. 作为使用临时房间的用户，我希望超过 7 天的旧草稿自动失效，以便浏览器不会长期恢复无关内容。
27. 作为禁用或限制浏览器存储的用户，我希望本地草稿保存失败不会阻止聊天，以便核心发送能力仍可使用。
28. 作为简体中文用户，我希望空状态、关闭按钮和状态提示使用中文，以便完整理解界面。
29. 作为英文用户，我希望相同功能拥有完整 English 文案，以便语言切换后没有缺失键或硬编码中文。
30. 作为键盘和辅助技术用户，我希望成员按钮、未读数、历史图标和关闭图标拥有清晰的焦点与无障碍名称，以便无需依赖鼠标或纯视觉信息。
31. 作为移动端用户，我希望本次桌面优化不改变现有全屏聊天与会话列表，以便已验证的移动端流程不受影响。

## Implementation Decisions

### 1. 范围与兼容边界

- 只修改桌面三栏房间工作区中的成员导航、右侧空状态、选中会话标题、未读徽标和草稿状态。
- 移动端聊天继续使用现有全屏覆盖层、现有会话列表、现有返回按钮和现有关闭入口。本次不得把桌面空状态或桌面关闭逻辑直接套到移动端。
- 不修改数据库表、数据迁移、聊天模型、聊天服务、聊天 API、DTO、错误码、SSE 事件或房间生命周期。
- 离线消息已经由现有聊天服务持久化。本次只修正前端是否允许选择离线有效成员，不重复实现消息队列或离线投递。
- 不自动打开最近会话、第一位成员或新消息所属会话。桌面初始选择必须为空。

### 2. 桌面会话选择状态

- 房间工作区成为桌面当前聊天成员 ID 的唯一状态拥有者。
- 当前成员 ID 初始为未定义；左侧单击成员时写入对应用户 ID；右侧关闭时清空。
- 右侧聊天组件接收受控的桌面成员 ID，并在该值变化时加载对应历史。不得在消费初始值后立即让父级忘记当前成员，否则左侧无法持续高亮。
- 重复点击已经选中的成员不得清空会话；可以保持现状，也不得产生第二个聊天组件或第二份消息状态。
- 自己的成员项不得调用打开聊天逻辑。
- 聊天资格以成员业务状态是否仍为有效房间成员为准，不以在线状态为准。`online`、`away`、`offline` 都允许打开聊天。
- 如果房间快照更新后当前成员已不在有效成员集合中，父级必须清空选择，右侧回到空状态。不得继续展示可输入的失效会话。
- 收到未选中成员的新消息时只更新未读状态，不修改当前成员 ID。

### 3. 桌面与移动端渲染模式必须显式分离

- 聊天组件需要能够区分“桌面受控右栏”和“移动端现有会话列表”两种渲染模式。
- 桌面模式没有选中成员时渲染空状态；移动端模式没有选中成员时仍渲染现有会话列表。
- 桌面选中会话标题使用历史图标和关闭图标；移动端继续保留现有返回会话列表行为，不因共享组件修改而丢失。
- 不允许用仅依赖窗口宽度的临时判断在组件内部混合两套业务状态。调用方应明确传递模式或等价的显式配置。
- 桌面和移动端可以继续复用消息列表、发送框、历史搜索、右键菜单、撤回、转发和删除能力，不复制消息业务实现。

### 4. 左侧成员项交互与视觉

- 成员项主体使用单个按钮承载头像、昵称和状态，支持单击与键盘激活。移除多余的双击入口，避免一次操作触发重复加载。
- 自己的主体按钮禁用聊天打开行为，但仍正常展示头像、昵称、“我”和在线状态。
- 房主踢出按钮继续作为独立按钮，不能嵌套在聊天按钮中，也不能因点击而打开会话。
- 恢复状态行为：绿色圆点对应在线，橙色圆点对应暂离，灰色圆点对应离线；圆点右侧显示对应本地化文字。
- 修正成员按钮内部信息容器的样式选择器，使圆点、文字、间距、字号和颜色与聊天改造前保持一致。
- 当前成员项增加稳定的选中类和 `aria-current` 或等价状态。选中背景采用现有浅色品牌体系，并与普通悬停状态可区分。
- 头像容器保持相对定位。房主皇冠固定在左上角；未读徽标固定在右上角，二者不得重叠。
- 未读数为 1～99 时显示真实数字，大于 99 时显示 `99+`，为 0 时不渲染徽标。
- 未读徽标不得改变头像尺寸、昵称对齐或成员行高度；辅助技术可读取“与某成员有 N 条未读消息”的本地化说明。

### 5. 未读数据流

- 右侧不渲染会话列表，但聊天状态仍需获取现有会话摘要，因为每位成员未读数和总未读数依赖该数据。
- 聊天组件向房间工作区上报按成员用户 ID 索引的未读数量映射；房间工作区把对应值传给桌面成员列表。
- 现有顶部聊天入口总未读数继续由所有有效成员的未读数求和，超过 99 仍显示 `99+`。
- SSE 新消息、已读更新、撤回和本地删除导致会话摘要失效后，按现有查询刷新规则更新映射，不建立第二套未读事实来源。
- 打开当前会话并满足页面可见、窗口聚焦等既有已读条件后，服务端已读推进；摘要刷新后左侧徽标消失或减少。
- 当前选择与未读映射是两类独立状态。更新未读数不得触发选中、切换、关闭或消息历史重载。

### 6. 右侧桌面空状态

- 没有选中成员时，右侧整个区域只显示居中的空状态图标和提示文案，不显示成员、消息预览、在线状态列表或未读列表。
- 空状态不显示“一对一聊天”“房间会话”等顶部标题，不保留一条无内容标题栏。
- 中文建议文案为“请选择左侧成员开始聊天”，英文提供语义一致的翻译；最终文本必须通过 i18n 键读取。
- 空状态不得调用消息历史接口，也不得推进任何会话已读游标。

### 7. 右侧桌面选中会话标题

- 标题栏左侧依次显示成员头像、包含昵称与状态的文本区；状态行使用与左侧一致的圆点颜色和本地化状态文字。
- 标题栏右侧依次显示聊天记录图标和关闭图标。
- 聊天记录图标继续打开当前会话已有的历史查看与搜索抽屉，不修改搜索范围、查询接口或定位高亮行为。
- 关闭图标清理消息菜单、历史抽屉等依赖当前会话的临时浮层，然后通知父级清空当前成员 ID。
- 关闭不得退出房间、关闭浏览器覆盖层、删除历史、标记其他消息已读或清除草稿。
- 桌面标题栏移除现有返回会话列表箭头，因为右侧不再存在会话列表。
- 所有图标按钮必须有简体中文和英文的 `aria-label` 与悬停标题，并保留可见键盘焦点。

### 8. 按成员隔离的本地草稿模块

- 草稿存储封装成独立纯前端模块，聊天组件不得散落拼接本地存储键、JSON 解析或过期判断。
- 存储键必须带版本号，并至少由房间唯一 ID、当前用户 ID、对方用户 ID 共同组成。使用房间唯一 ID，不只使用可能被回收的房间号，避免新房间误读旧草稿。
- 每条记录只保存正文和最后更新时间，结构等价于 `{ content, updatedAt }`；不得保存昵称、会话历史、Token、Cookie 或其他身份数据。
- 过期时间为最后编辑后 7 天。每次非空编辑更新 `updatedAt`；读取时若当前时间减去更新时间达到或超过 7 天，则删除记录并返回空草稿。
- 读取到非法 JSON、缺少字段、正文不是字符串、时间不是有效数字或未来时间明显异常时，删除该记录并返回空草稿。
- 输入内容变为空字符串时删除对应存储记录，不保留空对象。
- 所有本地存储读取、写入和删除都必须捕获异常。隐私模式、配额不足或用户禁用存储时，聊天仍使用当前内存草稿继续工作，不显示阻断式错误。
- 模块允许注入等价存储对象和当前时间，以便单元测试验证外部行为；生产环境使用浏览器 `localStorage`。

### 9. 草稿状态与异步发送规则

- 聊天组件内存中也按对方用户 ID 保存草稿，而不是只保存一个全局字符串。
- 首次打开某成员会话时，从本地草稿模块加载该成员草稿；同一页面生命周期内再次打开时使用内存中的最新值，不覆盖用户刚输入的内容。
- 输入框每次变化同时更新该成员的内存草稿和本地草稿。切换成员只切换当前展示值，不复制或移动草稿。
- 提交发送时先捕获接收者 ID 和正文，后续成功或失败都必须操作被捕获的那位成员草稿，不能使用请求完成时可能已经变化的当前选择。
- 发送成功后清空并删除该接收者草稿。用户已经切换到其他成员时，不得清空当前屏幕上另一位成员的草稿。
- 发送失败后把正文恢复到原接收者草稿并持久化。用户已经切换到其他成员时，不得把失败正文写入当前输入框对应的其他草稿。
- “撤回并编辑”成功后通过同一个草稿更新入口写入当前成员草稿，因此刷新、关闭或切换后仍可恢复；已有草稿时继续使用现有替换确认流程。
- 关闭当前会话只清空选择，不删除内存或本地草稿。

### 10. 国际化

- 新增或调整的空状态、关闭当前会话、未读说明和无障碍文案必须同时补齐 `zh-CN` 与 `en`。
- React 组件不得硬编码中文或英文用户可见句子。
- 现有“在线”“暂离”“离线”“聊天记录”等翻译键优先复用，避免建立语义重复的键。
- 双语词典的键集合和非空值测试必须继续通过。

### 11. 实施顺序

1. 先实现并验证草稿存储深模块，包括版本化键、房间／用户／成员隔离、7 天过期、安全降级和单元测试。
2. 再把桌面当前成员与按成员未读映射提升到房间工作区，改造左侧成员项的点击、选中、高亮、圆点文字和头像未读徽标。
3. 再为聊天组件增加显式桌面／移动端模式，桌面移除重复会话列表并实现空状态、紧凑标题和关闭操作，移动端保持现状。
4. 最后接入按成员内存草稿、发送成功／失败的接收者隔离处理、撤回并编辑持久化和双语文案。
5. 完成后运行前端单元测试、前端生产构建、Go 全量测试和代码差异检查，再进行桌面手动验证。

## Testing Decisions

### 自动测试原则

- 只测试可观察行为和纯逻辑契约，不测试 CSS 选择器内部实现、不添加 DOM 快照，也不引入 Playwright。
- 本次没有后端业务变化，不新增聊天服务或数据库测试；继续运行现有 Go 全量测试防止接口回归。
- 草稿的隔离、过期和异常恢复属于有边界条件的状态逻辑，需要新增聚焦的纯逻辑单元测试。

### 草稿模块测试

至少覆盖以下行为：

1. 相同房间、当前用户和对方用户可以保存并读取草稿。
2. 不同房间、不同当前用户或不同对方用户不会读到彼此草稿。
3. 每次写入更新最后编辑时间，7 天以内可读。
4. 达到或超过 7 天后返回空值并删除旧记录。
5. 空内容会删除记录。
6. 非法 JSON、错误字段类型和无效时间安全返回空值并清理记录。
7. 存储对象在读取、写入或删除时抛错，不向调用方传播异常。

### 手动验收场景

1. 桌面进入房间，右侧只有选择成员提示，没有第二份成员列表和顶部标题。
2. 左侧每位成员显示彩色圆点与在线／暂离／离线文字，外观与用户提供的原始截图一致。
3. 单击自己不会打开聊天；单击在线、暂离或离线的其他有效成员都会在右侧打开对应会话。
4. 当前成员左侧行保持高亮；切换成员后高亮和右侧头像、昵称、状态、消息历史同步切换。
5. 右侧顶部左侧显示成员信息，右侧只显示聊天记录和关闭图标，不显示返回箭头或额外标题。
6. 点击聊天记录图标仍能查看、搜索和定位当前会话历史。
7. 点击关闭图标后右侧回到空状态，左侧高亮取消，房间页面保持打开。
8. 未选中成员收到新消息时，右侧不自动切换；对应头像右上角显示未读数。
9. 房主皇冠与未读徽标分别显示在头像左上角和右上角；未读超过 99 显示 `99+`。
10. 打开未读会话并满足现有已读条件后，徽标按摘要刷新结果减少或消失。
11. 在甲会话输入草稿，切换乙后输入框不出现甲草稿；再次点回甲可恢复。
12. 关闭会话或刷新页面后，在 7 天内重新打开同一成员仍可恢复草稿。
13. 消息发送成功后刷新页面，已发送正文不再恢复为草稿。
14. 模拟发送失败并在请求期间切换成员，失败正文只回到原接收者草稿。
15. 在浏览器存储不可用时仍可切换会话、输入和发送消息。
16. 将界面分别切换为简体中文和 English，所有新增提示和按钮名称均正确显示。
17. 在移动端断点打开聊天，现有全屏聊天、会话列表和返回流程与改动前一致。

## Acceptance Criteria

1. 桌面右侧未选中时不再渲染任何聊天对象列表。
2. 左侧成员状态恢复为圆点加文字，且在线状态不决定聊天资格。
3. 自己不可打开聊天；其他有效成员包括离线成员都可打开。
4. 左侧选中高亮、右侧当前成员和关闭后的空状态始终一致。
5. 左侧头像右上角显示准确的会话未读徽标，房主皇冠不受影响。
6. 右侧选中标题符合确认结构，只包含成员信息、聊天记录图标和关闭图标。
7. 新消息不会自动打开或切换会话。
8. 每位成员草稿相互隔离，切换与关闭保留，成功发送清除，失败恢复到原会话，7 天后过期。
9. 本地存储异常不会阻断聊天。
10. 移动端现有交互没有变化。
11. 简体中文与英文词典完整，自动测试、生产构建和差异检查全部通过。

## Out of Scope

- 移动端聊天布局、全屏覆盖层、移动端成员抽屉和移动端会话列表重构。
- 首页、其他房间页、通知 Icon、浏览器系统通知或全局通知中心的聊天记录聚合。
- 自动打开最近会话、收到消息后自动弹出或自动切换聊天窗口。
- 群聊、跨房间聊天、好友列表或新的联系人体系。
- 服务端草稿、IndexedDB 消息缓存、草稿多端同步或跨浏览器同步。
- 数据库表结构、聊天 API、SSE 契约、后端离线投递和房间清理逻辑修改。
- 聊天历史、右键菜单、撤回、删除、转发、搜索和已读规则的功能扩展。
- 全新的头像图片、状态图标资源或视觉主题重做。
