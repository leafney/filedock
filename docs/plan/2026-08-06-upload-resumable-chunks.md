# 文件上传断点续传与分片

## Problem Statement

当前上传流程为每个文件创建元数据和容量预留后，使用一次性 HTTP `PUT` 上传完整文件。大文件上传过程中如果网络中断、页面短暂切换或请求失败，客户端只能从头重新上传；服务端也无法知道已成功接收的字节范围。现有右下角传输浮层只支持取消和失败重试，不能暂停、继续或删除未完成上传。

本阶段不扩展应用级下载断点恢复。下载继续使用上一阶段已经实现的 `HEAD`、单区间 `Range`、`206/416` 和 2 秒短时重放；外部下载器自行使用这些 HTTP 能力。

## Solution

将上传统一为可恢复的分片协议。创建批次仍负责文件元数据、权限校验和容量预留；每个文件都对应一个上传会话，直接复用现有 `fileId` 作为 `uploadId`。文件不超过 10 MiB 时使用一个分片，超过 10 MiB 时按 5 MiB 分片。分片请求可以乱序、幂等重试，并以 SHA-256 校验内容。服务端把分片写入临时文件的指定偏移，记录分片状态；所有分片收齐后校验总大小并原子提交正式文件。

浏览器仅在 `localStorage` 保存上传会话元数据，不保存文件内容。当前页面网络中断、暂停、失败后可以继续；刷新后用户重新选择同一文件，若本地 `uploadId` 与文件元数据匹配则自动恢复，不再二次确认。一个上传会话同一时间只有一个标签页负责实际上传，其他标签页只读同步进度；暂停后可以由其他标签页接管。上传完成或房间失效时清理本地元数据。

右下角传输浮层按文件显示任务、分片进度、速度和状态，并提供暂停、继续、重试、取消/删除。上传或下载开始时浮层自动展开，全部任务完成后保持展开 5 秒再自动收回。现有 SSE `file.upload_progress` 继续推送按已确认分片累计的聚合进度。

## User Stories

1. 作为上传者，我希望小文件可以用一次分片请求完成上传，以减少不必要的请求开销。
2. 作为上传者，我希望大文件自动按 5 MiB 分片，以便网络中断时只重传失败部分。
3. 作为上传者，我希望分片可以乱序上传，以便客户端并发利用网络带宽。
4. 作为上传者，我希望每个分片带 SHA-256 校验，以便发现传输损坏而不污染正式文件。
5. 作为上传者，我希望同一个分片重复提交时幂等成功，以便网络超时后安全重试。
6. 作为上传者，我希望同一序号但内容不同的分片被拒绝，以避免错误覆盖。
7. 作为上传者，我希望上传过程中可以暂停，以便临时释放网络或浏览器资源。
8. 作为上传者，我希望暂停后可以继续，从已完成分片处恢复，不从头开始。
9. 作为上传者，我希望网络错误的分片自动重试 3 次，仍失败后可以手动重试。
10. 作为上传者，我希望可以删除未完成上传，服务端临时文件、会话、分片记录和容量预留同时清理。
11. 作为上传者，我希望删除上传前有明确确认，避免误删不可恢复的上传进度。
12. 作为上传者，我希望刷新页面后重新选择文件时能自动发现并继续未完成上传。
13. 作为上传者，我希望恢复时看到提示和当前服务端进度，不需要再次确认上传意图。
14. 作为上传者，我希望文件内容变化时旧会话不会被错误复用，并能自动重新开始上传。
15. 作为上传者，我希望同一文件在多个标签页不会同时写入，暂停一个标签页后可由另一个标签页接管。
16. 作为上传者，我希望切换首页或其他房间时传输继续，返回原房间后仍能查看任务。
17. 作为上传者，我希望一个批次中的文件分别显示状态，单个文件失败或删除不影响其他文件。
18. 作为上传者，我希望右下角浮层显示已完成分片、总分片、字节进度、速度和状态。
19. 作为上传者，我希望上传开始时传输浮层自动展开，全部完成后 5 秒自动收回。
20. 作为上传者，我希望失败任务收回后仍有失败数量和图标提示，便于稍后重试。
21. 作为房间成员，我希望房间到期时未完成上传自动清理，不继续占用空间。
22. 作为系统维护者，我希望上传继续遵守现有全局、房间和用户并发上限，避免资源耗尽。
23. 作为系统维护者，我希望分片状态持久化到数据库，服务进程重启后仍可恢复。
24. 作为 API 调用者，我希望上传状态、分片范围、校验错误和冲突错误有明确且可国际化的响应。
25. 作为下载器用户，我希望现有 `HEAD` 和 `Range` 行为保持可用，而不引入新的应用级下载协议。

## Implementation Decisions

### 上传状态和数据模型

- 新增上传会话实体，与一个 `RoomFile` 一对一关联；会话标识直接复用 `fileId`，对外字段名可继续使用 `uploadId`。
- 会话至少包含：房间、文件、上传者、总大小、分片大小、总分片数、已接收字节数、状态、创建时间、更新时间、过期时间。
- 新增上传分片实体，至少包含：会话/文件 ID、分片序号、字节起止偏移、分片长度、SHA-256、完成时间；唯一约束为“文件 ID + 分片序号”。
- 分片状态只记录已完整写入并校验成功的分片。连接中断、长度不足、哈希不匹配的分片不得标记为完成。
- RoomFile 在分片上传期间保持现有 `uploading` 状态；所有分片完成并原子提交后转为 `available`。失败、取消和房间生命周期规则沿用现有文件状态及事件。
- 不新增服务端持久化的 `paused` 状态。暂停是客户端调度状态，服务端只保留未完成会话。
- 上传会话过期时间不得超过房间过期时间；房间默认最长 24 小时。后台清理任务删除过期会话、分片记录、临时文件并释放对应容量预留。

### 分片规则

- 所有大小使用字节传输；产品阈值使用 MiB：`10 MiB = 10 * 1024 * 1024`，标准分片 `5 MiB = 5 * 1024 * 1024`。
- `DeclaredSize <= 10 MiB` 时只有一个分片，范围为 `0` 到 `DeclaredSize-1`。
- `DeclaredSize > 10 MiB` 时按 5 MiB 切分，最后一片可小于 5 MiB。
- 分片数由声明大小计算并返回；受房间容量约束，不另设与当前容量冲突的大分片数上限。
- 每个分片请求必须提供分片序号、`Content-Range`/起止偏移、实际 `Content-Length` 和 SHA-256。服务端验证序号、偏移、长度、总大小和哈希后，才写入指定偏移。
- 服务端临时文件应支持按偏移写入。建议在会话创建或首片写入时预分配声明大小，避免并发随机写时文件大小不稳定；正式文件只能通过原子重命名产生。
- 分片允许乱序到达。最后一个收到的分片只在数据库确认全部分片齐全、累计字节等于声明大小、临时文件大小正确时触发合并。
- 合并过程中禁止新分片写入；合并失败进入失败状态并保留可诊断错误，清理策略遵循现有失败上传逻辑。

### 上传 API

保留创建批次接口，因为它负责容量、权限、批量元数据和私密接收者；不保留两套内容上传实现。内容上传统一使用现有文件内容 URL 的分片语义：

- 创建批次响应：每个文件返回 `fileId`、`uploadId`（值等于 `fileId`）、声明大小、分片大小、分片总数和上传 URL。
- 查询上传状态：按房间和文件/上传 ID 校验当前用户、成员状态和房间状态，返回会话状态、已完成分片序号及每片长度/哈希、累计字节和过期时间。查询不得改变文件状态或容量。
- 分片上传：使用 `PUT` 请求上传一个分片。请求必须带分片序号、`Content-Range`、分片 SHA-256 和正确的 `Content-Length`。服务端支持乱序和幂等重试。
- 重复分片：序号、范围、长度和哈希完全一致时返回成功及现有分片信息，不重复写入、不重复计数。
- 冲突分片：同一序号已有不同范围、长度或哈希时返回专用冲突错误，不覆盖已有分片。
- 最后一片自动完成：服务端检测全部分片齐全后，在事务中更新文件大小、MIME、进度、状态、批次状态、容量和文件事件；不增加单独的 `complete` 接口。
- 取消/删除：沿用现有删除上传接口，只有上传者可操作；取消活动请求、删除会话和临时文件、释放容量、记录取消事件并向相关标签页广播。
- 所有鉴权、房间成员、文件归属、文件状态、房间有效期校验沿用现有规则。房主不能通过上传接口修改其他成员的未完成文件。
- 后端仅返回错误码和参数，所有新增错误码同时补齐 `zh-CN` 与 `en` 翻译。

### 并发、租约和幂等

- 客户端每个文件最多并发 2 个分片；现有全局 4、房间 2、用户 2 的上传限制继续生效。未来只预留配置入口，不实现管理员配置 UI。
- 同一上传会话在同一浏览器只允许一个标签页作为写入者。使用 `BroadcastChannel` 通知、`localStorage` 租约和租约超时接管；其他标签页只读同步。
- 当前标签页暂停时取消正在进行的请求并释放租约；其他标签页可取得租约，查询服务端已完成分片后继续。
- 服务器端分片记录的唯一约束和内容哈希校验是跨标签页、重复请求和网络重试的最终幂等保护。
- 分片写入必须先写临时位置并完成长度/哈希校验，再以数据库记录标记完成，避免半片被误认为可恢复。

### 客户端本地元数据与恢复

- `localStorage` 按房间和文件指纹保存临时元数据：`uploadId/fileId`、房间号、文件名、文件大小、最后修改时间、过期时间和必要的客户端状态。
- 不保存文件二进制、完整 File 对象或大块内容。
- 上传完成后立即删除对应记录；主动删除/取消、文件冲突重建、房间失效也删除记录。
- 应用启动、进入房间、收到房间失效通知时清理已过期记录；清理操作只处理项目命名空间，不影响其他应用的 `localStorage`。
- 重新选择文件时只有本地明确保存的 `uploadId` 且文件名、大小、最后修改时间均匹配，才自动查询并恢复；不根据服务端文件名和大小模糊匹配。
- 恢复不弹确认 Modal。右下角浮层显示国际化提示，随后直接显示服务端已完成分片进度并继续。
- 若分片 SHA-256 冲突，停止并删除旧会话，释放资源，自动创建新会话从头上传，并显示文件内容已变化提示。

### 传输浮层和状态

- 继续使用现有右下角 `TransferBar`，按当前房间筛选上传和下载任务。
- 每个上传任务显示文件名、状态、累计字节/总字节、已完成分片/总分片、进度百分比和速度。
- 上传中操作：暂停、取消；暂停/失败操作：继续、重试；未完成任务操作：删除。
- 删除未完成上传必须经过轻量二次确认；确认后同时清理客户端、服务端和其他标签页状态。
- 上传或下载开始时自动展开浮层；全部任务完成后等待 5 秒自动收回；新任务重置计时。
- 失败任务收回后仍显示失败数量和状态图标，不能因自动收回而丢失重试入口。
- 单页应用切换房间时传输继续；浮层只展示当前房间，返回原房间后恢复任务详情。
- 现有 `file.upload_progress` SSE 继续使用聚合字节进度，服务端节流推送；不新增每分片 SSE 事件。新增暂停、恢复、删除、冲突等用户可见文案必须同时提供中英文翻译键。

### 批次和容量

- 批次中的文件独立上传、暂停、恢复、失败、重试和删除。
- 一个文件失败或删除不影响批次中其他文件；批次状态按所有文件汇总。
- 创建批次时仍按声明大小一次性预留容量；文件完成时将预留转为实际占用；文件取消、删除、失败或会话过期时释放该文件预留。
- 任何分片写入不得再次增加容量预留，避免重复占用。

### 模块拆分和实现重点

- 上传会话服务：负责创建、查询、校验生命周期、权限和状态转换。
- 分片存储模块：负责安全路径、随机偏移写入、预分配、分片读取校验、原子提交和清理。
- 分片协议模块：负责请求头解析、范围归一化、序号/偏移/长度验证和错误映射。
- 分片幂等模块：负责重复分片判断、冲突检测和唯一约束错误转换。
- 前端分片调度器：负责文件切片、SHA-256、每文件并发 2、失败重试、暂停/继续、进度聚合和上传队列。
- 前端跨标签页协调器：负责租约、接管、BroadcastChannel 同步和失效清理。
- 传输浮层：负责文件级操作、自动展开/收回和中英文状态展示。
- SSE 投影保持现有隐私投影规则，不将私密文件内容广播给无权成员。

## Testing Decisions

- 分片边界纯逻辑测试：10 MiB 阈值、10 MiB 单片、10 MiB+1 字节、5 MiB 整除、最后小片、空/负/超界范围、序号和偏移错误。
- 哈希和幂等测试：正确 SHA-256、错误哈希、同片重复成功、同序号内容冲突、并发重复提交。
- 上传会话服务测试：创建会话、查询已完成分片、乱序上传、缺片不能完成、全部完成自动合并、取消、失败、过期和房间失效清理。
- 存储模块测试：随机偏移写入、并发分片写、临时文件预分配、短写、进程重启后继续、原子提交、路径穿越和符号链接防护。
- 容量测试：批次预留、部分文件完成、单文件删除、失败/过期释放预留、批次中其他文件不受影响。
- API 集成测试：权限校验、请求头校验、重复/冲突响应、状态查询、最后一片自动完成、取消清理和双语错误响应。
- 前端分片调度器测试：切片阈值、并发上限、乱序完成、重试、暂停/继续、冲突自动重建、任务删除和进度聚合。
- 前端租约测试：同一 `uploadId` 单写者、暂停后接管、租约超时接管、跨标签页同步和房间到期清理。
- 传输浮层测试：开始自动展开、完成 5 秒收回、失败提示保留、文件级操作互不影响。
- 保留现有 Go 服务/API 测试、Bun 前端测试、构建和错误码词典完整性测试；不引入新的端到端框架。

## Out of Scope

- 不实现应用级下载断点恢复、下载分片数据库、浏览器端文件合并或 File System Access API 下载器。
- 不支持多区间 `multipart/byteranges` 下载响应。
- 不做文件去重、整文件哈希强制校验或跨用户内容复用。
- 不实现管理员配置 UI；只为未来调整分片并发预留配置边界。
- 不支持跨设备上传恢复；恢复依赖当前浏览器 `localStorage` 元数据和用户重新选择文件。
- 不保存上传文件二进制到浏览器 IndexedDB 或其他持久缓存。
- 不允许服务端按文件名、大小自动模糊合并多个上传会话。
- 不改变现有房间成员权限、私密文件接收、通知聚合和回收站规则。
- 不引入旧上传协议兼容层；当前项目开发阶段允许直接升级现有接口和数据表。

## Further Notes

- “分片”主要解决大文件可靠性、暂停恢复和失败重传，不承诺小文件提速。
- 上传会话的本地元数据只是恢复索引，不是权限凭证；每次状态查询、分片写入和删除仍需服务端会话鉴权、房间成员和文件归属校验。
- 任何用户可见文案、API 错误提示和 SSE 提示必须同时补齐 `zh-CN` 与 `en`，React 组件不得硬编码文案。
- 实现前须阅读本 PRD全文；如果实现需要改变已确认的协议、状态或表结构，应先更新 PRD并重新取得批准。
