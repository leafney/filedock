# 容量详情弹窗优化 PRD

## Problem Statement

个人中心弹窗经过多次宽度试调后，`440px` 仍不符合最终视觉预期，需要恢复到更合适的 `460px`。房间容量详情目前使用自定义浮层，不能点击遮罩关闭，外观和项目内其他 Ant Design Modal 不统一，容量信息卡片也偏松散。

## Solution

将个人中心桌面宽度恢复到 `460px`。将容量详情由自定义 Overlay 改为 Ant Design Modal，桌面宽度同样使用 `460px`，移动端根据视口自动收缩。Modal 支持关闭按钮、点击遮罩和 Esc 关闭。容量数据继续使用现有计算结果和权限规则，以紧凑的卡片行展示。

## User Stories

1. 作为桌面端用户，我希望个人中心宽度恢复到 `460px`，以便内容不显拥挤。
2. 作为房间用户，我希望容量详情使用统一 Modal，以便弹窗体验与其他页面一致。
3. 作为鼠标用户，我希望点击弹窗外空白区域可以关闭容量详情，以便快速返回房间。
4. 作为键盘用户，我希望按 Esc 可以关闭容量详情，以便使用标准弹窗操作。
5. 作为移动端用户，我希望容量弹窗不超出屏幕，以便完整查看容量信息。
6. 作为房主，我希望继续查看总文件、共享文件、私密文件、回收站和上传预留容量，以便了解完整占用情况。
7. 作为普通成员，我希望只看到总容量信息，以便不暴露房主管理视角的数据。
8. 作为深色主题用户，我希望容量卡片和 Modal 保持可读，以便正常识别标签和数值。
9. 作为中文或英文用户，我希望现有容量文案继续正常显示，以便无需新增翻译内容。

## Implementation Decisions

- 共用个人中心 Modal 的桌面宽度改回 `460px`，首页和房间页同时生效。
- 容量详情不再使用通用自定义 Overlay，改用 Ant Design Modal。
- 容量 Modal 的宽度设置为 `460px`，无 footer，销毁隐藏内容；关闭事件统一更新现有打开状态。
- 保持 Ant Design Modal 默认的遮罩关闭和键盘关闭能力，不禁用 `maskClosable` 或 `keyboard`。
- 容量 Modal 继续使用现有标题翻译键，不新增用户可见文案。
- 容量内容仍由独立的容量面板渲染；只优化结构类名和样式，不改变容量来源、格式化方式和权限判断。
- 房主仍显示五项：总文件大小与上限、共享文件、私密文件、回收站、上传预留。
- 普通成员仍只显示总文件大小与上限。
- 每项容量使用独立卡片行：标签在左，数值在右；数值加粗；长值允许安全收缩，不产生横向溢出。
- 卡片区域采用紧凑间距和内边距，减少弹窗纵向占用。
- 深色主题补齐 Modal 内容量卡片的背景、标签和数值颜色。
- 保留成员列表和分享浮层现有 Overlay，不在本需求中迁移。
- 不修改后端、数据库、API、SSE、容量算法、路由或本地存储。

## Testing Decisions

- 测试面向用户可观察行为，不测试 Ant Design 内部实现。
- 验证个人中心在首页和房间页的桌面宽度均为 `460px`。
- 验证容量详情桌面宽度为 `460px`，移动窄屏不超出视口。
- 验证关闭按钮、遮罩点击和 Esc 均能关闭容量详情。
- 验证房主显示五项容量，普通成员只显示总容量。
- 验证中文、英文、浅色和深色主题下内容可读且无横向溢出。
- 运行现有前端业务逻辑测试、TypeScript 检查和生产构建。
- 本次不新增容量业务测试；现有容量纯逻辑测试继续覆盖数据汇总与角色差异。

## Out of Scope

- 不修改容量计算、容量限额或上传预留规则。
- 不增加容量进度图、饼图、清理按钮或容量管理操作。
- 不迁移成员列表和分享房间浮层。
- 不修改个人中心内部布局、字段或交互。
- 不新增后端接口、数据库字段或翻译键。

## Further Notes

- 两个弹窗统一使用 `460px`，形成更稳定的桌面弹窗尺寸基线。
- 当前项目处于开发阶段，本次无数据迁移或兼容处理。
