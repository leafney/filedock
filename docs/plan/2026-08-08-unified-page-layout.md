# 统一首页与房间页布局 PRD

## Problem Statement

首页和房间页虽然都已有顶部区域，但两页分别维护自己的页面结构：首页使用普通页面流和 `AppFooter`，房间页使用独立的全屏三行网格并让传输栏占用底部行。两页切换时 Header、Footer、内容边界和滚动行为不完全一致，造成页面位置跳变。

房间页还有以下布局问题：

- 房间摘要位于 Header 中央，但倒计时数字宽度变化会导致摘要区域抖动；成员数量、容量和英文文案也可能产生类似位移。
- 桌面端 Header 中的聊天入口与左侧成员列表功能重复。
- 用户头像、昵称右侧下箭头与新的简洁布局不一致，但头像和昵称仍需要整体作为下拉菜单入口。
- 传输记录需要继续位于页面右下角，不能占用公共 Footer 或推动中间内容。
- 房间加入确认、审批等待、加载和错误状态仍是旧版页面，需要先接入统一壳，视觉重做另行规划。
- 品牌链接因 Grid 默认拉伸可能让左侧空白区域也成为可点击的返回首页区域。

## Solution

引入可插槽化的统一 `AppShell`，由路由层承载公共页面骨架。AppShell 负责 Header、Footer、主题背景、页面高度和公共容器；各页面只提供中间内容及可选的 Header/Footer 插槽。

页面采用 CSS Grid 三行结构：`Header / 中间内容 / Footer`，使用 `min-height: 100dvh`，不使用 fixed Header/Footer。首页不设置独立滚动容器，正常情况下作为整体展示；极小视口、浏览器放大或大字体导致内容溢出时允许页面自然滚动。房间页壳本身不滚动，由文件列表、文件动态、回收站、聊天、成员等业务面板自行滚动。

公共 Header 左侧固定品牌链接，中央提供可选房间摘要，右侧提供全局通知和用户下拉入口，并允许注入房间操作。公共 Footer 中间显示版本信息；房间传输浮层作为独立 `footerOverlay` 固定在 Footer 右下角上方，不改变壳高度。

## User Stories

1. 作为普通用户，我希望在首页和房间页看到 Logo、标题和说明位于相同位置，以便切换页面时保持稳定的视觉锚点。
2. 作为普通用户，我希望首页和房间页的用户头像、昵称和通知入口位于相同的右侧区域，以便快速找到个人和通知功能。
3. 作为普通用户，我希望点击品牌 Logo、标题或说明区域可以返回首页，以便快速退出当前房间。
4. 作为普通用户，我不希望品牌左侧的无内容空白区域也能触发返回首页，以免误操作。
5. 作为普通用户，我希望头像和昵称整体仍能打开用户下拉菜单，即使下箭头被移除，也不影响主题、语言和个人设置操作。
6. 作为普通用户，我希望头像与昵称之间有适当间距，以便二者作为整体入口时仍然清晰美观。
7. 作为房间成员，我希望房间 Header 中央继续显示成员数量、剩余时间和房间容量，以便无需进入内容区即可了解房间状态。
8. 作为房间成员，我希望倒计时每秒变化时中央摘要位置不抖动，以便页面保持稳定。
9. 作为房间成员，我希望成员数量、容量变化或英文文案变长时中央摘要仍保持列对齐，以便信息易于比较。
10. 作为英文用户，我希望较长的状态文本优先保持单行，空间不足时显示省略号，并能查看完整内容。
11. 作为房间成员，我希望桌面端不再显示重复的聊天入口图标，以便 Header 右侧更简洁；我仍可点击左侧成员进入聊天。
12. 作为窄屏用户，我希望成员列表隐藏后仍能通过成员入口图标打开成员抽屉。
13. 作为窄屏用户，我希望聊天入口继续存在，以便打开聊天覆盖层。
14. 作为房主或成员，我希望房间页右侧保留分享房间入口，并与通知和用户入口合理排列。
15. 作为普通用户，我希望首页中央为空时 Header 仍保持左右区域稳定，不因为缺少房间摘要而改变品牌或用户区位置。
16. 作为房间成员，我希望传输任务提示位于 Footer 右下角，不遮挡 Footer 中央版本信息。
17. 作为房间成员，我希望展开传输任务面板时不改变 Header、Footer 和中间工作区高度，以免文件列表发生跳动。
18. 作为房间成员，我希望上传或下载开始时传输面板自动展开，任务完成后 5 秒自动收回，延续现有行为。
19. 作为普通用户，我希望 Footer 中间优先显示版本号；没有版本号时显示短 Commit ID。
20. 作为普通用户，我希望悬停或键盘聚焦 Footer 版本信息时看到版本号、短 Commit ID 和构建时间等可用信息。
21. 作为普通用户，我希望点击 Footer 版本信息复制短 Commit ID，而不是复制版本号。
22. 作为普通用户，我希望复制成功或失败时获得清晰的中文或英文反馈。
23. 作为局域网访问用户，我希望通过 `127.0.0.1` 或局域网 IP 的 HTTP 地址也能正常复制 Commit ID。
24. 作为键盘用户，我希望可以聚焦 Footer 版本按钮并通过 Enter 或 Space 执行复制。
25. 作为本地开发用户，当版本号和 Commit ID 都不可用时，我希望 Footer 显示 `dev`，而不是显示容易误解的短横线。
26. 作为房间访客，我希望加入确认、审批等待、加载和异常状态页面也使用统一 Header/Footer，以便状态变化时页面骨架不跳变。
27. 作为房间访客，我希望未成功加入房间时不显示房间摘要、分享和传输等需要房间权限的内容。
28. 作为后续页面开发者，我希望通过 `headerCenter`、`headerActions`、`footerOverlay` 和 `content` 等插槽复用页面壳，而不是修改公共组件中的页面判断。
29. 作为用户，我希望本次布局重构不改变首页、房间页、分享弹层和复制邀请链接的现有 URL 与行为。
30. 作为用户，我希望浅色、深色和跟随系统三种主题下 Header/Footer 都与当前页面背景协调，而不是出现突兀的独立背景。

## Implementation Decisions

### 页面壳与路由

- 新增可复用 `AppShell`，由路由层统一承载；路由切换只替换中间内容和可选插槽。
- AppShell 提供 `headerCenter`、`headerActions`、`footerOverlay` 和 `content` 四个组合区域。
- 保持现有路由：首页 `/`，房间及所有房间过渡状态 `/rooms/:code`；不新增或修改 URL。
- 分享继续作为房间页内的弹层，不改为新路由。
- AppShell 使用 `min-height: 100dvh` 和 CSS Grid 三行布局，不使用 fixed Header/Footer。

### 公共 Header

- 左侧品牌链接只包裹 Logo、标题和说明的实际内容，使用内容宽度定位，禁止空白列区域触发跳转。
- 品牌区域始终链接 `/`，保留可访问名称和键盘焦点样式。
- 右侧公共区域顺序为通知入口、用户头像和用户昵称；头像/昵称整体为 Dropdown 触发按钮。
- 首页和房间页均移除用户下箭头；头像与昵称之间统一约 `0.5rem` 间距。
- 房间页桌面端移除聊天入口图标；聊天仍通过左侧成员列表进入。
- 房间页窄屏保留聊天入口；当成员列表被隐藏时显示成员入口图标。
- 房间页通过 `headerCenter` 显示成员、剩余时间、房间容量，通过 `headerActions` 显示分享及响应式房间操作。
- 桌面端房间操作排列为分享、通知、用户头像/昵称；不再加入桌面成员图标。窄屏沿用现有成员/聊天入口规则。

### 房间中央摘要

- 三项摘要使用固定或可控的网格列宽，避免任一项变化导致其他项位移。
- 剩余时间按最大显示格式预留宽度，数字使用 `font-variant-numeric: tabular-nums` 或等效等宽数字。
- 成员、容量和剩余时间文本默认单行；空间不足时 `text-overflow: ellipsis`，禁止自动换行。
- 中文和英文可以使用不同的最小宽度或网格配置；英文按较长状态文本适配。
- 被截断的信息提供 Tooltip 或 `title`；手机端使用现有容量详情等入口，不依赖悬停。
- `<=760px` 隐藏中央摘要，保持现有移动端规则。

### 公共 Footer 与版本信息

- 所有页面统一使用 `AppFooter`，Footer 位于页面壳第三行且高度一致。
- 桌面端保留轻量 Info 图标；图标与版本文本共同组成可点击按钮。移动端可隐藏图标，仅显示版本文本。
- 显示值：有版本号时显示版本号；无版本号时显示短 Commit ID；两者都没有时显示 `dev`。
- Tooltip 动态显示可用字段：版本号（如有）、短 Commit ID（如有）、构建时间（如有）。不显示无意义的 `-`。
- 点击复制短 Commit ID；无 Commit ID 时不复制并显示 i18n 提示。
- 复制使用现有公共 Clipboard 工具，兼容安全上下文 Clipboard API 和 HTTP legacy fallback。
- 新增复制成功、复制失败和无 Commit ID 提示时，必须补齐 `zh-CN` 与 `en` 翻译键。

### 传输浮层

- `TransferBar` 不再占用公共 Footer 的网格行，作为 `footerOverlay` 注入 AppShell。
- 传输摘要按钮和展开面板固定在 Footer 右下角上方；不影响 Footer 中央版本信息。
- 继续支持任务开始自动展开、任务完成后停留 5 秒并自动收回。
- 桌面端沿用右下角面板宽度和最大高度；移动端根据安全区使用全宽底部面板，但不得遮挡 Footer 版本入口。

### 页面背景与主题

- 首页和房间中间内容保留各自页面背景和面板层级。
- Header/Footer 使用页面级主题变量，与当前页面保持同色系并通过轻微层次和边框区分。
- 浅色、深色、跟随系统模式均需覆盖 AppShell、Header、Footer、Tooltip 和传输浮层。

### 过渡页

- `RoomGate`、加载、加入确认、审批等待、异常和失效状态接入 AppShell。
- 这些状态只显示公共 Header/Footer 和状态内容，不显示房间专属摘要、分享或传输浮层。
- 本 PRD 不重做过渡页中间卡片和业务交互；其视觉重构另立下一阶段 PRD。

### 兼容性与业务边界

- 不修改后端 API、数据库、URL、通知和分享业务逻辑。
- 不改变房间文件、聊天、传输任务本身的状态管理，只调整其容器和入口位置。
- 新增或修改的用户可见文案全部使用 i18n，补齐 `zh-CN` 和 `en`。

## Testing Decisions

- 重点验证外部行为和视觉布局，不测试 CSS 私有实现细节。
- 复用现有前端测试体系，必要时为 Footer 版本选择逻辑、复制回退和摘要格式化增加边界测试。
- 验证首页、房间成功页、房间加载页、加入确认页、审批等待页、错误/失效页均使用相同 Header/Footer 骨架。
- 验证中文/英文、浅色/深色/跟随系统、桌面/平板/手机断点。
- 验证三项中央摘要不会因倒计时、成员数量、容量数值或英文文案变化而横向抖动；长文本单行省略且 Tooltip 可查看完整值。
- 验证 Header 品牌链接只有实际品牌内容可点击，周围空白不能触发跳转。
- 验证房间桌面端不显示聊天入口和成员入口，窄屏端按现有规则显示聊天/成员入口。
- 验证 Footer 点击复制短 Commit ID，覆盖 `http://127.0.0.1`、局域网 HTTP、HTTPS、鼠标点击、键盘 Enter/Space、成功和失败反馈。
- 验证传输浮层位于 Footer 右下角，展开/收回不改变页面壳高度，且不遮挡 Footer 中央版本信息。
- 自动验证：`bun test`、`bun run build`、`make build`、`git diff --check`。
- 完成自动验证后进行浏览器手动验证，并保留现有功能回归检查。

## Out of Scope

- 不修改首页、房间页和分享弹层的 URL 路由。
- 不重做加入确认、审批等待、加载和异常过渡页的中间内容视觉；仅接入公共页面壳。
- 不新增房间、聊天、通知、文件、上传、下载或回收站业务功能。
- 不修改后端 API、数据库结构、SSE、权限和状态机。
- 不改变现有移动端成员抽屉、聊天覆盖层和房间工作区功能，仅适配公共壳。
- 不把房间传输任务并入 Footer 中间版本信息区域。
- 不支持复制完整 Commit ID；本阶段只复制短 Commit ID。
- 不引入新的页面专属硬编码 Header/Footer 分支，后续页面通过插槽扩展。

## Further Notes

- 本 PRD 的实现顺序建议为：先抽取 AppShell 和公共容器，再接入首页与房间成功页，随后接入 RoomGate 状态，最后调整 Header/Footer 细节、传输浮层和复制反馈。
- 每个主要阶段完成后提交 Git，提交信息遵循项目 Conventional Commits 规则。
- 过渡页中间内容视觉优化作为下一阶段重点，建议在本阶段完成并手动验证后另行 grill-me 和 PRD。
