# 文件动态操作卡片合并优化 PRD

## Problem Statement

一次上传、下载或其他文件操作会产生多条动态记录，导致文件动态列表高度膨胀、信息重复，用户难以快速判断当前状态。私密文件转发还涉及多个接收者及后续接受/拒绝状态，如果简单按事件显示，会把一个完整生命周期拆散，且可能泄露接收者信息。

## Solution

后端为每次文件操作分配独立 `operationId`，保留所有原始事件，并在查询时按“文件 + operationId”聚合。前端每个操作只展示一张紧凑卡片，卡片显示最新状态；用户通过三点入口查看该操作的完整历史。

上传、下载、转发、回收、恢复、永久删除分别属于独立操作。私密文件转发卡片覆盖“转发、待接收、已接收/已拒绝”生命周期；下载和后续删除等操作不会修改转发卡片。SSE 在状态变化后推送聚合卡片更新。

## User Stories

1. 作为房间成员，我希望一次上传只看到一张动态卡片，以便快速了解上传结果。
2. 作为房间成员，我希望上传卡片能显示最新的完成、失败或取消状态。
3. 作为房间成员，我希望查看上传卡片的完整历史，以便了解创建、开始和终态时间。
4. 作为房间成员，我希望批量上传的每个文件独立展示，以便定位单个文件失败原因。
5. 作为房间成员，我希望同一文件的多次下载分别展示，以便区分不同下载任务。
6. 作为房间成员，我希望下载中能看到进度或“下载中”状态。
7. 作为房间成员，我希望下载失败或取消后卡片保留最终状态。
8. 作为房间成员，我希望重新下载创建新卡片，不覆盖历史失败记录。
9. 作为房间成员，我希望断点续传沿用原下载任务卡片。
10. 作为私密文件上传者，我希望再次转发历史文件时生成独立卡片，以便区分每一次转发。
11. 作为私密文件上传者，我希望一次转发多个文件时每个文件各有一张卡片。
12. 作为私密文件上传者，我希望同一文件转发给多人时只显示一张卡片。
13. 作为私密文件上传者，我希望转发卡片显示接收者数量。
14. 作为私密文件上传者，我希望在详情中查看完整接收者名单。
15. 作为私密文件上传者，我希望看到每名接收者从待处理到接受或拒绝的状态时间线。
16. 作为私密文件上传者，我希望部分接收者已存在时只统计本次真正新增的接收者。
17. 作为私密文件上传者，我希望所有接收者均无需变化时不产生重复动态卡片。
18. 作为私密文件上传者，我希望接收者拒绝后再次转发时生成新的操作卡片。
19. 作为私密文件接收者，我希望看到发给我的私密文件及自己的接收状态。
20. 作为私密文件接收者，我不希望看到同一转发操作中的其他接收者信息。
21. 作为房主，我希望私密文件动态使用文件编号而非真实文件名。
22. 作为房主，我希望私密转发动态只显示接收者数量，不泄露成员名单。
23. 作为普通成员，我不希望看到与自己无关的私密转发动态。
24. 作为文件上传者，我希望删除、恢复和永久删除各自产生独立卡片。
25. 作为房间成员，我希望删除、恢复和永久删除不会修改之前的上传、转发或下载卡片。
26. 作为房间成员，我希望房间内动态状态变化通过 SSE 实时更新。
27. 作为房间成员，我希望卡片按最新事件时间排序，更新后的卡片移动到顶部。
28. 作为房间成员，我希望重新进入页面时直接看到最新状态，不重复播放历史动画。
29. 作为房间成员，我希望桌面端卡片尽量单行显示，长文件名自动省略。
30. 作为移动端用户，我希望卡片最多两行且不出现横向滚动。
31. 作为房间成员，我希望通过三点图标查看操作的完整状态历史。
32. 作为键盘用户，我希望聚焦三点图标时可以打开历史详情并按 Esc 关闭。
33. 作为移动端用户，我希望点击三点图标打开底部详情抽屉。
34. 作为房间成员，我希望历史记录按时间倒序展示。
35. 作为房间成员，我希望长历史支持加载更多，而不是一次渲染大量内容。
36. 作为产品维护者，我希望所有新增文案同时支持简体中文和 English。

## Implementation Decisions

- 在文件事件模型中增加独立操作标识；每个文件的一次上传、下载、转发、回收、恢复、永久删除使用独立标识。
- 原始文件事件继续 append-only 保存；聚合查询不删除、不改写原始事件。
- 聚合键为文件与操作标识。事件类型仅在同一操作生命周期内合并。
- 上传操作合并创建、开始、完成、失败、取消事件。
- 下载操作按 `downloadTaskId` 合并开始、完成、失败、取消；新任务创建新卡片，断点续传沿用原任务。
- 转发操作为同步操作，成功直接进入“已转发”状态，失败进入“转发失败”状态并保存安全的失败原因。
- 转发接受者状态沿用转发操作标识，接受或拒绝更新同一张卡片，不创建新的接受/拒绝卡片。
- 同一文件转发给多人时，主卡片显示接收者总数和已接收、待处理、已拒绝数量；详情按接收者展示时间线。
- 转发时仅统计本次实际新增或重置的接收关系；无实际变化时不创建动态卡片。
- 被拒绝后再次转发生成全新的操作标识和卡片。
- 接受或拒绝不新增全局通知；保留新文件 `file_received` 和拒绝 `file_declined` 通知。房间动态状态通过 SSE 更新。
- 接收完成后的下载是独立下载操作，不修改转发卡片。
- 删除、恢复、永久删除均创建独立操作卡片，不与上传、转发、下载合并。
- 动态卡片按最新事件时间倒序排列；状态变化后卡片移动到顶部；首次加载不回放历史动画。
- 桌面端卡片采用单行紧凑布局：状态、操作用户与文件名、大小/共享或私密、时间、三点入口。长文件名省略；移动端最多两行，不允许横向滚动。
- 三点入口支持桌面悬停、点击、键盘聚焦和移动端触摸；移动端使用底部抽屉。点击外部或 Esc 关闭；详情只读，历史倒序，超过 50 条加载更多。
- 私密转发权限投影：转发者可见真实文件名和完整接收者名单；接收者只见自己的关系；房主只见私密文件编号和接收者数量；无关成员不可见。
- 文件进入回收站时保留动态并新增删除卡片；恢复新增恢复卡片；永久删除后保留必要占位信息并脱敏。房间失效后停止展示和 SSE 更新，原始事件按既定清理周期保留。
- 后端 API 返回聚合卡片、最新状态、操作标识、历史事件及按权限投影后的详情；前端不负责业务聚合。
- 新增或修改的 API 错误、SSE 提示和前端文案使用 i18n 翻译键，同时提供 `zh-CN` 与 `en`。

## Testing Decisions

- 测试外部行为，不绑定内部实现细节。
- 后端聚合服务：验证同一操作的事件合并、不同操作不合并、最新时间排序、游标分页和重新加载结果。
- 转发状态机：验证多人转发的新增/跳过统计、接受/拒绝聚合、拒绝后再次转发生成新卡片、全拒绝/全接受/混合状态。
- 权限投影：验证转发者、接收者、房主和无关成员看到的文件名、接收者名单及卡片可见性。
- 下载状态：验证同一 `downloadTaskId` 更新原卡片、新任务创建新卡片、失败/取消/完成终态。
- SSE：验证状态变化只推送对应房间和有权限的聚合更新。
- 前端展示逻辑：验证状态数量、长文件名省略、移动端两行布局数据和详情打开/关闭行为；优先测试可抽离的状态格式化函数。
- i18n：验证所有新增翻译键在简体中文和英文词典中完整存在。
- 不为纯样式像素差异单独编写测试。

## Out of Scope

- 文件预览功能。
- 下载断点续传协议本身的新增实现；本 PRD 只定义动态卡片如何反映已有下载任务状态。
- 全局通知中心新增“接受私密文件”通知。
- 多端同步操作草稿或动态状态的额外持久化。
- 修改房间顶部通用样式及其他无关页面布局。

## Further Notes

- 当前项目仍处于开发阶段，表结构和业务逻辑允许直接调整，不要求旧接口和旧数据兼容。
- 建议先完成后端事件关联与聚合 API，再实现 SSE 投影，最后调整前端卡片和详情交互。
- 实现阶段每个主要阶段完成后提交 Git，提交信息遵守 Conventional Commits，描述使用简体中文。
