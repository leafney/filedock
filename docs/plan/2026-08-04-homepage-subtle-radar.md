# 首页轻量全域雷达波优化开发 PRD

Related discussion: [docs/discuss/2026-08-04-homepage-subtle-radar.md](../discuss/2026-08-04-homepage-subtle-radar.md)

- 日期：2026-08-04
- 状态：已完成，待人工验收
- 变更类型：前端视觉动效增量修订
- 前置规格：`docs/plan/2026-08-03-homepage-water-ripple.md`
- 影响范围：首页雷达波、雷达范围计算、移动端动效、减少动态效果、装饰节点呼吸

## Problem Statement

当前首页已经把固定圆环改为连续扩散水波，并把最大直径提高到右侧雷达面板宽度的 `80%`。人工验收截图表明，这一方案仍未达到目标。

首先，水波在传播过程中存在两次明显加深，最高透明度分别为 `45%` 和 `35%`，并叠加同色柔光。多个清晰圆环同时占据页面中心，使雷达成为首页第一视觉焦点，压过昵称设置、房间操作和用户身份。用户更希望雷达保持早期版本“微微可见”的背景氛围。

其次，之前把用户所说的“右侧 80%”错误理解为雷达面板内部宽度的 `80%`。用户实际指的是截图红框表示的完整右侧雷达面板。仅按宽度计算圆形终点无法覆盖矩形面板四角；主要可见峰值又只传播到动画中段，导致外侧房间节点看起来位于雷达范围之外。

最后，节点本体呼吸峰值 `1.08` 在实际页面中仍不明显。雷达波降低为背景后，周围节点需要通过稍清楚但仍平滑的本体呼吸表达局域网活跃状态。

本增量 PRD 需要终止水波模型，改为轻量单峰雷达波；按面板对角线覆盖完整雷达区域；降低桌面与移动端视觉强度；并把节点呼吸峰值提高到 `1.12`。前置 PRD 中已经正确实现的中心对齐、纯展示语义、节点错峰和裁剪规则继续保留。

## Solution

首页雷达改为四个低对比度脉冲。每圈仍从中心头像外缘约 `10px` 处开始，但单圈周期延长到 `8s`，相邻波纹错峰 `2s`。透明度只出现一次峰值：在动画 `8%` 达到桌面 `12%`，之后持续下降，在 `55%` 为 `6%`、`92%` 为 `2%`、终点为 `0`。删除圆环柔光，只保留 `1px` 青绿色细线，使雷达退回背景层。

最大直径改为雷达面板对角线的 `105%`。圆形波纹从中心扩散时能够扫过矩形面板四角及所有合法节点位置；超出面板的部分由现有裁剪隐藏。终点继续通过现有尺寸观察机制更新，不新增观察器或逐帧 React 状态。

移动端沿用四圈、`8s`、`2s` 和对角线范围，但峰值降为 `8%`，中段与外段按相同比例降低。减少动态效果模式停止所有动画，只显示三圈 `5% / 3% / 1%` 静态细环。

周围节点呼吸由 `1 → 1.08 → 1` 调整为 `1 → 1.12 → 1`，周期和错峰保持不变。雷达线经过节点时不触发闪烁、缩放或变色；节点标签、中心头像和所有交互语义不变。

## User Stories

1. 作为首页用户，我希望雷达波只是微弱背景，以便首先关注昵称设置和房间操作。
2. 作为首页用户，我希望雷达不再出现两次明显加深，以便页面不会产生强烈水波感。
3. 作为首页用户，我希望单圈出现后持续渐淡，以便更接近雷达脉冲而不是靶环。
4. 作为首页用户，我希望同屏清晰圆环数量减少，以便长时间查看页面不会眼晕。
5. 作为首页用户，我希望圆环不带柔光，以便线条不会扩大成高对比发光带。
6. 作为首页用户，我希望圆环保持 `1px` 青绿色细线，以便仍能识别 FileDock 雷达语义。
7. 作为首页用户，我希望波纹缓慢扩散，以便动画不会制造急促感。
8. 作为首页用户，我希望雷达持续发射，以便中心区域不会长时间完全静止。
9. 作为首页用户，我希望首次进入页面时已有错峰波纹，以便不会看到圆环同时从中心启动。
10. 作为首页用户，我希望雷达波覆盖完整右侧面板，以便所有房间节点都显得位于发现范围内。
11. 作为首页用户，我希望波纹能够扫过面板四角，以便红框区域不是只有中间部分具有雷达效果。
12. 作为首页用户，我希望波纹接近外侧节点时仍微弱可见，以便外侧节点与雷达存在空间联系。
13. 作为首页用户，我希望波纹超出面板时被裁剪，以便不会覆盖左侧操作栏、顶栏或页脚。
14. 作为首页用户，我希望波纹经过节点时节点保持稳定，以便不会误认为出现通知或可点击状态。
15. 作为首页用户，我希望房间节点本体呼吸稍明显，以便雷达减弱后页面仍有活跃感。
16. 作为首页用户，我希望节点呼吸保持平滑错峰，以便五个节点不会同步跳动。
17. 作为首页用户，我希望节点标签不随本体缩放，以便房间号持续清晰。
18. 作为首页用户，我希望中心头像保持静止，以便页面仍有稳定视觉锚点。
19. 作为移动端用户，我希望雷达比桌面更淡，以便小画布不会被圆环占据视觉焦点。
20. 作为移动端用户，我希望雷达仍覆盖完整画布，以便外侧节点没有脱离发现范围。
21. 作为减少动态效果的用户，我希望雷达扩散和节点呼吸停止，以免持续运动造成不适。
22. 作为减少动态效果的用户，我希望保留极淡静态圆环，以便页面仍能表达雷达结构。
23. 作为键盘用户，我希望装饰波纹和节点不进入焦点顺序，以便不会访问无操作内容。
24. 作为屏幕阅读器用户，我希望随机装饰节点继续被隐藏，以便不会误认为它们是真实房间。
25. 作为维护者，我希望复用现有尺寸观察器，以便不增加重复生命周期。
26. 作为维护者，我希望终点只在画布尺寸变化时计算，以便动画不产生逐帧 React 渲染。
27. 作为维护者，我希望节点生成、替换和避让算法保持不变，以便视觉修订不扩张业务风险。
28. 作为维护者，我希望本次不新增依赖和文案，以便构建与中英文词典保持稳定。
29. 作为维护者，我希望现有测试和生产构建继续通过，以便确认没有结构回归。

## Implementation Decisions

### 1. 增量变更边界

- 本 PRD 覆盖 2026-08-03 前置规格中的波纹数量、范围、周期、透明度、柔光、移动端强度、静态环强度和节点呼吸峰值。
- 前置规格中的头像与波纹同心、`132px` 起点、层级、裁剪、节点纯展示语义、标签不缩放、中心头像不呼吸继续有效。
- 不修改首页双栏布局、左侧 `300px` 操作区、`900px` 响应式断点、房间卡、昵称、顶栏、后端、API 或房间页面。
- 不新增依赖、Canvas、SVG 动画库、JavaScript 逐帧动画或计时状态。

### 2. 波纹结构与数量

- 正常模式由五个波纹元素减少为四个。
- 四个元素共用同一基础直径、终点、颜色、边框和关键帧。
- 删除第五个波纹元素及其延迟规则，不能仅通过透明度隐藏后继续保留无用动画。
- 波纹继续位于房间节点和中心头像下方，禁止指针事件并对辅助技术隐藏。

### 3. 起点与终点

- 基础直径继续为约 `132px`，即距离 `112px` 头像外缘单侧约 `10px`。
- 每次雷达画布尺寸有效变化时，同时使用宽度和高度计算对角线。
- 最大直径目标为“面板对角线 × `105%`”。
- 终点缩放系数等于“最大直径目标 ÷ `132px`”，且不得小于 `1`。
- 复用当前 `ResizeObserver` 回调更新终点和静态环参数；不得创建第二个观察器。
- 终点计算不得再使用宽度 `80%`、较短边或固定桌面像素值。
- 圆形波纹超过矩形面板的部分继续由雷达画布裁剪。对角线 `105%` 应确保终点超过四角距离，使线条完整扫过全部合法节点区域。

### 4. 静态环位置参数

- 减少动态效果继续复用前三个波纹元素作为静态环，第四个隐藏。
- 三圈位置均在 `132px` 起点与对角线 `105%` 终点之间插值。
- 建议位置进度为约 `24% / 58% / 90%`，分别覆盖中心、中段和接近外侧区域。
- 静态位置通过现有 CSS 自定义属性提供；桌面和移动端尺寸变化时必须同步更新。

### 5. 桌面时间模型

- 单圈周期由 `5s` 调整为 `8s`。
- 相邻波纹错峰由 `1s` 调整为 `2s`。
- 四个波纹延迟分别约为 `0s / -2s / -4s / -6s`。
- 继续使用负延迟，首屏必须直接进入稳定相位，不能让四圈先重叠再散开。
- 缩放使用 `linear` 匀速，从 `scale(1)` 到响应式终点缩放系数。
- 一个周期结束时透明度必须为 `0`，避免外圈瞬间跳回中心。

### 6. 桌面透明度关键帧

- `0%`：透明度 `0`，位于起点。
- `8%`：透明度 `12%`，为唯一峰值。
- `55%`：透明度 `6%`。
- `92%`：透明度 `2%`，此时圆环已接近对角线终点并能扫过外侧节点。
- `100%`：透明度 `0`，到达最大直径。
- `8%` 之后透明度必须单调下降，不允许增加第二峰值或奇偶圈强弱差异。
- 数值代表最终元素可见度。边框使用完整青绿色并由元素 `opacity` 控制，避免透明度重复相乘后低于目标。

### 7. 边框与柔光

- 圆环保持 `1px` FileDock 青绿色实线边框。
- 删除波纹元素的 `box-shadow`、滤镜、伪元素光晕及对应柔光颜色变量。
- 不增加虚线、粗线、实心填充、多色渐变、扫描扇形或粒子。

### 8. 移动端强度

- 在现有移动端断点内覆盖雷达透明度变量，不创建第二套关键帧或 DOM。
- 移动端唯一峰值为 `8%`。
- 中段按桌面相同比例降为约 `4%`，外段降为约 `1%`，起点与终点仍为 `0`。
- 移动端继续使用四圈、`8s`、`2s` 错峰和对角线 `105%` 范围。
- 移动端不得通过缩短终点或隐藏外圈来降低强度。

### 9. 节点呼吸

- 稳定可见节点呼吸关键帧从 `scale(1) → scale(1.08) → scale(1)` 改为 `scale(1) → scale(1.12) → scale(1)`。
- 五个槽位继续使用现有 `2.8～4.2s` 周期和负延迟，不改变节奏。
- 圆内数字、边框和基础阴影随头像本体缩放；四位房间号标签不缩放。
- 进入和退出动画继续作用于节点外层，呼吸作用于头像内层，避免 `transform` 冲突。
- 中心头像不呼吸，不恢复彩色外扩光圈。

### 10. 节点与雷达波关系

- 雷达波经过节点时不添加任何检测或状态联动。
- 不使用碰撞计算、动画事件、距离监听或逐帧判断波纹是否经过节点。
- 节点不因雷达波闪烁、变色、缩放、改变阴影或显示提示。
- 节点继续禁止指针事件、不可聚焦，并对辅助技术隐藏。

### 11. 减少动态效果

- 运行时减少动态类名与 `prefers-reduced-motion: reduce` 媒体查询必须同时覆盖，避免首屏短暂动画。
- 停止雷达扩散、节点呼吸、节点进入和退出动画。
- 只显示三圈静态雷达环，透明度依次为 `5% / 3% / 1%`；隐藏第四圈。
- 静态环使用对角线终点派生的内、中、外三组缩放参数。
- 静态节点、中心头像、昵称和标签继续显示，雷达画布不得塌陷。

### 12. i18n 与性能

- 本阶段不新增或修改用户可见文案，不新增翻译键。
- React 组件不得新增硬编码说明文案。
- 动画只修改 `transform` 和 `opacity`，不得在关键帧中修改布局尺寸。
- 尺寸变化只更新少量 CSS 自定义属性和现有节点布局；不得增加逐帧状态更新。

### 13. 实施顺序

1. 把终点公式改为面板对角线 `105%`，同步调整三圈静态位置进度。
2. 把波纹元素从五个减少到四个。
3. 把周期改为 `8s`、错峰改为 `2s`，重写单峰透明度关键帧。
4. 删除圆环柔光和对应样式变量。
5. 增加移动端 `8% / 4% / 1%` 低强度覆盖。
6. 把节点呼吸峰值提高到 `1.12`。
7. 更新减少动态效果为三圈 `5% / 3% / 1%` 静态环。
8. 运行自动检查并执行人工浏览器验收。

## Acceptance Criteria

### 轻量雷达波

1. 正常模式只运行四个雷达波实例。
2. 每圈从约 `132px` 直径开始。
3. 单圈周期约 `8s`，相邻波纹错峰约 `2s`。
4. 首屏四圈处于不同传播相位，不在中心重叠启动。
5. 波纹以匀速从中心扩散到终点。
6. 桌面透明度按 `0 / 12% / 6% / 2% / 0` 变化。
7. `8%` 后透明度持续下降，没有第二次加深。
8. 同屏不再出现多个高对比完整圆环。
9. 波纹保持 `1px` 青绿色细线。
10. 波纹没有柔光、阴影、滤镜或发光伪元素。
11. 雷达视觉权重低于昵称设置卡、房间卡、中心身份和彩色节点。

### 全域覆盖

12. 最大直径约为当前雷达面板对角线 `105%`。
13. 改变面板宽度或高度后，终点根据新对角线更新。
14. 波纹能够扫过面板上下左右边缘及四角。
15. 所有合法位置的外侧房间节点都会被微弱波纹经过。
16. 超出面板的圆环部分被雷达画布裁剪，不覆盖页面其他区域。
17. 终点计算不再使用面板宽度 `80%` 或较短边。

### 移动端

18. 移动端继续显示四个错峰雷达波。
19. 移动端峰值约 `8%`，中段约 `4%`，外段约 `1%`。
20. 移动端周期、错峰和全域范围与桌面一致。
21. 移动端雷达不盖过昵称、房间卡或中心身份的视觉优先级。

### 节点呼吸与语义

22. 五个稳定节点本体在 `1` 与 `1.12` 之间呼吸。
23. 五节点继续使用 `2.8～4.2s` 不同周期和不同相位。
24. 圆内数字、边框和基础阴影随本体缩放。
25. 四位房间号标签保持静止。
26. 中心头像不呼吸，节点周围没有外扩彩色光圈。
27. 雷达波经过节点时，节点不闪烁、不变色、不额外缩放。
28. 节点不可点击、不可聚焦、无悬停提示，并继续对辅助技术隐藏。

### 减少动态效果

29. 开启减少动态效果后，雷达扩散停止。
30. 开启减少动态效果后，节点呼吸、进入和退出动画停止。
31. 只显示三圈 `5% / 3% / 1%` 静态雷达环。
32. 静态环覆盖中心、中段和外侧，不全部重叠在起点。
33. 静态环随面板对角线更新，页面布局不塌陷。

### 回归与质量

34. 首页左侧操作区、右侧雷达、`900px` 断点和移动端顺序不变。
35. 昵称设置、房间列表、创建、加入、进入及顶栏行为不变。
36. 雷达继续维护五个随机装饰节点及原有生命周期。
37. 中心头像、昵称和波纹继续严格同心。
38. 没有新增用户可见硬编码文案或不完整翻译键。
39. 现有前端测试全部通过。
40. TypeScript 编译和生产构建通过。
41. `git diff --check` 通过。
42. 浏览器控制台没有新增 React 警告、ResizeObserver 循环或未捕获异常。

## Testing Decisions

- 本阶段只修改视觉参数、装饰 DOM 数量和响应式终点公式，不包含业务规则、鉴权、支付或复杂状态转换；按照项目规则不新增单元测试。
- 现有节点生成、避让和生命周期算法不修改，不为随机装饰数据增加测试。
- 自动检查继续运行正式前端测试、历史原型测试、TypeScript 编译、生产构建和 `git diff --check`。
- 不使用 Playwright。动效强度、全域覆盖和节点呼吸采用人工浏览器验收。
- 桌面建议使用约 `1440×900`，持续观察至少 `16s`：确认两轮完整传播、单峰持续渐淡、波纹扫过四角和外侧节点、节点错峰呼吸。
- 在桌面拖动窗口宽度和高度：确认对角线终点及时更新，没有观察器警告、布局跳动或波纹永久停留。
- 移动端建议使用约 `390×844`：确认峰值低于桌面、全域覆盖保留、操作区和中心身份仍为视觉重点。
- 开启减少动态效果：确认只显示三圈极淡静态环，雷达和节点动画全部停止。
- 鼠标经过节点并等待雷达线经过：确认节点没有悬停或波纹联动反馈。
- 人工验收期间检查控制台，不得出现新增错误或警告。

## Further Notes

- “红框区域”指截图中完整右侧雷达面板，不是面板内部宽度的 `80%`。
- 圆形波纹覆盖矩形四角所需直径为面板对角线；额外 `5%` 用于确保边缘和合法节点位置被完整扫过。
- “扫过四角”不表示四角始终显示圆环。波纹经过后会继续扩散并消失。
- 桌面 `12%`、移动端 `8%` 是元素最终透明度，不应再与半透明边框或柔光相乘。
- 外段 `2%` 有意保持极淡，只用于建立外侧节点属于雷达范围的空间联系。
- 四个波纹实例配合 `8s` 周期和 `2s` 错峰，可形成稳定连续波列，无需 JavaScript 定时创建 DOM。
- 节点呼吸提高到 `1.12` 后仍只作用于头像本体，标签与节点定位盒不参与缩放。
- 本 PRD 获得用户明确批准后才能修改生产代码。
