# FileDock 房间工作区交互原型 PRD

## Problem Statement

FileDock 新版首页已经使用浅色视觉系统、蓝绿色强调色和 Ant Design 风格组件，但生产房间页仍是旧深色界面。现有房间页只承载房间信息、成员列表、加入申请和生命周期操作，没有为共享文件、定向文件、文件历史、一对一聊天、上传下载进度和回收站预留稳定布局。桌面右栏大部分时间为空，二维码常驻页面底部，移动端只是把桌面区块纵向堆叠，无法表达“文件操作优先”的产品目标。

直接修改生产 `RoomPage` 风险过高：未来文件与聊天业务尚未实现，原始 PRD 的“全部文件定向可见”规则也已被本轮讨论推翻。若先编码生产页面，后续业务字段、权限投影、容量口径或移动布局变化会造成重复返工。

当前需要一个与生产代码完全隔离、可离线运行、可切换角色和状态的交互原型。原型必须同时验证桌面 PC 微信式三栏工作区、文件优先的移动布局，以及共享／定向双作用域、单一文件时间轴、回收站容量、匿名私密文件、传输进度和一对一聊天等关键产品决策。

## Solution

在仓库 `examples/room-workspace-prototype/` 下制作零依赖的原生 HTML、CSS、JavaScript 原型。原型不引用生产前端，不修改现有 Vite 配置、路由、依赖、API、数据库或构建流程；通过简单静态 HTTP 服务即可离线访问。

桌面端使用固定房间顶栏、左侧成员／会话栏、中间文件主区、右侧一对一聊天和全局传输任务栏。中间文件主区提供共享上传、定向发送、历史文件复用，并通过“文件列表／文件动态／回收站”三个视图表达当前文件、详细操作历史和可恢复删除。

移动端不复制桌面三栏，也不把文件、聊天、成员做成三个等权 Tab。默认主界面只突出文件列表、文件动态、回收站、上传、定向发送和下载；聊天通过未读入口进入二级全屏页，成员通过抽屉查看，管理动作收入更多菜单。

原型内置可重复的模拟数据、权限投影、容量计算和传输进度。一个明确标注“仅原型”的演示控制器允许评审者切换房主／成员、中文／English、回收站计费策略、加入状态和文件状态。原型必须能展示用户实际可观察的交互，但不得假装调用真实服务。

## User Stories

1. 作为房间成员，我希望进入页面后立即看到房间号、剩余时间和容量，以便确认当前房间状态。
2. 作为桌面用户，我希望房间页面像 PC 微信一样紧凑稳定，以便长时间停留和操作。
3. 作为桌面用户，我希望成员、文件和聊天同时可见，以便减少频繁跳页。
4. 作为平板用户，我希望成员栏在空间不足时收进抽屉，以便文件与聊天仍有足够宽度。
5. 作为手机用户，我希望默认看到文件列表，以便快速上传和下载。
6. 作为手机用户，我希望聊天和成员成为二级页面，以便非主要功能不挤占文件空间。
7. 作为手机用户，我希望关键上传按钮始终容易触达，以便单手选择文件。
8. 作为用户，我希望复制房间号，以便发送给附近的人。
9. 作为用户，我希望查看房间二维码，以便其他设备快速加入。
10. 作为房主，我希望看到待处理加入申请数量，以便及时审批。
11. 作为房主，我希望从更多菜单延期或解散房间，以便主界面保持简洁。
12. 作为普通成员，我希望从更多菜单退出房间，以便避免误触危险操作。
13. 作为用户，我希望文件列表默认打开，以便直接查看当前可用文件。
14. 作为用户，我希望文件列表和文件动态明确分开，以便不会把文件集合与操作日志混淆。
15. 作为用户，我希望回收站有独立入口，以便查看可恢复文件。
16. 作为用户，我希望搜索文件名，以便快速找到目标文件。
17. 作为用户，我希望按公共、定向、我上传、发给我筛选文件，以便缩小范围。
18. 作为用户，我希望按时间或大小排序，以便处理大量文件。
19. 作为桌面用户，我希望多选文件执行批量下载或再次发送，以便减少重复操作。
20. 作为手机用户，我希望文件以卡片展示，并把下载作为主操作，以便触控友好。
21. 作为手机用户，我希望其他文件动作收入更多菜单，以便卡片保持简洁。
22. 作为用户，我希望上传共享文件时不必选择接收者，以便快速放入房间共享目录。
23. 作为用户，我希望拖放多个文件进入待发送区，以便批量上传。
24. 作为用户，我希望点击按钮使用系统文件选择器，以便在不支持拖放的设备上传。
25. 作为用户，我希望文件释放后先看到待发送确认，而不是立即上传，以便避免误公开私密内容。
26. 作为用户，我希望在待发送区删除误选文件，以便修正发送内容。
27. 作为用户，我希望看到文件总数、总大小和预计占用，以便发送前检查容量。
28. 作为用户，我希望切换为定向发送并多选成员，以便把文件只发给指定人员。
29. 作为用户，我希望当前聊天成员在定向模式中自动选中，以便减少操作。
30. 作为用户，我希望全选在线成员，以便快速进行一对多定向发送。
31. 作为用户，我希望已经收到该文件的成员不可重复选择，以便避免重复授权。
32. 作为原始上传者，我希望选择已上传定向文件并新增接收者，以便不重复上传。
33. 作为原始上传者，我希望把定向文件发布到共享目录，以便全房间使用同一物理文件。
34. 作为用户，我希望发布为共享文件前看到明确警告，以便理解公开操作不可直接逆转。
35. 作为聊天用户，我希望引用共享文件，以便告诉对方查看指定文件而不重复占用容量。
36. 作为房间成员，我希望查看所有当前共享文件，以便把房间当作临时共享目录。
37. 作为后加入成员，我希望查看加入前的共享文件，以便获得完整公共资料。
38. 作为定向文件发送者，我希望只有自己和接收者看到原文件信息，以便保护私密内容。
39. 作为定向文件接收者，我希望在聊天和文件列表看到完整文件名，以便决定是否接受。
40. 作为无关普通成员，我希望完全看不到他人的定向文件，以便隐私边界明确。
41. 作为房主，我希望看到无关定向文件的匿名记录和大小，以便治理容量。
42. 作为房主，我希望匿名记录不能泄露原名、扩展名或 MIME，以便治理不等于读取内容。
43. 作为房主，我希望每个私密文件有稳定随机别名，以便区分删除和恢复目标。
44. 作为用户，我希望公共上传、下载、撤回和恢复分别显示在详细时间轴，以便追踪操作。
45. 作为用户，我希望时间轴最新记录在顶部，以便优先看到最近变化。
46. 作为用户，我希望时间轴按日期分组并逐步加载历史，以便长记录仍可浏览。
47. 作为用户，我希望上传或下载中的时间轴节点原位更新进度，以免每个百分比制造新日志。
48. 作为普通成员，我希望时间轴只显示公共记录和与自己相关的定向记录，以便避免泄密。
49. 作为房主，我希望同一时间轴额外显示匿名的无关定向记录，以便不需要第二个审计页面。
50. 作为用户，我希望新文件事件到达时收到提示，但页面不突然跳到顶部，以便继续阅读历史。
51. 作为用户，我希望看到单文件上传百分比、速度和剩余时间，以便判断等待时间。
52. 作为用户，我希望看到多文件总进度，以便了解整个批次状态。
53. 作为下载者，我希望看到接收百分比、速度和剩余时间，以便确认传输仍在进行。
54. 作为下载者，我希望 100% 显示为“传输完成”而非“已保存”，以便文案符合浏览器能力。
55. 作为用户，我希望切换文件视图或聊天后传输继续，以便多任务操作。
56. 作为用户，我希望全局迷你任务栏持续显示当前传输，以便不丢失进度。
57. 作为接收者，我希望定向文件提供接受并下载或拒绝，以便主动决定是否接收。
58. 作为发送者，我希望看到每位接收者的待处理、接受、拒绝和下载状态，以便了解结果。
59. 作为上传者，我希望删除自己的文件时选择回收站或永久删除，以便平衡恢复与释放空间。
60. 作为房主，我希望强制删除无关定向文件时默认进入回收站，以便不经参与者同意的操作仍可恢复。
61. 作为上传者，我希望自己主动移入回收站的文件可直接恢复，以便快速撤销误操作。
62. 作为上传者，我希望房主强制删除的文件只能申请恢复，以便不能绕过房主管理。
63. 作为房主，我希望审批恢复申请，以便决定文件是否重新可用。
64. 作为接收者，我希望不能恢复他人文件，以便所有权边界明确。
65. 作为用户，我希望公共回收站文件对全员可见，以便理解共享目录变化。
66. 作为定向参与者，我希望只看到与自己相关的回收站私密文件，以便隐私延续到删除状态。
67. 作为房主，我希望回收站中的无关私密文件仍匿名显示，以便能够恢复或永久删除。
68. 作为房主，我希望看到公共、定向、上传预留和回收站计费占用，以便理解容量来源。
69. 作为普通成员，我希望只看到总占用和总容量，以便不通过容量细分推断他人私密文件。
70. 作为管理员，我希望通过 Switch 决定回收站是否计入房间容量，以便选择存储策略。
71. 作为管理员，我希望回收站不计入容量时配置免费额度，以便限制附赠物理空间。
72. 作为房主，我希望免费额度超出后只把超出部分计入房间容量，以便删除不会被直接拒绝。
73. 作为成员，我希望点击成员切换一对一聊天，以便交互符合桌面即时通讯习惯。
74. 作为成员，我希望看到在线、暂离、离线和未读数，以便选择联系对象。
75. 作为房主，我希望从成员菜单移出成员，以便管理房间。
76. 作为聊天用户，我希望发送文字和 Unicode 表情，以便快速沟通。
77. 作为聊天用户，我希望发送图片并内联预览，以便分享视觉内容。
78. 作为聊天用户，我希望发送定向文件，以便文件只对参与者可见。
79. 作为聊天用户，我希望看到发送中、失败、已送达和已读，以便了解消息状态。
80. 作为聊天用户，我希望撤回自己发送的消息，以便修正误发。
81. 作为聊天用户，我希望文件已读与文件已下载分开显示，以便状态语义准确。
82. 作为聊天用户，我希望刷新或短暂断线后恢复聊天和已读状态，以便协作连续。
83. 作为离开后重新加入的同一匿名用户，我希望恢复自己的文件管理权和私聊历史，以便身份连续。
84. 作为键盘用户，我希望所有按钮、菜单、Tab、抽屉和对话框有清晰焦点，以便无需鼠标操作。
85. 作为屏幕阅读器用户，我希望图标按钮有可读名称、状态变化可感知，以便完成主要流程。
86. 作为减少动态效果的用户，我希望进度动画和抽屉过渡尊重系统设置，以免不适。
87. 作为中文用户，我希望所有原型文字使用简体中文，以便完整评审。
88. 作为 English 用户，我希望切换语言后所有可见文字同步变化，以便检查双语布局。
89. 作为评审者，我希望切换房主和成员身份，以便验证权限投影。
90. 作为评审者，我希望切换回收站计费开关与额度，以便验证容量公式。
91. 作为评审者，我希望切换加入、解散、被踢和错误状态，以便评审完整页面生命周期。
92. 作为评审者，我希望重置模拟数据，以便重复执行演示流程。
93. 作为项目维护者，我希望原型不修改生产代码和依赖，以便删除或迭代原型不会影响应用。
94. 作为后续编码模型，我希望权限、容量、状态和验收标准足够明确，以便无需猜测产品意图。

## Implementation Decisions

### 1. 本 PRD的唯一交付范围

- 当前交付物是房间工作区交互原型，不是生产功能。
- 原型根目录固定为 `examples/room-workspace-prototype/`。
- 禁止修改 `frontend/`、`internal/`、`core/`、`pkg/`、`wire/`、`config/`、`static/`、现有路由、数据库和构建脚本。
- 禁止新增 npm、Bun、Go 或 CDN 运行时依赖。
- 禁止调用 FileDock API、SSE 或真实文件存储。
- 原型可读取用户在浏览器选择的文件名与大小用于模拟，但不得上传、持久化或读取文件内容。
- 原型确认前，不修改 `docs/first/LanShare_PRD.md`，不编写生产开发 PRD。

### 2. 原型目录与模块

- `index.html`：语义化页面骨架、原型控制器挂载点、主工作区挂载点、无脚本提示。
- `styles.css`：设计变量、桌面三栏、平板双栏、移动文件优先布局、组件外观、状态样式、焦点、减少动画和打印无关规则。
- `js/app.js`：启动、事件委托、定时器、拖放、文件选择、进度模拟和控制器绑定。
- `js/mock-data.js`：固定成员、文件、聊天、时间轴、回收站、容量和加入状态夹具。
- `js/state.js`：单一内存状态、动作分发、派生选择器入口、重置逻辑；不得把业务状态散落到 DOM 属性。
- `js/permissions.js`：按身份投影文件列表、时间轴、回收站和操作权限；不得在各渲染函数重复写权限判断。
- `js/capacity.js`：公共、定向、上传预留、回收站实际、免费额度、计费量、总占用和可用容量的纯函数。
- `js/i18n.js`：`zh-CN` 与 `en` 完整字典、语言切换和插值；机器值、随机别名代码、文件名和状态键不翻译。
- `js/render.js`：从已投影状态生成顶栏、成员栏、文件列表、时间轴、回收站、聊天、抽屉、Modal、任务栏和空／错状态。
- `tests/permissions.test.js` 与 `tests/capacity.test.js`：只测试纯函数的外部行为。
- `README.md`：说明原型目的、与生产代码隔离、启动方式、演示控制器、测试命令和已知限制。

### 3. 视觉系统

- 继承新版首页的浅色中性背景、深色正文、蓝绿色主强调色和柔和状态色。
- 使用语义 CSS 变量表达背景、面板、边框、正文、次要文字、主色、成功、警告、危险、阴影和焦点；不得把未来深色主题实现混入本期。
- 模拟 Ant Design 的按钮、标签、表格、Tab、抽屉、Modal、Badge、进度条和 Dropdown 视觉，但不得复制 Ant Design 源码或引入 CDN。
- 功能图标使用本地内联 SVG；禁止用 Emoji 充当按钮图标。
- 页面工作区占满视口。顶栏固定，各主栏内部独立滚动；桌面不得依赖整个页面纵向滚动。
- 常规 Hover 和开合过渡控制在 150～300ms；进度变化平滑但不得延迟真实数值。
- `prefers-reduced-motion: reduce` 时关闭非必要平移、缩放和循环动画。

### 4. 桌面布局

- `1200px` 及以上展示三栏：左栏固定约 `240px`，中栏自适应且不得小于约 `560px`，右栏固定约 `340px`。
- 顶栏高度保持紧凑，按顺序展示返回、房间号与标题、成员数、剩余时间、容量、二维码、加入申请和更多。
- 房间号可复制；复制成功使用轻量提示，不弹阻塞对话框。
- 容量摘要点击后展示详情。房主看到全部细分，普通成员只看到总占用。
- 加入申请使用右侧抽屉；二维码使用 Modal；延期、退出、解散和房间详情使用更多菜单。
- 左栏正常状态用于聊天切换；定向文件选择时进入临时多选状态，选择结束后恢复。
- 中栏顶部是紧凑文件操作栏，中栏主体是三级文件视图。
- 右栏始终保留当前一对一聊天；没有选择成员时显示明确空状态和操作提示。
- 全局传输任务栏固定在不遮挡内容的位置，允许展开查看全部模拟任务。

### 5. 平板与移动布局

- `768px` 至 `1199px` 隐藏常驻成员栏，改用抽屉；文件主区保持主要宽度，聊天保留可关闭的侧栏或二级面板。
- 小于 `768px` 时使用单栏文件优先布局，不渲染三栏压缩版。
- 移动顶栏只保留房间号、容量、聊天未读和更多；房间标题、成员数、二维码等放入详情或菜单。
- 移动主区顶部提供“文件列表／文件动态／回收站”，默认文件列表。
- 移动底部固定“上传共享文件”和“定向发送”，同时显示迷你传输状态。
- 聊天从顶栏未读入口进入全屏二级页面；聊天页顶部可切换成员或打开成员抽屉。
- 文件卡直接显示下载主按钮；发布共享、再次发送、移入回收站、永久删除等放入更多菜单。
- 禁止横向滚动；Modal 在移动端改为全宽对话框或 Bottom Sheet。

### 6. 原型状态模型

- 所有原型数据只保存在当前页面内存；刷新默认恢复固定夹具。
- 状态至少包含：当前语言、当前演示身份、当前页面场景、活动文件 Tab、当前聊天成员、成员多选、文件多选、待发送文件、模拟任务、文件、文件事件、聊天消息、已读游标、回收站配置、容量、抽屉和 Modal。
- 文件状态至少展示：待发送、上传中、可用、上传失败、回收站、永久删除。
- 接收关系状态至少展示：待处理、已接受、已拒绝、下载中、已下载、已撤回。
- 聊天消息状态至少展示：发送中、已送达、已读、失败、已撤回。
- 场景至少包含：免验证加入、PIN 加入、审批等待、正常工作区、加入申请、解散倒计时、被踢、房间不存在、加载失败、空文件、空聊天、空回收站。
- 状态变化必须通过集中动作更新；渲染函数只消费状态，不直接改业务数据。

### 7. 演示身份与夹具

- 默认夹具至少包含一名房主、三名普通成员以及在线、暂离、离线三种状态。
- 默认当前身份为房主，控制器可切换为普通成员。
- 夹具至少包含：可用共享文件、上传中共享文件、当前用户发送的定向文件、发给当前用户的定向文件、与当前普通成员无关但房主可匿名查看的定向文件、回收站公共文件、回收站相关定向文件和失败任务。
- 私密文件必须有稳定别名代码。参与者视图显示原名和别名；无关房主视图只显示本地化前缀和稳定代码。
- 夹具必须包含多个聊天会话、未读消息、已读消息、图片消息、定向文件卡和共享文件引用卡。
- 演示控制器不得伪装为生产功能。它应可折叠，并在截图时允许隐藏。

### 8. 文件作用域与可见性投影

- 文件作用域只有 `shared` 与 `direct`。
- 共享文件对全部当前成员及后加入成员完整可见。
- 定向文件的原始元数据只对原始上传者和明确接收者可见。
- 无关普通成员既看不到定向文件，也看不到其列表数、回收站数和事件数。
- 房主对无关定向文件只能获得匿名投影：稳定私密别名、发送者、接收者、准确大小、状态、操作类型和时间。
- 匿名投影不得包含原文件名、扩展名、MIME、检测类型、预览、缩略图、哈希、下载入口或聊天文本。
- 若房主本身是发送者或接收者，则按参与者身份显示完整信息。
- 权限投影必须先于渲染执行；不得先渲染完整数据再用 CSS 隐藏。

### 9. 私密文件别名

- 每个定向文件创建时生成一次房间内唯一的稳定随机代码。
- 示例中文显示为 `私密文件#7K2M-A9Q4`，English 显示为 `Private file #7K2M-A9Q4`。
- 代码必须与原文件名、扩展名、内容哈希和内部文件 ID 无关。
- 上传、再次发送、下载、回收站、恢复和发布共享期间代码不变。
- 永久删除后代码作废；模拟重新上传同一文件时生成新代码。
- 原型使用固定夹具代码保证截图可复现；“新增模拟文件”可生成新的安全样式随机代码，但不承担生产安全保证。

### 10. 文件上传与历史复用

- 桌面整个文件主区是拖放目标。拖入时显示覆盖层，离开时恢复，释放后进入待发送面板。
- 文件选择或拖放只读取浏览器提供的名称、大小和类型，不读取内容。
- 待发送面板必须先选择“共享到房间”或“定向发送”，共享为默认模式。
- 定向模式显示接收者多选；聊天附件入口自动切换定向并预选当前聊天成员。
- 点击最终发送前展示文件数量、每个文件、总大小、作用域和接收者摘要。
- 点击发送后才创建模拟任务并启动进度；取消待发送不得产生文件或时间轴事件。
- “选择已有文件”只展示当前用户原始上传且仍可复用的文件。
- 再次发送历史定向文件只新增接收关系与事件，不新增文件大小。
- 已拥有权限的接收者在选择器中禁用并说明原因。
- 接收者不能再次发送自己只接收的文件。
- 定向文件发布共享需要明确二次确认。确认后模拟文件作用域改为共享，定向占用转为公共占用，总物理占用不变。
- 共享文件发送到聊天是引用消息，不改变文件作用域、授权或容量。

### 11. 文件列表

- 文件列表只展示当前有效、当前身份有权看到的文件；永久删除记录不显示，回收站文件只在回收站视图显示。
- 桌面列固定为文件名／匿名名、作用域、上传者、大小、上传时间、状态和操作。
- 支持关键词搜索；无关匿名私密文件只能按别名搜索，不能通过隐藏原名命中。
- 支持全部、公共、定向、我上传、发给我筛选。
- 支持最新、最旧、大小升序和大小降序。
- 多选只允许当前身份可执行共同操作的文件；混合不可操作项时应禁用批量动作并说明。
- 房主无关定向文件的操作只允许强制移入回收站或查看匿名状态，不允许下载、预览、引用、再次发送或发布共享。
- 移动文件卡展示主名称、作用域、上传者、大小、时间和状态；下载为主按钮。

### 12. 文件动态时间轴

- 时间轴是单一视图，不为房主另建审计页。
- 默认最新事件在顶部，按今天、昨天和完整日期分组。
- 事件节点采用左侧轴与时间、右侧信息卡布局。
- 事件类型包括上传开始／完成／失败、定向发送、接受、拒绝、下载开始／完成／失败、历史再次发送、发布共享、移入回收站、申请恢复、恢复、拒绝恢复和永久删除。
- 进度更新修改原事件卡，不新增百分比事件；完成后固定最终状态和时间。
- 普通成员看到全部公共事件和与自己相关的完整定向事件。
- 房主除上述内容外，还看到无关定向事件的匿名投影。
- 新事件到达且用户不在顶部时显示“有新记录”提示；点击才滚动到顶部。
- 时间轴筛选至少包含全部、公共文件、定向文件、我上传和我下载。
- 原型模拟逐步加载更早记录，但不实现真实 API 游标。

### 13. 定向接受与下载

- 共享文件无需接受，可直接触发模拟下载。
- 定向文件在参与者聊天和文件列表中提供“接受并下载”与“拒绝”。
- 每位接收者状态独立；一人拒绝不影响其他接收者。
- 接受后允许在房间生命周期内重复下载。
- 发送者可展开查看每位接收者的待处理、接受、拒绝和下载状态。
- 房主无关匿名投影只展示已确认允许的状态摘要，不提供参与动作。

### 14. 上传与下载进度

- 每个上传任务展示百分比、已传字节、总字节、模拟速度、剩余时间和状态。
- 批量上传同时展示总百分比；总百分比按总字节加权，不使用文件数量平均。
- 下载进度语义固定为服务端传输字节除以文件总字节。原型使用定时器模拟，不宣称浏览器真实写盘。
- 下载完成文案为“传输完成”及对应 English，不使用“已保存到下载目录”。
- 进度事件应节流更新，视觉上约每 300～500ms 变化即可。
- 切换文件 Tab、聊天、抽屉或移动二级页不得停止任务。
- 全局任务栏汇总活动任务；完成任务短暂保留后归入已完成状态。

### 15. 回收站与容量模型

- 用户删除自己上传的文件时提供“移入回收站”和“永久删除”两个清晰选项。
- 房主删除其他成员的共享文件或强制删除无关定向文件时默认移入回收站；永久删除必须再次确认。
- 回收站入口所有成员可见，内容继续应用相同权限投影。
- 上传者主动移入的文件可由上传者直接恢复。
- 房主强制移入的文件由上传者提交恢复申请，房主批准后恢复；接收者不能恢复。
- 房主可直接恢复或永久删除任意文件，但对无关定向文件始终只操作匿名投影。
- 公共文件恢复后重新对全部成员可见；定向文件恢复原接收关系。
- 回收站生命周期跟随房间，原型场景说明房间销毁会全部硬删除。
- 容量计算使用以下固定口径：
  - 活动占用等于公共文件、定向文件和上传预留之和。
  - 回收站计入开关开启时，全部回收站实际大小进入计费量，管理员免费额度无效。
  - 回收站计入开关关闭时，管理员配置免费额度；回收站计费量等于实际大小减免费额度后的非负结果。
  - 房间已占用等于活动占用加回收站计费量。
  - 可用容量等于房间总容量减已占用后的非负结果。
- 房主容量详情显示公共、定向、上传预留、回收站实际、免费额度、回收站计费量、总占用和总容量。
- 普通成员只显示总占用和总容量；不得显示公共／定向／回收站细分或无关私密文件数量。
- 从回收站恢复前必须重新计算容量；容量不足时模拟阻止恢复并说明原因。

### 16. 一对一聊天

- 只支持同房间成员之间的一对一聊天，不提供群聊入口。
- 左侧成员列表即会话切换列表；自己不作为聊天对象。
- 成员行展示首字头像、昵称、房主标记、在线状态、最后消息摘要和未读数。
- 聊天头部展示当前成员与状态；正文按时间从上到下，最新消息在底部。
- 输入区支持纯文本、Unicode 表情、图片、定向文件和共享文件引用。
- 图片作为定向文件模拟并计入定向容量；共享图片引用不增加容量。
- 多接收者定向文件在每个一对一会话生成独立上下文卡，但复用同一文件记录。
- 允许撤回自己的模拟消息；撤回后保留占位，不直接移除时间位置。
- 不实现语音、视频、通话、Markdown、富文本、好友关系和跨房间聊天。

### 17. 已读回执

- 已读回执在产品决策中强制启用，原型不提供关闭开关。
- 只有当前聊天被选中且页面可见时，模拟更新该会话已读游标。
- 浏览器标签进入后台时不得自动把新消息标为已读。
- 发送者最后一组连续消息只在最后一条下显示“已送达”或“已读”，避免每条重复。
- 文件消息已读只代表看见卡片，下载状态继续独立展示。
- 原型内存状态模拟未来 SQLite 已读游标；README 必须说明生产设计以服务端为事实来源，localStorage 不是事实来源。

### 18. 房间生命周期状态

- 免验证加入、PIN 输入和房主审批等待沿用现有业务语义，但视觉改为浅色工作区风格。
- PIN 原型使用四位数字输入，完整后只模拟验证，不发网络请求。
- 房主加入申请抽屉展示申请人、剩余有效时间、同意与拒绝。
- 解散和过期使用全屏不可操作状态，展示倒计时并模拟返回首页；不得保留可点击上传或聊天控件。
- 被踢状态展示明确原因与返回首页主按钮。
- 房间不存在、加载失败和无身份状态提供返回或重试入口。

### 19. i18n 与无障碍

- 所有可见文字、提示、按钮、状态、错误、空状态和演示控制器同时提供 `zh-CN` 与 `en`。
- 前缀“私密文件”本地化，稳定别名代码不翻译。
- 文件名、房间号、用户输入、容量数值、时间、机器状态键和模拟 ID 不翻译。
- 语言切换后页面结构、当前状态和模拟任务不得重置。
- 页面根元素 `lang` 必须同步更新。
- Tab、Dialog、Drawer、Menu、Progressbar、Alert 和列表使用合适语义或 ARIA 属性。
- 图标按钮必须有可见 Tooltip 或屏幕阅读器名称。
- 键盘可完成语言切换、Tab 切换、成员切换、文件上传入口、发送、下载、回收站和关闭弹层。
- 焦点不得在关闭抽屉或 Modal 后丢失；应返回触发控件。
- 文本和控件对比度至少满足 WCAG AA 常规要求。

### 20. 演示控制器

- 控制器默认折叠，不进入生产布局语义。
- 支持切换房主／普通成员、中文／English、桌面场景状态、回收站计入开关、免费额度和模拟文件状态。
- 支持快速注入上传、下载、聊天、已读、回收站和恢复申请事件。
- 支持重置到固定夹具。
- 控制器改变身份后必须重新运行权限投影，不能只替换用户名。
- 截图前可隐藏控制器，隐藏后不得改变主布局宽度。

### 21. 实施顺序与确认点

低智能编码模型必须严格按以下顺序实施。每个主要文件阶段完成后停止，等待用户确认；不得自动修改生产代码。

1. 创建原型目录、README、HTML 语义骨架和基础设计变量；只展示静态桌面三栏骨架。完成后等待确认。
2. 完成桌面与响应式 CSS、顶栏、成员栏、文件三级视图、聊天栏和任务栏的静态视觉。完成后等待确认。
3. 完成模拟数据、集中状态、权限投影、容量计算和对应自动测试。完成后等待确认。
4. 完成文件拖放、待发送、共享／定向切换、历史复用、文件列表、时间轴、回收站和进度模拟。完成后等待确认。
5. 完成一对一聊天、成员切换、共享引用、定向文件卡、已读回执和加入／解散／被踢状态。完成后等待确认。
6. 完成中英文、无障碍、演示控制器、桌面／平板／移动人工验收和截图。输出问题修正后等待原型最终确认。
7. 原型最终确认后结束本 PRD。不得在同一任务中继续修改原始 PRD或生产应用。

## Testing Decisions

### 自动测试原则

- 测试外部可观察规则，不测试变量名、函数拆分、DOM 层级或 CSS 类名。
- 本期不采用 TDD；先完成对应纯函数，再补充边界测试。
- 不新增测试框架依赖；使用仓库现有可用的 Bun 测试能力执行原型纯 JavaScript 测试。

### 权限投影测试

- 普通成员看到全部共享文件。
- 后加入成员看到既有共享文件与公共历史。
- 普通成员看到自己发送或接收的定向文件完整信息。
- 普通成员看不到无关定向文件及其数量。
- 房主看到无关定向文件匿名别名、参与者、大小、状态和时间。
- 房主匿名投影不包含原文件名、扩展名、MIME、预览、哈希和下载能力。
- 房主作为定向参与者时看到完整信息。
- 回收站复用同一权限规则。
- 上传者、接收者、房主对恢复、申请恢复、永久删除和再次发送的权限符合决策。
- 身份切换后结果重新投影，不残留上一身份完整数据。

### 容量计算测试

- 公共、定向和上传预留正确求和。
- 回收站计入开关开启时，全部回收站大小进入已占用，免费额度不生效。
- 回收站计入开关关闭且未超过免费额度时，回收站计费量为零。
- 回收站计入开关关闭且超过免费额度时，只计算超出部分。
- 删除到回收站、永久删除、恢复、定向发布共享和历史再次发送后的占用变化正确。
- 历史再次发送和共享引用不增加物理占用。
- 定向发布共享只移动分类，不改变总物理占用。
- 恢复导致容量不足时返回不可恢复结果。
- 所有计算结果不得为负数或超过显示容器允许范围。

### 构建与静态检查

- HTML、CSS 和 JavaScript 不依赖网络资源。
- 浏览器控制台无语法错误、未捕获异常、404 资源或无效模块导入。
- 原型目录之外的 `git status` 不应因启动或测试产生构建产物。
- 生产前端既有构建和 Go 测试不是原型逻辑测试，但最终应运行一次，确认原型文件没有影响现有工程。

### 浏览器人工验收

- 使用可见浏览器在约 `1440×900` 检查桌面三栏、独立滚动、固定顶栏和任务栏。
- 在约 `1024×768` 检查成员抽屉、文件与聊天空间和无横向滚动。
- 在约 `390×844` 检查文件优先、三级文件视图、底部上传、聊天二级页和成员抽屉。
- 分别切换房主与普通成员，检查文件列表、时间轴、回收站、容量详情和操作按钮。
- 切换中文与 English，检查页面 `lang`、长英文布局、按钮溢出和全部文案。
- 拖放或选择多个本地文件，确认只读取元数据、先进入待发送面板、确认后才模拟上传。
- 测试共享上传、定向多选、历史再次发送、发布共享和共享文件聊天引用。
- 测试上传、批量总进度、下载、失败、重试和全局任务栏。
- 测试文件列表搜索、筛选、排序、多选和移动文件卡。
- 测试时间轴日期分组、身份投影、新事件提示和进度原位更新。
