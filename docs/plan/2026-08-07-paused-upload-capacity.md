# 暂停上传容量与未完成任务管理 PRD

## Problem Statement

断点续传上传暂停后，服务端仍保留临时文件、已完成分片和上传会话。房间容量必须防止这些未完成任务被忽略，否则其他用户可能继续上传并消耗同一部分空间，导致原任务恢复时容量不足。另一方面，如果用户刷新页面或网络异常，前端不能依赖本地 `File` 对象恢复任务，可能出现用户看不到记录、无法释放服务端预留容量的问题。

当前实现已经具备完整文件大小的 `reservedBytes` 预留、房间到期清理和上传者取消接口，但还需要把容量展示、刷新后的任务管理和删除失败重试行为统一起来。

## Solution

将暂停上传视为仍然有效的可续传会话：暂停期间继续占用完整声明大小的预留容量，但不计入已完成文件的 `usedBytes`。房主的容量进度纳入预留容量，普通成员继续只看到通用容量不足提示。浏览器刷新后使用 `localStorage` 中的上传元数据创建占位任务，用户重新选择匹配文件后才能继续上传；用户也可以直接删除占位任务释放服务端资源。删除以服务端清理成功为准，失败时保留任务并允许重试。

## User Stories

1. 作为上传者，我希望暂停大文件上传后仍保留已上传分片，以便稍后继续上传而无需重新开始。
2. 作为房间系统，我希望暂停任务按完整声明大小预留容量，以便恢复上传时容量结果稳定可预测。
3. 作为上传者，我希望暂停任务不会修改已完成文件的已使用容量统计，以便已使用和未完成预留含义清晰。
4. 作为上传者，我希望暂停不会延长房间有效期，以便所有临时资源都在房间生命周期内自动回收。
5. 作为上传者，我希望房间到期后未完成上传自动清理，避免临时文件和分片永久残留。
6. 作为上传者，我希望主动删除暂停任务后立即释放房间容量，以便马上上传其他文件。
7. 作为上传者，我希望删除操作不可恢复且有明确提示，避免误以为文件会进入回收站。
8. 作为上传者，我希望删除请求遇到网络错误时任务不会从列表消失，以便稍后重试释放服务端资源。
9. 作为上传者，我希望刷新页面后仍能看到未完成上传的文件名、大小和进度，知道服务端仍保留上传会话。
10. 作为上传者，我希望没有重新选择本地文件时可以删除占位任务，但不能误触发继续上传。
11. 作为上传者，我希望重新选择文件后，系统能匹配房间、文件名、大小和修改时间，自动恢复对应会话。
12. 作为上传者，我希望服务端取消接口重复调用具有幂等性，网络重试不会重复扣减或产生错误状态。
13. 作为房主，我希望顶部容量进度包含已完成使用量和未完成上传预留量，准确反映可用空间。
14. 作为房主，我希望容量详情继续分别显示已使用、回收站和上传预留，便于定位容量来源。
15. 作为普通成员，我希望上传失败时只看到“房间容量不足”，不看到其他成员文件信息或预留细节。
16. 作为普通成员，我希望自己可以正常上传，不需要知道其他成员具体占用了多少预留空间。
17. 作为房主，我希望一期只能查看上传预留总量，不能直接删除其他成员未完成任务，避免误删成员正在续传的内容。
18. 作为多标签页用户，我希望暂停或删除操作通过现有单写者租约和跨标签通信同步，避免同一任务重复清理。
19. 作为系统维护者，我希望服务端继续使用 `active` 上传会话状态，不增加 paused 数据库状态，降低状态同步复杂度。
20. 作为系统维护者，我希望 API 保留 `usedBytes` 与 `reservedBytes` 的独立语义，避免影响回收站和实际文件容量统计。

## Implementation Decisions

### 容量与生命周期

- 创建上传批次时，按每个文件 `declaredSize` 增加房间 `reservedBytes`。
- 暂停、浏览器关闭、页面刷新不会释放预留；预留只在上传完成、主动取消、失败、会话过期或房间清理时释放。
- 上传完成时，将对应声明大小预留转换为实际 `usedBytes`，实际大小必须通过现有校验。
- 上传会话的到期时间继续使用房间到期时间；暂停不刷新 `expiresAt`，不新增独立暂停 TTL。
- 房间生命周期清理继续删除临时文件、上传分片、上传会话和未完成文件元数据，并释放预留容量。

### 状态模型

- 服务端上传会话继续使用 `active` 表示“允许续传”，不新增 `paused` 数据库状态。
- 前端任务可以显示 `paused`，该状态保存在传输状态和续传元数据中。
- `usedBytes` 只表示已完成文件及回收站的实际占用；`reservedBytes` 单独表示未完成上传预留。
- 容量校验继续使用 `capacityBytes - usedBytes - reservedBytes`。

### 容量展示

- 房主顶部容量进度使用 `usedBytes + reservedBytes` 作为当前占用值，分母仍为 `capacityBytes`，超过容量时限制在 100%。
- 房主容量详情保留独立的已使用、共享文件、私密文件、回收站和上传预留字段。
- 普通成员不展示房间级 `reservedBytes` 明细；创建上传因容量不足时继续返回现有“房间容量不足”错误，不新增面向普通成员的原因提示。

### 刷新后的未完成任务

- 前端从 `localStorage` 恢复上传元数据占位记录，不恢复文件二进制内容。
- 占位记录至少包含房间、上传 ID、文件 ID、文件名、文件大小、最后修改时间、已知进度、分片计划和会话过期时间。
- 未重新选择匹配文件时，浮层显示等待重新选择状态，只提供删除操作，不提供继续上传操作。
- 用户重新选择文件后，按房间、文件名、文件大小和 `lastModified` 匹配服务端会话；匹配成功后自动加入上传队列，不再次询问确认。
- 房间到期或服务端返回会话不存在/已过期时，清理对应本地元数据并将任务标记为不可恢复。

### 删除与重试

- 删除未完成上传前先停止分片请求并显示删除中状态。
- 服务端取消操作必须完成文件状态更新、容量释放、分片和会话删除、临时文件删除；重复调用应安全幂等。
- 仅在服务端确认清理成功后删除 `localStorage` 记录和前端任务。
- 服务端或网络错误时保留本地记录，显示删除失败并允许重试；不得静默丢弃本地记录。
- 删除未完成上传不进入文件回收站，也不提供恢复入口。
- 只有上传者本人可取消自己的未完成上传；房主一期不提供强制取消其他成员任务的能力。

### 多标签页

- 继续使用现有 `BroadcastChannel` 和 `localStorage` 租约，单个上传 ID 同时只能由一个标签页执行分片请求。
- 暂停时释放租约，其他标签页可以接管并继续；删除时广播删除状态，其他标签页移除对应任务但不重复执行服务端清理。

### 国际化

- 新增或修改所有前端提示必须同时补齐 `zh-CN` 与 `en` 翻译键。
- 删除中、删除失败、等待重新选择文件、会话已过期等状态不得在 React 组件中硬编码。
- 后端继续返回错误码，普通成员容量不足沿用现有错误码和双语响应层。

## Testing Decisions

- 测试外部行为，不测试具体实现细节。
- 服务端容量测试：暂停或未完成任务保留完整 `reservedBytes`；完成时预留转为 `usedBytes`；取消、失败、过期和房间清理释放预留。
- 服务端幂等测试：重复取消同一上传不会重复扣减容量，临时文件最终被删除；取消失败时可安全重试。
- 服务端权限测试：上传者可以取消自己的未完成上传，其他成员和房主不能取消该任务。
- 前端容量展示测试：房主顶部进度使用 `used + reserved`，详情字段保持拆分；普通成员不显示预留明细。
- 前端续传元数据测试：刷新后恢复占位记录；无文件时只能删除；匹配文件后自动续传；过期会话被清理。
- 前端删除状态测试：请求成功后移除记录；请求失败保留记录并支持重试；多标签页只执行一次服务端取消。
- 前端国际化测试：中英文翻译键集合一致且无空文案。
- 参考现有上传恢复、容量统计、文件服务和多标签页租约测试风格，补充边界场景：0 分片、重复取消、网络断开、房间即将到期和容量恰好耗尽。

## Out of Scope

- 不新增下载断点续传或下载分片协议。
- 不新增服务端 paused 状态或暂停 SSE 事件。
- 不允许房主一期强制删除其他成员的未完成上传。
- 不将未完成上传放入回收站，不支持恢复已删除的未完成上传。
- 不把文件内容、Blob 或二进制分片保存到 `localStorage`。
- 不改变普通成员容量不足错误的现有文案和错误码。
- 不调整上传并发数、分片大小或管理员配置能力。

## Further Notes

- 临时文件采用预分配方式，业务容量按完整声明大小预留；实际物理磁盘是否立即占满取决于底层文件系统的稀疏文件实现，不影响房间配额判断。
- 这份 PRD 主要收口容量展示、刷新后任务可管理性和删除失败恢复；已有分片协议、校验、合并、过期清理和多标签页上传逻辑应保持兼容。
- 实现时优先按“后端清理可靠性 → 前端元数据占位 → 容量展示 → 测试”的顺序分阶段提交 Git。
