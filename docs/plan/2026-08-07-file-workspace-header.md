# 文件工作区头部布局优化 PRD

## Problem Statement

房间页面的文件工作区当前使用两层头部：第一层显示“文件工作区 / 房间文件”和文件操作按钮，第二层显示“文件列表 / 文件动态 / 回收站”Tab。标题信息与页面上下文重复，两层头部占用了较多垂直空间，压缩了文件列表内容区，整体视觉显得松散。

## Solution

删除文件工作区标题层，将“添加文件”和“发送已有私密文件”移动到 Tab 头部右侧。桌面端将 Tab 和操作按钮保持在同一行，窄屏端保留图标按钮并允许在空间不足时自适应换行。三个 Tab 下始终显示操作按钮，不改变任何文件业务逻辑。

## User Stories

1. 作为房间成员，我希望文件工作区头部更紧凑，以便看到更多文件内容。
2. 作为房间成员，我希望“文件列表、文件动态、回收站”与常用文件操作位于同一视觉区域，以便快速理解操作层级。
3. 作为房间成员，我希望删除重复的“文件工作区 / 房间文件”标题，减少无效信息。
4. 作为上传者，我希望在任意文件 Tab 下都能看到“添加文件”，以便随时开始上传。
5. 作为上传者，我希望在任意文件 Tab 下都能看到“发送已有私密文件”，以便随时复用历史文件。
6. 作为桌面端用户，我希望 Tab 和操作按钮在同一行对齐，保持页面整洁。
7. 作为窄屏用户，我希望操作按钮不会挤压 Tab 文案，以便所有入口仍可使用。
8. 作为键盘用户，我希望 Tab 的键盘导航和按钮焦点行为不受布局调整影响。
9. 作为深色模式用户，我希望移动后的按钮和 Tab 继续使用现有深色主题样式。
10. 作为英文用户，我希望布局在英文长文案下仍能自适应，不发生不可用的重叠。

## Implementation Decisions

### 组件结构

- 删除独立的文件标题工具栏及其标题节点。
- 新增一个合并后的文件头部容器，左侧为 Tab 列表，右侧为文件操作区。
- Tab 继续使用现有 `tablist`、`tab`、`aria-selected`、焦点顺序和方向键移动逻辑。
- 文件操作区继续包含“添加文件”和“发送已有私密文件”两个按钮，事件处理函数不变。
- 操作按钮在文件列表、文件动态和回收站三个视图中始终显示。

### 桌面布局

- 合并头部使用左右分区的弹性布局。
- Tab 区占据剩余宽度，操作区靠右排列。
- 保留头部底部边框和激活 Tab 下划线。
- 合并后文件工作区网格从“标题栏 + Tab 栏 + 内容区”调整为“合并头部 + 内容区”。
- 头部高度以现有 Tab 和操作按钮可完整容纳为准，不保留原 70 像素标题栏高度。

### 响应式布局

- 窄屏端操作按钮继续使用现有图标化规则，文本通过 CSS 视觉隐藏，但可访问名称仍由按钮内容或 `aria-label` 提供。
- 在宽度不足时允许合并头部换行；Tab 区保持完整可操作，不因按钮导致文字截断到不可辨识。
- Tab 区必要时允许横向滚动或保持最小宽度，操作区不得覆盖 Tab。
- 移动端文件筛选栏和内容列表布局保持不变。

### 视觉与主题

- 两个按钮沿用现有主按钮、次按钮、边框、圆角和颜色规则。
- 移动后的按钮继续支持浅色、深色和跟随系统主题。
- 删除只服务于旧标题栏的样式选择器，避免遗留无效规则。
- 不改变文件筛选栏、搜索框、排序、批量选择、文件列表和传输浮层样式。

### 国际化

- 从正式前端 `zh-CN` 与 `en` 词典同时删除不再使用的“文件工作区”和“房间文件”翻译键。
- 保留“添加文件”和“发送已有私密文件”的现有双语翻译。
- 不修改示例原型目录中的独立词典。

## Testing Decisions

- 本次为布局调整，不新增业务状态测试。
- 运行正式前端双语词典完整性测试，确保删除后中英文键集合仍一致。
- 运行 TypeScript 编译和生产构建，确保组件结构及样式引用有效。
- 手动验证桌面宽屏下 Tab 与两个按钮在同一行，旧标题完全消失。
- 手动验证“文件列表、文件动态、回收站”三个视图下按钮均可点击。
- 手动验证窄屏下 Tab、图标按钮、换行和焦点状态无重叠。
- 手动验证浅色、深色和跟随系统模式。

## Out of Scope

- 不修改文件上传、断点续传、私密文件发送或回收站业务逻辑。
- 不改变文件 Tab 数量、名称、顺序和权限。
- 不重新设计文件筛选栏或文件列表。
- 不修改房间左侧成员区、右侧聊天区或全局顶部栏。
- 不修改示例原型页面。
- 不增加新的后端接口、数据库字段或 SSE 事件。

## Further Notes

- 实现应优先复用现有按钮和 Tab 样式，避免为简单布局创建重复组件。
- 需要特别检查英文文案“Send existing private files”在中等宽度下的占用；窄屏应及时切换为图标化按钮或换行。
- PRD 实现完成后应提交一个独立的布局优化 Git 提交。
