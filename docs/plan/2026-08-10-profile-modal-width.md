# 个人中心弹窗宽度优化 PRD

## Problem Statement

个人中心弹窗当前使用 Ant Design 默认宽度，桌面端占用空间偏大。首页和房间页共用该弹窗，因此需要统一缩小桌面宽度，同时不能影响移动端可用性和弹窗内部信息阅读。

## Solution

为共用的个人中心弹窗设置桌面端固定宽度 `460px`。首页、房间页通过同一组件自动获得一致效果。移动端继续采用当前响应式宽度，保证小屏幕不出现横向溢出。弹窗内部结构、间距、文案、交互、主题样式和业务逻辑保持不变。

## User Stories

1. 作为桌面端用户，我希望个人中心弹窗更紧凑，以便同时看到更多背景内容。
2. 作为首页用户，我希望个人中心弹窗宽度稳定，以便每次打开时布局一致。
3. 作为房间页用户，我希望个人中心弹窗与首页保持相同宽度，以便页面切换时视觉统一。
4. 作为移动端用户，我希望弹窗仍根据屏幕宽度自适应，以便所有内容都能正常查看和操作。
5. 作为用户，我希望头像、名称编辑、服务信息和重置身份等现有内容继续保留，以便功能不受影响。
6. 作为中文或英文用户，我希望弹窗在两种语言下都能正常显示，不因宽度调整导致关键内容不可读。
7. 作为深色主题用户，我希望宽度调整不改变已有主题颜色和对比度。

## Implementation Decisions

- 修改共用 `ProfileModal` 的 Modal 配置，设置桌面端宽度为 `460px`。
- 首页和房间页继续复用同一个 `ProfileModal`，不增加页面级重复实现。
- 保留现有移动端响应式规则；当视口较窄时，弹窗宽度不得超过视口可用宽度，并保持现有左右边距。
- 不修改弹窗内部 DOM 结构、字段顺序、间距、按钮状态、关闭方式、名称保存逻辑、随机名称逻辑、版本信息和重置身份逻辑。
- 不修改后端、数据库、API、SSE、路由或本地存储。
- 不新增用户可见文案，因此无需新增翻译键；现有中文和英文文案必须继续生效。
- 采用弹窗组件级宽度配置，避免影响加入房间、创建房间、通知等其他弹窗。

## Testing Decisions

- 以外部行为为准，不测试 Ant Design 内部实现细节。
- 在桌面视口验证首页打开个人中心时弹窗宽度为 `460px`，且内容未被裁切。
- 在房间页打开个人中心，验证宽度与首页一致。
- 在窄屏移动视口验证弹窗不超出视口、无横向滚动条，输入框和按钮可操作。
- 在中文、英文及深色主题下进行人工检查，确认文字可读、布局无异常。
- 运行现有前端测试和构建，确认没有回归。
- 本次仅为样式配置调整，不新增业务逻辑测试。

## Out of Scope

- 不重新设计个人中心内容布局。
- 不调整弹窗标题、头像大小、表单间距、服务信息字段或按钮文案。
- 不修改首页、房间页 Header/Footer。
- 不修改其他弹窗的宽度。
- 不新增个人资料字段、头像上传、主题设置或后端能力。

## Further Notes

- 若后续需要统一全站弹窗规范，应另行提出需求，避免本次个人中心宽度调整影响其他功能。
- 当前项目处于开发阶段，本次没有数据结构或兼容性变更。
