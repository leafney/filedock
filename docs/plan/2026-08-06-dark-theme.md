# 全局深色主题与主题切换

## Problem Statement

FileDock 当前只有浅色视觉。页面样式和 Ant Design 组件主题大量使用固定浅色值，首页、房间工作区、聊天、文件、通知中心以及浮层无法统一切换。用户在夜间使用时需要承受较强亮度，且浏览器滚动条、原生控件和 Canvas 雷达可能与页面主题不一致。

## Solution

新增全局三态主题系统：跟随系统（默认）、深色、浅色。用户从右上角头像下拉菜单的“主题模式”二级菜单选择模式，选项前用单选圆点表示当前模式。主题偏好保存在浏览器 `localStorage`，同一浏览器的多个标签页同步；跟随系统模式监听 `prefers-color-scheme` 并实时响应。

使用统一主题状态模块驱动 Ant Design `ConfigProvider` 和项目自定义 CSS 变量。深色主题采用深灰蓝背景层级，保留现有青绿色品牌色和语义颜色含义并调整对比度。主题覆盖整个前端应用、所有浮层、Canvas 雷达和浏览器级主题表现；浅色主题保持现有视觉不变。切换提供约 180ms 过渡并尊重减少动画偏好，首次加载避免主题闪烁。所有用户可见文案补齐 `zh-CN` 与 `en`。

## User Stories

1. 作为首页用户，我希望默认使用跟随系统主题，以便首次打开时符合设备偏好。
2. 作为用户，我希望在头像菜单中看到主题模式入口，以便无需寻找额外设置页。
3. 作为用户，我希望在主题模式菜单中选择跟随系统、深色或浅色，以便按当前环境或个人偏好使用。
4. 作为用户，我希望当前主题选项前显示圆点，以便快速识别当前设置。
5. 作为用户，我希望选择主题后立即看到结果，以便确认操作成功。
6. 作为用户，我希望刷新页面后主题选择仍然保留，以便不必重复设置。
7. 作为用户，我希望手动选择深色或浅色后不被操作系统主题变化覆盖，以便保持个人选择。
8. 作为跟随系统的用户，我希望操作系统切换浅色/深色时页面即时同步，以便无需刷新页面。
9. 作为多标签页用户，我希望在一个标签页切换主题后其他标签页同步变化，以便浏览体验一致。
10. 作为首页用户，我希望品牌栏、房间卡片、表单、空状态和错误状态都适配深色，以便页面没有突兀的浅色区域。
11. 作为房间用户，我希望顶部栏、成员列表、文件列表、文件动态、回收站和容量信息都适配深色，以便房间操作连续可读。
12. 作为聊天用户，我希望聊天气泡、输入框、右键菜单、历史记录和私聊区域都适配深色，以便阅读和发送消息舒适。
13. 作为通知用户，我希望通知中心、通知条目、未读标记和审批弹窗都适配深色，以便通知内容清晰可辨。
14. 作为用户，我希望 Modal、Drawer、Dropdown、Tooltip、Message、Alert 等浮层组件与当前主题一致，以便不会出现白色浮层。
15. 作为用户，我希望品牌青绿色在深色背景上仍清晰可见，以便保持产品识别度。
16. 作为用户，我希望成功、警告、错误、在线和离线颜色仍表达原有含义，以便状态判断不产生歧义。
17. 作为首页用户，我希望雷达 Canvas 的网格、文字、轨迹和背景随主题变化，以便 Canvas 不与页面割裂。
18. 作为用户，我希望头像、文件缩略图及文件内容保持原始颜色，以便内容本身不被主题滤镜改变。
19. 作为移动端用户，我希望头像菜单和主题模式入口保持可用，以便小屏幕也能切换主题。
20. 作为键盘用户，我希望主题菜单支持焦点移动、Enter/空格选择，以便不依赖鼠标操作。
21. 作为辅助技术用户，我希望当前主题选项暴露明确的选中状态，以便理解当前设置。
22. 作为对动画敏感的用户，我希望系统减少动画时主题立即切换，以便避免不适。
23. 作为用户，我希望首次加载时直接显示正确主题，不经历浅色到深色的闪烁。
24. 作为移动浏览器用户，我希望浏览器顶部栏颜色与当前主题一致，以便页面外观统一。
25. 作为用户，我希望原生滚动条和表单控件与当前主题一致，以便页面边缘没有白色区域。
26. 作为中文用户，我希望主题菜单文案使用简体中文，以便理解选项。
27. 作为英文用户，我希望主题菜单文案使用 English，以便在英文界面中完成设置。
28. 作为维护者，我希望浅色主题现有布局、间距和交互不改变，以便降低回归风险。

## Implementation Decisions

- 建立统一 ThemeProvider/Hook，公开主题模式（`system`、`dark`、`light`）、实际渲染主题、设置方法和系统模式状态。
- `system` 是默认值。读取本地存储时只接受三个合法值；缺失、未知或损坏值回退到 `system`。
- 使用固定的本地存储键；主题偏好只存在浏览器，不新增后端接口、数据库字段、SSE 事件或账户同步。
- 监听 `prefers-color-scheme`：仅当模式为 `system` 时使用其结果，并在媒体查询变化时更新实际主题。
- 监听 `storage` 事件同步其他同源标签页；事件数据无效时按回退规则处理。
- 在 React 根部包裹主题提供者，并把实际主题传给 Ant Design `ConfigProvider`。浅色使用现有主题配置，深色使用 Ant Design `darkAlgorithm`，保留品牌主色、圆角和链接色的产品约束。
- 在文档根节点设置 `data-theme` 和 `color-scheme`，自定义页面通过 CSS 变量引用背景、表面、边框、文字、阴影、交互和语义颜色。
- 将现有自定义 CSS 中影响页面观感的固定浅色值收敛为变量；不得在 React 组件内新增主题分支或用户可见硬编码文案。
- 深色调色板使用深灰蓝背景层级、足够亮度的主文字和次文字、可辨识边框及阴影；浅色变量应复现当前已验证视觉。
- 主题切换为约 180ms 的颜色/背景/边框/阴影过渡；使用减少动画媒体查询禁用过渡。首次初始化阶段不应用过渡类。
- 在 HTML 初始加载阶段读取本地主题并结合系统偏好设置根节点主题，避免 React 挂载前闪烁；无本地值按系统偏好计算。
- 头像下拉菜单新增“主题模式”二级菜单，三项顺序固定为跟随系统、深色、浅色；当前项前显示单选圆点，不显示勾选图标。选择后写入本地存储、立即应用并关闭下拉菜单。
- 主题菜单使用 Ant Design 的可选菜单能力，提供键盘导航和可访问的选中状态；圆点仅是视觉呈现，不能牺牲语义状态。
- 主题菜单及相关辅助文案在 `zh-CN` 和 `en` 词典中同时增加，并通过现有 i18n 类型约束保持结构一致。
- 更新浏览器 `meta theme-color`，使移动端浏览器顶部栏匹配实际主题；设置 `color-scheme` 以适配原生滚动条和表单控件。
- 为 Canvas 雷达渲染器增加主题变化输入或主题色读取机制；主题变更时重新绘制网格、文字、轨迹和背景，避免依赖一次性初始化颜色。
- 文件内容、图片、头像和缩略图不应用主题滤镜；仅调整其周围容器和交互控件。
- 所有页面和浮层均通过统一变量或 Ant Design 主题渲染，包含加载、空数据、错误、审批、通知和右键菜单状态。
- 不修改后端、数据库、文件传输协议、通知协议或权限逻辑。

## Testing Decisions

- 测试关注外部行为和状态转换，不测试具体 React 内部实现或 CSS 选择器细节。
- 为独立主题逻辑模块增加单元测试，覆盖：合法模式解析、缺失/非法本地值回退、system 到实际 light/dark 的解析、系统媒体查询变化、手动模式忽略系统变化、跨标签 storage 更新。
- 复用现有前端 Bun 测试组织方式，不引入新测试框架。
- 手动验收覆盖：
  - 首页和房间页的浅色、深色、跟随系统；
  - 头像菜单二级主题菜单、圆点状态、中文/英文文案；
  - 刷新恢复、非法 localStorage 回退、多标签页同步；
  - 操作系统主题切换时 system 模式即时变化；
  - 全部页面区域、Ant Design 浮层、消息提示、Canvas 雷达和浏览器滚动条；
  - 移动端布局、键盘操作、减少动画偏好和首次加载无闪烁。
- 完成后运行现有前端单元测试和生产构建，并检查浅色页面无明显回归。

## Out of Scope

- 不新增账户级主题偏好、后端存储、数据库迁移或跨设备同步。
- 不提供独立设置页、悬浮主题按钮或除头像菜单以外的入口。
- 不修改文件、图片、头像、缩略图和文档内容本身的颜色。
- 不实现文件预览主题适配或内容编辑器主题（文件预览仍按后续规划）。
- 不重做页面布局、间距、字体、品牌 Logo 或顶部通用样式。
- 不引入 Playwright、截图基准或完整视觉回归平台。

## Further Notes

- 主题实际值与用户选择值应分离：用户选择是三态模式，实际渲染只有 light/dark 两态。
- `system` 模式发生系统变化时只更新实际主题，不覆盖本地保存的 `system` 选择。
- 主题 token 仅用于前端呈现，不属于安全凭证，也不影响业务通知、文件恢复申请或聊天状态。
- 实现应按模块提交 Git，提交信息遵循项目 Conventional Commits 约束；开始编码前需先获得本 PRD 的明确批准。
