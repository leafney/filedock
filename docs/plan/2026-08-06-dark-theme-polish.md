# 深色主题局部显示问题优化

## Problem Statement

全局深色主题上线后，房间工作区仍存在局部浅色样式泄漏。聊天未选择成员时右侧区域显示白色；选择成员后聊天输入区和文本框仍是白色，输入文字对比度错误；文件列表的批量选择按钮在未选中状态显示白色；自定义文件信息弹窗标题栏仍为白色，内容区文字也偏暗。局部颜色不一致破坏深色主题连续性，并影响聊天输入和文件信息阅读。

## Solution

基于现有主题变量和 Ant Design 主题配置补齐深色覆盖。聊天空态、聊天工作区顶部/消息/输入区域使用深色层级；批量选择及批量操作控件使用深色未选中态和青绿色选中态；自定义文件信息弹窗及所有 Ant Design Modal/Drawer 的标题、内容和操作区跟随深色主题；信息字段提高对比度。浅色模式保持现状，不修改后端、数据库或业务行为。

## User Stories

1. 作为深色主题用户，我希望未选择聊天成员时右侧区域也是深色，以便房间页面没有白色断层。
2. 作为深色主题用户，我希望聊天顶部用户信息栏使用独立深色面板，以便清晰区分聊天对象和消息区。
3. 作为深色主题用户，我希望聊天消息列表使用深色渐变，以便消息内容和空白区域层次清楚。
4. 作为深色主题用户，我希望聊天空态图标和文字使用灰蓝色，以便在深色背景上可读但不刺眼。
5. 作为聊天用户，我希望输入区使用深色面板，以便输入区域与页面主题一致。
6. 作为聊天用户，我希望 textarea 使用独立深色表面，以便输入内容和输入区边界清晰。
7. 作为聊天用户，我希望输入文字为浅灰白色，以便输入内容清晰可见。
8. 作为聊天用户，我希望占位文字为灰蓝色，以便与实际输入内容区分。
9. 作为聊天用户，我希望输入框聚焦时显示青绿色描边，以便知道当前输入焦点。
10. 作为聊天用户，我希望发送按钮继续使用青绿色主色，以便保持操作识别度。
11. 作为文件管理用户，我希望批量选择按钮未选中时使用深色表面，以便不再出现白色按钮。
12. 作为文件管理用户，我希望批量选择按钮悬停时使用青绿色反馈，以便知道按钮可操作。
13. 作为文件管理用户，我希望批量选择按钮选中时使用青绿色边框、深青绿色背景和青绿色图标文字，以便识别批量模式。
14. 作为文件管理用户，我希望批量操作栏使用深青绿色背景，以便与批量模式状态一致。
15. 作为文件管理用户，我希望批量下载和批量发送按钮使用深色表面与青绿色描边，以便在操作栏中保持可读。
16. 作为文件管理用户，我希望文件列表原生复选框在深色主题下可见且选中态使用青绿色。
17. 作为用户，我希望文件信息弹窗标题栏使用深色背景，以便弹窗与页面主题一致。
18. 作为用户，我希望文件信息弹窗标题文字使用浅色主文字，以便清晰阅读。
19. 作为用户，我希望文件信息弹窗关闭按钮使用灰蓝色并在悬停时变为青绿色，以便保持交互反馈。
20. 作为用户，我希望文件信息字段卡片使用深色表面，以便字段分组清晰。
21. 作为用户，我希望文件名、大小、上传者等字段值提高对比度，以便快速读取。
22. 作为用户，我希望 Modal、Drawer 的标题、内容和底部操作区都适配深色，以便任何弹窗都不出现白色区域。
23. 作为移动端用户，我希望聊天输入区、批量按钮和弹窗样式与桌面端深色规则一致，以便跨设备体验统一。
24. 作为浅色主题用户，我希望本次修复不改变浅色布局、颜色和交互，以便已有视觉不回归。
25. 作为维护者，我希望本次修复只涉及主题呈现，不触碰聊天、文件、通知业务逻辑，以便降低风险。

## Implementation Decisions

- 继续使用现有 `data-theme="dark"` 和 FileDock 主题变量，不新增主题模式或存储键。
- 聊天空态、聊天工作区、顶部标题区、消息列表和输入区分别使用页面、面板、内容区三个深色层级；消息气泡保持既有深色主题规则并确保主文字对比度。
- 深色聊天输入区使用主题面板色；textarea 使用独立表面色，文字使用主文字色，占位符使用次级文字色，边框使用主题边框色，焦点保留青绿色描边。
- 批量选择按钮按 `未选中 / 悬停 / 选中 / 禁用` 四种状态提供深色样式；选中态使用主题主色和深青绿色背景，未选中态不得使用白色背景。
- 批量操作栏及其中的下载、发送按钮同步使用深色表面和青绿色描边；原生复选框依赖 `color-scheme` 并补充主题选中色。
- 自定义 `.room-overlay` 文件信息弹窗的 section、header、内容字段卡片和关闭按钮增加深色覆盖；标题栏不得继续使用白色。
- Ant Design Modal、Drawer、Message、Alert 等继续由 `ConfigProvider` 深色算法提供基础主题；必要时增加局部 CSS token 覆盖，确保标题、内容和 footer 不出现浅色泄漏。
- 文件信息字段标签使用次级灰蓝色，字段值使用主文字色；不改变字段顺序、布局、间距或数据。
- 浅色主题规则不修改，所有新增覆盖必须限定在 `html[data-theme="dark"]` 下。
- 不修改 React 业务状态、API、SSE、数据库和权限逻辑；不新增用户可见文案，因此不新增 i18n 键。

## Testing Decisions

- 测试关注主题下的外部视觉行为和现有业务不回归，不测试具体 CSS 实现细节。
- 运行现有前端 Bun 单元测试，确认聊天、文件和通知业务逻辑未受影响。
- 运行生产构建，确认主题样式和 Ant Design 覆盖可以正常打包。
- 执行 `git diff --check` 检查格式。
- 手动验收至少覆盖：
  - 深色模式下未选成员聊天空态；
  - 深色模式下选中成员的聊天顶部、消息列表、输入框、占位符和发送按钮；
  - 批量选择按钮未选中、悬停、选中、退出批量和批量操作栏；
  - 文件信息弹窗标题、关闭按钮、字段标签和值；
  - 文件删除/恢复等 Ant Design Modal、首页 Drawer、移动端聊天浮层；
  - 浅色模式对照检查。

## Out of Scope

- 不新增主题切换入口、主题模式或主题存储机制。
- 不调整浅色模式视觉，不重做布局、尺寸、字体或交互。
- 不修改聊天、文件、批量操作、通知、恢复审批的业务逻辑和接口。
- 不修改文件内容、图片、头像或缩略图本身的颜色。
- 不引入 Playwright、截图基准或新的端到端测试框架。

## Further Notes

- 本次修复属于全局深色主题的回归收口，样式应优先复用已有 `--fd-*`、`--room-*` 主题变量。
- 截图中的白色文件信息标题来源于自定义弹窗，不应只修复 Ant Design Modal。
- 所有提交继续遵循 Conventional Commits：type/scope 使用英文，描述使用简体中文。
