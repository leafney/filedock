# FileDock 一期收口 PRD

状态：已完成

日期：2026-08-03

修订说明：根据用户反馈，将原先完整发布审计式验收简化为 10 个核心手动场景。自动测试由 Agent 执行，不计入用户手动验收项目。验收发现成员事件缺少明确反馈，本次补充当前房间页的成员加入临时消息规则。

## Problem Statement

FileDock 已实现匿名身份、房间生命周期、SSE、在线状态、二维码和共享／私密文件传输，但这些能力尚未经过一次连贯的真实浏览器手动验证。

上一版收口规格把所有历史 PRD 验收条目、权限角色、设备信息和失败模板全部展开，形成 71 个检查项目。该方式超出用户需求。用户只需要通过少量核心场景判断一期主流程是否可用；自动测试已经覆盖大量权限、容量和状态边界，不需要在人工验收中机械重复。

## Solution

一期收口改为轻量手动验证：Agent 先运行现有自动质量门禁，再启动服务并提供访问地址。用户使用三个独立浏览器会话，按固定顺序完成 10 个核心场景。每个场景只记录“通过”或“失败”；只有失败时才补充问题详情。

用户负责在验收前自行删除 `data` 目录中的旧数据库数据。Agent 不删除或清理数据库。发现范围内缺陷后，Agent 按单个问题修复、运行相关测试，再交给用户复验。

## User Stories

1. 作为用户，我希望用少量连续步骤验证一期主流程，以便快速判断项目是否可继续开发。
2. 作为首次访问者，我希望创建匿名身份并在刷新后恢复，以便确认会话可用。
3. 作为房主，我希望创建房间并让其他浏览器加入，以便确认基础协作链路。
4. 作为房主，我希望验证 PIN 或审批加入，以便确认受保护房间可用。
5. 作为成员，我希望看到其他成员和在线状态，以便确认 SSE 同步可用。
6. 作为成员，我希望上传和下载共享文件，以便确认核心传输链路。
7. 作为成员，我希望发送、接收和拒绝私密文件，以便确认基础隐私规则。
8. 作为上传者，我希望复用已有文件并看到容量正确变化，以便确认文件复用逻辑。
9. 作为房主或成员，我希望验证退出、踢出和解散，以便确认生命周期终止操作。
10. 作为手机与 English 用户，我希望核心操作仍可完成，以便确认基本响应式和双语能力。
11. 作为减少动态效果用户，我希望首页持续动画停止，以便避免视觉不适。
12. 作为验收人，我希望只在失败时记录详情，以便验收文档保持简短。

## Implementation Decisions

### 1. 范围

- 本阶段只验证并修复现有一期功能，不开发新功能。
- 后续已批准 PRD 仍优先于原始总 PRD。
- Range、哈希、续传、分块、预览、聊天、回收站、全局通知中心和发布部署不属于一期缺陷。
- 不整理历史文档，不重放历史验收中的所有细项。

### 2. 自动质量门禁

人工验收前由 Agent 执行：

1. Go 全包测试。
2. 前端现有 Bun 测试。
3. TypeScript 与 Vite 生产构建。
4. `git diff --check`。

自动结果只在验收记录顶部写一段摘要，不拆成用户手动项目。任一自动检查失败时，先修复，再开始人工验收。

### 3. 验收环境

- 会话 A：桌面浏览器，房主。
- 会话 B：另一个独立桌面浏览器或独立浏览器配置，成员甲。
- 会话 C：同一局域网中的真实手机浏览器，成员乙。
- 三个会话必须拥有独立 Cookie；不要求额外建立五个长期会话。
- 用户在开始前自行删除 `data` 目录中的旧数据库数据，并明确通知 Agent。
- Agent 不执行数据库删除、迁移清理或验收后清理。
- 文件样本只需一个小文件、一个可观察进度的中等文件；文件名至少包含一次中文或空格。

### 4. 十个手动场景

#### 场景 1：匿名身份

- A、B、C 分别创建匿名身份。
- 刷新后仍恢复各自身份。
- 任一会话修改昵称后，相关页面最终显示新昵称。

#### 场景 2：开放房间

- A 创建开放房间。
- B 通过房间号或分享链接加入。
- A、B 均能进入同一房间并看到正确成员。

#### 场景 3：受保护房间

- A 创建 PIN 房间或房主审批房间，二选一完成主流程。
- PIN 模式验证一次错误 PIN 和一次正确 PIN；审批模式验证一次申请和批准。
- 另一种模式只做基本入口检查，不要求完整重复流程。

#### 场景 4：成员与 SSE

- A、B、C 同时进入房间。
- 三方成员列表和在线状态最终一致。
- 一个会话离开或关闭后，其他会话能看到状态变化。

#### 场景 5：共享文件

- 任一成员上传共享文件。
- 其他成员能看到并通过浏览器原生下载。
- 文件名、列表状态和传输进度基本正确。

#### 场景 6：私密文件

- A 或 B 向另一成员发送私密文件。
- 接收者能接收并下载，也能对另一份私密文件执行拒绝。
- 未被选中的第三个会话看不到私密文件完整信息。

#### 场景 7：复用与容量

- 上传者选择已有私密文件再次发送。
- 复用不重新上传文件内容。
- 房间容量不会因为复用重复增加。

#### 场景 8：生命周期结束

- 验证一次普通成员退出。
- 验证一次房主踢出成员。
- 最后由房主解散房间，其他会话收到状态变化并停止新操作。

#### 场景 9：手机与 English

- C 在真实手机上完成加入、查看文件和一次核心文件操作。
- 任一会话切换到 English，检查首页、房间和主要操作无明显缺失翻译或布局阻断。

#### 场景 10：减少动态效果

- 开启系统或浏览器减少动态效果。
- 首页水波和节点持续动画停止。
- 首页结构、身份和房间入口仍可正常使用。

### 5. 验收记录格式

- 验收文件只保留环境简表、自动检查摘要、10 个场景和最终结论。
- 每个场景只填写：`待验收`、`通过`、`失败`、`不适用`。
- 通过时不填写冗长证据。
- 失败时记录场景、复现步骤、期望结果、实际结果和截图或错误信息；修复后追加复验结果。
- Agent 不得替用户填写人工“通过”。

### 6. 缺陷处理

- 无法建立身份、加入房间、上传、下载或页面崩溃：必须修复。
- 越权、隐私泄漏、容量错误、错误用户收到 SSE：必须修复并增加回归测试。
- 影响主操作的移动端、双语或焦点问题：必须修复。
- 不影响使用的小型视觉问题由用户决定是否阻断。
- 每次只处理一个已复现问题；修改一个主要文件后等待用户确认。
- 修复改变已批准行为时，先更新 PRD并重新获得批准。

### 7. 国际化

- 修复涉及的用户文案必须同时支持 `zh-CN` 和 `en`。
- React 组件不得硬编码用户文案。
- 新增后端错误码时同时补齐两种语言，并通过词典完整性测试。
- 后端继续按 `Accept-Language` 生成用户消息，不持久化语言。

### 8. 成员加入临时消息

- 新成员首次加入或重新加入房间后，后端现有 SSE 事件 `room.member_joined` 必须携带 `roomCode`、`userId`、`displayName` 和 `role`。
- 仅当前正在打开对应房间页面的原有成员显示顶部临时消息；消息内容为“成员显示名 + 加入了房间”的双语文案。
- 新加入者本人不显示该消息。首页和其他房间页面不显示该消息。
- 继续复用现有 SSE 连接，不新增 SSE 通道、通知表、通知聚合接口或未读状态。
- 成员加入／退出消息均不写入右上角通知 Icon。通知历史、未读状态和跨页面提醒留到后续全局通知中心实现。
- 后端回归测试覆盖开放加入、PIN 加入和审批加入，确认 `room.member_joined` 包含完整成员信息。

### 9. 实施停止点

1. 本简化 PRD 获得重新批准后，才能修改验收文件。
2. 简化验收文件后，等待用户确认。
3. 自动检查完成并提供服务地址后，等待用户确认数据库已自行清空。
4. 用户逐场景反馈；发现问题时进入单问题修复循环。
5. 十个场景完成后，等待用户明确确认一期收口。

## Acceptance Criteria

1. Go 全包测试通过。
2. 前端现有测试通过。
3. TypeScript 与 Vite 生产构建通过。
4. `git diff --check` 通过。
5. 用户完成三个独立浏览器会话准备。
6. 用户完成 10 个核心手动场景。
7. 匿名身份、开放房间和一种受保护房间主流程通过。
8. 三会话成员与 SSE 基本同步通过。
9. 共享文件上传和下载通过。
10. 私密文件接收、拒绝和第三方基础隔离通过。
11. 文件复用不重复上传或增加容量。
12. 退出、踢出和解散主流程通过。
13. 真实手机、English 和减少动态效果基本验证通过。
14. 所有阻断、安全、权限和数据一致性问题完成修复与复验。
15. 用户明确确认一期收口完成。
16. 新成员首次加入或重新加入时，仅当前房间页的其他成员收到双语顶部临时消息。
17. 新加入者本人、首页、其他房间页和右上角通知 Icon 不显示或记录本次加入消息。

## Testing Decisions

- 不引入 Playwright、浏览器自动化、视觉快照或新测试框架。
- 自动测试验证业务边界；手动场景验证真实浏览器主流程。
- 普通视觉问题不补单元测试。
- 权限、容量、会话、文件状态和复杂状态缺陷修复时增加回归测试。
- 修复后运行相关测试，再重跑完整自动质量门禁。

## Out of Scope

- 逐项重放现有文件传输专项的全部 50 项人工清单。
- 五个同时在线身份的完整隐私角色矩阵。
- 全浏览器、全操作系统和全设备兼容性矩阵。
- 极限容量、并发和性能压测。
- 一对一聊天、全局通知中心、回收站、预览、哈希、去重、续传、Range 和分块传输。
- 深色主题、管理后台和正式配置增强。
- 发布部署、跨平台产物、安装包、Docker 或运维文档。
- 历史文档整理、能力矩阵和待办清理。
- Agent 删除或清理数据库数据。

## Further Notes

- 本修订取代上一版 71 项完整审计式验收设计。
- 现有文件传输专项验收保留为历史参考，不要求本阶段逐项勾选。
- 当前前端构建的大分块警告不阻断一期；自动构建成功即可。
- 本 PRD 重新获得用户明确批准前，不得继续修改验收文件或产品代码。
