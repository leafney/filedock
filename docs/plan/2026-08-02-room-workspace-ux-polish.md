# 房间工作区界面优化开发 PRD

Related discussion: [docs/discuss/2026-08-02-room-workspace-ux-polish.md](../discuss/2026-08-02-room-workspace-ux-polish.md)

- 日期：2026-08-02
- 状态：已批准，实施中
- 变更类型：前端信息架构、界面与交互优化
- 影响范围：全局顶栏、用户菜单、个人信息弹窗、房间分享、房间成员栏、文件选择入口、文件列表拖放、响应式样式、双语词典和待办文档

## Problem Statement

当前首页和房间页使用两套不同的顶部区域。首页左侧展示 FileDock 品牌，右侧展示通知与用户菜单；房间页左侧展示返回按钮、房间号和房间标题，中间展示房间摘要，右侧单独展示语言、二维码、当前房间通知和三个点菜单。用户在两个页面之间切换时，需要重新理解品牌入口、用户入口和操作位置。

房间成员栏也存在信息重复。现有“房间会话／成员／人数”与顶栏的成员人数重复，当前房间名称和房间号反而只位于顶栏。房主与普通成员仅能通过列表顺序或业务认知区分，没有稳定且简洁的房主视觉标识。

文件区域存在两个直接问题。用于唤起系统文件选择器的原生文件输入框没有正确隐藏，与现有“添加文件”按钮同时显示；拖放事件只绑定在较小的虚线框，文件拖到共享或私密列表时没有整区反馈。虚线框还能点击选择文件，与顶部按钮职责重复。

此外，用户明确希望未来把通知 Icon 定义为全局通知中心，但完整通知聚合、文件通知和聊天通知不应扩张本期范围。本期需要保留现有审批通知作为过渡，并把完整全局通知中心记录到待办事项。

## Solution

首页与房间页使用统一的顶栏内容组件。两者共享品牌区域、用户区域、尺寸、图标、间距、菜单和响应式规则；首页继续使用原有浅灰页面外壳，房间页继续使用白色固定顶栏和底部分隔线。房间页品牌区域替代返回箭头，点击后返回首页；房间摘要保留在顶栏中间；右侧改为分享、通知、头像、昵称和下拉箭头。

房间页头像菜单复用首页个人能力，并新增一级菜单“房间操作”。房主通过二级菜单延期或解散房间，普通成员通过二级菜单退出房间。原二维码与三个点入口被移除，分享 Icon 打开扩展后的分享 Modal，统一承载二维码、房间号、加入链接和邀请信息。

左侧成员栏改为房间上下文区域。顶部显示房间名称以及房间号与复制入口，不再显示“房间会话”“成员”或成员数量；下方直接显示成员列表。当前用户保留“我”标识，房主头像左上角通过金色三角和皇冠标识角色。

文件区域只保留顶部“添加文件”作为手动选择入口。原生文件输入框以无障碍方式隐藏；大块虚线框删除，替换为轻量非交互提示。整个文件列表可视内容区接收外部文件拖放，拖入后显示整区浮层，释放后进入待发送区而不是立即上传。文件动态不接受拖放，手机窄屏不显示拖放提示。

## User Stories

1. 作为用户，我希望首页和房间页使用一致的品牌与用户顶栏，以便切换页面时不需要重新寻找常用入口。
2. 作为用户，我希望点击 FileDock 品牌区域返回首页，以便不再依赖房间页单独的返回箭头。
3. 作为桌面用户，我希望顶栏显示完整的 FileDock 图标、名称和 Slogan，以便明确当前产品身份。
4. 作为手机用户，我希望顶栏保留 FileDock 图标与名称但隐藏 Slogan，以便有限空间仍能识别产品。
5. 作为房间成员，我希望顶栏中间继续显示成员人数、剩余时间和房间容量，以便快速掌握房间状态。
6. 作为用户，我希望房间页右侧的分享、通知和用户入口顺序固定，以便形成稳定操作习惯。
7. 作为用户，我希望房间页头像菜单继续提供与首页相同的个人信息和语言切换，以便个人能力不因页面改变。
8. 作为用户，我希望房间操作位于头像菜单中的独立一级子菜单，以便个人菜单含义清楚且房间操作不会平铺混杂。
9. 作为房主，我希望在“房间操作”二级菜单中延期房间，以便继续使用现有生命周期能力。
10. 作为房主，我希望在“房间操作”二级菜单中解散房间，并看到明确危险样式与二次确认，以便避免误操作。
11. 作为普通成员，我希望在“房间操作”二级菜单中退出当前房间，以便不同角色使用一致菜单入口。
12. 作为用户，我希望房间页可以打开与首页相同的个人信息 Modal，以便修改昵称、查看注册时间和服务版本。
13. 作为用户，我希望分享 Icon 的语义就是分享房间，而不是打开延期或解散菜单，以便图标与行为一致。
14. 作为邀请者，我希望分享 Modal 同时提供二维码与加入链接，以便适配手机扫码和电脑链接两种加入方式。
15. 作为邀请者，我希望一键复制房间号，以便通过其他沟通工具发送简短编号。
16. 作为邀请者，我希望一键复制加入链接，以便接收者直接打开房间页面。
17. 作为邀请者，我希望一键复制完整邀请信息，以便发送包含房间名称、房间号和链接的可读消息。
18. 作为房间管理者，我希望分享链接不包含 PIN 或审批凭证，以便分享行为不会降低房间安全性。
19. 作为桌面用户，我希望分享内容继续使用居中 Modal，以便与当前二维码查看方式一致。
20. 作为手机用户，我希望分享 Modal 从底部弹出，以便在窄屏中操作二维码和复制按钮。
21. 作为用户，我希望通知 Icon 保留在首页和房间页相同位置，以便未来接入全局通知时不再调整布局。
22. 作为当前房间房主，我希望本期仍能在房间页处理当前房间的加入审批，以便顶栏改造不丢失现有能力。
23. 作为普通成员，我希望本期房间页通知 Icon 清楚显示为禁用，以便不会误以为自己能处理当前房间审批。
24. 作为房间成员，我希望左侧顶部显示当前房间名称和房间号，以便品牌信息移入顶栏后仍能确认房间上下文。
25. 作为房间成员，我希望左侧不重复显示成员数量和“成员”标题，以便区域更简洁。
26. 作为房间成员，我希望房间名称过长时不破坏布局，并能查看完整名称。
27. 作为房间成员，我希望当前用户继续显示“我”标识，以便在列表中定位自己。
28. 作为房间成员，我希望通过头像角标快速识别房主，以便知道谁拥有管理权限。
29. 作为中英文用户，我希望房主角标不受文字长度影响，并能读取本地化 Tooltip 与无障碍说明。
30. 作为平板或手机用户，我希望成员抽屉与桌面侧栏显示相同的房间信息和角色标识，以便设备切换后结构一致。
31. 作为上传文件的用户，我希望页面只显示一个手动选择入口，以便不会困惑两个选择文件控件有什么区别。
32. 作为使用辅助技术的用户，我希望隐藏的原生文件输入和表单标签仍保留可访问语义，以便文件选择与筛选可以正常使用。
33. 作为桌面用户，我希望文件列表顶部显示简短拖放提示，以便知道列表支持拖放添加。
34. 作为桌面用户，我希望文件拖到共享或私密文件列表的任意可视位置时都能触发高亮，以便不必瞄准小范围目标。
35. 作为桌面用户，我希望拖入文件后看到覆盖整个列表内容区的反馈，以便确认页面已识别文件。
36. 作为桌面用户，我希望文件经过列表子元素时浮层保持稳定，以便不会反复闪烁。
37. 作为文件列表用户，我希望正常点击、滚动、下载、菜单和批量选择不受拖放能力影响，以便原有操作可靠。
38. 作为上传文件的用户，我希望释放文件后进入待发送区，以便继续选择共享／私密范围与接收者。
39. 作为查看文件动态的用户，我希望文件动态只用于查看记录，以便不会意外接收拖放文件。
40. 作为手机用户，我希望页面隐藏无效拖放提示并保留“添加文件”按钮，以便优先完成主要文件操作。
41. 作为中英文用户，我希望全部新增文案和邀请文本使用当前界面语言，以便语言体验完整。

## Implementation Decisions

### 1. 变更边界

- 本 PRD 只修改前端组件、查询组合、界面状态、样式、双语词典和待办文档。
- 不修改数据库表、后端接口、上传协议、文件权限、传输队列、SSE 协议或房间生命周期规则。
- 本期不实现真正的全局通知中心，不新增通知类型，不聚合文件或聊天通知。
- 首页现有布局主体、雷达区域和房间卡片不在本期重构；只调整其顶栏以复用统一组件。
- 文件拖放与顶部“添加文件”必须进入同一个现有文件草稿与待发送流程。

### 2. 统一顶栏模块

- 提取可复用顶栏内容模块，至少提供品牌区域、可选中间区域、通知入口、用户菜单和页面扩展操作插槽。
- 首页和房间页必须使用同一个品牌与用户区域实现，禁止复制两套头像菜单或响应式规则。
- 首页允许不传中间区域与分享操作；房间页传入房间摘要和分享按钮。
- 统一头像尺寸、昵称字体、下拉箭头、图标按钮尺寸、焦点样式、间距和 Tooltip 风格。
- 顶栏内容结构统一，但页面外壳保留差异：首页继续位于浅灰页面和既有最大宽度内；房间页继续全宽、白色、固定高度并带底部分隔线。
- 顶栏不得改变现有房间主工作区高度计算，房间内容和底部传输栏仍完整占据剩余视口。

### 3. 品牌与导航

- 品牌区域显示现有 FD 标识、`FileDock` 名称和现有品牌 Slogan，不新增另一套品牌文案。
- 品牌区域整体使用可导航语义，目标为首页根路由，并提供本地化无障碍名称。
- 房间页删除独立返回箭头和原房间顶栏中的 FD 方块，避免重复导航与品牌。
- 首页品牌视觉与文案保持当前效果，只增加一致的可点击返回行为。
- 手机窄屏保留 FD 标识和 `FileDock`，隐藏 Slogan。

### 4. 房间顶栏中间摘要

- 房间页继续展示成员人数、剩余时间和房间容量；数据来源、倒计时和容量详情行为保持不变。
- 成员人数只在顶栏中间展示，成员侧栏不再重复。
- 桌面和平板按可用宽度保留现有摘要；手机窄屏继续隐藏摘要，不把它挤入紧凑全局顶栏。
- 容量摘要继续可点击并打开现有容量详情。

### 5. 顶栏右侧顺序

- 房间页桌面端从左到右固定为：分享 Icon、通知 Icon、用户头像、用户昵称、下拉箭头。
- 房间页删除独立语言选择器、独立二维码 Icon 和三个点 Icon。
- 语言切换进入用户菜单；二维码进入分享 Modal；延期、解散和退出进入“房间操作”子菜单。
- 手机窄屏保留分享、通知和头像，隐藏昵称和下拉箭头；点击头像仍能打开菜单。
- 图标按钮必须提供中英文 `aria-label` 和 Tooltip，不依赖图标形状作为唯一说明。

### 6. 用户菜单与个人信息

- 统一用户菜单保留首页现有一级菜单“个人信息”和语言切换。
- 房间页额外增加一级菜单“房间操作”，该菜单使用标准子菜单结构，不把房间动作与个人动作平铺。
- 房主子菜单：当现有 `canExtend` 为真时显示“延期房间”；始终显示“解散房间”。延期资格判断保持现有规则，不能绕过后端校验。
- 普通成员子菜单：只显示“退出房间”。
- “解散房间”使用危险颜色并执行现有二次确认；“退出房间”继续执行现有二次确认。
- 菜单执行后关闭，并遵循现有成功刷新、导航和错误展示逻辑。
- 房间页个人信息打开与首页同一个 Modal，不实现简化版本。
- 个人信息 Modal 继续支持昵称修改、随机昵称、注册时间、服务信息和重置身份。
- 房间页必须获得用户自建房间状态，以复用现有重置限制；存在有效或销毁中的自建房间时不能重置身份。
- 修改昵称成功后，统一更新会话和相关房间查询，确保顶栏、成员列表和后续页面显示一致。

### 7. 分享入口与 Modal

- 分享 Icon 只负责分享，不承载延期、解散或退出操作。
- 点击分享 Icon 打开扩展后的分享 Modal；复用现有二维码查询和错误处理，不创建第二套二维码接口。
- 桌面 Modal 居中显示；手机沿用现有房间弹层规则，从底部弹出。
- Modal 标题为本地化“分享房间／Share room”。
- 内容显示房间名称、房间号、二维码和完整加入链接。
- 加入链接根据当前页面 `origin` 与房间路由构造，使用当前服务协议、主机和端口，不能写死开发地址。
- 加入链接只包含房间路由和房间号，不附加 PIN、审批令牌、会话标识或其他敏感查询参数。
- 打开链接后继续执行现有免验证确认、PIN 验证或房主审批流程。
- 提供“复制房间号”“复制链接”和“复制邀请信息”三个明确按钮。
- 中文邀请模板包含邀请语、房间名称、房间号和加入链接；英文使用对应英文模板。
- 邀请信息不包含房间密码、审批状态、邀请人昵称或内部房间标识。
- 每次复制成功显示本地化短反馈；失败时显示可理解错误，不静默失败。
- Modal 支持关闭按钮、遮罩关闭和 `Escape`，并遵循现有焦点管理。

### 8. 通知过渡方案

- 通知 Icon 保留在统一位置，但本期不实现全局通知数据源。
- 首页继续使用现有逻辑：根据用户有效自建房间查询加入审批，显示待处理数量并打开首页现有通知面板。
- 房间页继续使用现有逻辑：只有当前房间房主查询并处理当前房间加入审批。
- 普通成员在房间页显示禁用通知 Icon，不显示角标，并提供本地化禁用说明。
- 本期不得新增全局通知接口、通知表、通知聚合 Hook 或第二条 SSE 连接。
- 完整全局通知中心写入待办：未来首页和房间页使用同一用户级数据源，并扩展文件与聊天通知。

### 9. 左侧房间信息与成员列表

- 成员栏顶部不再显示“房间会话”“成员”或成员数量。
- 顶部主要文字显示当前房间名称；单行溢出时省略，鼠标悬停或键盘聚焦可以查看完整名称。
- 次要行显示本地化“房间”与四位房间号，并提供复制按钮和复制成功反馈。
- 房间信息与成员列表之间使用现有边界风格区分；信息区下方直接进入成员列表，不增加第二个成员标题。
- 当前用户继续参与正常列表顺序，并在昵称旁显示本地化“我／Me”标签。
- 桌面侧栏和平板／移动端成员抽屉复用同一房间信息和成员条目。
- 房主踢人、在线状态、列表滚动和成员数据来源保持不变。

### 10. 房主头像角标

- 房主成员的头像使用相对定位包装层，左上角覆盖一个以左上角为直角顶点的金色三角区域。
- 三角区域内显示小型皇冠图标，不显示“房主”文字，避免遮挡头像与中英文长度差异。
- 皇冠和三角必须在浅色头像背景、悬停背景以及移动端抽屉中保持足够对比度。
- 房主角标提供本地化 Tooltip“房主／Owner”和可访问名称，不能只依赖金色表达角色。
- 角标不能改变头像整体尺寸、成员行高度或昵称对齐。
- 当前用户若同时是房主，头像显示房主角标，昵称旁同时保留“我”标签。

### 11. 原生文件输入框隐藏

- 原生多文件输入框继续承担系统文件选择能力，不能删除。
- 为当前视觉隐藏类补齐标准无障碍样式：元素脱离视觉布局、压缩尺寸并裁剪，但不使用 `display: none`。
- 同一视觉隐藏类还用于搜索和筛选的辅助标签；这些标签修复后也不得出现在可见布局。
- 顶部“添加文件”按钮保持当前样式、图标和点击行为，是唯一可见的手动选择入口。
- 选择完成后继续清空原生输入值，保证连续选择同一个文件仍会触发变更。
- 常驻拖放提示不能点击，也不能再次触发文件选择器。

### 12. 常驻拖放提示

- 删除现有大块虚线拖放按钮、虚线边框、辅助文字和点击处理。
- 文件列表顶部增加一条非交互提示，中文为“将文件拖放到列表区域添加”，英文为“Drop files onto the list to add them”。
- 提示只使用轻量文本排版，不模拟按钮，不获得键盘焦点，不包含“点击选择文件”。
- 手机窄屏隐藏常驻提示，顶部“添加文件”保持可用。

### 13. 文件列表整区拖放

- 拖放监听安装在文件列表内容外层，不安装在文件动态视图，也不提升到整个房间页面。
- 有效目标覆盖常驻提示、共享分组、私密分组、文件行、空状态、加载更多和列表留白所在的整个可视内容区。
- 顶部房间文件工具栏、页签、搜索和筛选栏不被拖放浮层覆盖。
- 只有拖拽数据类型包含外部 `Files` 时才激活；文本拖动、页面内部元素拖动和文字选择不激活。
- 有效 `dragover` 阻止浏览器默认打开文件，并设置复制语义。
- 使用拖拽层级计数处理子元素边界：有效进入时递增，离开时递减，只有计数归零才关闭浮层。
- `drop`、拖出和清理路径必须重置计数与激活状态，不能残留高亮。
- 释放时读取全部外部文件；文件集合为空时不打开待发送区。
- 有文件时调用现有草稿添加逻辑并打开待发送区，不能在释放回调中直接创建上传批次。
- 待发送区继续要求确认共享／私密范围；私密发送继续要求至少一个接收者。

### 14. 拖放浮层

- 浮层只在外部文件位于有效列表区域时渲染，正常状态完全不存在。
- 浮层覆盖文件列表可视内容区，使用浅绿色半透明背景、上传图标和居中文案。
- 激活文案中文为“释放文件以添加”，英文为“Drop to add files”。
- 浮层不显示文件名、数量、大小或发送范围。
- 浮层使用 `pointer-events: none`，事件由外层列表处理，不能拦截点击。
- 浮层层级高于文件分组与文件行，但低于全局 Modal、移动端操作面板和底部传输任务面板。
- 正常状态下，下载、接收并下载、拒绝、三个点菜单、折叠、加载更多、搜索、筛选、滚动和批量选择全部保持可用。
- 减少动态效果环境下不得依赖动画表达拖入状态。

### 15. 响应式规则

- 桌面显示完整品牌、Slogan、房间摘要、分享、通知、头像、昵称和箭头。
- 平板按现有断点隐藏常驻成员栏并通过成员抽屉查看；顶栏在不溢出的前提下保留摘要与主要操作。
- 手机显示品牌 Icon 与名称、分享、通知和头像；隐藏 Slogan、房间摘要、昵称和下拉箭头。
- 手机成员抽屉显示房间名称、房间号、成员列表、房主角标和“我”标识。
- 手机文件列表隐藏常驻拖放提示，不增加拖放入口。
- 所有断点不得出现顶栏重叠、横向滚动、菜单超出视口或长房间名称挤压操作按钮。

### 16. i18n

- 所有新增或修改的用户可见文案使用 i18n 翻译键，不在 React 组件中硬编码。
- 简体中文与英文必须同时补齐，词典键结构一致且值非空。
- 至少覆盖：分享房间、复制链接、复制邀请信息、邀请模板、房间操作、房主 Tooltip、通知禁用说明、常驻拖放提示和释放提示。
- 用户昵称、房间名称、房间号、文件名、URL 和内部状态值不翻译。
- “添加”表示进入待发送区，不能使用暗示立即传输的文案。

### 17. 实施顺序

1. 提取统一顶栏内容模块、用户菜单和可复用个人信息 Modal，先迁移首页且保持首页既有行为。
2. 将房间页接入统一顶栏，完成品牌导航、中间摘要、右侧顺序、响应式规则和通知过渡。
3. 实现用户菜单“房间操作”子菜单，迁移延期、解散和退出操作，删除三个点与独立语言入口。
4. 扩展二维码弹窗为分享 Modal，增加安全加入链接和三种复制操作，删除独立二维码 Icon。
5. 重构成员栏为房间信息头部，增加房主三角皇冠角标和“我”标识共存规则。
6. 修复视觉隐藏类，确保原生文件控件与辅助标签不再出现在可见布局。
7. 删除虚线拖放框，增加常驻提示、整区拖放状态与浮层。
8. 补齐双语词典、移动端样式和 `todo.md` 全局通知事项。
9. 运行自动检查并执行桌面、平板和手机人工验收。

## Acceptance Criteria

### 顶栏与菜单

1. 首页和房间页品牌、头像、昵称、图标按钮、菜单和响应式尺寸一致。
2. 首页保留浅灰外壳，房间页保留白色固定顶栏与底部分隔线。
3. 房间页左侧显示 FileDock Icon、名称和 Slogan，不再显示返回箭头或重复 FD 标识。
4. 点击品牌区域可以返回首页，键盘可聚焦并触发。
5. 房间页中间成员数、倒计时和容量数据正确，容量详情仍可打开。
6. 桌面房间页右侧顺序为分享、通知、头像、昵称、下拉箭头。
7. 房间页不再显示独立语言选择、二维码 Icon 或三个点 Icon。
8. 头像菜单包含个人信息、语言切换和一级“房间操作”。
9. 房主二级菜单在允许时显示延期，并显示解散；普通成员只显示退出。
10. 解散和退出继续要求确认，失败仍显示可理解错误。
11. 房间页个人信息 Modal 与首页内容和行为一致。
12. 手机顶栏只显示 FileDock Icon 与名称、分享、通知和头像，无重叠或横向滚动。

### 分享与通知过渡

13. 点击分享 Icon 打开分享 Modal，桌面居中、手机从底部弹出。
14. 分享 Modal 正确显示房间名称、房间号、二维码和当前服务地址生成的加入链接。
15. 加入链接不包含 PIN、审批令牌或会话信息。
16. 复制房间号、复制链接和复制邀请信息均可操作，并显示成功或失败反馈。
17. 中英文邀请信息使用对应模板，内容包含房间名称、房间号和链接。
18. 首页通知行为保持不变。
19. 当前房间房主仍能通过房间页通知处理加入审批并看到正确角标。
20. 普通成员在房间页看到禁用通知 Icon，不会请求当前房间审批列表。
21. 本期没有新增全局通知接口、通知表或第二条 SSE。

### 房间信息与成员

22. 左侧顶部显示房间名称、房间号和复制按钮。
23. 左侧不显示“房间会话”“成员”或成员数量。
24. 长房间名称单行省略，并可以查看完整值。
25. 房间信息下方直接显示成员列表。
26. 当前用户昵称旁保留“我／Me”。
27. 房主头像左上角显示金色三角和皇冠，不显示房主文字角标。
28. 房主角标提供中英文 Tooltip 与无障碍说明。
29. 当前用户同时是房主时，皇冠角标与“我”标识同时正确显示。
30. 桌面成员栏和移动端成员抽屉结构一致。

### 文件选择与拖放

31. 页面不再显示浏览器原生“选择文件／未选择任何文件”控件或可见辅助标签。
32. 顶部“添加文件”可以选择多个文件，连续选择同一个文件仍有效。
33. 旧的大块虚线拖放框完全移除。
34. 文件列表顶部只显示“将文件拖放到列表区域添加”，不能点击选择文件。
35. 外部文件拖到共享列表、私密列表、文件行、空状态或留白时均显示整区浮层。
36. 浮层显示“释放文件以添加”，覆盖列表可视内容区但不遮挡顶部工具栏和筛选栏。
37. 文件经过列表子元素时浮层不闪烁；拖出列表时浮层消失。
38. 释放一个或多个文件后打开待发送区，不直接开始上传。
39. 文本拖动和页面内部元素拖动不会激活浮层。
40. 正常状态下，文件列表全部点击、菜单、滚动和批量操作保持可用。
41. 文件动态不显示拖放提示、不接受释放且不出现浮层。
42. 手机窄屏不显示拖放提示，顶部“添加文件”仍可用。

### 质量

43. 简体中文与英文词典键一致、值非空，无新增硬编码用户文案。
44. 前端测试、TypeScript 编译和生产构建通过。
45. 开发者控制台没有新增 React 警告、状态更新循环或未捕获异常。
46. `git diff --check` 通过。

## Testing Decisions

- 本变更以组件组合、浏览器交互和响应式布局为主，不采用 TDD，不新增后端测试。
- 不使用 Playwright；浏览器行为按项目要求进行人工验收。
- 现有前端测试必须继续通过，特别是中英文词典完整性测试。
- 生产构建必须通过，用于检查 TypeScript、未使用导入、菜单类型和打包问题。
- 首页回归验收覆盖品牌返回、通知、头像菜单、个人信息、语言切换、昵称修改和移动端收缩。
- 房间顶栏验收分别使用房主和普通成员身份，覆盖分享、通知、个人菜单、房间操作、延期、解散、退出和容量详情。
- 分享验收覆盖免验证、PIN 和审批三种房间，确认链接均不携带凭证且打开后进入正确验证流程。
- 成员验收覆盖当前用户是房主、当前用户不是房主、房主在线／离线、长昵称和长房间名称。
- 拖放验收覆盖单文件、多文件、拖入后拖出、跨多个子元素、共享分组、私密分组、空列表、文本拖动和文件动态。
- 点击冲突验收覆盖下载、接收并下载、拒绝、三个点菜单、折叠、加载更多、搜索、筛选、滚动和批量选择。
- 响应式人工验收至少覆盖桌面常驻成员栏、平板成员抽屉和手机窄屏。
- 人工验收期间检查控制台，不能出现新增警告或运行时错误。

## Out of Scope

- 不实现完整全局通知中心、通知聚合接口、通知数据库表、通知历史或跨类型未读状态。
- 不增加文件接收、上传完成或聊天消息通知。
- 不实现一对一聊天、聊天附件或回收站。
- 不修改共享文件、私密文件、匿名投影和待接收权限。
- 不改变文件分组、搜索、筛选、排序、分页和批量操作规则。
- 不修改上传下载并发、进度计算、断点续传、Range、分块传输、文件哈希、秒传或物理去重。
- 不让文件动态接受拖放，不增加手机拖放入口。
- 不实现头像上传、头像编辑或自定义房主徽章。
- 不修改后端接口、数据库、房间容量、生命周期或 SSE 协议。
- 不把首页和房间页强制改成相同背景、最大宽度或主内容布局。

## Further Notes

- 本 PRD 的顶栏与成员栏决定覆盖第一轮“成员栏顶部显示当前用户头像、昵称和在线状态”的方案。当前用户信息最终位于统一顶栏右侧。
- “全局顶栏”在本期表示统一视觉结构和入口位置，不表示已经完成全局通知数据聚合。
- “分享”是独立房间分享能力；“房间操作”是用户菜单的一级子菜单，两者不能混用。
- “隐藏原生文件输入框”表示隐藏浏览器默认外观，不是删除文件选择能力。
- “添加”表示进入待发送区。用户确认共享／私密范围和接收者后才开始上传。
- 旧讨论曾允许文件动态接收拖放，本次最终决定明确覆盖：文件动态不接受拖放。
- 本 PRD 获得用户重新明确批准后，才能开始修改生产代码。
